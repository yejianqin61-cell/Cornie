## 2. 归档原因

桌宠模块已经完成一次方向性重定义。

旧方案的问题在于：

1. 过度强调角色展示本身。
2. 信息层级太重，更像缩小版聊天页。
3. 与当前“轻陪伴桌面入口”的产品目标不一致。

因此，自 2026-06-28 起，桌宠模块统一以新版设计为准，不再沿用早期角色拼装思路。

## 3. 当前有效模块定义

桌宠模块的当前定义是：

1. 独立透明窗口。
2. 轻陪伴入口。
3. 极简聊天入口。
4. 与主窗口共享同一份当日会话的桌面壳层。

桌宠模块不再承担：

1. 复杂角色展示。
2. 复杂确认卡展示。
3. 工具结果面板展示。
4. 治理型信息展示。

## 4. 当前有效实现原则

当前有效原则如下：

1. 默认仅显示小型颜文字框。
2. 鼠标移入后显示轻量对话浮层。
3. 点击即可输入，回车发送。
4. 一次只显示两条消息，但支持滚动回看。
5. 与主窗口聊天内容实时同步。

## 5. 技术边界

当前桌宠模块仍保留以下技术骨架：

1. Electron 独立 `cornieWindow`
2. 透明、无边框、可拖动窗口
3. 独立渲染入口 `cornie.html`
4. 桌宠渲染组件 `CorniePet.vue`

需要逐步退场的旧实现包括：

1. 旧桌宠调试工具
2. 旧桌宠配置文件
3. 旧桌宠专用动画控制器
4. 与旧展示形态强耦合的样式与资源
