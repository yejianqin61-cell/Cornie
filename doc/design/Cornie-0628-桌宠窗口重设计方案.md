## 1. 背景

当前桌宠窗口已经具备以下基础能力：

1. 独立透明窗口。
2. 可拖动。
3. 可直接发消息给 Cornie。
4. 可展示完整气泡流、确认卡片、工具结果。

但它仍然属于上一代思路，核心问题有四个：

1. 视觉上仍然依赖旧角色拼装形态，与当前产品方向不一致。
2. 交互上过于像“缩小版聊天页”，不够克制。
3. 信息层级过重，把工具结果、确认流、长文本都塞进了小窗。
4. 桌宠没有清楚区分“陪伴层”和“主工作区”。

本次重设计不取消独立桌宠窗口，而是保留这个窗口壳体，彻底重做它的视觉形态、状态机和展示边界。

## 2. 设计目标

本次桌宠窗口的目标是：

1. 把桌宠定义为 `轻陪伴交互层`，不是第二套完整工作台。
2. 默认安静、轻量、不打扰，只在用户靠近时展开。
3. 不再使用旧立绘方案，改用颜文字表达情绪和状态。
4. 与主窗口共享同一份当天聊天上下文，保证消息同步。
5. 只保留最必要的输入、回复、提醒能力，把复杂治理留给主窗口。

一句话概括：

`桌宠窗口应该像趴在桌角陪你说话的小铃湾，而不是一个缩在角落里的后台页面。`

## 3. 新定位

桌宠窗口的新产品定位如下：

1. 陪伴入口。
2. 快速对话入口。
3. 轻提醒入口。
4. 主窗口聊天的桌面镜像壳层。

桌宠窗口不是：

1. 工具执行监控台。
2. 确认中心。
3. 记忆治理台。
4. 复杂列表浏览器。
5. 完整聊天历史浏览页。

## 4. 视觉方案

## 4.1 基础形态

安静状态下，桌宠只显示一个很小的颜文字框。

建议形态：

1. 一个圆角小浮层。
2. 中间显示颜文字。
3. 透明背景悬浮于桌面右下角。
4. 不出现大面积底板，不占视觉重量。

建议示例：

1. 平静：`(•‿•)`
2. 思考：`( •_• )`
3. 开心：`(≧▽≦)`
4. 害羞：`(//▽//)`
5. 提醒：`( •̀ .̫ •́ )`
6. 离线或异常：`(._.)`

## 4.2 展开形态

鼠标移入后，在颜文字框上方浮现轻量对话框。

展开层包含：

1. 顶部两条可视消息区。
2. 底部一条输入框。
3. 极简发送反馈。

不应包含：

1. 大面积功能按钮。
2. 工具结果长卡片。
3. 长确认面板。
4. 后台式标签、状态码、来源说明。

## 4.3 情绪表达

桌宠的“表情”不靠角色立绘动作，而靠三类变化表达：

1. 颜文字切换。
2. 气泡浮现/收起。
3. 微小位移、轻呼吸、轻摇摆。

这意味着桌宠的情感呈现从“形象驱动”改为“文本符号驱动”。

## 5. 状态机设计

建议桌宠窗口采用以下状态机。

## 5.1 状态列表

1. `idle`
2. `hover`
3. `focus`
4. `thinking`
5. `notify`
6. `sleep`

## 5.2 各状态说明

### `idle`

默认静止状态。

表现：

1. 仅显示颜文字框。
2. 输入框与消息框不常驻。
3. 允许拖动。

### `hover`

用户鼠标移入桌宠区域时进入。

表现：

1. 上方浮现对话气泡容器。
2. 可显示最近两条消息。
3. 输入框淡入，但不抢焦点。

### `focus`

用户点击输入框或桌宠主体后进入。

表现：

1. 输入框获得焦点。
2. 可输入并回车发送。
3. 保持最近两条消息可见。

### `thinking`

发送消息后等待模型回复时进入。

表现：

1. 颜文字切换为思考态。
2. 消息区显示“正在想你说的话……”这类轻提示。
3. 不出现技术性 loading 文案。

### `notify`

存在新回复、待查看提醒、轻提醒时进入。

表现：

1. 颜文字切换为提醒态。
2. 可有轻微浮动或边框呼吸。
3. 不自动弹出大面板。

### `sleep`

长时间无交互时进入。

表现：

1. 颜文字进入更安静的状态。
2. 动画频率降低。
3. 仍可被 hover 唤醒。

## 5.3 状态流转

建议主流转如下：

1. `idle -> hover`
2. `hover -> focus`
3. `focus -> thinking`
4. `thinking -> hover`
5. `hover -> idle`
6. `idle -> notify`
7. `notify -> hover`
8. `idle -> sleep`
9. `sleep -> hover`

## 6. 交互规则

## 6.1 鼠标交互

1. 鼠标移入颜文字框，展开上方气泡层。
2. 鼠标移出后，若未锁定且无焦点，延时收起。
3. 点击桌宠主体，不直接打开复杂页面，只进入输入状态。
4. 按住桌宠主体可拖动窗口。

## 6.2 输入交互

1. 点击输入框开始输入。
2. 回车发送。
3. `Shift + Enter` 不建议支持换行，桌宠场景应保持单行短输入。
4. 发送后立即把用户消息压入可视消息区。

## 6.3 消息显示规则

桌宠窗口一次只显示两条消息。

建议规则：

1. 默认显示最近两条。
2. 用户发送后，自己的消息先入列。
3. Cornie 回复后，把用户消息自然顶上去。
4. 支持滚轮向上查看更早上下文。
5. 离开桌宠后，滚动位置可重置到最新。

这套规则保证：

1. 桌宠永远轻。
2. 当前对话足够清楚。
3. 需要回看时仍有滚动能力。

## 6.4 文案规则

桌宠窗口文案必须比主窗口更轻。

例如：

1. 不说“工具执行成功”。
2. 不说“策略判定为 confirm”。
3. 不说“参数缺失”。

而应说成：

1. “小铃湾记下啦。”
2. “这个我想先和你确认一下。”
3. “我还差一点点信息。”

## 7. 与主窗口的同步关系

## 7.1 同步原则

桌宠聊天与主窗口聊天不是两套系统，而是同一份当日会话的两个视图。

必须满足：

1. 在桌宠发出的消息，主窗口立即可见。
2. 在主窗口发出的消息，桌宠也能看到最新结果。
3. 两边共享同一天的对话记录。
4. 两边共享相同的待确认事项来源。

## 7.2 数据同步方式

建议采用统一聊天数据源，而不是桌宠自己维护一套消息状态。

推荐方案：

1. 抽离共享 `chat session store / composable`。
2. 主窗口和桌宠窗口都订阅同一份当日聊天状态。
3. 通过现有 `sendMessage / getConversation / listConfirmations / submitConfirmationDecision` 维持同一后端真源。
4. 窗口间用渲染层事件总线或 Electron IPC 广播“消息新增”“确认状态变化”“数据已刷新”。

## 7.3 同步边界

同步的是：

1. 消息内容。
2. 发送状态。
3. 待确认状态。
4. 新回复提醒状态。

不同步的是：

1. 两个窗口的展开/收起状态。
2. 两个窗口的滚动位置。
3. 两个窗口的输入焦点。

## 8. 桌宠可展示与不可展示边界

## 8.1 可以展示的内容

1. 最近两条聊天消息。
2. 极轻量提醒。
3. 一句话确认提示。
4. 一句话错误恢复提示。
5. 轻量的“记下了”“改好了”“我想确认一下”。

## 8.2 不应展示的内容

1. 工具结果面板。
2. 长确认卡片。
3. 复杂待办、日程、收支列表。
4. 观察日志原文列表。
5. 记忆治理细节。
6. Memory Wiki 页面编辑器。
7. 审计、版本、回滚、合并候选。
8. 技术报错栈。

## 8.3 关于确认流的处理

桌宠场景下不建议展示完整确认卡。

推荐处理：

1. 只显示一句轻提醒：“这件事我想先和你确认一下。”
2. 提供一个“去主窗口看”入口。
3. 或只支持极简二选一确认，前提是内容很短且风险足够低。

现阶段更稳妥的方案是：

1. 桌宠仅提示有待确认事项。
2. 复杂确认统一回到主窗口完成。

## 9. 技术落地建议

## 9.1 Electron 主进程

当前 [main.js](/C:/Users/USER/Desktop/Cornie/Cornie/electron/main.js) 已经保留了独立 `cornieWindow`，这个架构可以继续使用，不需要推翻。

建议改造点：

1. 保留第二窗口。
2. 调整窗口尺寸，使其更接近小浮层而非长条聊天面板。
3. 继续保留透明、无边框、可拖动能力。
4. 后续可增加“收起态尺寸”和“展开态尺寸”的切换。

## 9.2 桌宠渲染层

当前 [CorniePet.vue](/C:/Users/USER/Desktop/Cornie/Cornie/src/renderer/CorniePet.vue) 需要从“旧桌宠渲染组件”重构为“轻交互桌宠组件”。

建议拆分为：

1. `PetShell`
2. `PetFace`
3. `PetBubble`
4. `PetInput`
5. `usePetStateMachine`
6. `useSharedChatSession`

其中：

1. `PetFace` 只负责颜文字和微动画。
2. `PetBubble` 只负责两条消息的轻量展示。
3. `PetInput` 只负责单行输入。
4. `usePetStateMachine` 管状态切换。
5. `useSharedChatSession` 负责和主窗口共享聊天数据。

## 9.3 聊天共享层

当前 [useChat.js](/C:/Users/USER/Desktop/Cornie/Cornie/src/renderer/composables/useChat.js) 已经具备基础复用价值，但它更偏向单页面使用。

下一步建议：

1. 把“消息列表加载”“发送”“确认恢复”“同步通知”提成共享会话能力。
2. 主窗口聊天页与桌宠页共同复用。
3. 补充窗口间状态广播，避免两个窗口各自刷新后出现时序差。

## 9.4 动画与表现层

不再维护：

1. 旧桌宠身体部件拼装。
2. 眼睛覆盖层编辑。
3. 旧立绘眨眼校准工具链。

改为维护：

1. 颜文字状态映射表。
2. 小幅度呼吸动画。
3. hover 浮现动画。
4. notify 轻提醒动画。

这会显著降低桌宠资源维护成本。

## 10. 开发阶段建议

建议按四步落地。

### 阶段 1：状态壳层重建

1. 保留独立桌宠窗口。
2. 去掉现有旧桌宠渲染结构。
3. 实现颜文字框 + hover 浮层 + 单行输入框。
4. 保留基本拖动能力。

### 阶段 2：聊天同步重建

1. 抽离共享聊天会话层。
2. 打通主窗口与桌宠窗口消息同步。
3. 支持桌宠显示最近两条消息与滚动查看。

### 阶段 3：提醒与确认边界收口

1. 把桌宠中的复杂确认卡移除。
2. 改为轻提醒 + 跳转主窗口。
3. 增加新消息提醒态。

### 阶段 4：表现微调

1. 情绪颜文字映射。
2. 收起/展开动效。
3. 安静态与睡眠态节奏。
4. 字体、配色、留白优化。

## 11. 验收标准

桌宠重设计完成后，至少应满足：

1. 默认状态下只看到一个轻量颜文字框。
2. 鼠标移入时，上方浮现轻量聊天气泡层。
3. 点击后可直接输入，回车发送。
4. Cornie 回复后，桌宠与主窗口消息同步。
5. 桌宠一次只显示两条消息，但支持滚动回看。
6. 桌宠不再暴露工具结果卡、复杂确认卡、治理信息。
7. 整体气质更像陪伴层，而不是后台面板。

## 12. 最终结论

桌宠窗口不应该再承担“缩小版完整聊天页”的角色，而应当被重定义为：

`一个极轻、安静、可随时说话、与主窗口共享同一会话的小铃湾桌面陪伴层。`

它保留独立窗口的便利，放弃复杂系统信息的堆叠，把视觉重心从“旧角色展示”切换为“颜文字状态”，把交互重心从“功能展示”切换为“轻陪伴与快速说话”。
