## 1. 设计目标

这份视觉语言方案只服务一个目标：

`让桌宠看起来像一个安静、灵动、愿意陪你说话的小铃湾，而不是一个技术小面板。`

因此视觉上必须同时满足四点：

1. 轻。
2. 暖。
3. 留白。
4. 不后台。

## 2. 总体气质

桌宠窗口的整体气质应定义为：

1. 像贴在桌角的一张会呼吸的小纸条。
2. 像一个随时可以搭话的小陪伴气泡。
3. 像有情绪变化的文字生物，而不是卡通角色立绘。

应避免：

1. 厚重玻璃面板感。
2. 大片深色块压屏。
3. 复杂边框与分割线。
4. 后台式功能按钮堆叠。

## 3. 视觉关键词

建议统一使用以下关键词约束设计：

1. `轻漂浮`
2. `软边缘`
3. `暖纸感`
4. `安静发光`
5. `微表情`
6. `克制反馈`

## 4. 配色方案

## 4.1 主配色方向

桌宠不建议走纯黑半透明聊天框路线。

建议采用：

1. 米白
2. 浅奶油
3. 雾桃粉
4. 淡杏色
5. 很浅的灰蓝作为平衡色

整体像“温热灯光下的便签纸”。

## 4.2 推荐色板

```css
:root {
  --pet-bg: rgba(255, 250, 242, 0.92);
  --pet-bg-soft: rgba(255, 246, 236, 0.82);
  --pet-surface: rgba(255, 255, 255, 0.72);
  --pet-border: rgba(196, 168, 146, 0.24);
  --pet-shadow: rgba(124, 93, 72, 0.14);

  --pet-text: #5b4638;
  --pet-text-soft: #826b5b;
  --pet-text-faint: #a18d80;

  --pet-accent: #efb39a;
  --pet-accent-strong: #df8d70;
  --pet-accent-soft: #f7d8ca;

  --pet-user-bubble: #f6d3c4;
  --pet-cornie-bubble: rgba(255, 255, 255, 0.78);
  --pet-input-bg: rgba(255, 255, 255, 0.68);
  --pet-notify: #f0a66d;
  --pet-danger-soft: #f6d4d0;
}
```

## 4.3 配色原则

1. 背景必须浅，不能压迫。
2. 文字必须偏暖，不要纯黑。
3. 强调色只点到为止，主要用于发送、提醒、焦点。
4. 不用大面积高饱和色块。

## 5. 字体与文字风格

## 5.1 字体方向

桌宠的字体要避免“默认系统后台感”。

建议方向：

1. 中文正文用圆润、低攻击性的无衬线。
2. 颜文字可用更有手感的等宽或半等宽呈现。
3. 数字和时间信息弱化，不抢主文案。

若项目后续引入字体，建议倾向：

1. 中文：更柔和的人文无衬线
2. 英数与颜文字：轻微打字机感或半等宽风格

## 5.2 文案语气在视觉上的体现

视觉语言要配合“小铃湾”的说话方式：

1. 标题不要过硬。
2. 按钮文案短。
3. 尽量不用术语。
4. 提示文案像陪你说话，不像报系统状态。

## 5.3 文字层级

建议只保留三层：

1. 主文案
2. 次文案
3. 极弱辅助文案

不建议出现第四层、第五层信息密度。

## 6. 形状系统

## 6.1 圆角语言

桌宠所有元素都应使用偏软的圆角。

建议：

1. 颜文字小框：`18px - 22px`
2. 消息气泡：`16px - 20px`
3. 输入框：`999px`
4. 浮层容器：`20px - 24px`

不建议：

1. 锐角
2. 直硬矩形
3. 高对比描边

## 6.2 阴影语言

阴影必须很轻。

建议：

1. 用柔和扩散影，不用浓黑投影。
2. 阴影主要是让元素“浮起来”，不是让元素“压下来”。

推荐：

```css
box-shadow: 0 10px 30px rgba(124, 93, 72, 0.14);
```

## 7. 桌宠主体视觉设计

## 7.1 安静态颜文字框

安静态只显示一个极小浮层。

建议参数：

1. 宽度：`72px - 92px`
2. 高度：`42px - 50px`
3. 背景：浅暖色半透明
4. 边框：极淡描边
5. 中间只放一个颜文字

视觉感觉：

1. 不像按钮。
2. 更像一枚会呼吸的小便签徽章。

## 7.2 颜文字设计规则

颜文字不宜太复杂。

建议选型：

1. 默认平静：`(•‿•)`
2. 等待注意：`( •ᴗ• )`
3. 思考中：`( •_• )`
4. 开心：`(≧▽≦)`
5. 害羞：`(//▽//)`
6. 困困：`( ᴗ ᴗ )`

规则：

1. 同一状态尽量固定。
2. 不要每次随机换，避免人格漂移。
3. 变化要和状态机绑定，不要只做装饰。

## 8. 浮层与气泡设计

## 8.1 浮层结构

浮层建议由三块组成：

1. 消息区
2. 输入区
3. 极弱状态反馈区

布局上应强调纵向呼吸感，不要把每块挤得太近。

## 8.2 消息气泡

消息气泡视觉应明显区分“主人”和“小铃湾”，但差异不要过大。

建议：

1. 主人气泡：更暖一点，浅杏粉底
2. 小铃湾气泡：更轻一点，接近白色纸片底
3. 两者都不使用深色底白字

推荐样式：

```css
.bubbleUser {
  background: var(--pet-user-bubble);
  color: var(--pet-text);
}

.bubbleCornie {
  background: var(--pet-cornie-bubble);
  color: var(--pet-text);
}
```

## 8.3 可视消息规则的视觉处理

虽然只显示两条消息，但不能显得“局促”。

因此建议：

1. 两条消息之间保留明显呼吸间距。
2. 每条消息字数多时自动换行，但不超过太宽。
3. 整个浮层宽度以阅读舒适优先，不以尽量小优先。

建议宽度：

1. 浮层宽度 `260px - 320px`
2. 单条气泡最大宽度 `78% - 84%`

## 9. 输入区设计

## 9.1 输入框气质

输入框不能像管理后台搜索框。

建议做成：

1. 柔和胶囊形
2. 很浅的内底色
3. 无硬描边
4. 聚焦时只做暖色外发光

推荐：

```css
.petInput {
  height: 38px;
  border-radius: 999px;
  background: var(--pet-input-bg);
  border: 1px solid rgba(196, 168, 146, 0.18);
}

.petInput:focus {
  outline: none;
  border-color: rgba(223, 141, 112, 0.38);
  box-shadow: 0 0 0 4px rgba(239, 179, 154, 0.16);
}
```

## 9.2 发送按钮

发送按钮建议是一个小圆角胶囊，而不是功能感很重的小方块。

规则：

1. 文案短，建议“说”“发”“送”
2. 默认低存在感
3. 输入非空后再升高强调

## 10. 动效语言

## 10.1 动效原则

桌宠动效必须是“陪伴型动效”，不是“产品炫技动效”。

只允许三类动效：

1. 浮现
2. 呼吸
3. 轻摇

不建议：

1. 过快弹跳
2. 高频闪烁
3. 夸张缩放
4. 持续性抢眼动画

## 10.2 关键动效

### 安静态呼吸

1. 幅度极小
2. 周期较慢
3. 像轻轻起伏

### 浮层展开

1. 从下向上轻浮现
2. 同时透明度从 `0 -> 1`
3. 时长 `180ms - 240ms`

### 新消息提醒

1. 边框或阴影轻轻呼吸 1-2 次
2. 不闪烁
3. 不强制展开

## 11. 状态视觉映射

## 11.1 `idle`

1. 最小尺寸
2. 表情平静
3. 阴影最弱

## 11.2 `hover`

1. 浮层淡入
2. 颜文字稍微更有精神
3. 边框和阴影轻微增强

## 11.3 `focus`

1. 输入框焦点明显
2. 背景更稳定
3. 表情更专注

## 11.4 `thinking`

1. 表情切为思考态
2. 输入区可禁用或弱化
3. 给一句温和等待文案

## 11.5 `notify`

1. 强调色轻度提升
2. 颜文字更鲜活
3. 外圈轻提醒，不自动打断

## 11.6 `sleep`

1. 饱和度更低
2. 呼吸更慢
3. 表情更安静

## 12. 留白与密度规则

桌宠最重要的不是“放下更多信息”，而是“忍住不放”。

建议密度规则：

1. 每个区块至少保留 `10px - 14px` 内间距
2. 文案与边界不要贴太近
3. 浮层内不要出现多列布局
4. 不做密集 icon 栏

## 13. 不该出现的视觉元素

这部分非常重要。

以下元素不应进入桌宠窗口：

1. 大面积深灰黑底
2. 技术面板式边框
3. 复杂图标群
4. 参数标签
5. 工具卡片
6. 数据表格
7. 明显的管理后台按钮样式
8. 需要阅读很多说明文字的提示框

## 14. 与主窗口的视觉关系

桌宠与主窗口要“同产品，不同密度”。

关系应当是：

1. 主窗口是完整生活工作台
2. 桌宠是桌面角落的轻陪伴入口

因此桌宠视觉应当：

1. 比主窗口更软
2. 比主窗口更简
3. 比主窗口更安静
4. 比主窗口更像“情绪对象”

## 15. CSS 变量建议

建议后续把桌宠视觉变量独立成一组，例如：

```css
:root {
  --pet-radius-sm: 16px;
  --pet-radius-md: 20px;
  --pet-radius-pill: 999px;

  --pet-shadow-soft: 0 10px 30px rgba(124, 93, 72, 0.14);
  --pet-shadow-hover: 0 14px 34px rgba(124, 93, 72, 0.18);

  --pet-transition-fast: 160ms ease;
  --pet-transition-base: 220ms ease;
  --pet-transition-slow: 320ms ease;
}
```

这样后续前端实现时，桌宠可以有自己独立的一套视觉系统，而不是借主窗口样式硬凑。

## 16. 最终结论

桌宠前端视觉语言的正确方向，不是去做一个更精致的小组件集合，而是去做一种非常克制的陪伴气质。

它应该让人第一眼感觉到的是：

1. 轻松
2. 可爱
3. 温柔
4. 愿意靠近

而不是：

1. 功能很多
2. 技术很强
3. 面板很复杂
4. 系统感很重

一句话总结：

`小铃湾的桌宠视觉，不该像一只被摆出来展示的角色，而该像一小团会回应你的温柔存在。`
