## 2. 文档目标

这份文档用于明确：

1. 普通用户最终会接触到哪些前端页面。
2. 这些页面之间如何跳转。
3. 哪些页面属于主路径，哪些页面属于次路径。
4. 哪些能力不进入普通用户页面树。

## 3. 页面树设计总原则

1. 页面树必须面向普通人。
2. 主路径以聊天、日记、生活管理为核心。
3. 复杂治理能力不进入普通用户主树。
4. 页面命名尽量口语化、生活化。

## 4. 一级页面清单

一级页面建议固定为 7 个：

1. 聊天
2. 日记
3. 收支
4. 待办
5. 日程
6. 观察与记忆
7. 设置

## 9. 对前端重构的直接含义

这份页面树意味着：

1. 聊天必须是绝对主入口。
2. 日记、收支、待办、日程是生活管理层。
3. 观察与记忆必须重新包装成普通人能理解的模块。
4. 复杂治理能力必须从主路径移开。

## 10. 最终结论

Cornie 的前端页面树不应该像后台系统，而应该像一个面向普通人的生活与陪伴桌面应用。

一句话总结：

`主路径只放聊天、记录、回看、管理生活；复杂治理和技术性页面全部后置。`
