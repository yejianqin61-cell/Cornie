## 2. 文档目标

这份文档用于回答一个更具体的问题：

`每个一级页面的第一屏，到底应该放什么，不应该放什么。`

它不负责定义像素级视觉稿，而负责定义：

1. 页面首屏区块顺序
2. 页面主操作
3. 页面弱操作
4. 页面不该出现的信息
5. Claude Code 做 UI 时的结构准绳

## 3. 全局首屏原则

所有一级页面都应遵守：

1. 第一屏只放最重要的 3 到 5 个区块
2. 第一屏必须有一个明确主动作
3. 第一屏不堆专业信息
4. 第一屏必须留白，不能做成后台面板墙
5. 第一屏文案必须像面对普通人说话

## 4. 聊天首页原型结构

## 4.1 页面角色

聊天首页是整个产品的绝对主入口。

它的任务不是解释系统，而是：

1. 让人马上开始说话
2. 让人感到被接住
3. 在需要时顺手完成生活操作

## 4.2 首屏结构

建议首屏顺序如下：

1. `顶部陪伴区`
2. `主对话区`
3. `输入区`
4. `少量待确认提示`

## 4.3 区块说明

### 顶部陪伴区

内容：

1. 铃湾当下的简短问候
2. 当前日期或时间感
3. 一句极短的陪伴语

不要放：

1. 模型状态技术细节
2. 工具能力说明
3. 复杂统计信息

### 主对话区

内容：

1. 最近对话
2. 铃湾最终回复
3. 极简状态提示

不要放：

1. 多张过程卡瀑布
2. 工具流水
3. 长篇透明说明

### 输入区

内容：

1. 主要输入框
2. 发送按钮
3. 少量灵感提示词

### 少量待确认提示

内容：

1. 仅当存在必要确认时显示
2. 用极短卡片提示“有 1 条待确认”

不要做成：

1. 常驻大面板
2. 大量系统通知堆叠

## 4.4 主按钮

聊天首页首屏主按钮只有一个：

1. `发送`

次级按钮最多两个：

1. `查看聊天记录`
2. `查看待确认`

## 5. 日记首页原型结构

## 5.1 页面角色

日记首页是情感表达和回看入口。

## 5.2 首屏结构

建议首屏顺序如下：

1. `今天卡片`
2. `我的日记输入区`
3. `Cornie 日记展示区`
4. `往年今日入口`

## 5.3 区块说明

### 今天卡片

内容：

1. 今天日期
2. 当前心情引导句
3. 是否已写一点点内容的状态

### 我的日记输入区

内容：

1. 一大块可写区域
2. 保存按钮

### Cornie 日记展示区

内容：

1. 铃湾为今天写的日记
2. 重新生成入口

不要放：

1. 来源说明面板
2. 复杂生成依据

### 往年今日入口

内容：

1. 一张轻卡片
2. 可点开查看

## 5.4 主按钮

1. `保存今天的日记`
2. `让铃湾写一篇`

3. `待办列表`

## 7.3 区块说明

### 今日待办摘要

内容：

1. 今天还有几件

### 快速新增

## 9. 观察与记忆首页原型结构

## 9.1 页面角色

这是当前最容易做歪的模块。

它不应该像治理台，而应该像：

1. 生活片段记录入口
2. 重要回忆回看入口

## 9.2 首屏结构

建议首屏顺序如下：

1. `今天的小事与想记住的事`
2. `快速记一条观察`
3. `最近观察`
4. `重要记忆入口`

## 9.3 区块说明

### 今天的小事与想记住的事

内容：

1. 一句温和说明
2. 引导用户理解这里不是技术模块，而是记录模块

### 快速记一条观察

内容：

1. 标题或一句话输入
2. 保存按钮

### 最近观察

内容：

1. 最近几条观察记录
2. 点进详情继续编辑

### 重要记忆入口

内容：

1. 几条最重要的长期记忆
2. “查看更多记忆”入口

不要放：

1. 来源结构图
2. 关系网络图
3. 治理候选
4. Topic 热度
5. 版本系统

## 9.4 主按钮

1. `记下一件小事`
2. `查看我的记忆`

## 10. 设置首页原型结构

## 10.1 页面角色

设置页是收纳页，不是首页。

## 10.2 首屏结构

建议首屏顺序如下：

1. `铃湾连接状态`
2. `DeepSeek 配置入口`
3. `数据与隐私说明`
4. `高级设置入口`

## 10.3 区块说明

### 铃湾连接状态

内容：

1. 简单状态
2. 是否已配置

不要放：

1. 大量技术字段
2. 开发调试信息

### DeepSeek 配置入口

内容：

1. 配置钥匙
2. 重新检测

### 数据与隐私说明

内容：

1. 极简说明
2. 不做长篇协议展示

### 高级设置入口

内容：

1. 一个低调入口
2. 不在首屏铺开

## 11. 全局不该出现在首屏的内容

以下内容原则上都不应出现在任何一级页面首屏：

1. Memory Wiki 治理审核池
2. 巡检结果
3. 审计信息
4. 页面版本差异
5. 页面回滚
6. Topic 热度
7. 工具调用过程
8. 来源关系图
9. 内部透明面板

## 12. 给 Claude Code 的直接施工提示

做 UI 时应优先满足：

1. 主区块少
2. 主按钮明确
3. 页面第一屏能读完
4. 不像后台
5. 铃湾的陪伴感要先于系统复杂度

## 13. 最终结论

这份原型草案的核心意思很简单：

`每个一级页面第一屏，都只能回答普通人当下最关心的那一个问题。`

例如：

1. 聊天页：我现在可以和铃湾说什么？
2. 日记页：我今天想写点什么？
3. 收支页：我现在怎么快速记一笔？
4. 待办页：我今天要做什么？
5. 日程页：我接下来有什么安排？
6. 观察与记忆页：我想记住什么？
7. 设置页：铃湾现在连得上吗？
