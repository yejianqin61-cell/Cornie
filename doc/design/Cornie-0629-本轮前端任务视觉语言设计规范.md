# Cornie-0629-本轮前端任务视觉语言设计规范

## 1. 文档目的

本文档用于约束本轮前端任务的统一视觉语言，覆盖以下开发任务：

- `329` 主聊天窗口吸底与浏览态滚动增强
- `330` 主聊天页工具结果视觉分层增强
- `331` 待办归档视图与完成态闭环增强
- `332` 日程月历视图与按日筛选联动
- `333` 收支页日历筛选与图表可视化增强

本文档不是全产品品牌手册，而是本轮开发执行期间必须遵守的视觉边界与实现方向说明。  
目标只有一个：

`让本轮新增页面与交互在视觉上成为同一套产品，而不是五个各做各的功能块。`

---

## 2. 本轮设计定位

本轮前端不是做“后台工具加强版”，也不是做“数据面板合集”，而是做：

`一个温和、清晰、适合普通人每天打开使用的陪伴型生活界面。`

因此本轮视觉必须同时满足四点：

1. 好理解
2. 好停留
3. 好回看
4. 不压人

---

## 3. 适用范围

本规范主要约束以下界面：

1. 聊天主页面
2. 聊天中的工具结果卡、确认卡、错误提示卡
3. 待办首页与归档视图
4. 日程首页与月历视图
5. 收支首页、收支日历区、收支图表区

不直接覆盖：

1. 桌宠窗口独立视觉
2. 高级治理界面
3. 后台脚手架或测试页

---

## 4. 总体视觉原则

### 4.1 第一原则：生活应用感，强于系统控制台感

页面看起来应像生活记录与陪伴应用，而不是：

1. SaaS 后台
2. 数据驾驶舱
3. AI 控制面板
4. 开发者工具集合

### 4.2 第二原则：情绪温和，信息清楚

页面既不能冷硬，也不能幼态。  
正确的感觉应是：

1. 轻柔
2. 清爽
3. 稳定
4. 有被接住的感觉

### 4.3 第三原则：主次分明，拒绝堆叠

每个页面必须先让人看懂“现在最重要的是什么”，再让人继续探索次级功能。  
不能所有区块一样重，不能所有按钮一起喊。

### 4.4 第四原则：少说术语，多说人话

视觉不仅是颜色和排版，也包括标签和文案。  
页面命名、提示语、按钮文案都必须服务普通人理解，而不是服务系统内部概念表达。

---

## 5. 本轮核心气质关键词

本轮所有 UI 设计统一使用以下关键词：

1. `温和`
2. `透气`
3. `低压`
4. `轻陪伴`
5. `可回看`
6. `有秩序但不生硬`

不允许走向以下关键词：

1. `炫技`
2. `赛博`
3. `面板化`
4. `高密度`
5. `专业治理感`

---

## 6. 配色规范

### 6.1 总体配色原则

1. 以浅暖中性色为大底。
2. 强调色只用于关键动作、关键状态和局部标记。
3. 不允许大面积高饱和撞色。
4. 不允许默认紫色 AI 套路色主导。
5. 不允许用纯黑、深蓝黑做大面积背景。

### 6.2 页面基础色建议

建议全局优先使用：

1. 奶白
2. 暖灰白
3. 极浅米色
4. 雾感暖灰

页面背景应略带暖意，不要纯白刺眼，也不要深色压迫。

### 6.3 强调色建议

本轮建议只保留一组主强调和少量模块偏色：

1. 主强调：柔和珊瑚 / 杏桃暖色
2. 成功态：低饱和草木绿
3. 提醒态：浅茶橙
4. 危险态：柔和暖红
5. 次级冷平衡色：极低饱和海盐蓝

### 6.4 模块偏色建议

各模块可以有“轻微偏色”，但不能像拼色看板：

1. 聊天：暖白 + 柔和珊瑚
2. 待办：暖灰白 + 浅茶橙
3. 日程：雾白 + 淡杏色
4. 收支：浅米白 + 草木绿 / 暖红对比

### 6.5 明确禁止

1. 大面积紫色
2. 黑底霓虹
3. 强渐变铺满页面
4. 每个模块都一套鲜艳高饱和主题色

---

## 7. 排版与密度规范

### 7.1 页面排版原则

页面必须有“空气感”。  
用户打开后应先感到轻松，而不是先感到信息太多。

### 7.2 密度要求

1. 首页首屏尽量控制在 3 到 5 个主要区块。
2. 区块之间要有明显呼吸间距。
3. 单个区块内部 padding 要宽松。
4. 列表项之间要有轻微留白，不做硬挤压。

### 7.3 信息层级

每个页面最多保留三层文本层级：

1. 主标题 / 核心信息
2. 次级说明 / 辅助信息
3. 极弱提示 / 状态说明

不应出现满屏五六种字号、权重、提示色同时竞争注意力。

### 7.4 禁止项

1. 两栏都塞满
2. 一屏出现十几个强操作按钮
3. 列表做成表格化密集排布
4. 每一条说明都包成一个重卡片

---

## 8. 容器与卡片规范

### 8.1 卡片使用原则

卡片只用于真正需要被独立感知的信息块。  
不是所有内容都必须卡片化。

### 8.2 卡片风格

卡片应满足：

1. 轻边框
2. 浅阴影
3. 柔和圆角
4. 低对比底色

卡片应像“轻托住内容”，而不是“把内容框死”。

### 8.3 圆角建议

本轮统一偏柔和圆角：

1. 页面主卡片：`16px - 20px`
2. 列表行：`10px - 14px`
3. 标签胶囊：`999px`
4. 输入框：`12px - 16px`

### 8.4 阴影建议

阴影必须很轻，只用于建立层次，不用于制造“豪华感”。

### 8.5 禁止项

1. 玻璃拟态堆叠
2. 过多半透明浮层
3. 边框又粗又多
4. 每个区块都像浮空控制台

---

## 9. 按钮与交互控件规范

### 9.1 主按钮

主按钮必须做到：

1. 明确
2. 温和
3. 愿意点

它应该像“邀请动作”，不是“命令按钮”。

### 9.2 次级按钮

次级按钮必须明显退后，不与主按钮争夺视觉中心。

### 9.3 危险按钮

删除、清空、彻底移除等危险动作要提示风险，但不能像系统报错警报。  
危险色应是柔和暖红，不是刺眼猩红。

### 9.4 输入控件

输入框、下拉框、筛选控件都应：

1. 低压
2. 易读
3. 不像后台表单

焦点态建议使用柔和外圈或边框变化，不使用刺眼蓝光。

---

## 10. 状态反馈规范

### 10.1 成功态

成功态应像：

`已经帮你处理好了。`

而不是：

`操作成功 / code 200`

### 10.2 失败态

失败态应像：

`这次没做好，我们可以再试一下。`

而不是：

`系统错误 / 请求失败`

### 10.3 空态

空态必须：

1. 安静
2. 温和
3. 不让用户觉得自己做错了

### 10.4 加载态

加载态必须克制。  
不做重型骨架屏堆叠，不做夸张跳动，不做高频闪烁。

---

## 11. 聊天页面专项视觉规范

### 11.1 页面角色

聊天页是本轮第一主入口。  
它首先是“和铃湾相处”的页面，其次才是“完成工具动作”的页面。

### 11.2 聊天气泡规范

1. 用户气泡与铃湾气泡必须清晰区分。
2. 不使用深色大气泡。
3. 用户气泡可略暖，铃湾气泡可略白。
4. 气泡不应太宽，保持阅读舒适。

### 11.3 工具结果视觉层次

工具调用后的消息与结果卡必须比普通回复更明显，但不应像后台日志面板。

建议：

1. 用更明确的边框或底色区分工具结果
2. 用简短自然语言标题替代专业标签
3. 确认卡、失败卡与成功卡要彼此区分

### 11.4 “回到底部”按钮

该按钮必须：

1. 轻量
2. 不遮挡主要内容
3. 看得见但不刺眼

不应做成大面积悬浮操作块。

---

## 12. 待办页面专项视觉规范

### 12.1 页面角色

待办页不是任务管理后台，而是日常安排的小工作篮。

### 12.2 主列表与归档区关系

视觉上必须明确：

1. 当前待办是主区
2. 已归档是次区

归档页不应比当前待办更抢眼。

### 12.3 完成态表达

完成态应表达“已放下”，而不是“已报废”。  
因此可以降低饱和度、弱化对比，但不要处理成脏灰、不可读。

### 12.4 空态要求

当当前待办为空时，空态应有轻松感，不要像系统无数据提示。

---

## 13. 日程页面专项视觉规范

### 13.1 页面角色

日程页是“按时间看生活安排”的页面，不是行程管理系统后台。

### 13.2 月历风格

月历必须：

1. 清爽
2. 易扫视
3. 有安排的日期清楚但不炸眼

### 13.3 选中态与今天态

需要同时区分：

1. 今天
2. 当前选中日期
3. 有日程的日期

但三者不能都用同等强度高亮，必须分层。

建议：

1. 今天：细致边框或柔和底色
2. 选中：主强调色
3. 有日程：小点或轻标记

### 13.4 列表联动

当筛选某一天后，页面必须在视觉上明确提示“现在看的就是这一天”，避免用户以为列表没变。

---

## 14. 收支页面专项视觉规范

### 14.1 页面角色

收支页不是财务系统，也不是报表后台。  
它是“帮普通人看懂自己最近花钱和进账”的页面。

### 14.2 收入支出区分原则

收入和支出必须一眼区分，但不只靠颜色。

建议同时使用：

1. 颜色区分
2. 正负号
3. 图标或方向符号

### 14.3 日历视图风格

收支日历应像浏览生活记录，而不是记账系统月账单大表。  
日期标记要轻，不要每个格子塞数字造成拥堵。

### 14.4 图表风格

图表必须满足：

1. 可理解
2. 不花
3. 不刺眼
4. 不像 BI 面板

要求：

1. 减少网格线存在感
2. 标签不过密
3. 图例用自然语言
4. 用色克制

### 14.5 图表区位置

图表应成为“帮助理解”的区域，不应抢走记账入口本身。  
因此图表要有存在感，但不能压过“记一笔”和“最近记录”的主实用性。

---

## 15. 动效规范

### 15.1 总原则

动效只做三件事：

1. 帮助理解状态变化
2. 缓和界面切换
3. 让界面更有呼吸感

### 15.2 推荐动效

1. 页面淡入
2. 卡片轻微浮起
3. 筛选切换平滑过渡
4. 悬浮按钮轻显轻退

### 15.3 禁止项

1. 夸张弹跳
2. 强缩放
3. 高频闪烁
4. 大片流光
5. 为了“灵动”而做无意义动画

---

## 16. 文案与命名规范

### 16.1 文案要求

文案要：

1. 平实
2. 易懂
3. 有点温度

### 16.2 避免术语

避免在本轮新增页面中高频出现：

1. 编排
2. 策略
3. 治理
4. 命中
5. 审计
6. 协议
7. 工具调用链

### 16.3 推荐表达方式

优先写成用户一眼懂的话，例如：

1. `回到底部`
2. `已归档`
3. `今天的安排`
4. `这一天的收支`
5. `铃湾已经帮你记下了`

---

## 17. 本轮明确禁止的设计倾向

1. 把聊天页做成工具过程监控面板
2. 把待办页做成项目管理系统
3. 把日程页做成企业排期后台
4. 把收支页做成 BI 仪表盘
5. 把所有新能力都通过大卡片堆满首页
6. 用很多颜色证明功能很多
7. 用很多边框和标签证明结构完整

---

## 18. 与开发任务的对应关系

### `329`

重点遵守：

1. 回到底部按钮轻量化
2. 滚动状态变化不制造视觉干扰

### `330`

重点遵守：

1. 工具结果分层要明显
2. 不把工具反馈做成后台日志

### `331`

重点遵守：

1. 当前待办与归档视图主次分明
2. 完成态是“收起”，不是“报错式变灰”

### `332`

重点遵守：

1. 月历清爽易扫视
2. 日期筛选反馈明确但不过强

### `333`

重点遵守：

1. 图表服务理解，不服务炫技
2. 日历、图表、列表三者层级清楚

---

## 19. 最终结论

本轮前端任务的视觉语言，核心不是“做得更丰富”，而是：

`在功能变多的同时，仍然让普通人觉得轻松、顺手、愿意每天打开。`

一句话总结：

`Cornie 本轮新增前端界面，应当像温和陪伴型生活应用的自然延展，而不是像不断长出功能块的系统面板。`
