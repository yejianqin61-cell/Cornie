# Cornie 0625 前端配套设计备忘录

本备忘录用于补齐 [Cornie-0625-模型侧改进设计.md](/C:/Users/USER/Desktop/Cornie/Cornie/doc/design/Cornie-0625-模型侧改进设计.md:1) 在前端侧缺失的配套设计问题。

它不是完整 UI 设计稿，而是：

- 前端需要同步跟进的 issue 清单
- 后续前端专题设计的输入清单
- 防止后端先走太远、前端完全失联的补充备忘

## 2. 当前前端缺口总判断

0625 设计已经完成了很多模型侧和后端侧约束，但前端当时没有同步细化以下内容：

- 模型状态配置与健康展示
- 工具调用过程的可视化反馈
- 工具确认流的全链路交互
- 类目映射失败时的人类确认交互
- 长期记忆、观察日志、聊天记录在前端的可见边界

## 3. 需要补的前端 issue

### Issue 1：模型状态与配置入口缺失

问题：

- 前端缺少 DeepSeek 当前连接状态展示。
- 前端缺少 API Key 配置/检测入口。

需要设计：

- 模型状态角标
- 模型健康页或设置入口
- Key 缺失、失效、限流、超时提示态

### Issue 2：工具调用过程不可见

问题：

- 当前用户只能看到结果，难以理解模型中间做了什么。

需要设计：

- “铃湾正在查看类目 / 查询日程 / 写入观察日志” 等过程态文案
- 只读补查与写工具的视觉区分
- 成功/失败/取消三态

### Issue 3：确认流信息密度不足

问题：

- 用户需要确认时，前端未必能清楚展示“为什么要确认、确认后会发生什么、拒绝会怎样”。

需要设计：

- 确认卡片结构
- 风险等级标识
- 操作摘要
- 影响说明
- 同意/拒绝后的后续状态

### Issue 4：类目映射失败的交互缺乏统一规范

问题：

- 当模型无法匹配记账/待办/日程类目时，用户需要看懂“模型建议新建类目”还是“建议改用已有类目”。

需要设计：

- 映射失败提示卡
- 已有类目候选列表
- 新建类目建议展示
- 人类确认入口

### Issue 5：长期记忆在前端的边界未定义

问题：

- 用户目前没有清晰前端入口理解“哪些内容会变成长期记忆”。

需要设计：

- 长期记忆提示语
- 长期记忆是否展示给用户
- 长期记忆写入后是否即时提示

### Issue 6：观察日志与日记边界未明确

问题：

- 用户很难从前端区分“观察日志”和“Cornie 日记”的本质区别。

需要设计：

- 观察日志入口
- 日记入口
- 解释文案
- 是否允许用户查看观察日志原文

## 4. 需要前端后续专题化设计的页面

建议后续单独补前端设计的页面/模块：

1. 模型设置与状态页
2. 工具调用反馈层
3. 通用确认流卡片系统
4. 类目映射与新建确认弹层
5. 长期记忆提示与查看入口
6. 观察日志 / 聊天记录 / 日记三者关系页

## 5. 结论

0625 设计并不是不能开发，而是：

`后端与模型侧已经能先推进，但前端同步设计明显不足，需要补独立交互设计。`
