# Cornie 0627 前端配套设计备忘录

## 1. 文档定位

本备忘录用于补齐 [Cornie-0627-长期记忆LLM-Wiki正式设计.md](/C:/Users/USER/Desktop/Cornie/Cornie/doc/design/Cornie-0627-长期记忆LLM-Wiki正式设计.md:1) 在前端侧缺失的配套设计问题。

0627 正式设计已经定义了长期记忆的核心架构，但前端还没有形成可落地的配套交互方案。

## 2. 当前前端缺口总判断

当前最明显的问题是：

`LLM Wiki 已经有正式后端设计，但前端还没有对应的管理界面、治理界面、版本界面和索引界面。`

## 3. 需要补的前端 issue

### Issue 1：缺少 Memory Wiki 管理页

问题：

- 用户无法直接浏览全部记忆页面。

需要设计：

- 页面列表
- 筛选：状态 / 类型 / 重要性
- 搜索：标题 / 别名 / 关键词

### Issue 2：缺少记忆页面详情页

问题：

- 用户不能完整查看单个页面的摘要、正文、来源、相关页。

需要设计：

- 页面头部信息区
- 摘要区
- 正文区
- 来源引用区
- 相关页面区

### Issue 3：缺少页面编辑体验

问题：

- 正式设计要求用户可直接改记忆页面，但前端还没有编辑体验设计。

需要设计：

- 编辑模式 / 只读模式切换
- 标题、摘要、别名、正文编辑
- 保存前 diff 提示

### Issue 4：缺少页面合并审核界面

问题：

- 页面合并被定义为高风险治理动作，但前端没有审核与确认入口。

需要设计：

- 合并候选卡片
- 两页差异并排展示
- 保留页选择
- 风险提示
- 同意/拒绝入口

### Issue 5：缺少版本历史与回滚界面

问题：

- 用户看不到页面版本，也无法通过前端选择回滚。

需要设计：

- 版本列表抽屉/侧栏
- 版本时间、操作者、原因
- 版本 diff 查看
- 回滚确认交互

### Issue 6：缺少主题索引管理界面

问题：

- 主题索引虽然有后端设计，但前端没有“索引页”。

需要设计：

- 主题索引列表
- 热度排序
- 关联页面数
- 关联聊天日期
- 别名编辑
- 合并主题入口

### Issue 7：缺少审计与巡检结果界面

问题：

- 审计日志、断链巡检、孤儿页巡检当前只有后端概念。

需要设计：

- 巡检结果面板
- 问题分类标签
- 修复建议展示
- 跳转到目标页面

### Issue 8：缺少“模型使用了哪些记忆”的透明提示

问题：

- 用户无法感知铃湾这轮对话到底用了哪些长期记忆。

需要设计：

- “本轮使用的长期记忆”轻提示
- 可展开查看的摘要引用
- 避免恐怖谷的展示边界

## 4. 建议补的前端模块

建议未来拆成这些前端专题模块：

1. Memory Wiki 列表页
2. Memory Wiki 详情与编辑页
3. 页面合并审核弹层
4. 版本历史与回滚面板
5. 主题索引管理页
6. 审计与巡检结果页
7. 对话中的记忆引用提示层

## 5. 结论

0627 文档在后端和架构上是完整的，但前端仍停留在“尚未建模”的状态，需要专门的记忆治理前端设计文档承接。
