## 2. 当前前端缺口总判断

当前最大的问题是：

`0628 已经把“该有什么能力”写清楚了，但前端还没有把这些能力组织成页面、入口、流程和状态。`

## 3. 需要补的前端 issue

### Issue 1：工具能力总入口缺失

问题：

- 用户没有一个统一入口看到当前可操作的记账、待办、日程、记忆能力。

需要设计：

- 工具能力总览页
- 分域入口：记账 / 待办 / 日程 / 记忆

### Issue 2：记账全生命周期前端入口缺失

问题：

- 后端已有较多记账工具，但前端没有相应 CRUD 体验。

需要设计：

- 记录列表
- 记录详情
- 编辑与删除
- 按类目筛选
- 最近记录入口

### Issue 3：待办全生命周期前端入口缺失

问题：

- 缺少未完成、已完成、重新打开等完整体验。

需要设计：

- 开放待办列表
- 已完成待办列表
- 重新打开待办
- 类目筛选与类目管理

### Issue 4：日程全生命周期前端入口缺失

问题：

- 缺少 upcoming、cancelled、恢复等完整体验。

需要设计：

- 未来日程列表
- 已取消日程列表
- 恢复入口
- 日程类目管理

### Issue 5：记忆治理前端入口缺失

问题：

- 页面合并、归档、压缩、热度、巡检等治理动作都没有前端入口。

需要设计：

- 合并候选队列
- 归档候选队列
- 热度视图
- 巡检面板
- 修复建议面板

### Issue 6：用户可见可控的记忆编辑体验未专题化

问题：

- 文档里定义了“用户可见可控”，但界面上怎么体现还没设计。

需要设计：

- 权限边界
- 可编辑字段范围
- 保存与撤销
- 风险操作确认

### Issue 7：测试体系缺少前端配套验证策略

问题：

- 0628 讲了系统测试，但前端交互层也需要最小验证策略。

需要设计：

- 关键交互快照清单
- 核心路径手工回归清单
- 关键页面状态矩阵

0628 文档已经把能力清单和治理原则写出来了，但前端仍缺：

- 页面结构
- 信息架构
- 入口设计

所以必须补前端专题设计，不能再只补后端。
