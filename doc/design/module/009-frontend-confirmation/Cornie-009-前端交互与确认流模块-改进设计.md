# Cornie 009 前端交互与确认流模块改进设计

## 1. 模块目标

负责把 AI 的工具执行结果、确认请求、追问请求以清晰的前端交互方式呈现给人类用户。

## 2. 模块范围

- 工具执行结果展示
- 确认流 UI
- 追问 UI
- 观察日志 / 日记 / 记忆入口

## 3. 交互场景

| 场景 | 前端行为 |
| --- | --- |
| AI 自动记账成功 | 显示“已记录”提示 |
| 需要新增类目确认 | 弹出确认卡片 |
| 需要追问金额或类目 | 直接在对话中继续追问 |
| 写入长期记忆待确认 | 展示可同意/拒绝的确认项 |
| 巡检产生的记忆治理候选 | 不在聊天中打断，进入 Memory Wiki 待审核区 |

## 4. 状态类型

- 普通回复
- 工具成功
- 工具失败
- 待确认
- 待追问

## 5. 补充原则

- 前端确认流只处理当前轮对话中必须由用户立即拍板的事项。
- Memory Wiki 的巡检结果，例如合并候选、归档候选、压缩候选、修复建议，不占用聊天确认通道。
- 这类异步治理任务统一沉淀到 Memory Wiki 模块的“待审核区”，由用户自行进入处理。
- 巡检新增待审核项时，前端通过 Memory Wiki 入口角标、待审核计数或模块内通知条提醒用户。
- 聊天页最多只显示轻提示或跳转入口，不在聊天流里逐条展开巡检审核卡片。
