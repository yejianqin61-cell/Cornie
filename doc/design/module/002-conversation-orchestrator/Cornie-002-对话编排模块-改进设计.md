## 2. 模块目标

本模块负责把一次用户对话编排成完整的 Agent 执行流程。

流程包括：

- 读取上下文
- 拼接 prompt
- 调用 DeepSeek
- 解析 JSON
- 走策略层
- 调用工具
- 二次调用模型生成最终回复

## 3. 模块职责

| 职责 | 说明 |
| --- | --- |
| 上下文装载 | 读取对话、类目、观察日志摘要、待办摘要、日程摘要、长期记忆摘要 |
| prompt 构造 | 组织人格、协议、工具说明、上下文摘要 |
| 模型首轮调用 | 获取 reply 或 tool_call |
| 工具后续编排 | 接收 tool_result 后再次调用模型 |
| 消息持久化 | 保存用户消息与 Cornie 回复 |
| 回合控制 | 控制轮次上限、修复重试上限 |

## 4. 上下文策略

进入 prompt 的内容：

- 当前全部类目
- 长期记忆摘要
- 未完成待办摘要
- 近期日程摘要
- 今日观察日志摘要
- 最近几轮对话摘要

不直接进入 prompt 的内容：

- 完整待办
- 完整日程
- 完整观察日志
- 全量长期记忆

这些内容通过只读工具按需查询。

## 5. 流程序列

```text
用户输入
-> 保存消息
-> 装载摘要上下文
-> 调用模型
-> 解析 JSON
-> 若 reply：直接返回
-> 若 tool_call：走策略层和工具层
-> 取 tool_result 再调用模型
-> 保存最终回复
-> 返回前端
```

## 6. 风险与约束

- prompt 过长会推高成本
- 轮次失控会导致来回通信过多
- 上下文摘要质量会直接影响首轮命中率
