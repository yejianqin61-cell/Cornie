## 2. 模块目标

本模块用于在模型提出 tool_call 后，先做业务与风险判断，再决定是否真正执行。

## 3. 模块职责

| 职责 | 说明 |
| --- | --- |
| 风险分级 | 区分低风险、中风险、高风险工具 |
| 执行决策 | 直接执行 / 要求确认 / 改为追问 / 拒绝 |
| 条件校验 | 检查金额、时间、类目映射、记忆写入条件等 |
| 自动降级 | 把过强动作降为查询或追问 |
| 轮次控制 | 限制单轮工具调用次数 |

## 4. 风险分级

| 风险级别 | 示例 | 默认策略 |
| --- | --- | --- |
| 低风险 | 查询类工具 | 直接执行 |
| 中风险 | 新增收支、待办、日程、观察日志 | 置信度足够时可执行 |
| 高风险 | 新增类目、删改历史数据、写长期记忆 | 默认确认或拦截 |

## 5. 输出结果

```ts
{
  decision: 'allow' | 'confirm' | 'ask_back' | 'deny',
  reason: string,
  rewrittenToolCalls?: []
}
```

## 6. 核心规则示例

- 没金额不允许 `ledger.add_expense`
- 没可映射类目时不允许直接写入，转确认流
- 长期记忆写入需满足稳定性条件
- 与今日观察日志高度重复时不允许新增观察日志
