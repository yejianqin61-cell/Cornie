# Cornie-0629-GitHub-Issue-001-005前端体验增强落地设计

## 1. 文档目的

本文档用于将 GitHub 仓库当前开放的 5 个前端体验类 Issue 正式收敛为可开发、可排期、可验收的设计方案，为后续任务拆解与实现提供统一依据。

对应 Issue：

- `#1` 主聊天窗口细节优化
- `#2` 收支页面更丰富一点
- `#3` 主聊天页面
- `#4` 待办
- `#5` 日程

本文档关注前端页面交互、可视反馈、信息组织与最小必要的数据调用方式，不引入与当前目标无关的后端治理扩张。

---

## 2. 当前判断

### 2.1 问题性质

这 5 个 Issue 本质上都不是“底层能力缺失”问题，而是“已有能力未被良好呈现”的问题。  
当前系统已经具备对话、记账、待办、日程等基础数据读写能力，但前端仍存在以下短板：

- 高频使用页面的交互细节不到位
- 工具调用后的结果反馈不够直观
- 事务型页面缺少归档、筛选、日历等管理视角
- 数据型页面缺少图形化表达与按时间浏览能力

### 2.2 总体产品原则

本轮设计遵循以下原则：

1. 优先优化最高频入口。
2. 先补功能闭环，再补视觉增强。
3. 优先做“用户能立即感知到更顺手”的改动。
4. 尽量复用现有接口与数据结构，避免无必要的后端扩张。
5. 前端展示应保持轻量、亲和、非专业化，不把治理细节直接暴露给普通用户。

---

## 3. 优先级结论

建议按以下顺序推进：

### 第一优先级：聊天体验专项

- `#1` 主聊天窗口细节优化
- `#3` 主聊天页面

原因：

- 聊天是 Cornie 的主入口，也是用户停留时间最长、感知最直接的页面。
- 若主聊天体验不顺滑，其他页面价值会被稀释。

### 第二优先级：事务闭环专项

- `#4` 待办
- `#5` 日程

原因：

- 待办与日程已经具备基础功能，但未形成完整管理闭环。
- 完成归档、日期检索这类能力属于“够用”迈向“好用”的关键一步。

### 第三优先级：数据表达升级专项

- `#2` 收支页面更丰富一点

原因：

- 收支页面当前已可用，但图表和日历更多属于增强价值。
- 在主聊天和事务页体验尚未补齐前，不应优先堆叠可视化能力。

## 4. Issue 001：主聊天窗口细节优化

### 4.1 Issue 原文目标

当用户发送新消息或收到新消息推送时，会话视图须自动锚定并滚动至最新消息处。  
确保最新信息始终处于可视区域底部；若用户正处于历史消息查看状态，不得强制滚动，待用户退出浏览态或点击“回到底部”按钮时再执行该动作。

### 4.2 当前现状

当前主聊天页在发送消息和同步消息后，基本总是执行滚到底部。  
这会导致以下问题：

- 用户向上翻历史消息时，新的同步会打断阅读
- 主窗口与桌宠窗口后续若统一体验，当前逻辑不够稳健
- 缺少“浏览态”和“吸底态”的明确状态定义

### 4.3 目标方案

新增聊天滚动状态机：

- `吸底态`
  - 用户当前位于底部附近
  - 新消息进入时自动滚到底部
- `浏览态`
  - 用户主动向上浏览历史消息
  - 新消息进入时不强制滚动
- `待返回底部态`
  - 浏览态下收到新消息后，出现“回到底部”按钮

### 4.4 交互细则

1. 当滚动位置距离底部小于阈值时，判定为吸底态。
2. 当用户手动上滑离开底部阈值时，进入浏览态。
3. 在吸底态下：
   - 发送消息后自动滚到底部
   - 收到回复后自动滚到底部
   - 工具结果、确认卡片插入后自动滚到底部
4. 在浏览态下：
   - 不自动滚动
   - 若有新消息，显示“回到底部”按钮
5. 用户点击“回到底部”后：
   - 立即滚到底部
   - 恢复吸底态

### 4.5 实现范围

- `src/renderer/composables/useChat.js`
- `src/renderer/components/ChatHome.vue`
- 如桌宠窗口共享同一会话流，则同步接入同套滚动逻辑

### 4.6 验收标准

- 用户位于底部时，发送和收消息都能自然吸底
- 用户浏览历史消息时，不会被强制拉回底部
- 有新消息进入时，用户能看到明确的“回到底部”入口
- 主窗口与桌宠窗口在共享会话场景下表现一致

## 5. Issue 003：主聊天页面

### 5.1 Issue 原文目标

当 Cornie 需要调用工具，调用完成的消息气泡颜色可以深一点、对比度强一点，并可加入轻量图案等视觉提示。

### 5.2 当前现状

当前聊天区已区分：

- 用户消息
- 铃湾消息
- 工具结果面板
- 追问消息
- 确认卡片

但问题在于：

- 工具调用后的成功反馈不够“显眼”
- 铃湾已经完成了什么动作，不够一眼看懂
- 工具结果面板和普通消息的节奏关系不够清晰

### 5.3 目标方案

强化“工具已执行”这一状态的视觉反馈，但不走重装饰路线。

建议表现方式：

1. 工具调用完成后的铃湾消息气泡使用更强对比度样式。
2. 工具结果面板增加状态化标题。
3. 面板中加入轻量图标或标识，而非复杂花纹。
4. 保持整体清爽，避免再次走向信息堆叠。

### 5.4 推荐视觉策略

- 工具成功：偏暖色高亮边框或浅底深边框
- 待确认：提醒色边框
- 执行失败：危险色边框与明确错误文案

工具气泡可增加简短前缀：

- “已帮你记下”
- “已写入待办”
- “已加入日程”
- “需要你确认”

### 5.5 实现范围

- `src/renderer/components/ChatHome.vue`
- `src/renderer/components/ToolResultPanel.vue`
- `src/renderer/style.css`

### 5.6 验收标准

- 用户能快速分辨普通回复与“已执行工具”的回复
- 工具结果区域层次清晰，不与普通气泡混淆
- 不增加明显视觉噪音，不破坏当前简洁方向

## 6. Issue 004：待办

### 6.1 Issue 原文目标

勾选完成的要归档，因此需要多一个归档页面。

### 6.2 当前现状

当前待办页支持：

- 新增待办
- 勾选完成
- 恢复待办
- 删除待办

但完成后的条目仍和未完成条目混在同一主列表中，仅通过灰化区分。  
这会导致：

- 主列表不够干净
- 已完成事项仍占据注意力
- 缺少“我已经完成了什么”的回顾视角

### 6.3 目标方案

将待办分为两个视图：

- `当前待办`
- `已归档`

其中：

- 勾选完成后，条目从主列表移出
- 在归档区可查看已完成条目
- 支持从归档中恢复
- 支持在归档中彻底删除

### 6.4 页面设计建议

待办首页结构调整为：

1. 顶部摘要
   - 未完成数量
   - 已归档数量
2. 快速新增区
3. 当前待办列表
4. 归档入口按钮或页签

归档区建议优先做页签，不一定单独路由：

- `待办`
- `已归档`

若后续数据量增大，再升级为独立页面。

### 6.5 数据与状态建议

若当前后端 `status=done` 已存在，则前端直接按状态分流展示即可。  
本期不强制引入新的归档字段。

推荐展示规则：

- `pending` / `active`：显示在当前待办
- `done`：显示在归档
- `cancelled`：暂不面向普通用户重点展示

### 6.6 实现范围

- `src/renderer/components/TodoHome.vue`
- `src/renderer/components/TodoWorkspace.vue`
- 必要时补充 API 调用参数以支持状态筛选

### 6.7 验收标准

- 勾选完成后，条目立即离开主列表
- 用户可查看已归档事项
- 归档条目支持恢复与删除
- 主待办区始终保持聚焦于未完成事项

## 7. Issue 005：日程

### 7.1 Issue 原文目标

加上日历视图，放在日程页面上部。

### 7.2 当前现状

当前日程页为：

- 今日摘要
- 快速新增表单
- 近期日程列表

问题在于：

- 用户只能线性看列表
- 缺少按天定位日程的入口
- 无法快速回答“某天有什么安排”

### 7.3 目标方案

在日程首页顶部加入月历视图，并与下方列表联动。

核心能力：

1. 以月为单位展示日期
2. 有日程的日期做轻量标记
3. 点击某一天后，下方仅显示该日安排
4. 支持切回“本月全部”或“今天”

### 7.4 推荐交互

日程页布局建议为：

1. 顶部摘要
2. 月历视图
3. 日历筛选状态条
4. 快速新增区
5. 日程列表

筛选状态条可展示：

- 当前筛选日期
- 清除筛选按钮
- “回到今天”按钮

### 7.5 实现策略

初版先实现：

- 单月月历
- 单日筛选
- 当天与有安排日期高亮

本期暂不实现：

- 周视图
- 拖拽调整日程
- 复杂重复日程渲染

### 7.6 实现范围

- `src/renderer/components/ScheduleHome.vue`
- 推荐新增 `src/renderer/components/ScheduleCalendar.vue`

### 7.7 验收标准

- 用户可通过日历快速定位某日安排
- 当月有日程的日期具有明显提示
- 点击日期后，下方列表正确联动筛选
- 今日定位与清除筛选操作顺手直观

## 8. Issue 002：收支页面更丰富一点

### 8.1 Issue 原文目标

- 加入按类目分类的饼图
- 加入按照日期推进的折线图
- 日历视图，分日期筛选收支条目
- 收支条目采用对比度强的不同颜色区分开

### 8.2 当前现状

当前收支页已有：

- 本月收支概览
- 快速记一笔
- 最近记录
- 类目管理入口

但仍存在明显不足：

- 数据只以列表呈现，难以快速建立整体印象
- 无法按日期浏览历史记录
- 收入与支出在列表中的视觉对比仍偏弱
- 用户难以回答“最近钱花在哪”“这几天开销走势如何”

### 8.3 总体方案

收支页应从“可录入”升级为“可回顾、可理解、可筛选”。

建议拆为三个落地阶段：

#### 阶段 A：列表增强

- 明确区分收入与支出颜色
- 每条记录更完整展示：
  - 事项
  - 类目
  - 日期
  - 金额
- 增加基础筛选：
  - 日期范围
  - 收入/支出

#### 阶段 B：日历视图

- 在页面上部增加月历
- 有收支记录的日期做轻量标记
- 点击日期后，下方仅显示该日收支

#### 阶段 C：图表视图

- 类目饼图：看钱花在哪些方向
- 日期折线图：看支出或净额走势

### 8.4 图表使用原则

图表必须服务于理解，而不是装饰。

建议初版只做：

- 月度类目支出饼图
- 月度按日收支折线图

本期不建议一开始做过多切换：

- 不急于支持年视图
- 不急于支持大量对比维度
- 不急于叠加复杂统计面板

### 8.5 技术建议

若当前前端尚无图表能力，可引入轻量图表库。

推荐候选：

- `ECharts`
- `Chart.js`

建议优先考虑：

- 与 Vue 集成成本
- 主题样式可控性
- 后续日历/图表联动灵活度

### 8.6 实现范围

- `src/renderer/components/LedgerHome.vue`
- `src/renderer/components/LedgerWorkspace.vue`
- 视情况新增图表组件与日历组件

### 8.7 验收标准

- 收入与支出列表项具有明显区分
- 用户可按日期查看收支记录
- 用户可通过图表快速理解当月花销结构与时间趋势
- 页面在信息丰富后仍保持可读，不出现拥挤堆叠

## 9. 技术与实现边界

### 9.1 是否需要后端扩展

本轮优先按“前端可独立落地”处理。

初步判断：

- `#1` 仅前端改造即可
- `#3` 仅前端改造即可
- `#4` 大概率仅前端改造即可
- `#5` 以前端为主，现有接口基本可支撑
- `#2` 以前端为主，可能需要引入图表库，但不一定需要新增后端接口

### 9.2 本轮不做的事情

为防止范围失控，本轮明确不纳入：

- 聊天页复杂装饰动画
- 日程拖拽编辑
- 重复日程高级规则
- 收支页多层钻取分析
- 面向普通用户的治理后台信息暴露

## 11. 最终结论

这 5 个 Issue 可以视为 Cornie 当前前端体验的第一轮“可用到好用”升级。  
它们不要求推翻已有架构，也不应扩散为大规模后端改造，而应聚焦：

- 让聊天更顺手
- 让待办和日程更像真正的日常工具
- 让收支页面从记录器升级为理解工具

建议下一步基于本文档继续拆解为正式 task 文档，并按“聊天优先、事务次之、数据增强最后”的顺序执行。
