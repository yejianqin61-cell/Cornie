# BE-03 业务校验 400 化与日期真实性校验（Business Validation → 400）

## 背景

服务层业务校验抛裸 Error，HTTP 层一律 500（Cornie-022 §3.3.1 B3 + §3.3.2 N5）：

- `ledger/service.js:36`（amount is required）、`todo/service.js:64`、`schedule/service.js:72`、`settings/service.js:30`（invalid timeoutMs）、`observation/service.js:120`、`confirm/service.js` createPending 必填——均裸 Error → 500。
- `validators.js:3-8` 日期只查正则 `^\d{4}-\d{2}-\d{2}$`，`2026-99-99` 可通过。
- `http/middleware.js:3-17` 只有两档（HttpError→status、其余 500），带 code 的业务错误（invalid_model_protocol / tool_execution_failed / category_name_similar 等）塌缩为 500，无 details 透出。
- 注：todo/schedule 的 HTTP 路由已补 title/startAt 必填（该路径已 400），其余路径仍 500。

## 目标

1. 服务层业务校验改抛 `HttpError(400)`（可带 code/details），输入类错误不再 500。
2. 日期/月份校验加真实性校验（Date 构造 + 回读比对），拒绝 `2026-99-99`。
3. HTTP 错误中间件支持 `error.code` 映射（4xx 语义表 + 保留 code/details）。

## 范围

- `electron/backend/http/errors.js`、`http/middleware.js`（错误码映射）
- `electron/backend/validators.js`（日期真实性）
- `electron/backend/ledger/service.js`、`todo/service.js`、`schedule/service.js`、`settings/service.js`、`observation/service.js`、`confirm/service.js`（业务校验改抛 HttpError(400)）
- `tests/services/business-services.test.mjs`、`tests/services/confirm-service.test.mjs`、`tests/protocol/*`（新增 400 断言）

## 设计要求

### 1. 业务校验 400 化

- 各服务层"输入非法"路径改抛 `HttpError(400, message, { code, details? })`；`code` 用稳定业务码（如 `amount_required`、`invalid_timeout`、`title_required`、`invalid_date` 等，与现有错误文案保持兼容）。
- 工具调用路径（gateway 捕获转 ok:false）不受影响；HTTP 直调路径得到 400 + `{error}`。

### 2. 日期真实性校验

- `requireISODate`/`optionalISOMonth` 在正则通过后追加真实性校验：解析为 Date 并回读 y/m/d 与输入一致（拒绝 `2026-99-99`、`2026-02-30` 等）。
- 错误信息沿用现有风格（如"日期格式应为 YYYY-MM-DD"→ 400）。

### 3. 错误码映射

- `jsonErrorHandler`：识别 `error.code` 并按 4xx 语义表映射（如 invalid_* → 400/422），响应体保留 `{ error, code?, details? }`；无 code 的 HttpError 按 status；其余 500。
- 不改变现有已通过测试的响应形状（仅新增字段）。

## 验收标准

1. 新增测试通过：缺 amount → 400 + `{error}`（含 code）；非法 timeoutMs → 400；`2026-99-99` 日期被拒（400）；缺 title/startAt 各路径 400。
2. 现有 services/protocol/policy 测试不回归；`npm run test:full` 全绿。
3. 手工冒烟（可选）：HTTP 直调缺参接口返回 400 而非 500。
4. 提交为 `fix(backend): ...` 单提交，符合 commit 规范。
