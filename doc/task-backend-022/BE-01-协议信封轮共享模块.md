# BE-01 协议信封轮共享模块（Shared Protocol Envelope Round）

## 背景

对话编排与确认执行两条路径各有一套「组装 messages → 调模型 → 解析候选 JSON → 修复重试 → telemetry 记录」实现（Cornie-022 §3.3.1 B1）：

- `agent/orchestrator.js:55-100`（trimMessages / sumPromptChars / requestProtocolEnvelope）与 `confirm/executor.js:24-69` 三组函数逐行同构，`MAX_PROTOCOL_REPAIR_RETRIES=1` 各自定义。
- tool followup 拼接双份：`orchestrator.js:164-211`（appendToolRoundMessages）vs `executor.js:86-113`（buildToolFollowupMessages），均为"assistant 信封 JSON + user 追问"结构，且 executor 版**缺 lookupContexts 分支**（已漂移）。

影响：协议格式改动需双文件同步（Shotgun Surgery），两处已出现行为差异。

## 目标

1. 抽共享**协议信封轮模块**：信封请求 + 解析 + 修复重试 + telemetry 记录 + trim/sum，双路径共同调用。
2. tool followup 拼接收敛为模块内单一 builder（含 lookupContexts 分支，修复漂移）。
3. **行为等价**：现有 orchestrator 与 confirm 测试不回归（重构判据）。

## 范围

- `electron/backend/agent/` 下新建协议信封轮模块（如 `protocolEnvelope.js`，orchestrator 与 executor 共同 import）
- `electron/backend/agent/orchestrator.js`（改用共享模块，删除本地双份）
- `electron/backend/confirm/executor.js`（改用共享模块，删除本地双份）
- `tests/orchestrator/conversation-orchestrator.test.mjs`、`tests/services/confirm-service.test.mjs`（保持通过 + 新增信封轮单元用例）

## 设计要求

### 1. 模块接口

- `trimMessages(messages, maxChars?)`、`sumPromptChars(messages)`、`MAX_PROTOCOL_REPAIR_RETRIES` 常量。
- `requestProtocolEnvelope(messages, telemetry, { phase, chatFn?, ... })`：组装 → 调模型（非流式）→ 解析候选 JSON → 修复重试（1 次）→ recordModelCallTelemetry → 返回 `{ envelope, repaired }`。
- `buildToolFollowupMessages(baseMessages, toolCalls, { lookupContexts? })`：生成"assistant 信封 + user 追问"拼接，**支持 lookupContexts 分支**（当前仅 orchestrator 版有）。
- 模块内不直接 import api 层业务；chatFn 由调用方注入（沿用现有注入模式，便于测试 mock）。

### 2. 双路径接入

- orchestrator 的初始轮/恢复轮/工具轮与 executor 的确认恢复轮全部改走共享函数；各路径的 phase 标识（'conversation_initial' / 'conversation' / 'confirmation' 等）作为参数传入，telemetry 语义不变。
- 删除两文件内的本地实现与各自 `MAX_PROTOCOL_REPAIR_RETRIES` 定义。

### 3. 行为等价保障

- prompt 组装顺序、修复 prompt 文案、telemetry 字段与调用时机均与现状一致（只收敛实现，不改语义）。
- 工具轮 followup 在 executor 侧接入后补齐 lookupContexts 传递（若 executor 调用链有 lookup 上下文则传入，没有则传空数组，行为不变）。

## 验收标准

1. grep 确认 `requestProtocolEnvelope`/`trimMessages`/`sumPromptChars` 全仓仅模块内一份定义；`MAX_PROTOCOL_REPAIR_RETRIES` 单一定义。
2. `tests/orchestrator/conversation-orchestrator.test.mjs`、`tests/services/confirm-service.test.mjs` 全部通过（无回归）。
3. 新增信封轮模块单元用例：trim 上限、sum 计数、修复重试触发（坏 JSON → 1 次重试）、lookupContexts 分支拼接。
4. `npm run test:full` 全绿。
5. 提交为 `refactor(backend): ...` 单提交，符合 commit 规范。
