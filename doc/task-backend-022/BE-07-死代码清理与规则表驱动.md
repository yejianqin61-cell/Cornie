# BE-07 死代码清理与规则表驱动（Dead-Code Cleanup & Rule Table-Drive）

## 背景

死代码三处 + 规则重复（Cornie-022 §3.3.1 B4/B5）：

1. `policy/rules.js:486-500` `applyMemoryRule` **不可达**：`evaluateToolRule` 链（:619-633）中 `applyLegacyMemoryDeprecationRule`（:412-422）对 `memory.*` 工具先返回 deny，applyMemoryRule（:627）永远执行不到。
2. `confirm/service.js:92-101` `reject(id)` **无调用方**（路由只调 `rejectConfirmation`）。
3. `contextBuilder.js:39-55` `summarizeTodos`/`summarizeSchedules` **未被引用**（buildConversationContext 内联实现了同逻辑）。
4. `policy/rules.js:424-484` 三个 `apply*Rule`（Ledger/Todo/Schedule）函数体近逐行相同，仅 ledger 多一步 validateToolCall。

## 目标

1. 删除三处死代码。
2. 三个 apply*Rule 表驱动合并为单一"类目域规则"函数，域差异从 domainRegistry 数据读取。
3. 行为等价：策略决策结果不变（回归判据）。

## 范围

- `electron/backend/policy/rules.js`（删 applyMemoryRule + 合并 apply*Rule）
- `electron/backend/confirm/service.js`（删 reject(id)）
- `electron/backend/agent/contextBuilder.js`（删 summarizeTodos/summarizeSchedules，内联逻辑保留）
- `tests/policy/tool-policy.test.mjs`、`tests/services/confirm-service.test.mjs`、`tests/orchestrator/conversation-orchestrator.test.mjs`（保持通过）

## 设计要求

### 1. 死代码删除

- `applyMemoryRule` 连同 evaluateToolRule 链上挂载点（:627）删除（`applyLegacyMemoryDeprecationRule` 已覆盖其语义）。
- `confirm/service.js` 的 `reject(id)` 删除（确认无任何 import/调用，删除前 grep 复核）。
- `summarizeTodos`/`summarizeSchedules` 删除（buildConversationContext 内联版保留，含 PROMPT_LOADING_POLICY 预算切片）。

### 2. 规则表驱动合并

- 单一 `applyCategoryDomainRule(toolCall, sourceText, options)`：从 domainRegistry 取域配置（actionToolNames、validateToolCall 有无），统一执行候选解析/追问/确认逻辑。
- ledger/todo/schedule 三域共用该函数；域差异（validateToolCall）由注册数据驱动。
- 决策结果与现有一致（allow/confirm/deny 语义不变）。

## 验收标准

1. grep 确认：`applyMemoryRule`、`reject(id)`、`summarizeTodos`、`summarizeSchedules` 全仓零引用；`applyLedgerRule/applyTodoRule/applyScheduleRule` 无独立函数体（或合并后仅一个入口）。
2. `tests/policy`、`tests/services/confirm-service`、`tests/orchestrator` 全部通过（策略决策无回归）。
3. `npm run test:full` 全绿。
4. 提交为 `refactor(backend): ...` 单提交（可拆 2 个：死代码清理 / 规则合并，各保持全绿），符合 commit 规范。

## 依赖
