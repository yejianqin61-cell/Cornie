# BE-08 一致性收尾（Consistency Cleanup）

## 背景

多处一致性裂缝（Cornie-022 §3.3.1 B10 + §3.3.2 N4/N5）：

1. **工具注册重名静默覆盖**：`tools/registry.js:7` `toolRegistry.set` 无重名检查（与 `domainRegistry.js:94` 重名抛错不一致）。
2. **HTTP 错误码不映射**：`http/middleware.js:3-17` 带 code 的业务错误塌缩为 500（N5 的中间件部分——BE-03 已做 400 化与 code 映射时若已覆盖此点，本任务仅核对补齐）。
3. **observation 路由风格分裂**：全文件手写 try/catch+next（`observation/routes.js:8-113`），无参数校验。
4. **启动注册竞态**：`server.js:112-114` memory_wiki 工具注册异步失败仅 console，且注册在 conversation 路由挂载之后（首轮对话可能 tool_not_found）。

## 目标

1. 工具注册重名即 throw（列出新旧定义来源）。
2. HTTP 错误码映射补齐（若 BE-03 未完全覆盖）。
3. observation 路由改 asyncHandler + 路由层参数校验。
4. 启动期工具注册 await 化，失败显式抛错退出启动，消除首轮竞态。

## 范围

- `electron/backend/tools/registry.js`（重名检测）
- `electron/backend/http/middleware.js`（错误码映射核对/补齐）
- `electron/backend/observation/routes.js`（asyncHandler + 校验）
- `electron/server.js`（registerMemoryWikiTools await 化 + createServer 改 async 或启动链调整）
- `electron/main.js`（启动链适配，如 createServer 变 async）
- `tests/tools/registry-gateway.test.mjs`、`tests/services/business-services.test.mjs`（observation 校验用例）

## 设计要求

### 1. 重名检测

- `registerTool` 遇到已存在同名工具即 `throw`（错误信息含新旧注册来源文件名/描述）；与 domainRegistry 行为一致。
- 现有可能重名的情况：全仓扫描确认无冲突（若有，先修复冲突再启用检测）。

### 2. observation 路由对齐

- 全部 handler 改 asyncHandler；date/type/q/limit 等参数在路由层校验（日期格式真实性沿用 validators，limit 数值边界）。

### 3. 启动 await

- `createServer` 改 async：内部 await `registerMemoryWikiTools(...)` 完成后再挂载 conversation 等路由；失败显式抛错（启动进程退出，不再静默）。
- `main.js`/启动链相应 await 适配；确保 dev/打包两路径都正确。

## 验收标准

1. 新增/更新测试通过：重名注册抛错；observation 非法 date/limit 返回 400；启动链单测（或 verify 脚本）确认 memory_wiki 工具先于会话路由注册。
2. `tests/tools`、`tests/services` 通过；`npm run test:full` 全绿。
3. 人工冒烟：应用启动正常，首轮对话可用 memory_wiki.* 工具。
4. 提交为 `fix(backend): ...` 单提交（可拆 2 个：registry 重名 + observation/启动链，各保持全绿），符合 commit 规范。

## 依赖

- BE-03（错误码映射若已实现则本任务只核对）；启动链改动建议在 BE-01（协议信封轮）之后，避免与编排改动叠加冲突。
