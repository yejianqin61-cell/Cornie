## 2. 文档目的

本文档将 Cornie-020 §3 前端维度评估发现的缺陷（F1-F10）转化为可开发、可验收的改进设计。本期治理目标为**前端**，范围严格限定在 `src/renderer/**` 与前端测试，不涉及后端、数据库与记忆层。

每个缺陷均已在本文档编写前做过代码核实（文件与行号见 §3 问题清单），保证事实准确；实现决策层不依赖具体文件路径，只描述模块职责与接口契约，避免快速过时。

## 3. 问题陈述（Problem Statement）

### 3.1 用户视角的问题

用户在使用 Cornie 时，会实际遇到以下体验问题：

1. **最终回复不流式**：发送消息后要等整段回复生成完毕才一次性上屏，长回复期间界面看起来"卡住"；后端已支持 SSE 流式（454 能力已交付），但前端入口从未接线，能力闲置。
2. **日期可能记错天**：多个页面用 UTC 时间计算"今天"，在深夜/跨时区场景下会把今天的消息记到昨天；且"今天"的定义在 8 处重复实现，各页可能不一致。
3. **按钮点了没反应**：多处"管理类目 / 查看全部 / 进入详情"按钮看起来可点，实际点击无任何行为。
4. **配置 Key 两处不一致**：主壳层与首次引导页各有一套几乎逐行重复的模型设置逻辑，可能出现一边已配置、另一边显示未配置的状态分裂。
5. **切页时内容串台**：快速切换日期/视图时，旧请求的响应可能覆盖新选择的内容，显示的不是用户当前想看的数据。
6. **离开页面还有动作**：列表页的防抖定时器在组件卸载后仍可能触发请求；聊天页轮询在慢响应时可并发堆积。
7. **键盘/读屏不好用**：多处可点击元素是 div，键盘不可达；日记回顾区标题语义错误；个别弹窗配色与主题冲突。
8. **请求可能无限等待**：所有 API 请求无超时、无取消；后端无响应时界面只能干等。

## 4. 解决方案（Solution）

对应用户视角的问题，目标态为：

1. 聊天入口默认走**流式回复**：最终回复逐字上屏，层间话语/工具结果照常上屏，失败自动回退为完整回复或明确提示，发送中禁止重复提交。
2. **"今天"只有一种定义**：统一按本地时区计算，全仓单一日期工具，跨模块一致。
3. **界面无死按钮**：每个可点击元素要么有真实行为，要么被移除；子页面通过统一导航出口跳转。
4. **模型设置单一状态源**：主壳层与引导页共享同一设置逻辑与状态，任何一处变更两处一致。
5. **视图永远显示最新选择**：日期/视图切换采用"请求序号 + 取消"守卫，旧响应不得覆盖新状态；离开页面自动取消在途请求。
6. **离开即停**：定时器统一由组合式工具管理，组件卸载自动清理；轮询防重入、慢响应不堆积。
7. **键盘可达、语义正确**：可点击元素均为真按钮或等价语义；标题层级正确；配色统一。
8. **请求有界**：所有请求带超时与可取消信号，错误分类（网络/超时/HTTP/业务）后给出对应提示。

## 5. 用户故事（User Stories）

### 5.1 流式回复

1. 作为聊天用户，我希望发送消息后 Cornie 的最终回复能逐字流式显示，这样长回复可以边生成边读，不用干等。
2. 作为聊天用户，我希望流式输出期间钻取联想话语与工具结果仍能照常上屏，这样我能看到 Cornie"在思考/在做事"的过程。
3. 作为聊天用户，我希望流式中断（网络/后端错误）时能看到明确的失败提示，而不是一条永远"正在输入"的残缺消息。
4. 作为聊天用户，我希望流式失败后能回到稳定的完整回复或重试入口，这样对话不会卡死。
5. 作为聊天用户，我希望回复流式期间不能重复发送消息，这样不会产生重复请求。
6. 作为聊天用户，我希望非流式发送与流式发送的最终结果形态一致（消息 id、确认卡、工具结果都正常出现），这样两种路径体验无落差。
7. 作为开发者，我希望流式与非流式发送共享同一套消息状态机（占位、确认、错误回退），这样只维护一份发送逻辑。

### 5.2 日期与时区

8. 作为用户，我希望"今天"始终按电脑的本地时区计算，这样深夜或跨时区时消息不会记到错误的一天。
9. 作为用户，我希望聊天、日记、观察、收支等所有页面看到的是同一天，这样跨模块跳转不会出现日期断层。
10. 作为用户，我希望日期显示格式（如 2026-08-21）在全局一致，这样阅读不混乱。
11. 作为开发者，我希望全仓只有一处日期工具实现，这样时区修复只改一个地方。
12. 作为开发者，我希望日期工具提供跨日边界的可测用例（如 UTC+8 深夜 00:30），这样时区回归不会复发。

### 5.3 死交互

13. 作为用户，我希望"管理类目"按钮能跳到对应类目管理区，这样真的可以管理类目。
14. 作为用户，我希望"查看全部"按钮能展开或跳转到完整列表，这样真的可以看到全部。
15. 作为用户，我希望界面中不存在"看起来可点但点击无效"的元素，这样不会被误导。
16. 作为开发者，我希望子页面通过统一的导航出口（`@go`/路由）上抛跳转意图，这样壳层集中处理导航，组件不再各自为政。

### 5.4 模型设置

17. 作为用户，我希望首次引导页与主设置页配置 API Key 的行为完全一致，这样不会出现"这边配好了那边还提示未配置"。
18. 作为用户，我希望保存 Key 成功/失败都有统一的"铃湾口吻"反馈，这样体验一致。
19. 作为用户，我希望两处页面同时打开时状态能同步刷新，这样不会看到互相矛盾的设置。
20. 作为开发者，我希望模型设置状态与提交逻辑只有一份实现，这样两处入口天然一致。

### 5.5 巨型组件拆分

21. 作为记忆维护者，我希望记忆工作台按职责（列表/详情/治理/审计/设置）拆分为独立区块组件，这样长页面操作响应更快、问题定位更准。
22. 作为记忆维护者，我希望记忆详情页的页面类型相关逻辑用配置表表达（类型→图标/字段/模板），这样新增类型不需要改多处 if。
23. 作为开发者，我希望拆分后各区块可以独立测试，这样回归成本更低。

### 5.6 竞态与请求取消

24. 作为用户，我希望快速切换日期/视图时最终显示的是最新选择的内容，这样旧响应不会覆盖新视图。
25. 作为用户，我希望连续切换时界面不被中间态的加载闪烁打扰，这样阅读连续。
26. 作为用户，我希望切换离开页面后，在途请求被取消，这样不会产生多余负载与迟到错误提示。
27. 作为开发者，我希望竞态防护是一个可复用的守卫模式（请求序号 + 取消信号），这样所有日期/列表切换场景统一接入。

### 5.7 定时器与轮询

28. 作为用户，我希望离开列表页后防抖搜索不再触发请求，这样不会出现离开后的意外网络活动。
29. 作为用户，我希望聊天页在窗口隐藏时暂停轮询、恢复可见时继续，这样后台不空转。
30. 作为用户，我希望轮询在前一次同步未完成时不会叠加发起，这样不会并发堆积。
31. 作为开发者，我希望定时器统一由组合式工具管理并在卸载时自动清理，这样不会漏清。

### 5.8 可访问性

32. 作为键盘用户，我希望所有可点击元素都能用 Tab 聚焦并用 Enter/Space 触发，这样不需要鼠标也能完整使用。
33. 作为读屏用户，我希望标题层级正确（如日记回顾区不是按钮里套标题），这样朗读顺序合理。
34. 作为视觉用户，我希望弹窗气泡配色与全局主题一致，这样不会刺眼或突兀。
35. 作为键盘用户，我希望焦点在页面切换后落在合理位置（如主操作区），这样操作连续。

### 5.9 死代码

36. 作为开发者，我希望仓库中没有未被引用的组件文件，这样代码库更易维护、构建更快、搜索不误判。
37. 作为开发者，我希望删除死组件后测试与清理脚本能验证"无未引用组件"，这样死代码不会回潮。

### 5.10 请求层

38. 作为用户，我希望后端无响应时请求在合理时间内超时并给出"铃湾没收到回应"之类的提示，这样不会无限等待。
39. 作为开发者，我希望请求层统一错误分类（网络中断/超时/HTTP 错误/业务拒绝），这样页面可按类型给出不同提示。
40. 作为开发者，我希望所有 API 请求支持外部取消信号，这样页面切换时可统一取消在途请求。
41. 作为开发者，我希望流式请求同样支持超时与取消，这样断连场景可被明确处理而不是静默挂起。

## 6. 实现决策（Implementation Decisions）

> 决策只描述模块职责与接口契约，不绑定具体文件路径；落地时以本决策为准。

### ID-1 统一日期工具模块（解决 F2）

- 新建**日期工具模块**：提供 `today()`（本地时区当天 `YYYY-MM-DD`）、`formatDate()`、`parseLocalDate()`；明确"今天"= 本地时区日期，并在模块注释中固化该语义。
- 全仓 8 处 `toISOString().slice(0, 10)` 全部替换为该模块的 `today()`；日期解析/格式化一并收敛。
- 输出本地日期而非 UTC 的判定必须含跨日边界用例（UTC+8 深夜 00:30 属于"当天"）。

### ID-2 请求层加固（解决 F10）

- `apiFetch` 统一升级：默认超时（如 30s，可配置）；透传外部 `AbortSignal`；错误归一化为结构化错误 `{ kind: 'network'|'timeout'|'http'|'protocol', status?, message }`，替换裸字符串 throw。
- 流式请求 `streamConversation` 增加：接收 `signal`；基于同一超时机制；SSE 解析对半截行/坏行保持健壮；`kind:'error'` 事件与网络异常统一抛结构化错误。
- 所有页面在途请求的取消统一经由该信号机制，不再各自实现。

### ID-3 聊天发送收敛 + 流式接线（解决 F1）

- **流式为主路径**：聊天输入提交默认调用流式发送；非流式发送保留为回退（流式不可用时）。
- 流式与非流式收敛为**同一发送骨架**：占位消息、发送中禁发、用户消息 id 回填、错误回退文案（铃湾口吻）、确认卡/工具结果/`notifyDataChanged` 全部共用；差异仅在"最终回复是否逐字增量渲染"。
- 流式占位消息渲染"正在输入"态；收到 `delta` 追加文本；`done` 后替换为正式消息（id/内容）；失败时占位消息转为错误提示并可重试。
- 层间话语（interimReplies）与工具结果在流式路径中照常上屏（沿用现有 appendResponse 逻辑）。

### ID-4 轮询与定时器治理（解决 F7/F10）

- 轮询：`startConversationSync` 增加**防重入**（上一次同步未完成则跳过本轮）；窗口隐藏时暂停、恢复可见时继续并立即补一次同步。
- 新建**定时器组合式工具**（如 `useDebouncedValue` / `useInterval`）：统一管理 setTimeout/setInterval，组件卸载（`onUnmounted`）自动清理；观察列表防抖等全部接入。
- 目标：全仓组件卸载后不再有悬挂定时器。

### ID-5 竞态守卫模式（解决 F6）

- 新建**请求守卫工具**（请求序号 + AbortController）：发起新请求时使旧请求失效（取消并忽略其回调）。
- 日期/视图切换场景（日记编辑加载、聊天记录切换、观察列表筛选等）统一接入；断言"最终渲染 = 最后一次选择的内容"。
- 与 ID-2 的取消信号共用同一机制。

### ID-6 模型设置单一状态源（解决 F4）

- 抽取**模型设置组合式工具**：状态（status/settings/form/saving/loading/error/notice）+ 动作（refresh/check/submit/reset）+ 友好错误文案映射，整体一份。
- 主壳层与引导页组件改为消费同一工具；两处展示层各自渲染但状态与提交逻辑唯一。
- 验收语义：任一入口保存成功后，另一入口刷新可见一致状态。

### ID-7 死交互接线（解决 F3）

- 子页面（待办/日程/收支首页）补**导航出口**：需要跳到其他区域（类目管理、完整列表、设置）的按钮通过统一事件（`@go`）上抛，壳层集中处理跳转；无真实目标的按钮移除。
- 每个"看起来可点"的元素必须有行为或移除——以"点击必有响应"为验收底线。

### ID-8 死组件删除（解决 F9）

- 删除 4 个无引用组件；删除前以 grep 复核无动态 import 引用。
- 增加**未引用组件扫描**（并入现有仓库清洁检查脚本或前端测试）：删除后全仓 import 扫描通过。

### ID-9 工作台拆分与表驱动（解决 F5）

- 记忆工作台按职责拆分：列表区、详情编辑区、治理待审区、巡检审计区、设置区各自独立为组件，主工作台只做组合与状态协调。
- 记忆详情页 pageType 相关分支（图标/字段分组/摘要模板）收敛为**类型配置表**，新增类型只加配置。
- 拆分不改变现有 API 契约与用户可交互路径（纯结构重构）。

### ID-10 可访问性收口（解决 F8）

- 可点击 `div` 全部改为 `<button>`（或等价 `role="button"` + tabindex + keydown 处理）；焦点管理在视图切换时落在主操作区。
- 修正日记回顾区标题语义（`button` 内不渲染 `h1`，标题移出按钮）。
- 弹窗/气泡配色对齐全局主题色板，去除旧样式残留。

## 7. 测试决策（Testing Decisions）

### 7.1 测试接缝（从高到低，优先复用现有接缝）

| 接缝 | 测什么 | 说明 |
| --- | --- | --- |
| **组件行为层（最高接缝）** | 交互行为：按钮点击触发导航/动作、流式占位与增量渲染、确认卡、竞态最终态、键盘可达 | 现有 `tests/frontend/*.test.mjs`（vitest + jsdom + @vue/test-utils，88 用例）即此接缝，优先扩展 |
| **组合式工具层** | useChat（发送/流式/轮询防重入）、模型设置工具、日期工具、竞态守卫 | 直接调用 composable + mock api 模块，不依赖 DOM |
| **API 契约层** | apiFetch 超时/取消/错误分类、流式解析/断流/Abort | mock `globalThis.fetch`（沿用 `tests/frontend/setup.mjs` 现有 mock 先例） |

### 7.2 每缺陷对应测试要点

- **F1 流式**：`streamSend` 逐字增量渲染断言；`done` 后替换正式消息；失败回退文案；发送中禁发；层间话语/工具结果仍上屏。
- **F2 日期**：本地时区 `today()` 跨日用例（UTC+8 深夜）；全仓替换后一致性冒烟（抽查各页面 today 结果相同）。
- **F3 死交互**：点击"管理类目/查看全部"断言 emit 或导航发生；无行为按钮已移除（组件快照/断言）。
- **F4 模型设置**：主壳层与引导页共用工具后，任一入口保存成功另一入口状态一致（组件级断言）。
- **F5 拆分**：拆分后各区块组件独立挂载冒烟；pageType 配置表驱动（多类型渲染断言）；现有记忆页面测试全绿（防回归）。
- **F6 竞态**：快速切日期后断言最终渲染为最新选择内容、旧响应被丢弃（用受控 Promise mock 模拟乱序返回）。
- **F7 定时器**：卸载后断言不再触发请求（vi.useFakeTimers 推进时间）。
- **F8 a11y**：键盘触发等价点击；`button` 内无标题元素断言；焦点落位断言。
- **F9 死组件**：全仓 import 扫描通过（并入检查脚本）。
- **F10 请求层**：超时触发（fake timers）、Abort 触发、错误分类映射、流式半截行/error 事件/Abort。

### 7.3 先例

- `tests/frontend/api-contract.test.mjs`：mock fetch 的 API 契约测试。
- `tests/frontend/cornie-composer.test.mjs`、`app-navigation.test.mjs`：组件行为与导航测试。
- `tests/frontend/setup.mjs`：全局 fetch/ResizeObserver mock 基座。
- 后端记忆层 `tests/orchestrator/conversation-orchestrator.test.mjs` 的"受控 mock 乱序返回"手法可作为竞态测试参考。

### 7.4 好测试的标准

只测外部行为（用户可见的状态与交互），不测内部实现细节（不 assert 内部函数调用顺序、不依赖组件私有状态名）。每个测试以"用户操作 → 可见结果"书写。
