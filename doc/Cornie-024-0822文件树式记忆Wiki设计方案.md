## 2. 文档目的

将记忆 Wiki 的浏览方式从"列表页 → 详情页"跳转模式，重构为 **VSCode 式双栏布局：左侧文件树导航，右侧 Wiki 正文阅读/编辑**。

用户已确认的关键设计点：

1. **树层级：一级类型目录**——顶层为类型文件夹（关于你 / 重要的人 / 你的偏好 / 你的特征 / 事件 / 主题 / 目标 …），叶子为页面文件。
2. **树取代类型 Tab 与分页**——文件树本身即导航；树顶部保留搜索框。
3. **已归档独立目录、灰显、只读**——树底部"已归档"文件夹，归档文件灰显，可看正文不可编辑。

---

## 3. 背景与现状

Cornie-023 批次后（HEAD=`bff89ea`），记忆 Wiki 为：

- 导航第三栏「记忆 Wiki」→ `MemoryPageList`（类型 Tab + offset 分页 + 按更新时间排序）+ `MemoryPageDetail`（阅读/编辑两态）。
- 用户诉求：像文件树一样组织，左侧目录右侧正文，一屏完成"找 → 看 → 改"。

可行性结论：**完全可行**。现有 `listMemoryWikiPages` API（pageType/status/limit/offset）与 `MemoryPageDetail` 两态组件可直接复用；改动集中在**新的双栏容器与文件树组件**（纯前端）。

## 4. 目标态

```
┌─────────────────────────────────────────────────────────┐
│ 记忆 Wiki                                        [搜索框] │
├──────────────┬──────────────────────────────────────────┤
│ 📁 关于你    │  ┌────────────────────────────────────┐  │
│   📄 叶健钦  │  │  ✨ 关于你                          │  │
│ 📁 重要的人  │  │  叶健钦                             │  │
│   📄 钟奕菲  │  │  一个想被好好记住的人。             │  │
│ 📁 你的偏好  │  │  （正文…）                          │  │
│ 📁 你的特征  │  │  ──────────────────────────────    │  │
│ 📁 事件      │  │  [编辑]                    [删除]   │  │
│ 📁 主题      │  │  （来源：聊天/观察/相关页 弱化区）    │  │
│ 📁 已归档    │  └────────────────────────────────────┘  │
│   📄 旧页面… │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- 左侧树：类型目录（一级）→ 页面文件；目录可折叠；当前选中节点高亮。
- 右侧正文：选中树节点 → 加载该页（阅读态）；点"编辑"→ 编辑态（R-06 两态复用）；"新建记忆"按钮在树顶部 → 右侧编辑空页。
- 已归档：树底部独立目录，文件灰显，点击可读不可编辑。

## 5. 用户故事（User Stories）

1. 作为用户，我希望打开记忆 Wiki 就能看到左侧目录树，这样一眼看清有哪些类型的记忆。
2. 作为用户，我希望点击某个类型目录能看到该类型下的所有记忆页，这样按类型翻阅。
3. 作为用户，我希望目录可以折叠/展开，这样树不会太长。
4. 作为用户，我希望点击一个记忆页，右侧直接显示正文，这样不用来回跳页面。
5. 作为用户，我希望在阅读态点"编辑"就地进入编辑，保存后回到阅读态。
6. 作为用户，我希望树顶部能搜索记忆（标题/别名/摘要模糊匹配），这样不用一层层翻目录。
7. 作为用户，我希望已归档的记忆在树底部灰显，可查看但不可编辑。
8. 作为用户，我希望新建记忆在右侧直接打开空编辑页，创建后出现在对应类型目录下。
9. 作为用户，我希望删除/归档后树即时更新，当前选中的页面被移除。

## 6. 实现决策（Implementation Decisions）

> 决策只描述职责与契约，不绑定具体文件路径；落地以本决策为准。

### ID-1 双栏容器（Memory Wiki 主视图）

- 新建**记忆 Wiki 双栏容器**：左侧树面板（固定宽度，可拖拽调宽可选）+ 右侧正文面板（复用现有详情两态组件）。
- 替代当前"列表视图 → 详情视图"的子视图切换：`memory-detail` / `memory-create` 不再作为独立导航视图，由右侧面板按选中节点就地呈现。
- 顶部栏：标题"记忆 Wiki" + 搜索框 + "新建记忆"主按钮。

### ID-2 文件树组件

- 新建**树组件**：输入为扁平页面列表，内部构建树结构（`type → pages[]`）。
- 交互：目录折叠/展开（默认展开或记忆上次状态）、节点选中高亮、文件点击 → 选中并通知容器加载正文；目录点击仅展开（不选中内容）。
- 树节点顺序：身份 4 类固定在前（关于你/重要的人/你的偏好/你的特征），普通类型按固定顺序（事件/主题/目标/项目/习惯/需要），已归档固定最后。
- 空目录显示占位（如"（空）"弱化小字），仍可展开占位。

### ID-3 数据加载

- 进入容器一次性加载全部页面（含 active 与 archived，两批请求或 `status` 放宽），页面数通常为数十页量级，树内不做分页。
- `listMemoryWikiPages` 现有分页参数保留（树内使用大 limit 或循环拉取）；数据来源不变（后端零改动）。
- 变更联动：删除/归档/创建后重新拉取或局部更新树（沿用现有 `emitDataChanged` 或容器内刷新）。

### ID-4 已归档目录

- 树底部"已归档"文件夹：`status === 'archived'` 的页面归入；节点灰显。
- 点击已归档文件 → 右侧只读正文（编辑按钮隐藏）；恢复操作保留（归档页阅读态提供"恢复"按钮，R-06 已有 restore 逻辑可复用）。

### ID-5 搜索

- 树顶部搜索框：输入后对**标题 / 别名（aliasesText）/ 摘要**做模糊匹配（`includes` 即可，先不做分词）。
- 搜索态：树按命中结果折叠为"搜索结果"平铺列表（或命中的目录自动展开并高亮命中项），空结果给简短空态。
- 清空搜索恢复完整树。

### ID-6 右侧正文

- 复用现有详情两态组件（R-06）：props `id`（选中页面）或新建模式；emits back/created/deleted/open-* 由容器适配（back 不再需要，改为"取消选中"或隐藏）。
- 选中树节点即加载正文（阅读态）；新建在右侧打开空编辑页。
- 来源跳转（open-chat-source / open-observation / open-memory）保持：open-memory 改为树内选中对应节点。

### ID-7 状态保持

- 当前选中节点、目录展开状态可在容器内保持（组件生命周期内）；跨会话持久化（localStorage 记录展开的目录与上次选中页面）为可选增强。

### ID-8 与治理工作台分工

- 前台「记忆 Wiki」= 树 + 正文（普通用户日常翻阅编辑）。
- 高级设置「记忆治理工作台」= 版本/回滚/主题索引/治理审核/巡检审计（R-07 已收敛定位），不重复页面树。

## 7. 测试决策（Testing Decisions）

### 7.1 接缝（复用现有前端接缝）

| 接缝 | 测什么 | 说明 |
| --- | --- | --- |
| 树组件（新） | 树构建、折叠/展开、选中、已归档灰显、搜索过滤 | `tests/frontend/` 新增 `memory-wiki-tree.test.mjs` |
| 双栏容器 | 选节点 → 右侧加载正文；新建 → 空编辑；删除/归档后树更新 | `tests/frontend/` 新增 `memory-wiki-home.test.mjs` |
| 详情两态（复用） | R-06 既有用例保持通过（只读态/编辑态/来源跳转） | `memory-page-user-flow.test.mjs` |

### 7.2 每决策对应测试要点

- ID-2：树结构正确（类型分组、顺序、空目录占位、已归档独立）；折叠/展开状态切换。
- ID-4：归档页灰显、只读（无编辑按钮）、恢复可用。
- ID-5：搜索命中标题/别名/摘要；清空恢复；空结果空态。
- ID-6：选中加载正文；新建创建后出现在对应目录；open-memory 树内跳转。
- 旧列表相关测试（memory-page-list-browse 的类型 Tab/分页）随 MemoryPageList 退役一并适配移除。

### 7.3 好测试的标准

只测外部行为（树渲染结构、选中后正文加载、搜索过滤结果、归档只读），不测内部实现。
