# FE-03 流式回复接线与发送收敛（Streaming Reply Wiring）

## 背景

后端 SSE 流式能力（`POST /api/conversations/stream`，454 已交付）与前端实现（`api.js` 的 `streamConversation`、`useChat.js` 的 `streamSend`）均已存在，但 **`streamSend` 无任何组件调用**（Cornie-021 §3.2 F1）——聊天入口仍走非流式 `send`，用户要等整段回复生成完毕才看到内容。

同时 `send`（useChat.js L121-158）与 `streamSend`（L161-219）近乎逐行重复：占位消息、发送中禁发、错误回退文案（"唔...我好像走神了"）、消息 id 回填逻辑双份维护，后续改动需双处同步。

## 目标

1. 聊天输入提交默认走**流式**：最终回复逐字上屏；层间话语（interimReplies）与工具结果照常上屏。
2. `send` 与 `streamSend` 收敛为**同一发送骨架**（差异仅剩"最终回复是否增量渲染"）。
3. 流式失败自动回退为完整回复或明确错误提示，不出现"永远正在输入"的残缺消息。
4. 流式期间禁止重复发送。

## 范围

- `src/renderer/composables/useChat.js`（发送骨架收敛、流式状态机、轮询防重入部分见 FE-04）
- `src/renderer/components/CornieComposer.vue`（提交入口接线到流式）
- `src/renderer/api.js`（复用 FE-01 升级后的 `streamConversation`；本任务仅接线，不改契约）
- `tests/frontend/cornie-composer.test.mjs`、`tests/frontend/` 下聊天相关测试（新增用例）

## 设计要求

### 1. 统一发送骨架（核心）

- 提取单一发送流程，参数化"流式或否"（如内部 `send({ text, stream })` 或单一 `send(text, { stream: true })`）：
  1. 校验非空与 `sending` 禁发；
  2. 上屏用户占位消息（tempId + pendingSync）；
  3. 流式时上屏 Cornie 占位消息（streaming 态，内容为空并显示"正在输入"样式）；
  4. 请求（流式走 `streamConversation` + 增量回调，非流式走 `sendMessage`）；
  5. 用户消息 id 回填、Cornie 消息替换为正式 id/内容；
  6. `appendResponse` 的层间话语/工具结果/确认卡/`notifyDataChanged` 逻辑两种路径共用；
  7. 失败统一回退：用户占位标 error、Cornie 占位替换为铃湾口吻错误文案；流式失败时若已有部分增量内容，保留已显示内容并追加错误提示（不整条丢弃）。
- 删除重复的 catch/finally 分支，错误文案单一常量。

### 2. 流式状态机

- Cornie 占位消息字段：`{ id, role:'cornie', content:'', streaming:true }`。
- `delta` → 追加 `content`（沿用现有 `appendDelta` 逻辑，改为骨架内回调）。
- `done`（result 含 `cornieMessage.content`）→ 替换占位为正式消息（id、content、streaming:false、pendingSync:false）。
- 流式错误 → 占位转 `streaming:false, error:true` + 错误文案。
- 组件层：`streaming` 消息渲染打字指示（如光标/省略号），不渲染为最终文案。

### 3. 入口接线

- `CornieComposer.vue` 提交调用流式发送；`sending` 为 true 时禁用输入与发送按钮（已有逻辑保留）。
- 桌宠窗口（`CorniePet.vue`）本期**不接入**流式（Cornie-021 §8 范围外），保持非流式发送；骨架两种路径都可用即可。

### 4. 依赖 FE-01

- 流式请求支持超时/取消（FE-01）；页面切换离开聊天视图时取消在途流式（与 FE-05 的守卫协同，若 FE-05 未合入则至少保证组件卸载时停止回调）。

## 验收标准

1. 新增/更新测试全部通过：
   - 流式发送：mock SSE（delta 多次 → done）断言逐字增量追加、最终替换正式消息、interimReplies 与工具结果照常上屏。
   - 失败回退：流式 error → 占位转错误文案；已有增量内容保留。
   - 禁发：sending 期间再次提交被忽略。
   - 非流式路径：现有 composer 测试不回归（send 行为不变）。
2. `npx vitest run tests/frontend` 全绿。
3. 人工冒烟（可选）：本地启动后发送长回复，观察逐字渲染与层间话语顺序。
4. 本任务提交为 `feat(frontend): ...` 单提交，符合 commit 规范。
