# FE-06 模型设置单一状态源（Model Settings Single Source）

## 背景

模型设置（DeepSeek API Key / baseUrl / model / timeoutMs）逻辑在**两处几乎逐行重复**（Cornie-021 §3.2 F4）：

- 主壳层 `App.vue:67-155`：settingsForm/settingsLoading/settingsError/settingsNotice + `refreshModelState`/`checkModel`/`submitModelSettings`/`resetModelSettings`/`toFriendlySettingsError`。
- 首次引导页 `DeepseekConfig.vue:15-91`：同样的状态与动作（含相同的铃湾口吻错误文案映射）。

风险：一处修复另一处遗漏 → 状态分裂（一边已配置、另一边仍提示未配置）；文案/校验不一致。

## 目标

1. 抽取**单一模型设置组合式工具**：状态 + 动作 + 友好错误映射整体一份。
2. 主壳层与引导页改为消费同一工具（各自只保留展示层）。
3. 任一入口保存成功后，另一入口可见一致状态（同轮刷新语义）。

## 范围

- `src/renderer/` 下新增 `useModelSettings` 组合式（如 `src/renderer/composables/useModelSettings.js`）
- `src/renderer/App.vue`（模型设置段改为消费工具）
- `src/renderer/components/DeepseekConfig.vue`（改为消费工具）
- `tests/frontend/` 新增模型设置测试（如 `model-settings.test.mjs`）

## 设计要求

### 1. 组合式接口

- 状态：`modelStatus`、`modelSettings`、`form`（apiKey/baseUrl/model/timeoutMs）、`saving`、`loading`、`error`、`notice`。
- 动作：`refresh()`（并行拉 status+settings 并回填 form）、`check()`（仅 status）、`submit()`（保存→提示→refresh→check）、`reset()`（清除→提示→refresh→check）、`clearError()`。
- 错误文案：`toFriendlySettingsError` 移入工具，单一映射表（网络/超时/缺 Key/非法超时/其他 → 铃湾口吻文案）。
- 行为与原实现**逐项等价**（成功/失败提示文案、refresh 时序不变），只去重。

### 2. 两处入口

- `App.vue` 与 `DeepseekConfig.vue` 各自 `const settings = useModelSettings()`；模板绑定与现有渲染保持不变（或最小必要调整）。
- 两处同时挂载时各自独立实例（不强制跨组件共享同一响应式对象），但逻辑唯一 → 语义一致。
- 若实现允许，可进一步共享单例（模块级状态）使两处实时同步；非必须，但不得出现"一处已配置另一处显示未配置"的持久不一致（同一会话内 refresh 后一致即可）。

### 3. 契约不变

- 调用 `getModelStatus` / `getModelSettings` / `saveModelSettings` / `clearModelSettings` 的契约不变（api.js 不动）。

## 验收标准

1. 新增 `model-settings.test.mjs` 全部通过：
   - submit 成功：调用 save → refresh → check，提示文案正确。
   - submit 失败：错误分类映射为对应铃湾口吻文案。
   - reset 成功：clear → refresh → check。
   - 等价性：两处入口（App 与 DeepseekConfig 挂载场景）行为断言一致。
2. 现有设置相关测试（app-settings-flow 等）不回归；`npx vitest run tests/frontend` 全绿。
3. 人工冒烟：引导页保存 Key 后切到主设置页，状态一致。
4. 本任务提交为 `refactor(frontend): ...` 单提交，符合 commit 规范。
