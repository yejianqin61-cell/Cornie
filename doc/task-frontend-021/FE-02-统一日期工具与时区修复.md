# FE-02 统一日期工具与时区修复（Unified Local-Date Utilities）

## 背景

前端 8 处重复实现"今天"（`new Date().toISOString().slice(0, 10)`），全部基于 **UTC**（Cornie-021 §3.2 F2）：

`useChat.js:17`、`ChatHome.vue:106`、`CorniePet.vue:71`、`LedgerHome.vue:25,428`、`ObservationList.vue:15`、`ObserveMemoryHome.vue:98`、`PendingConfirmations.vue:10`（后者随 FE-08 删除）。

问题：UTC 取"今天"与用户本地时区不一致——东八区深夜 00:00~08:00 之间，UTC 日期仍是昨天，导致聊天/日记/观察记录被记到错误的一天；且各页面实现分散，修复只能逐处改。

## 目标

1. 新建**唯一**日期工具模块：`today()`（本地时区当天 `YYYY-MM-DD`）、`formatDate()`、`parseLocalDate()`，在模块注释固化"今天 = 本地时区日期"语义。
2. 全仓 8 处 `toISOString().slice(0, 10)` 替换为统一 `today()`；日期格式化/解析一并收敛到该模块。
3. 补跨日边界测试，防止时区问题回归。

## 范围

- `src/renderer/` 下新增日期工具模块（建议 `src/renderer/utils/date.js`；若已有 utils 目录则并入，否则新建）。
- 替换点：`useChat.js`、`ChatHome.vue`、`CorniePet.vue`、`LedgerHome.vue`、`ObservationList.vue`、`ObserveMemoryHome.vue`（`PendingConfirmations.vue` 随 FE-08 删除，无需处理；若 FE-08 未合入前本任务先行，可一并替换）。
- `tests/frontend/` 新增日期工具测试（如 `date-utils.test.mjs`）。

## 设计要求

### 1. 模块接口

- `today(): string` — 本地时区当天 `YYYY-MM-DD`。实现须用本地时间分量（getFullYear/getMonth/getDate）拼装，**禁止** `toISOString()`。
- `formatDate(dateLike): string` — 统一展示格式（沿用 `YYYY-MM-DD`），输入可为 Date/字符串/时间戳。
- `parseLocalDate(dateStr): Date` — 将 `YYYY-MM-DD` 解析为本地时区零点 Date（避免 `new Date('2026-08-21')` 被按 UTC 解析的陷阱）。
- 导出常量（如 `DATE_RE`）供校验复用；模块内不依赖任何组件/API。

### 2. 替换规则

- 所有"取今天日期字符串"的调用点替换为 `today()`。
- 涉及 `YYYY-MM-DDTHH:mm`（本地时间输入转 ISO 提交后端）的转换点（LedgerWorkspace/ScheduleWorkspace/TodoWorkspace 的 form 提交）不在本任务范围（它们提交的是用户选择的时刻，非"今天"语义）；如发现同类 UTC 陷阱可在本任务顺带修正并记录。
- 替换后不得改变任何 API 请求参数的格式（后端契约 `YYYY-MM-DD` 不变）。

### 3. 跨日边界测试

- 用例：模拟东八区 2026-08-21 00:30（UTC 仍是 2026-08-20）→ `today()` 返回 `2026-08-21`。
- 用例：时区为 UTC-5 时本地日期与 UTC 日期差异方向正确。
- 用例：`parseLocalDate('2026-08-21')` 的本地小时为 0（而非 UTC 解析的 16 点等）。
