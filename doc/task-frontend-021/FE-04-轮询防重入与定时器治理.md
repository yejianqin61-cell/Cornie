# FE-04 轮询防重入与定时器治理（Polling Reentrancy & Timer Hygiene）

## 背景

`useChat.js` 的 `startConversationSync`（L317-335）每 3s 轮询一次会话与待确认项，存在两个问题（Cornie-021 §3.2 F7/F10）：

1. **可并发堆积**：`runSync` 是 async，`setInterval` 到点直接触发下一次 `runSync()`（L330-332），上一次同步未完成时下一次又发起——慢响应场景下请求叠加。
2. **不随可见性暂停**：仅在 `runSync` 内部检查 `document.hidden`（L325）跳过本次，定时器仍在后台空转。

此外 `ObservationList.vue:145` 的防抖搜索定时器（keywordTimer）在组件卸载后未清理，离开页面后仍可能触发请求（Cornie-021 §3.2 F7）。

## 目标

1. 轮询**防重入**：上一次同步未完成则跳过本轮；窗口隐藏时暂停、恢复可见时立即补一次同步。
2. 定时器统一由**组合式工具**管理，组件卸载自动清理，全仓不再有悬挂定时器。
3. 观察列表防抖等既有定时器接入新工具。

## 范围

- `src/renderer/composables/useChat.js`（`startConversationSync` / `stopConversationSync` 改造）
- `src/renderer/` 下新增定时器组合式工具（如 `src/renderer/composables/useTimers.js`，提供 `useInterval` / `useDebouncedValue` 或等价能力，内部 `onUnmounted` 自动清理）
- `src/renderer/components/ObservationList.vue`（防抖定时器接入新工具）
- `tests/frontend/` 新增轮询与定时器测试

## 设计要求

### 1. 轮询防重入

- `startConversationSync` 内部维护"进行中"标记：`runSync` 开始时置位、结束时复位；定时器到点若标记为进行中则**跳过本轮**（不并发发起）。
- 清理时机不变：`stopConversationSync` 清除定时器并复位进行中标记；组件卸载（现有调用方）正常调用。
- 隐藏/可见：监听 `visibilitychange`（或沿用 `document.hidden` 检查）——隐藏时暂停定时器（clearInterval），恢复可见时立即补一次 `runSync` 并重启定时器。实现避免重复监听（start 前先 stop）。

### 2. 定时器组合式工具

- `useInterval(fn, ms, { immediate })`：挂载后按 ms 触发；`onUnmounted` 自动 clear；提供手动 stop/start。
- `useDebouncedValue(value, ms)` 或 `useDebounce(fn, ms)`：值变化/调用后延迟触发，卸载时清除未触发回调。
- 工具内部不引入业务逻辑，纯定时器生命周期管理；支持 fake timers 测试。

### 3. 观察列表接入

- `ObservationList.vue` 的搜索防抖改为 `useDebounce`（或等价），卸载时不再触发请求；行为（输入停顿 N ms 后搜索）保持不变。

### 4. 全仓卫生

- grep 全仓 `setInterval` / `setTimeout`（渲染层），除动画类（cornieBlink 等）与工具模块外，业务组件中的定时器均应出自本工具或显式清理。

## 验收标准

1. 新增测试全部通过（`vi.useFakeTimers`）：
   - 防重入：mock `syncConversation` 慢响应（受控 Promise），推进两个周期 → 断言只发起一次同步。
   - 可见性：隐藏 → 不再发起；恢复可见 → 立即补一次并继续周期。
   - 卸载清理：组件卸载后推进时间 → 不再触发请求/回调。
   - 观察列表防抖：卸载后不触发搜索请求。
2. `npx vitest run tests/frontend` 全绿（现有 88 用例不回归）。
3. 人工冒烟：聊天页后台标签页切换无请求风暴。
4. 本任务提交为 `fix(frontend): ...` 或 `refactor(frontend): ...` 单提交，符合 commit 规范。
