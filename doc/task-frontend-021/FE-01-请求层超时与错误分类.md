# FE-01 请求层超时与错误分类（API Request Layer Hardening）

## 背景

前端所有 API 请求经 `src/renderer/api.js` 的 `apiFetch` 发出（Cornie-021 §3.2 F10）。当前实现存在四个问题：

1. **无超时**：`apiFetch`（api.js L3-14）不设超时，后端无响应时界面无限等待。
2. **无取消**：`apiFetch` 与流式请求 `streamConversation`（api.js L53-107）均不支持外部 `AbortSignal`，页面切换无法统一取消在途请求。
3. **错误无分类**：非 2xx 时抛裸字符串（`res.text()` 原文，可能是 HTML 错误页），页面只能显示无意义文案；网络中断与超时无法区分。
4. **SSE 健壮性缺口**：`streamConversation` 无 signal、无超时；坏行静默跳过（L88）但半截行/中断场景无统一错误。

本任务是前端治理批次的**先行任务**：FE-03（流式接线）、FE-04（轮询治理）、FE-05（竞态守卫）均依赖本任务的超时/取消/错误分类能力（Cornie-021 §9.1）。

## 目标

1. `apiFetch` 统一升级：默认超时 + 外部取消信号透传 + 结构化错误分类。
2. `streamConversation` 同步升级：支持 signal、超时、SSE 异常统一归一化。
3. 全仓现有调用方零破坏（返回结构与错误抛出点行为兼容）。
4. 建立请求层契约测试（超时/取消/错误分类/SSE 断流），作为后续任务的基座。

## 范围

- `src/renderer/api.js`（apiFetch / streamConversation 改造；其余导出函数签名不变）
- `src/renderer/` 下新增请求层工具模块（如 `src/renderer/request.js`，放超时/Abort/错误归一化工具，api.js 复用）
- `tests/frontend/api-contract.test.mjs`（新增用例）
- `tests/frontend/setup.mjs`（如需要补充 AbortController mock 基座）

## 设计要求

### 1. 结构化错误（ApiError）

- 统一错误类型：`{ kind: 'network' | 'timeout' | 'http' | 'protocol', status?: number, message: string }`。
  - `network`：fetch 抛 TypeError / 连接拒绝。
  - `timeout`：超过默认超时时长被中止。
  - `http`：非 2xx 响应；`message` 优先取响应体 JSON 的 `error` 字段，取不到再取文本，再取 `HTTP ${status}`。
  - `protocol`：SSE 解析失败 / `kind:'error'` 事件 / 流被非预期中断。
- 错误对象保留 `name`/`message` 可读性；页面现有 `catch (e) { e.message }` 用法继续可用。

### 2. 超时与取消

- 默认超时 **30s**（模块级常量，允许调用方覆盖）。
- `apiFetch(path, init)` 新增支持 `init.signal` 外部取消；内部用 `AbortController` 实现超时，并**合并**外部 signal（任一触发即中止；中止后抛 `timeout` 或透传外部取消原因）。
- 取消语义：外部主动取消（页面切换）抛 `AbortError`（kind 可标记为 `aborted` 或直接抛原生 `AbortError`，由调用方静默处理）；超时抛 `{ kind: 'timeout' }`。
- `streamConversation({ message, date }, onDelta, { signal, timeoutMs })` 支持同样的超时与取消；取消后读取循环立即退出且不再回调 `onDelta`。

### 3. SSE 解析健壮性

- 保持现有 `data:` 行解析；遇到非 `data:` 行继续跳过；JSON.parse 失败的行跳过但记录（不抛）。
- 收到 `kind:'error'` 事件 → 抛 `{ kind: 'protocol' }`（含服务端 error 文本）。
- 流中途 `done` 之前 reader 返回 done（连接被服务端关闭）→ 若无 result 则抛 `{ kind: 'protocol', message: 'stream ended prematurely' }`。
- 半截行（buffer 尾部无换行）：读取结束时若有残留内容且含完整 `data:` 前缀，尝试解析为事件；否则丢弃。

### 4. 兼容性

- `apiFetch` 返回值结构不变（`res.json()` / 204 返回 null）。
- 所有现有导出函数（listEntries、sendMessage、getConversation、各业务 API 等）签名与返回结构**不变**，仅底层走新逻辑。
- `streamConversation` 现有调用方（`useChat.js` 的 `streamSend`）签名兼容（第三个参数为可选新参数）。

## 验收标准

1. `tests/frontend/api-contract.test.mjs` 新增用例全部通过：
   - 超时：mock fetch 永不 resolve，fake timers 推进超时 → 抛 `kind:'timeout'`。
   - 取消：外部 signal abort → 请求被中止，调用方静默捕获无未处理异常。
   - 错误分类：HTTP 400/500（含 JSON error 体、纯文本体）、网络拒绝、SSE `kind:'error'`、流提前结束 → 各自正确的 kind 与 message。
   - 兼容：现有契约用例（各 API 正常响应解析）不改动或仅适配后全绿。
2. `npx vitest run tests/frontend` 全绿（现有 88 用例 + 新增用例，不回归）。
3. 人工冒烟：后端未启动时页面操作得到"网络"类提示而非无限 loading；请求不挂起。
4. 本任务提交为 `feat(frontend): ...` 或 `fix(frontend): ...` 单提交，符合 commit 规范。
