# FE-07 死交互接线与导航出口（Dead-Interaction Wiring）

## 背景

界面存在多处"看起来可点、点击无效"的元素（Cornie-021 §3.2 F3）：

- `App.vue:281-288`：`<TodoHome />` / `<ScheduleHome />` 子页面无 `@go` 导航出口，组件内部"管理类目"类按钮无法上抛跳转意图。
- `TodoHome.vue:155`、"管理类目"按钮点击无行为。
- `ScheduleHome.vue:223`、`LedgerHome.vue:691,709`（"管理类目 / 查看全部"）点击无行为。
- 对比正例：观察与记忆模式已接入 `@go`（`App.vue:294,300`），子页面可上抛跳转。

原则：**界面不存在无行为的可点击元素**——每个按钮要么接线到真实动作/跳转，要么移除。

## 目标

1. 为子页面建立统一**导航出口**（`@go` 事件上抛），壳层集中处理跳转。
2. 待办/日程/收支首页的"管理类目/查看全部"等按钮接线到真实目标（类目管理区/完整列表/设置区）。
3. 无真实目标的按钮移除（不做"死按钮"）。

## 范围

- `src/renderer/App.vue`（壳层：接收子页面 `@go` 并路由到对应视图；必要时新增视图状态或复用现有 view 状态机）
- `src/renderer/components/TodoHome.vue`、`ScheduleHome.vue`、`LedgerHome.vue`（按钮接线 + `@go` 上抛）
- 同类问题组件（接入时以"按钮无 handler"grep 复查）
- `tests/frontend/app-navigation.test.mjs` 等导航测试（新增用例）

## 设计要求

### 1. 导航出口约定

- 子页面统一 `@go="(view, payload) => ..."` 上抛跳转意图（与观察/记忆模式一致），壳层 `App.vue` 集中处理：切换到对应 mode/view，必要时携带 id/参数。
- 目标视图若不存在（如"类目管理"无独立视图），优先**扩展现有视图**（如设置页类目区块）而非新增空壳页面；确无目标的按钮直接移除。

### 2. 各按钮接线（以实际 DOM 为准核对）

- TodoHome "管理类目" → 待办类目管理视图（设置类目区或类目列表视图）。
- ScheduleHome "管理类目" → 日程类目管理视图。
- LedgerHome "管理类目" → 收支类目管理视图；"查看全部" → 完整列表（若列表即当前视图则移除或改为滚动定位）。
- 接线后按钮有明确的跳转结果，不得出现仅改变内部状态但界面无变化的情况。

### 3. 无行为元素治理

- 全仓复查"看起来可点"元素：有 cursor:pointer/样式像按钮但无 click handler 的元素 → 接线或移除或改为纯展示（去点击样式）。
- 保留可点击元素的键盘可达性（与 FE-10 协同，但本任务先保证行为存在）。

## 验收标准

1. 新增导航测试全部通过：点击"管理类目/查看全部" → 断言组件 emit `go` 且壳层切换到目标视图（或按钮已移除）。
2. 现有导航测试（app-navigation）不回归；`npx vitest run tests/frontend` 全绿。
3. 人工冒烟：从待办/日程/收支首页点击各入口，均能到达目标页面。
4. 本任务提交为 `fix(frontend): ...` 单提交，符合 commit 规范。

## 依赖

- 无（独立；与 FE-10 有轻微交集——行为接线优先，键盘语义由 FE-10 收口）。
