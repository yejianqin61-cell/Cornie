# FE-05 竞态守卫模式接入（Race-Guard for View Switching）

## 背景

快速切换日期/视图时，旧请求的响应可能覆盖新选择的内容（Cornie-021 §3.2 F6）：

- `DiaryEditor.vue:99-106`：切换日期加载日记，旧日期响应晚到会覆盖新日期内容。
- `ChatHistory.vue:192-200`：切换聊天日期，旧响应覆盖新列表。
- 同类模式还存在于观察列表筛选、记忆页切换等异步加载场景。

根因：发起新请求时没有使旧请求失效（无请求序号/取消），回调无条件写入状态。

## 目标

1. 建立**可复用的竞态守卫**（请求序号 + 取消信号）：新请求发起时，旧请求失效（取消并忽略其回调）。
2. 日期/视图切换场景统一接入：日记编辑、聊天记录、观察列表，以及同类异步加载点。
3. 断言"最终渲染 = 最后一次选择的内容"，并配乱序响应测试。

## 范围

- `src/renderer/` 下新增守卫工具（如 `src/renderer/composables/useRequestGuard.js` 或并入 FE-01 的请求层工具；提供 `guardedFetch` 或 `useLatestRequest` 等价 API）
- `src/renderer/components/DiaryEditor.vue`、`ChatHistory.vue`、`ObservationList.vue`（接入）
- 其他存在同类模式的组件（接入时以 grep 定位：日期/筛选变化触发加载的地方）
- `tests/frontend/` 新增竞态测试

## 设计要求

### 1. 守卫工具

- 核心 API（建议）：`useLatestRequest()` → `{ run(key, fn), isCurrent(key) }` 或等价——
  - `run` 使同 key 的旧调用失效：旧调用的回调被忽略；若请求支持 Abort（FE-01 已提供 signal），同步取消底层请求。
  - 返回 Promise 或回调守卫均可，但必须保证"旧调用的状态写入被丢弃"。
- 纯工具、可独立测试；不绑定具体组件。

### 2. 接入规则

- **日期/筛选变化点**：`watch(date)` 或用户切换动作中，先 `guard.run(...)` 再发起加载；加载回调（成功/失败）先校验 `isCurrent` 再写状态。
- **失败路径同样守卫**：旧请求的失败回调也不得写入（否则切到新日期后弹出旧日期的错误提示）。
- **卸载兜底**：组件卸载时取消在途请求（与 FE-01 signal + FE-04 定时器清理协同）。

### 3. 状态一致性

- 加载中状态（loading flag）由最新请求管理：旧请求不得清掉新请求的 loading。
- 不改变现有 API 契约与加载逻辑顺序，只加守卫层。

## 验收标准

1. 新增竞态测试全部通过（受控 Promise mock 模拟乱序返回）：
   - 快速切换 A→B：A 的响应后到 → 最终渲染 B 的内容，A 被丢弃。
   - A 的失败后到 → 不出现 A 的错误提示覆盖 B 视图。
   - 加载中状态由最新请求控制（B 在途时 A 完成不清 B 的 loading）。
2. 既有日记/聊天/观察测试不回归；`npx vitest run tests/frontend` 全绿。
3. 人工冒烟：快速连续切换聊天日期，列表最终停在最后选择的一天且无闪回。
4. 本任务提交为 `fix(frontend): ...` 单提交，符合 commit 规范。

- 与 FE-04 的卸载清理协同；不依赖 FE-03。
