# FE-08 死组件删除与引用扫描（Dead-Component Removal）

## 背景

`src/renderer/components/` 下存在 **4 个全仓无引用的死组件**（Cornie-021 §3.2 F9，已 grep 核实无 `import`）：

- `LedgerWorkspace.vue`、`TodoWorkspace.vue`、`ScheduleWorkspace.vue`、`PendingConfirmations.vue`。

死组件残留会误导搜索、增加维护负担，且其中 `PendingConfirmations.vue` 还含一份重复的 `today()` 实现（与 FE-02 交集）。

## 目标

1. 删除 4 个无引用组件（删除前复核无静态/动态 import）。
2. 建立**未引用组件扫描**，防止死组件回潮（并入现有仓库清洁检查）。
3. 删除后全仓 import 扫描通过、前端测试全绿。

## 范围

- `src/renderer/components/LedgerWorkspace.vue`、`TodoWorkspace.vue`、`ScheduleWorkspace.vue`、`PendingConfirmations.vue`（删除）
- `scripts/check-repo-cleanliness.mjs`（或等价检查脚本：新增"渲染层未引用组件"扫描）
- 前端测试（若存在引用死组件的测试文件，一并清理）

## 设计要求

### 1. 删除前置复核

- grep `LedgerWorkspace|TodoWorkspace|ScheduleWorkspace|PendingConfirmations` 于 `src/renderer/**` 与 `tests/**`：
  - 确认无静态 `import ... from` 引用；
  - 确认无动态 `import('...')` / `defineAsyncComponent` / 字符串模板引用；
  - 确认无测试文件引用。
- 复核通过后删除文件；若发现引用（如某处仍在使用），暂停删除并上报（本任务范围以外的问题）。

### 2. 未引用组件扫描

- 在仓库清洁检查脚本中新增规则：遍历 `src/renderer/components/*.vue`，提取组件文件名（去扩展名），在 `src/renderer/**`（含 .vue/.js）中 grep 引用；无引用的组件输出警告（或按现有脚本风格处理）。
- 扫描规则需忽略自引用与大小写差异（Vue 注册名与文件名大小写映射）。
- 扫描结果纳入 `npm run check:cleanliness`（或等价入口），不通过即非零退出。

### 3. 联动事项

- `PendingConfirmations.vue` 删除后，FE-02 中"8 处 today()"实际变为 7 处（若 FE-02 已合入并替换了该文件，无影响；若未合入，该文件不再需要替换）。
- 删除后确认 `src/renderer/components/` 剩余组件均可从入口（App.vue 或 main 链）追踪。

## 验收标准

1. 4 个组件文件已删除，`git grep` 全仓（含测试）零引用。
2. `npm run check:cleanliness`（或对应脚本）通过，且包含"无未引用组件"规则；故意引入一个未引用文件时扫描应报警（可口头验证规则有效性，不落库）。
3. `npx vitest run tests/frontend` 全绿（现有 88 用例不回归）。
4. 本任务提交为 `chore(frontend): ...` 或 `refactor(frontend): ...` 单提交，符合 commit 规范。
