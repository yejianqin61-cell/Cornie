# FE-09 记忆工作台拆分与表驱动（Memory Workbench Decomposition）

## 背景

记忆工作台组件**单文件过大、职责混杂**（Cornie-021 §3.2 F5）：

- `MemoryWikiWorkspace.vue` 约 1773 行，同时承载列表、详情编辑、治理待审、巡检审计、设置等 5 类职责；修改任何一处都影响整文件，测试与定位困难。
- `MemoryPageDetail.vue` 存在 7 个对 `pageType` 的重复 if/else 分支（图标、字段分组、摘要模板等），新增页面类型需改多处。

本任务为**纯结构重构**：不改变任何 API 契约、不改变用户可交互路径与视觉呈现。

## 目标

1. 记忆工作台按职责拆分为独立区块组件，主工作台只做组合与状态协调。
2. 记忆详情页 `pageType` 相关分支收敛为**类型配置表**，新增类型只加配置。
3. 拆分后各区块可独立挂载冒烟；现有记忆页面测试全绿（防回归）。

## 范围

- `src/renderer/components/MemoryWikiWorkspace.vue`（拆分宿主，瘦身为组合层）
- `src/renderer/components/MemoryPageDetail.vue`（表驱动改造）
- 新增区块组件（如列表区 / 详情编辑区 / 治理待审区 / 巡检审计区 / 设置区，命名与划分以实际代码职责为准）
- `tests/frontend/memory-wiki-workspace-async.test.mjs`、`memory-page-user-flow.test.mjs`（保持通过 + 补充区块冒烟）

## 设计要求

### 1. 拆分原则

- 按**职责**拆分而非按行数均分：列表（含筛选/分页/搜索）、详情（展示/编辑/来源/版本）、治理（待审池/批量处置/结果历史）、巡检审计、设置/入口控制，各自独立组件。
- 主工作台保留：视图切换、共享状态（当前页面/筛选/治理队列数据）、跨区块的事件协调；区块组件通过 props/事件（或现有状态管理方式）通信，不引入新状态库。
- 拆分为**增量过程**：每次提交一个区块的迁移（或按主工作台一个提交 + 区块若干提交），每步保持测试全绿；最终主工作台瘦身完成。
- 拆分后视觉与交互零变化（纯结构）。

### 2. 表驱动改造（MemoryPageDetail）

- 将 `pageType` 相关分支（图标、类型名/标签、字段分组、摘要模板、可见操作）收敛为**类型配置表**：`type → { icon, label, fields, summaryTemplate, actions }`。
- 组件内按配置表渲染，删除重复 if 链；未知类型走默认配置（不报错、渲染通用形态）。
- 配置表放独立模块（或组件内常量，依现有结构），便于扩展。

### 3. 测试

- 现有记忆工作台与详情页测试**原样通过**（行为不变是重构成功的判据）。
- 新增：区块组件独立挂载冒烟（列表区可渲染、详情区可编辑等）；表驱动多类型渲染断言（至少覆盖 profile/person/preference/trait 与普通类型各一）。

## 验收标准

1. `MemoryWikiWorkspace.vue` 行数显著下降（目标 < 600 行，具体以拆分后为准），职责单一化（grep 复核各区块组件独立存在并被主工作台引用）。
2. `MemoryPageDetail.vue` 无重复 pageType if 链（grep 复核），新增类型仅需改配置表。
3. `tests/frontend/memory-wiki-workspace-async.test.mjs`、`memory-page-user-flow.test.mjs` 及新增区块冒烟全部通过；`npx vitest run tests/frontend` 全绿。
4. 人工冒烟：记忆工作台各入口（列表/详情/治理/巡检）行为与拆分前一致。
5. 本任务提交为 `refactor(frontend): ...`（可拆多提交，每提交保持测试全绿），符合 commit 规范。
