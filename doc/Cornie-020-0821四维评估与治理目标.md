## 2. 评估目的与口径

### 2.1 评估目的

回答四个问题：

1. **前端**（`src/renderer/**`，40 个文件）：组件与页面工程质量、状态管理、错误/竞态处理、死代码与技术债。
2. **后端核心**（`electron/server.js` + `electron/backend/` 业务/编排/工具链/模型层）：编排器与确认流、API 契约、工具策略链、可观测性、重复与死代码。
3. **数据库**（`electron/db.js`、chatlog 存储、sql.js 持久化模式、迁移体系、数据文件布局）：持久化正确性、崩溃安全、备份恢复、迁移卫生。
4. **记忆层**（`memory-wiki/**`、`agent/memoryDistillation.js`、`identity/*Upsert.js`、观察压缩/升级、钻取与注入侧）：对照最高设计原则的合规度、写入一致性、治理状态机、读取侧钻取、测试质量。

### 2.2 评估方法

- **范围**：全量现状评估（非 diff 审查）。四个维度各由一个独立子代理全量阅读代码后上报，父代理对关键结论做了交叉验证（见 §6/§7 标注）。
- **标准轴**：`criterion/Cornie-backend-api规范.md`、`criterion/Cornie-commit-message规范.md`、`criterion/Cornie-doc文档规范.md`；未覆盖处以 Fowler 代码味道基线（Mysterious Name / Duplicated Code / Feature Envy / Data Clumps / Primitive Obsession / Repeated Switches / Shotgun Surgery / Divergent Change / Speculative Generality / Message Chains / Middle Man / Refused Bequest）作判定补充。文档化标准优先于基线。
- **设计轴**：记忆层以 Cornie-019 §2.2 最高设计原则为基准（**是否载入记忆、记什么内容，只由 LLM 决定；后端执行与治理；人类最终把关；正则全面弃用**）。
- **基线**：git HEAD=`4feebd8`（记忆层 28 任务收官后）。工作区仅剩未跟踪的 `scripts/scan-memory-wiki-frontmatter.mjs`。
- **验证基线**：上一验收轮在同 HEAD 下 `npm run test:full` 通过、前端 vitest 88/88 通过（本轮未重跑，引用为历史验收记录）。

### 2.3 健康度定级口径

| 等级 | 含义 |

| A | 架构与实现与该维度标准/原则一致，仅有零散优化点 |

### 4.1 优点

- 确认流闭环完整：编排器暂停 → confirm 状态机（pending/approved/executed/failed）→ executor 恢复，类目创建后自动 resume 原动作（`confirm/executor.js:189-291`），拒绝路径有 fallback 复用建议（`confirm/fallback.js:17-71`）。

## 5. 维度三：数据库 — 健康度 B-

**一句话结论**：写路径收敛与迁移幂等是优点；但 `persist()` 非原子整库覆盖写、全仓零备份、跨层无原子性，**数据安全类 P0 未解**，是本轮最需要优先治理的维度。

### 5.1 优点

- 写路径收敛：所有写操作经 db.js 导出函数且同一同步帧内 `persist()`（`db.js:323-364`），grep 证实无绕过持久化的裸写；单进程事件循环内 DB 操作无并发竞态。
- 迁移幂等：全部 `IF NOT EXISTS` + `on conflict do nothing`（`db.js:41-297`），中断后重跑安全；v6 空槽保住版本号（266-271）。

## 7. 综合结论

### 7.1 四维健康度总表

| 维度 | 范围 | 健康度 | 一句话结论 |
| --- | --- | --- | --- |
| 前端 | `src/renderer/**`（40 文件） | B- | 契约对齐好，但流式未接线、UTC 跨日、重复/死代码待治理 |
| 后端核心 | server + 编排/确认/工具链/模型层 | B+ | 确认流与策略层扎实；协议代码与工具名单需收敛 |
| 数据库 | db.js / chatlog 存储 / sql.js 持久化 | B- | 写路径收敛但持久化非原子、零备份，数据安全 P0 未解 |
| 记忆层 | memory-wiki / 提炼 / identity / 治理 | A- | 设计原则合规最佳；队列共享不对称与摘要缺失待修 |

### 7.2 共性主题（跨维度）

1. **重复代码蔓延**：协议信封轮（B1）、工具名单（B2）、normalize 族（M7/D9）、模型设置（F4）、日期工具（F2）——同一逻辑多处手写，改动必漂移。
2. **死代码/死交互存量**：4 个前端死组件（F9）、流式未接线（F1）、后端不可达函数（B5）、driver 抽象残留（D7）。
3. **一致性未闭环**：跨层无原子性（D3）、队列与缓存共享不对称（M1）、快照覆盖写（M11）。
4. **可观测性缺口**：模型失败不入 telemetry（B6）、SSE 无断连中止（B7）。
5. **文档滞后**：backend-api 规范未覆盖现有路由（§4.2）、记忆层边界瑕疵未文档化（§6.2）。
