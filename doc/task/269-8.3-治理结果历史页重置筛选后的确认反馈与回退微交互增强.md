# 269-8.3-治理结果历史页重置筛选后的确认反馈与回退微交互增强

## 1. 任务目标

在 `251`、`263` 已补齐治理结果历史页筛选持久化与空态默认动作基础上，继续细化“重置筛选”后的确认反馈与回退微交互，让用户更有掌控感。

## 2. 背景与现状

一旦历史页支持复杂筛选和一键重置，用户会关心：

1. 我是不是已经真的清空了筛选
2. 有没有办法撤销刚才的重置
3. 当前列表变化是因为筛选重置，还是因为数据本身变化

如果没有细化微交互，这个动作会显得粗糙。

## 3. 涉及范围

- 治理结果历史页筛选区
- 重置筛选动作
- 反馈、撤销与回退微交互
- 对应前端测试

## 4. 前置依赖

1. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有筛选持久化
2. `263-8.3-治理结果历史页空态下次级入口排序与默认动作增强.md` 已完成或至少已有重置筛选入口

## 5. 具体开发项

### 5.1 触发后反馈

1. 重置筛选后给出轻量确认反馈
2. 告诉用户当前已回到默认结果视图或更宽的结果范围
3. 不用大弹窗打断列表浏览

### 5.2 撤销机制

1. 在短时间内提供撤销重置入口
2. 撤销后恢复原筛选条件和列表位置
3. 过期后自然收口，不长期悬挂

### 5.3 回退说明

1. 若重置后仍无结果，反馈应与空态解释协同
2. 让用户知道重置动作已生效，不是按钮失灵
3. 与来源提示、空态动作区保持语义一致

### 5.4 长期持久化兼容

1. 重置后新的默认视图应成为后续浏览上下文
2. 撤销后正确恢复原持久化状态
3. 不让撤销逻辑污染之后的新筛选选择

### 5.5 测试补齐

1. 覆盖重置筛选后的确认反馈
2. 覆盖撤销入口与状态恢复
3. 覆盖重置后仍无结果时的反馈协同
4. 覆盖持久化状态更新与回滚

## 6. 验收标准

1. 治理结果历史页重置筛选动作更有掌控感
2. 用户能清楚区分“筛选变化”与“数据变化”
3. 反馈与撤销足够轻量但有效
4. 对应前端测试通过
