# 379-主身份扩展字段的中文条件注入命中收口

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 中“主身份页默认稳定注入 + 扩展字段按需注入”的要求，修正 `identity_profile` 扩展字段在中文自然语言 query 场景下的命中策略，避免 `stressors`、`communicationPreference` 这类扩展信息因为只靠空格切词而长期无法被正常放开。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/agent/wikiContext.js`
- `scripts/`

## 4. 当前问题

当前主身份页扩展字段是否注入，主要依赖 `queryTerms` 命中：

- `stressors`
- `communicationPreference`

但中文自然句子通常不会按空格切开，例如：

- `我最近压力真的很大`
- `你温柔一点和我说话`

这种 query 进入系统后，常常只会形成整句，而不会生成可用的中文 token，导致扩展字段条件注入在中文场景下偏失效。

## 5. 目标设计

- 主身份页默认稳定注入仍保持克制
- 扩展字段只在更相关的 query 下进入主链
- 判定不只依赖 `queryTerms`
- 同时支持：
  - 中文整句子串命中
  - 现有 queryTerms 补充命中

## 6. 实现步骤

### Step 1

为 `identityProfileNeedsExtendedDetails` 增加 `normalizedQuery` 级别的整句命中判断。

### Step 2

保留 `queryTerms` 作为补充，不破坏已有英文 / 空格分词场景。

### Step 3

新增验证脚本，证明中文 query 下能够按需放开 `stressors` 与 `communicationPreference`。

## 7. 测试点

- 空 query 下不默认注入主身份扩展字段
- 中文压力相关 query 下可放开 `stressors`
- 中文陪伴/沟通相关 query 下可放开 `communicationPreference`
- `npm run build` 通过

## 8. 完成标准

- 主身份页条件注入在中文场景下恢复有效
- 主链 prompt 仍保持“默认克制、相关时放开”的边界
