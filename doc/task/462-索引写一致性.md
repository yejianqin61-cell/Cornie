# 462 索引写一致性

## 背景

memory-wiki 四个 JSON 索引（page-index / keyword-index / version-index / review-queue）均为整文件 read-modify-write，无锁（Cornie-018 D-08）；主窗口 + 桌宠窗口并发写时静默丢更新；页面文件与索引更新不在同一事务，中途崩溃进入不一致态。

## 目标

1. 索引写入串行化（进程内单写者队列或写后合并 debounce）。
2. 页面文件与索引更新纳入同一 try/catch 回滚流程。
3. 并发压力下无丢更新。

## 范围

- `electron/backend/memory-wiki/storage.js`（page-index 等）
- `electron/backend/memory-wiki/topicIndex.js`（keyword-index）
- `electron/backend/memory-wiki/versionStore.js`（version-index）
- `electron/backend/memory-wiki/governanceStore.js`（review-queue）

## 设计要求

1. 为四个 JSON 索引引入进程内 Promise 链串行化（单写者队列），或短窗口 debounce 合并写。
2. 页面文件与索引更新同一 try/catch：失败回滚或标记待修复（不自愈则留巡检兜底）。
3. 并发压力用例：10 并发写入无丢更新。

## 验收标准

1. 并发写入压力用例（10 并发）无丢更新。
2. 写失败时索引与页面状态一致（或可被巡检识别修复）。
3. verify 脚本全绿。
