# 106 记忆治理待审核服务层与工具接口接入

## 1. 任务目标

在 `105` 存储基础上，补齐待审核池服务层与模型工具接口，让模型与后端都能读取和写入治理候选。

本任务完成后，应至少具备：

- `memory_governance.create_request`
- `memory_governance.get_request`
- `memory_governance.list_requests`
- `memory_governance.update_request_status`

## 2. 任务来源

- `doc/design/Cornie-0628-工具对齐与记忆治理及测试体系设计.md` 第 5.1 节

## 3. 涉及范围

- `electron/backend/memory-wiki/service.js`
- `electron/backend/memory-wiki/tools.js`
- `scripts/`
- `package.json`

## 4. 当前问题

即使待审核池有了持久化，没有服务层和工具接口也无法：

- 把对话中的治理提议落到统一对象
- 让模型补查当前待审核项
- 让后续前端/人类接口复用同一逻辑

## 5. 目标设计

- 创建候选时明确高风险
- 读取与列表为只读低风险
- 状态流转为高风险
- 服务层对 requestType / status / riskLevel 做归一化

## 6. 实现步骤

### Step 1

在 Memory Wiki 服务层挂接治理待审核池。

### Step 2

注册正式工具接口。

### Step 3

补最小验证脚本。

## 7. 测试点

- 模型工具可创建治理请求
- 可读取单条与列表
- 可更新状态

## 8. 完成标准

- 治理请求工具可调用
- 风险分层明确
- 最小验证通过

## 9. 交付物

- 服务层代码
- 工具注册代码
- 验证脚本
