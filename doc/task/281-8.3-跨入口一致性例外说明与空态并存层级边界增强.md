# 281-8.3-跨入口一致性例外说明与空态并存层级边界增强

## 1. 任务目标

在 `276` 已补齐治理结果历史页跨入口一致性失败时的例外文案基础上，继续把该例外说明与空态主说明并存时的层级边界拆清楚，避免两个解释系统同时争抢主叙事。

## 2. 背景与现状

跨入口一致性失败本身已经是少见分支，而它又可能恰好与空态相遇。若没有单独规则，会出现：

1. 例外说明和空态解释都想回答“为什么现在是这样”
2. 页面顶部出现两套平级解释，用户更糊涂
3. 恢复动作入口不知道跟哪套说明走

## 3. 涉及范围

- 治理结果历史页
- 例外说明条
- 空态主说明与动作区
- 对应前端测试

## 4. 前置依赖

1. `276-8.3-治理结果历史页跨入口一致性失败时的例外文案增强.md` 已完成或至少已有例外说明
2. `260-8.3-治理结果历史页跨页回流后的空态降级与语义澄清增强.md` 已完成或至少已有空态解释体系
3. `263-8.3-治理结果历史页空态下次级入口排序与默认动作增强.md` 已完成或至少已有空态动作区

## 5. 具体开发项

### 5.1 主次解释边界

1. 明确空态主说明优先回答当前为什么没有结果
2. 例外说明只补充“为什么这次回流上下文与预期不同”
3. 不允许两者抢同一层级叙事

### 5.2 布局层次

1. 空态主说明位于主阅读区
2. 例外说明降为次级提示条或说明折叠块
3. 两者视觉层级有明显区分

### 5.3 动作挂载规则

1. 主恢复动作跟随空态主说明
2. 例外说明只在必要时提供辅助动作
3. 不让动作按钮在两套说明下重复出现

### 5.4 关闭与退场

1. 关闭例外说明后，不影响空态主解释
2. 解除空态后，例外说明也应同步评估是否退场
3. 保持空态和例外说明各自生命周期清晰

### 5.5 测试补齐

1. 覆盖空态与例外说明并存时的层级关系
2. 覆盖主恢复动作与辅助动作挂载差异
3. 覆盖关闭例外说明后的空态稳定性
4. 覆盖解除空态后的例外说明退场

## 6. 验收标准

1. 跨入口一致性例外说明与空态解释不会互相打架
2. 用户总能分清主解释和补充解释
3. 动作入口挂载清楚，不重复
4. 对应前端测试通过
