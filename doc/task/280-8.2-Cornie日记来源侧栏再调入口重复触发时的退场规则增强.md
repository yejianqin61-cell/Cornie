# 280-8.2-Cornie日记来源侧栏再调入口重复触发时的退场规则增强

## 1. 任务目标

在 `274` 和 `277` 已补齐 Cornie 日记来源侧栏再调入口与恢复默认并存优先级基础上，继续明确当用户短时间内多次触发“继续调整”入口时，入口本身如何退场、降级和重新出现。

## 2. 背景与现状

再调入口一旦可用，用户就可能连续点开、调整、返回、再点开。如果没有退场规则，会出现：

1. 再调入口长期霸占控制区
2. 重复触发后不知道何时该降级
3. 与恢复默认入口的层级关系反复震荡

## 3. 涉及范围

- Cornie 日记回看页
- 来源侧栏再调入口
- 重复触发后的退场与重现规则
- 对应前端测试

## 4. 前置依赖

1. `274-8.2-Cornie日记来源侧栏撤销超时后的再调入口增强.md` 已完成或至少已有再调入口
2. `277-8.2-Cornie日记来源侧栏再调入口与恢复默认并存优先级增强.md` 已完成或至少已有并存优先级规则

## 5. 具体开发项

### 5.1 重复触发识别

1. 识别短时间内的连续再调触发
2. 区分“用户还在调整流程中”和“用户已经结束本轮调整”
3. 不把每次点击都当成全新链路

### 5.2 退场与降级

1. 当用户完成一轮连续调整后，再调入口降级为次级控制点
2. 若用户仍持续频繁调整，可保持短期可见但降低强调度
3. 不让入口长期占据主位

### 5.3 重新出现条件

1. 当页面进入新的稳定态或新日期时，再调入口重新按主规则评估
2. 若用户刚完成恢复默认或切换弱数据态场景，可按需要再次上浮
3. 重现条件应和恢复默认入口优先级兼容

### 5.4 用户感知

1. 用户应感受到页面“知道我还在调”
2. 调整告一段落后，入口应自然退回低调状态
3. 不制造闪烁感和追着用户跑的按钮感

### 5.5 测试补齐

1. 覆盖短时间连续触发场景
2. 覆盖连续调整结束后的退场降级
3. 覆盖新日期或新稳定态下的重新评估
4. 覆盖与恢复默认入口层级兼容

## 6. 验收标准

1. 再调入口在重复触发下仍有清楚的退场规则
2. 控制区不会因频繁调整而长期失衡
3. 入口重现与降级逻辑可预测
4. 对应前端测试通过
