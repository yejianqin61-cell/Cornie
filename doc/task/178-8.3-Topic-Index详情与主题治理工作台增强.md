# 178-8.3-Topic-Index详情与主题治理工作台增强

## 1. 任务目标

在当前 Memory Wiki / Topic Index 首轮产品化基础上，继续把 Topic Index 从“列表附属区”升级为“可直接治理主题关系”的前端工作台，让用户能围绕主题查看详情、管理别名、处理页面关联，并为后续主题合并打下界面基础。

## 2. 背景与现状

当前前端已经具备：

1. Topic Index 基础查看入口
2. Memory Wiki 页面与 Topic 基础联动展示
3. 部分治理面板与证据面板

但 Topic Index 当前仍明显不够：

1. 用户还难以完整查看某个主题的详情
2. 用户还难以理解某个主题到底关联了哪些页面、哪些日期、哪些来源
3. 用户还没有正式的人类入口去维护主题别名、解绑页面、发起主题治理动作

## 3. 涉及范围

- `src/renderer/components/MemoryWikiWorkspace.vue`
- `src/renderer/api.js`
- 如有必要，补充 Topic Index 详情与治理接口
- 对应前端测试

## 4. 前置依赖

1. `167-8.3-Memory-Wiki页面与Topic治理首轮产品化.md` 已完成
2. `175-8.3-Memory-Wiki来源引用与关联阅读增强.md` 已完成或至少已提供来源联动底座

## 5. 具体开发项

### 5.1 Topic 详情面板

1. 提供单个 Topic 的详情视图
2. 至少显示主题名、别名、热度、最近提及日期、关联页面数
3. 支持查看与该主题相关的聊天日期或观察日期摘要

### 5.2 Topic 与页面关系工作区

1. 展示该 Topic 关联的 Memory Wiki 页面列表
2. 支持从 Topic 详情跳转到对应页面
3. 如后端能力允许，支持手动解绑错误关联页面
4. 无关联页面时提供空态说明

### 5.3 Topic 别名管理

1. 支持在前端查看和编辑 Topic 别名
2. 明确区分“主主题名”和“别名”
3. 在保存前对用户说明别名变更会影响后续匹配与检索

### 5.4 主题治理动作入口

1. 为后续主题合并预留显式入口
2. 至少支持“标记需要治理”“查看关联证据”“进入候选治理区”之类的人类动作
3. 对高风险动作保持克制，不直接在本任务中强上自动合并

### 5.5 测试补齐

1. 覆盖 Topic 详情渲染
2. 覆盖别名编辑分支
3. 覆盖关联页面空态与非空态
4. 覆盖 Topic 跳转或治理入口展示逻辑

## 6. 验收标准

1. Topic Index 不再只是简单列表，而具备主题详情与治理入口
2. 用户可清晰查看主题与页面、日期、来源之间的关系
3. 用户可在前端完成基础别名治理动作
4. 对应前端测试通过
