# 260-8.3-治理结果历史页跨页回流后的空态降级与语义澄清增强

## 1. 任务目标

在 `256` 和 `257` 已补齐治理结果历史页跨页回流说明、提示降级和冲突消解基础上，继续增强回流后遇到空态或无结果时的降级表达与语义澄清，让用户不把“当前筛选下没东西”误解为链路失效。

## 2. 背景与现状

用户从提醒中心或待审核池回到治理结果历史页时，常会带着筛选和期待。如果这时刚好没有结果，容易出现：

1. 用户以为历史页回流失败了
2. 用户分不清是“当前没有历史结果”还是“筛选条件过窄”
3. 来源提示和空态信息同时存在时，页面语义混乱

## 3. 涉及范围

- 治理结果历史页
- 跨页回流提示
- 空态卡与无结果说明
- 对应前端测试

## 4. 前置依赖

1. `256-8.3-治理结果历史页到提醒中心与待审核池的跨页回流说明增强.md` 已完成或至少已有跨页说明
2. `257-8.3-治理结果历史页多入口回流下的提示降级与冲突消解增强.md` 已完成或至少已有提示降级规则
3. `253-8.3-Memory-Wiki治理结果历史页空态与首次使用引导增强.md` 已完成或至少已有历史页空态基础

## 5. 具体开发项

### 5.1 空态语义澄清

1. 区分“回流过来了但当前条件下没有对应历史结果”和“历史页整体还没有数据”
2. 区分“当前问题尚未形成治理结果”与“结果存在但不在当前筛选里”
3. 不让用户把空态误读为导航错误

### 5.2 来源提示降级协同

1. 回流说明与空态并存时，来源提示自动降级为次级说明
2. 空态主文案优先回答“为什么现在看不到结果”
3. 来源提示仍保留链路语义，但不抢空态主叙事

### 5.3 恢复动作

1. 提供清空筛选、回到最近结果、去当前待审核池查看等快捷动作
2. 若当前问题还未形成历史结果，可引导回到当前治理工作台
3. 快捷动作应直接指向用户最可能下一步

### 5.4 情绪与边界

1. 空态表达应平实，不制造“丢数据了”的惊吓感
2. 文案要帮助用户理解“过去结果”和“当前问题”是两种不同对象
3. 在空态下依然保持页面结构稳定

### 5.5 测试补齐

1. 覆盖回流后无对应结果分支
2. 覆盖历史页本身无数据分支
3. 覆盖来源提示与空态共存时的降级表达
4. 覆盖快捷恢复动作

## 6. 验收标准

1. 用户从当前治理工作台回流历史页后，不会因空态而迷路
2. 空态能清楚解释“为什么现在没有结果”
3. 来源提示与空态表达彼此不打架
4. 对应前端测试通过
