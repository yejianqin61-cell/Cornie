# 293-8.3-Memory-Wiki来源阅读区刷新后来源组上下文恢复与误跳防护增强

## 1. 任务目标

在 `222`、`285`、`289` 已补齐来源区展开记忆、跨来源切换锚点和弱数据态降级基础上，继续细化页面刷新、重进详情页或数据重拉后，来源阅读区应优先恢复“正在看哪一组来源”的上下文，而不是只机械恢复一个滚动位置，从而避免用户被带到错误的来源段落。

## 2. 背景与现状

来源阅读区一旦支持分组切换、展开记忆和比较视角，就会产生两层上下文：

1. 当前正在阅读哪一组来源
2. 在该来源组里读到了哪里

如果刷新后只恢复滚动位置，不恢复来源组语义，就可能出现：

1. 视觉上落在某个位置，但用户不知道自己正在看哪组来源
2. 数据重排后，旧滚动位置对到了错误来源组
3. 来源比较视角已降级，旧滚动位置也不再有意义

## 3. 涉及范围

- Memory Wiki 来源阅读区
- 来源组选择状态、滚动位置和刷新恢复逻辑
- 来源比较视角降级后的上下文回落
- 对应前端测试

## 4. 前置依赖

1. `222-8.3-Memory-Wiki来源区展开记忆与批量查看增强.md` 已完成或至少已有展开状态记忆
2. `285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强.md` 已完成或至少已有跨来源锚点恢复
3. `289-8.3-Memory-Wiki来源比较视角在弱数据态下的自动降级与空态衔接增强.md` 已完成或至少已有降级判定

## 5. 具体开发项

### 5.1 来源组上下文优先恢复

1. 刷新后优先恢复最近阅读的来源组
2. 只有在来源组有效的前提下，才尝试恢复组内滚动位置
3. 若来源组失效，则回落到默认可读来源组并明确轻提示

### 5.2 数据重排后的误跳防护

1. 数据重拉后若来源组顺序变化，不应把旧滚动位置硬套到新结构
2. 若旧来源组仍存在，则重新在该组内寻找合理锚点
3. 若旧来源组不存在，则以来源组标题级回落取代像素级恢复

### 5.3 与比较视角降级兼容

1. 若刷新后来源比较视角被自动降级，应同步降级上下文恢复策略
2. 不保留已经失去意义的“继续比较下一组来源”状态
3. 降级后仍让用户看懂当前进入的是哪类来源阅读模式

### 5.4 提示与退场

1. 轻提示说明“已帮你回到刚才那组来源”或“原来源组不可用，已回到默认来源”
2. 用户手动切到新来源组后，旧恢复提示自动退场
3. 提示不压过来源正文内容本身

### 5.5 测试补齐

1. 覆盖刷新后先恢复来源组再恢复组内锚点
2. 覆盖数据重排后的误跳防护
3. 覆盖来源组失效后的默认组回落
4. 覆盖比较视角降级后的上下文恢复调整

## 6. 验收标准

1. 来源阅读区刷新后恢复的是阅读语义，而不只是机械滚动位置
2. 数据重排和降级场景下不会把用户带去错误来源段落
3. 用户能持续看懂自己当前正在阅读哪组来源
4. 对应前端测试通过
