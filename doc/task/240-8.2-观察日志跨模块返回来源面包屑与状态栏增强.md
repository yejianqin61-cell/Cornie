# 240-8.2-观察日志跨模块返回来源面包屑与状态栏增强

## 1. 任务目标

在 `230` 已补齐观察日志跨模块整理队列与返回原位能力的基础上，继续增加返回来源面包屑和轻量状态栏，让用户更容易理解自己当前是从哪里跳来的、还在处理哪一天的哪条素材。

## 2. 背景与现状

跨模块返回原位功能一旦存在，用户接下来会需要更清楚的导航语义。若没有专门承接，会出现：

1. 返回后虽然回到了原位，但不清楚自己为何会在这里
2. 连续跨多个模块跳转后，当前整理上下文容易变模糊
3. 缺少一个平实的小状态栏来提示“你现在正在整理什么”

## 3. 涉及范围

- 观察日志工作台顶部或详情区状态栏
- 面包屑式来源说明
- 跨模块返回链路提示
- 对应前端测试

## 4. 前置依赖

1. `230-8.2-观察日志跨模块整理队列与返回原位增强.md` 已完成或至少已有返回原位能力
2. `240` 前的相关跨模块任务已提供到聊天记录 / Cornie 日记 / 长期记忆的跳转入口
3. `235-8.2-观察日志批量补全小控制台与连续处理增强.md` 已完成或至少已有连续整理控制台

## 5. 具体开发项

### 5.1 来源面包屑

1. 当用户从聊天记录、Cornie 日记、Memory Wiki 等模块跳回观察日志时，显示轻量来源面包屑
2. 面包屑只表达当前来源链路，不模拟完整浏览器历史
3. 支持一键返回上一个来源模块

### 5.2 轻量状态栏

1. 在观察日志详情区显示当前日期、当前条目标题、整理状态等信息
2. 当用户处于连续整理模式时，状态栏提示当前是“第几条 / 还剩几条待补完”
3. 状态栏视觉上应克制，不和主表单竞争注意力

### 5.3 跨模块上下文说明

1. 明确告诉用户这条日志与哪个外部模块动作有关
2. 当来源链路失效时，给出轻量兜底说明
3. 让用户在复杂跳转后仍能判断当前上下文是否正确

### 5.4 状态同步

1. 跨模块返回后，状态栏与面包屑同步更新
2. 切换到别的日期或条目时，旧来源信息应合理清空或降级
3. 与返回原位、草稿恢复、连续整理状态保持兼容

### 5.5 测试补齐

1. 覆盖不同来源模块回流时的面包屑展示
2. 覆盖连续整理状态栏内容变化
3. 覆盖来源失效后的兜底说明
4. 覆盖切换条目后来源状态清理

## 6. 验收标准

1. 用户能一眼看懂自己当前为何停留在这条观察日志
2. 复杂跨模块整理路径更容易被人脑跟住
3. 面包屑和状态栏不会破坏观察日志主工作流
4. 对应前端测试通过
