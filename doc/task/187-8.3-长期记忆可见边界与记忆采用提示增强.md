# 187-8.3-长期记忆可见边界与记忆采用提示增强

## 1. 任务目标

在现有记忆引用透明提示基础上，继续把“哪些内容进入长期记忆、哪些长期记忆被本轮采用、用户能看到和控制到什么程度”这组边界做成完整的前端体验，既保证透明，也避免形成恐怖谷。

## 2. 背景与现状

当前前端已经具备或已规划：

1. 聊天侧工具结果面板
2. 记忆引用轻提示
3. Memory Wiki 工作台与页面详情
4. 长期记忆写入、治理、版本、审计的后端基础

但仍有明显产品缺口：

1. 用户不知道“刚刚哪句话被建议记进长期记忆”
2. 用户不知道“这一轮回复里铃湾实际参考了哪些长期记忆”
3. 用户不知道“进入长期记忆后，自己在哪里看、怎么改、怎么撤”
4. 若提示做得过度细碎，容易带来被持续监视的压迫感

## 3. 涉及范围

- 聊天消息渲染链路
- `ToolResultPanel.vue`
- `ConfirmCard.vue`
- `MemoryWikiWorkspace.vue`
- 如有必要，补充记忆采用摘要读取接口
- 对应前端测试

## 4. 前置依赖

1. `174-8.3-记忆引用透明提示与工具结果面板增强.md` 已完成
2. `175-8.3-Memory-Wiki来源引用与关联阅读增强.md` 已完成
3. `183-8.3-聊天侧轻量治理提示与跳转入口.md` 已完成或至少具备聊天侧轻提示入口

## 5. 具体开发项

### 5.1 长期记忆写入候选提示

1. 当本轮对话提出长期记忆写入建议时，前端应展示清楚的候选摘要
2. 说明为什么建议记住这件事，例如长期偏好、重要事件、稳定需求
3. 明确区分“建议写入”与“已经写入”

### 5.2 本轮记忆采用提示

1. 当本轮回复参考了长期记忆时，提供轻量提示
2. 支持展开查看有限数量的记忆摘要或页面标题
3. 控制展示颗粒度，不逐句复述模型内部过程
4. 文案强调“铃湾参考了一些过往记录”，而不是制造监控感

### 5.3 用户可见可控入口

1. 从聊天提示可跳转到对应 Memory Wiki 页面
2. 从写入确认卡可跳转到记忆详情或待审核区
3. 在 Memory Wiki 中明确展示用户可编辑、可回滚、可归档的入口
4. 让用户知道“长期记忆不是黑箱”

### 5.4 边界与静默策略

1. 并非每次使用长期记忆都必须高调提示
2. 对低风险、低存在感的普通引用，可只做轻量标识
3. 对明显影响回答立场或涉及偏好的引用，优先展示更清楚的提示
4. 保持透明与不过度打扰之间的平衡

### 5.5 测试补齐

1. 覆盖长期记忆写入建议卡展示
2. 覆盖已写入与待确认两种状态分支
3. 覆盖本轮记忆采用轻提示的展示与展开
4. 覆盖跳转到 Memory Wiki 的入口
5. 覆盖无记忆采用时的静默状态

## 6. 验收标准

1. 用户能够理解哪些内容被建议写入长期记忆
2. 用户能够感知本轮是否参考了长期记忆，但不会被过度惊扰
3. 用户能够从聊天侧顺畅进入对应记忆页面或治理入口
4. 长期记忆的“透明、可控、不过度拟人化”边界表达成立
5. 对应前端测试通过
