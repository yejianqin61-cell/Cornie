# 463 列表性能与分页

## 背景

`memory-wiki/service.js` 的 `listSummaries` 对每页调用 `this.get(pageId)` 逐页读文件（N+1，Cornie-018 D-09），页面增长后列表加载变慢；无分页上限。该问题同时影响消费侧目录构建（451）与前端列表。

## 目标

1. `listSummaries` 基于 page-index.json 轻索引直接产出摘要，不逐页读文件。
2. 增加 `limit/offset` 分页参数并贯通 REST 与前端。
3. 100 页规模下列表响应达标（记录性能基线）。

## 范围

- `electron/backend/memory-wiki/service.js`（listSummaries）
- `electron/backend/memory-wiki/routes.js`（分页参数）
- `electron/backend/memory-wiki/storage.js`（page-index 读取）
- 前端列表组件（`MemoryPageList.vue` 等，分页透传）

## 设计要求

1. `listSummaries` 改为基于 page-index 轻索引产出摘要（正文类字段按需延迟读取）。
2. REST 与前端贯通 `limit/offset`（或 cursor）。
3. 性能基线记录到 `doc/test/`（100 页规模 listSummaries 响应时间对比）。

## 验收标准

1. 100 页规模 listSummaries 响应时间下降（对比基准记录在 `doc/test/`）。
2. 分页参数前后端贯通，翻页正确。
3. 无逐页读全文（埋点或代码审查确认）。

## 依赖与衔接

- 依赖：462（索引一致性，轻索引读取依赖索引可信）。
- 衔接：451（消费侧目录构建复用轻索引）。
- 上游设计：Cornie-018 I-10（Phase 3）。
