# 232-8.3-巡检提醒中心与待审核入口统一收口增强

## 1. 任务目标

在 `181` 和 `179` 已提供异步提醒、巡检结果工作台的基础上，继续统一“巡检发现的问题”和“待审核处理入口”的前端收口方式，让用户不需要分别记忆多个入口。

## 2. 背景与现状

当前巡检结果、待审核候选、侧栏角标、模块内提醒条都在逐步成型，但继续产品化时容易出现：

1. 用户知道有问题，却不清楚应该去“巡检结果”还是“待审核池”
2. 入口分散，提醒语义不够统一
3. 一部分问题是只读巡检结果，一部分问题需要人工决策，前端边界还需更清楚

## 3. 涉及范围

- Memory Wiki 工作台内的提醒区域
- 巡检结果页与待审核池入口关系
- 对应前端测试

## 4. 前置依赖

1. `179-8.3-Memory-Wiki巡检结果与审计工作台落地.md` 已完成或至少已有巡检结果区
2. `181-8.2-Memory-Wiki待审核角标与异步提醒增强.md` 已完成或至少已有异步提醒
3. `195-8.3-Memory-Wiki巡检结果分类阅读与跳转收口.md` 已完成或至少已有分类阅读
4. `231-8.3-Memory-Wiki待审核池排序模式与批量浏览增强.md` 已完成或至少已有待审核池增强基础

## 5. 具体开发项

### 5.1 统一提醒中心

1. 在 Memory Wiki 工作台内提供统一的提醒中心或摘要区
2. 清楚区分“只需查看的问题”和“需要你做决定的问题”
3. 用统一的文案结构表达数量、来源和建议动作

### 5.2 入口关系收口

1. 从提醒中心可以直接跳到巡检结果或待审核池对应分区
2. 避免用户在多个入口间来回试错
3. 保持入口命名一致，减少概念重叠

### 5.3 状态联动

1. 当巡检结果已被查看、待审核项已被处理时，提醒中心同步更新
2. 对已处理完的状态保持克制，不长期制造“红点焦虑”
3. 在无提醒时提供安静但不空洞的说明

### 5.4 文案与边界

1. 对“可稍后处理”和“建议尽快处理”做轻量区分
2. 不把只读巡检结果误包装成必须立刻决策的事务
3. 让用户能看懂系统为什么把某项放入待审核，而不是只看到结论

### 5.5 测试补齐

1. 覆盖统一提醒中心渲染
2. 覆盖跳到巡检结果和待审核池的两类入口
3. 覆盖已处理后提醒同步消退
4. 覆盖无提醒状态与低打扰表达

## 6. 验收标准

1. 用户能从一个统一位置理解当前 Memory Wiki 需要关注什么
2. 巡检结果与待审核池的边界更清楚，入口更顺手
3. 提醒状态联动稳定，不制造过度打扰
4. 对应前端测试通过
