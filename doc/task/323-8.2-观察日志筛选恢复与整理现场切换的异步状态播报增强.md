# 323-8.2-观察日志筛选恢复与整理现场切换的异步状态播报增强

## 1. 任务目标

在 `173`、`192`、`229-319` 这批观察日志工作台任务基础上，继续补齐筛选条件恢复、工作篮恢复、跨天降级、来源说明重开与整理现场切换时的异步状态播报，让用户能明确感知“系统刚刚替我恢复了什么、降级了什么、当前又在处理哪一条观察”。

## 2. 背景与现状

当前观察日志侧已经逐步补齐：

1. 按日定位与筛选持久化
2. 工作篮、草稿恢复态与互斥规则
3. 跨天失效后的降级恢复
4. 重开说明入口后的按钮、焦点、折叠层级同步

但若没有状态播报，仍会出现：

1. 刷新后系统悄悄恢复了筛选和工作现场，用户不知道为什么列表变了
2. 跨天降级后用户只看到内容不一样，却不知道旧现场已失效
3. 切换条目后来源说明已切走，但读屏用户不知道当前上下文属于哪条观察

## 3. 涉及范围

- 观察日志列表、工作篮、来源说明区
- 恢复态、降级态、切换态的轻播报与读屏可感知反馈
- 对应前端测试

## 4. 前置依赖

1. `283-8.2-观察日志筛选条件持久化与按日工作上下文恢复增强.md` 已完成或至少已有恢复逻辑
2. `291-8.2-观察日志恢复现场跨天失效后的降级恢复与轻提示增强.md` 已完成或至少已有跨天降级
3. `319-8.2-观察日志重开说明入口跨条目切换后的键盘焦点回落与折叠层级同步增强.md` 已完成或至少已有焦点与层级同步

## 5. 具体开发项

### 5.1 筛选与工作篮恢复播报

1. 页面恢复上次筛选条件、工作篮或草稿现场时，提供轻量状态说明
2. 说明应帮助用户理解“为什么现在看到的是这一组内容”
3. 已处在相同状态时不重复播报，避免高噪声

### 5.2 跨天降级与现场失效播报

1. 若旧恢复现场因跨天失效而被降级，需明确说明“已改为当前可恢复的最近现场”
2. 文案以用户能理解的方式表达，不使用“恢复失败栈”之类工程说法
3. 降级播报应与当前列表、条目高亮、顶部提示保持一致

### 5.3 条目切换与来源说明上下文播报

1. 用户切换到新条目并重开来源说明时，应可感知当前处理对象已变化
2. 读屏用户需要知道当前说明区属于哪一条观察，而不是沿用旧条目语义
3. 若用户已进入深度整理流，不再重复播报外围提示细节

### 5.4 测试补齐

1. 覆盖筛选恢复与工作篮恢复播报
2. 覆盖跨天降级后的状态说明
3. 覆盖跨条目切换后来源说明的上下文播报
4. 覆盖进入深度整理流后的静默收口

## 6. 验收标准

1. 观察日志恢复态、降级态、切换态对人类用户和读屏用户都清晰可感知
2. 状态播报不干扰实际整理主链路
3. 当前条目、当前筛选、当前恢复现场三者的语义能被用户理解
4. 对应前端测试通过
