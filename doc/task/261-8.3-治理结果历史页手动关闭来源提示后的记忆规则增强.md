# 261-8.3-治理结果历史页手动关闭来源提示后的记忆规则增强

## 1. 任务目标

在 `257` 已补齐治理结果历史页多入口回流提示降级与冲突消解规则的基础上，继续处理用户手动关闭来源提示后的记忆规则，让历史页提示行为更稳、更尊重使用习惯。

## 2. 背景与现状

当历史页来源提示越来越细时，用户也会希望关掉自己不需要的说明。若没有继续设计，会出现：

1. 用户关闭提示后很快又出现
2. 用户不确定关闭的是当前一次还是这类提示
3. 关键提示和普通提示被同样对待，容易走向两个极端

## 3. 涉及范围

- 治理结果历史页顶部来源提示
- 用户关闭行为持久化
- 再次出现规则
- 对应前端测试

## 4. 前置依赖

1. `257-8.3-治理结果历史页多入口回流下的提示降级与冲突消解增强.md` 已完成或至少已有提示体系
2. `256-8.3-治理结果历史页到提醒中心与待审核池的跨页回流说明增强.md` 已完成或至少已有跨页回流说明

## 5. 具体开发项

### 5.1 关闭记忆

1. 记录用户关闭过哪类来源提示
2. 在合理时效内减少同类提示重复出现
3. 关闭记忆范围要清楚，不误伤其他页面说明

### 5.2 重新出现条件

1. 当来源链路或结果上下文发生明显变化时，允许提示重新出现
2. 对关键首次回流说明保留更高出现优先级
3. 对纯重复回流说明则更积极抑制

### 5.3 分层策略

1. 普通来源提示遵循更克制的重现规则
2. 关键风险相关的说明可拥有更强保留权
3. 用户手动关闭后仍应保留极端关键场景的最低提醒能力

### 5.4 状态隔离

1. 不同筛选上下文、不同时间范围下的关闭记忆需合理隔离
2. 从提醒中心回流与从待审核池回流的关闭状态要能区分
3. 页面重置筛选后，关闭记忆行为保持可预期

### 5.5 测试补齐

1. 覆盖关闭后的重复抑制
2. 覆盖关键变化后的重新出现
3. 覆盖不同来源链路的关闭状态隔离
4. 覆盖重置筛选后的行为一致性

## 6. 验收标准

1. 治理结果历史页提示更尊重用户手动关闭行为
2. 关键说明仍不会被彻底误压制
3. 关闭记忆与重新出现规则清楚、可靠
4. 对应前端测试通过
