# 365-重要人物页到观察日志来源反查链路补齐

## 1. 目标

根据以下设计稿，补齐 `identity_person` 页面到观察日志来源的自动补链能力，让重要人物页不仅能回查聊天来源，也能回查同轮观察日志来源，并同步沉淀到 Topic Index：

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 2. 背景

当前重要人物页已经具备：

- 对话到人物页自动沉淀
- 人物页到 Topic Index 的 `chatRefs / memoryPageIds / dates` 自动联动
- 人物页高风险字段治理候选

但仍有一个明显断口：

- 同一轮对话写入的观察日志，没有自动补进人物页 `sourceRefs`
- Topic Index 也没有自动补人物相关 `observationRefs`
- 结果是人物页来源反查仍偏“只有聊天，没有观察层”

这和设计稿中“人物页能反查聊天、观察、日期”的要求还不一致。

## 3. 涉及范围

- `electron/backend/agent/orchestrator.js`
- `electron/backend/identity/personUpsert.js`
- `electron/backend/memory-wiki/service.js`
- `scripts/`

## 4. 任务要求

### 4.1 对话写入时补 observation sourceRef

当本轮对话已经成功形成观察日志记录时：

- `upsertIdentityPersonFromConversation` 应接收 observation 上下文
- 创建人物页时自动写入：
  - `kind: observation`
  - `observationId`
  - `date`
  - `title`
  - `type`
- 更新已有人物页时也应避免重复地补 observation 来源

### 4.2 Topic Index 自动补 observationRefs

当人物页在本轮被创建或更新，并且存在 observation 来源时：

- 其对应人物 Topic 需要自动补：
  - `observationRefs`
- 与 `chatRefs / memoryPageIds / dates` 一样保持幂等

### 4.3 来源追溯结构保持统一

补链后，`memoryWiki.getPageSourceTrace(pageId)` 的人物页来源结果中应能稳定看到：

- chat source
- observation source

且 observation source 可通过现有 trace 结构正常读取。

## 5. 验收标准

- 同轮对话触发“观察日志 + 人物页自动沉淀”后，人物页 `sourceRefs` 含 observation 来源
- Topic Index 对应人物主题含 `observationRefs`
- 重复触发同一 observation 不会重复写入
- 新增验证脚本
- `npm run build` 通过
