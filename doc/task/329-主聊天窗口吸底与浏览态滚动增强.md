# 329-主聊天窗口吸底与浏览态滚动增强

## 1. 任务目标

为主聊天窗口补齐“吸底态 / 浏览态 / 回到底部”滚动机制，使新消息到达时既能保证默认顺手，又不会打断用户查看历史消息。

## 2. 对应来源

- GitHub Issue `#1` 主聊天窗口细节优化
- 设计文档：`doc/design/Cornie-0629-GitHub-Issue-001-005前端体验增强落地设计.md`

## 3. 背景与现状

当前聊天页在发送消息、收到新消息、会话同步后，基本都会直接滚到底部。  
这会造成以下问题：

1. 用户上滑查看历史消息时，会被强制打断。
2. 缺少“当前是否允许自动吸底”的状态判断。
3. 后续桌宠窗口与主窗口共用聊天状态时，滚动行为不稳定。

## 4. 涉及范围

- `src/renderer/composables/useChat.js`
- `src/renderer/components/ChatHome.vue`
- 如已共用同一会话展示逻辑，则检查 `src/renderer/CorniePet.vue` 是否需要同步策略

## 5. 前置依赖

1. 当前共享聊天会话逻辑可正常发送、同步、展示。
2. 重复消息问题已修复，避免滚动优化时被旧问题干扰。

## 6. 开发项

### 6.1 定义滚动状态

在聊天页引入以下前端状态：

1. `isPinnedToBottom`
   - 当前是否位于底部附近。
2. `hasUnreadBelow`
   - 用户处于浏览态时，是否有新消息到达。
3. `autoStickThreshold`
   - 判定“距离底部足够近”的阈值，建议 24px 到 48px。

### 6.2 监听滚动行为

为聊天消息容器增加滚动监听：

1. 当滚动位置接近底部时，设置为吸底态。
2. 当用户上滑离开底部阈值时，退出吸底态。
3. 在退出吸底态后，不要继续因同步消息而强制滚动。

### 6.3 统一滚动触发规则

以下事件发生时，都通过统一函数判断是否执行自动滚动：

1. 用户发送消息成功插入后
2. 铃湾回复插入后
3. 工具结果卡插入后
4. 确认卡插入后
5. 定时同步加载到新消息后

规则：

1. 若当前为吸底态，则滚到底部。
2. 若当前为浏览态，则不滚动，只设置 `hasUnreadBelow=true`。

### 6.4 增加“回到底部”入口

在聊天区右下方或输入区上方增加轻量按钮：

1. 仅在用户处于浏览态且有新消息时显示。
2. 点击后：
   - 滚到底部
   - 清空 `hasUnreadBelow`
   - 恢复吸底态

### 6.5 处理初始化与切页行为

1. 首次进入聊天页时，默认滚到底部。
2. 当天会话首次加载完成后，默认吸底。
3. 切换日期或重新进入聊天页时，不保留旧的浏览态脏状态。

## 7. 实现建议

### 7.1 逻辑归属建议

优先将“滚动状态判断”留在 `ChatHome.vue` 视图层，避免把 DOM 滚动状态塞进 `useChat.js` 这种偏数据层的 composable 中。

推荐拆出局部辅助函数：

1. `isNearBottom(el)`
2. `scrollToBottom(force = false)`
3. `handleChatScroll()`
4. `handleMessagesUpdated()`

### 7.2 桌宠同步

若桌宠也需要共享此能力，可复用同样的视图层状态机，不建议把主窗口 DOM 细节直接抽到通用聊天数据层。

## 8. 验收标准

1. 用户位于底部时，发送消息和收到消息都会自动吸底。
2. 用户上滑查看历史消息时，新消息到达不会打断阅读。
3. 浏览态下收到新消息后，会出现明确的“回到底部”入口。
4. 点击“回到底部”后，可恢复自动吸底。
5. 构建通过，且不会引入新的重复滚动抖动问题。

## 9. 自测清单

1. 打开聊天页，首次加载是否自动在底部。
2. 连续发送 3 条消息，是否始终保持底部可见。
3. 上滑查看旧消息，等待同步新消息，是否不会被拉回底部。
4. 出现“回到底部”按钮后，点击是否恢复到底部。
5. 有工具调用结果和确认卡时，滚动行为是否仍一致。
