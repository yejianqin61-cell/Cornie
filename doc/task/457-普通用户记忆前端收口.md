# 457 普通用户记忆前端收口

## 背景

记忆层后端能力已成型，但普通用户前端的 Memory Wiki 增删改查未收口（Cornie-018 D-03 / I-03）：`MemoryPageDetail.vue` 创建/删除入口不完整、详情页偏基础文本编辑、identity 类型差异无表达；前端对齐度 50%-65%（Cornie-018 §2.2）。后端审查（Cornie-019 关联）确认用户感知不到后端强能力。

## 目标

1. 普通用户长期记忆页的"新建→编辑→保存→删除"全流程可用。
2. 页面类型（profile/person/preference/trait）有差异表达，治理术语（pageId/status/importance）隐去。
3. 来源摘要可读化（聊天/观察/相关页分组展示）。

## 范围

- `src/renderer/components/MemoryPageDetail.vue`
- `src/renderer/components/MemoryPageList.vue`
- `src/renderer/components/ObserveMemoryHome.vue`
- `src/renderer/api.js`
- 相关测试（`tests/frontend/`）

## 设计要求

### 1. 新建与删除闭环

- 新建完整表单（页面类型选择 + 字段引导）；删除二次确认。
- 保存失败/加载失败的状态可见（避免空表单覆盖真实页面，修复 Cornie-019 前端审查 P1-4）。

### 2. 类型差异表达

- 按 identity 类型（profile/person/preference/trait）分组、图标/标签表达。
- 隐藏高级术语（pageId/status/importance/ownerConfirmed 原文），改平实文案。
- 高级治理入口（MemoryWikiWorkspace）保持冻结，不作为普通用户目标。

### 3. 来源可读化

- 来源摘要分组展示（聊天来源回跳消息定位、观察来源、相关记忆页互相回流）。
- 配合 `@open-chat-source` 跳转链路（现有 App.vue 已支持）。

### 4. 回归

- 前端 smoke 用例覆盖"新建→编辑→保存→删除"全流程；视觉回归覆盖四类页面。

## 验收标准

1. 普通用户可在前端完成记忆页全生命周期操作。
2. 四类页面展示有类型差异；无治理术语暴露。
3. 删除有二次确认；加载失败不出现可覆盖真实数据的空表单。
4. 相关前端测试（smoke/视觉）通过。
