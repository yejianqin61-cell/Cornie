# 437-普通用户长期记忆入口与高级工作台路由隔离

## 1. 任务目标

把“普通用户长期记忆入口”和“高级治理工作台入口”在前端路由与导航层彻底分开，避免用户在普通使用场景里误入治理界面，或在普通入口里看到不该承担的复杂概念。

本任务要解决的是产品分层问题，而不是记忆能力缺失问题。

## 3. 背景与现状

前序任务已经补齐了普通用户长期记忆入口的多个能力点，例如：

1. `412-普通用户长期记忆新建编辑删除闭环`
2. `414-普通用户长期记忆列表分组与主入口强化`
3. `415-普通用户长期记忆详情页类型自适应与主身份强化`
4. `424-435` 观察与记忆首页收口

但当前仍存在一个结构性问题：

1. 普通入口和高级入口虽然概念上不同，导航和组件边界上未必彻底分离
2. `MemoryWikiWorkspace.vue` 仍可能被误当作普通入口扩展
3. 后续继续开发时，容易再次把治理能力漏进普通入口

## 5. 开发项

### 5.1 明确普通用户长期记忆主入口

要求从“观察与记忆”域进入后，普通用户看到的是：

1. 观察日志
2. 长期记忆内容入口
3. 与自己和重要的人相关的阅读、编辑能力

而不是：

1. Topic
2. 审计
3. 治理池
4. 巡检
5. 回滚

### 5.2 高级工作台单独挂载

将高级工作台明确视为：

1. 设置域入口
2. 高级治理入口
3. 非普通用户默认浏览路径

要求：

1. 普通用户主导航不直接暴露高级治理词汇
2. 高级工作台不再被普通用户长期记忆页面复用为主容器

### 5.3 导航回流语义收口

从普通用户长期记忆详情页、观察页等位置返回时：

1. 返回到普通用户语义路径
2. 不突然跳到高级工作台
3. 不出现“我刚刚明明在看记忆，怎么回到了治理台”的体验断层

### 5.4 后续扩展边界固化

要求在实现中留下明确边界，避免后续再把下面这些内容扩回普通入口：

1. Topic Index
2. 页面合并
3. 版本历史
4. 审计
5. 治理请求内部状态

## 6. 不做事项

本任务不处理：

1. 高级工作台本身的 UI 重做
2. Topic Index 新能力开发
3. 审计、回滚、合并流程功能新增
4. 普通入口的具体卡片文案微调

## 7. 验收标准

1. 普通用户可在不进入高级工作台的前提下完成长期记忆主流程
2. 高级治理入口与普通记忆入口在导航层清晰分离
3. 普通路径中不再混入治理术语和治理回流
4. 高级工作台仍可独立进入，不影响现有治理能力

## 8. 自测清单

1. 从“观察与记忆”首页进入长期记忆，检查全流程是否始终停留在普通入口语义
2. 从长期记忆详情返回列表，再返回首页，检查回流路径是否自然
3. 从设置或高级入口进入工作台，检查高级能力是否仍可用
4. 检查普通入口是否仍有任何直接暴露的治理主入口按钮
