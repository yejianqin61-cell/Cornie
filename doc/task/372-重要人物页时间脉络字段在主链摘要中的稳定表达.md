# 372-重要人物页时间脉络字段在主链摘要中的稳定表达

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 中对 `identity_person` 的字段定义，把 `timeline_summary` 与 `first_known_period` 正式接入主链 `memorySummary` 的稳定表达，避免这些时间脉络字段虽然已经落库，却没有稳定进入模型可读摘要。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/agent/wikiContext.js`
- `scripts/`

## 4. 当前问题

当前 `identity_person` 已经具备：

- `sharedExperienceSummary`
- `timelineSummary`
- `firstKnownPeriod`

但主链 `memorySummary` 中的人物摘要仍主要表达：

- 关系
- 角色
- 性格
- 对用户意义
- 共同经历

这会导致：

- 设计稿里的“时间线”字段存在感不稳定
- 模型跨天注入时不容易直接拿到“首次已知阶段 / 时间脉络”
- 人物页虽有结构化字段，但主链摘要对这些字段利用不足

## 5. 目标设计

- 在 `buildIdentityPersonSummaryLine()` 中稳定表达：
  - `firstKnownPeriod`
  - `timelineSummary`
- 保持摘要克制，不整页展开
- 保持旧字段兼容，不破坏现有人物摘要结构
- 新增验证脚本，证明人物 query 命中时主链摘要能带出时间脉络

## 6. 实现步骤

### Step 1

增强 `wikiContext` 中 `identity_person` 摘要模板。

### Step 2

补验证脚本，覆盖“带明确时间经历的人物页”进入 `memorySummary` 的场景。

## 7. 测试点

- 命中人物 query 时 `memorySummary` 包含 `首次已知` 信息
- 命中人物 query 时 `memorySummary` 包含 `时间线` 信息
- 未破坏现有人物意义/关系字段表达
- `npm run build` 通过

## 8. 完成标准

- 重要人物页的时间脉络字段不再只停留在落库层
- 主链长期记忆摘要与 0630 Identity 设计稿更一致
