# 245-8.2-观察日志到Cornie日记生成后回看链路与来源回跳增强

## 1. 任务目标

在 `204` 已补齐从观察日志进入 Cornie 日记生成入口的基础上，继续增强生成后的回看链路、来源回跳和上下文说明，让“素材层 -> 日记层 -> 再回看素材层”形成完整闭环。

## 2. 背景与现状

当前设计已经强调观察日志是 Cornie 日记的来源之一，但真正做完生成动作后，用户还会需要：

1. 看看今天生成出来的 Cornie 日记是否符合预期
2. 从日记页回跳到当日观察日志核对来源
3. 理解这篇日记和当天素材之间到底是什么关系

如果这一段没有细化，就会出现生成后链路断掉的问题。

## 3. 涉及范围

- 观察日志工作台
- Cornie 日记生成后入口与回看入口
- 观察日志与日记页之间的双向回跳
- 对应前端测试

## 4. 前置依赖

1. `204-8.2-观察日志到Cornie日记生成联动入口收口.md` 已完成或至少已有生成入口
2. `184-8.1-Cornie日记来源透明与生成后工作流.md` 已完成或至少已有生成后工作流方向
3. `240-8.2-观察日志跨模块返回来源面包屑与状态栏增强.md` 已完成或至少已有返回来源说明基础

## 5. 具体开发项

### 5.1 生成后回看入口

1. 生成成功后，在观察日志侧明确显示“查看今天的 Cornie 日记”入口
2. 若当天已存在 Cornie 日记，入口语义应改为“回看”而非“生成”
3. 入口要能区分首次生成和后续回看两类场景

### 5.2 双向来源回跳

1. 从观察日志跳去 Cornie 日记后，支持再回跳到当日观察日志
2. Cornie 日记页中应有轻量来源说明，说明它来自当天素材整理
3. 不要求一条条强绑定，但要保留“回看素材层”的自然路径

### 5.3 上下文说明

1. 告诉用户 Cornie 日记是文学化整理结果，不等于逐条照抄观察日志
2. 告诉用户观察日志仍然是事实素材层，可继续修正和补充
3. 让回看链路服务于核对与关怀，而不是强制造成机械追溯感

### 5.4 生成后状态同步

1. 生成完成后，同步刷新观察日志侧的状态提示
2. 同日关系面板中 Cornie 日记状态应同步更新
3. 若日记被重新生成或删除，相关回看入口状态也要正确回退

### 5.5 测试补齐

1. 覆盖生成成功后的回看入口展示
2. 覆盖日记页回跳观察日志链路
3. 覆盖首次生成与已存在日记两类入口差异
4. 覆盖状态回退后的入口更新

## 6. 验收标准

1. 观察日志到 Cornie 日记的链路不仅能发起生成，也能生成后回看
2. 用户能在素材层和日记层之间自然往返
3. 前端清楚表达两层内容的边界关系
4. 对应前端测试通过
