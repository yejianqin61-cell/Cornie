# 195-8.3-Memory-Wiki巡检结果分类阅读与跳转收口

## 1. 任务目标

在 `179` 巡检结果与审计工作台基础上，继续把巡检结果做成真正可阅读、可分类、可跳转的前端工作区，让用户能快速区分：

1. 只是需要了解的问题
2. 可以跳去处理的治理候选
3. 需要回看目标页面或来源证据的问题

## 2. 背景与现状

`179` 已经把巡检结果和审计工作台立了起来，但若要提升为正式工作台，还需要更明确的阅读与跳转收口：

1. 不同问题类型的阅读优先级
2. 信息型结果与治理型结果的明显分层
3. 结果到页面详情、待审核区、审计记录的顺畅跳转

## 3. 涉及范围

- `src/renderer/components/MemoryWikiWorkspace.vue`
- 巡检结果列表与详情面板
- 对应前端测试

## 4. 前置依赖

1. `179-8.3-Memory-Wiki巡检结果与审计工作台落地.md` 已完成或至少已有巡检结果区

## 5. 具体开发项

### 5.1 巡检结果分类阅读

1. 按断链、孤儿页、来源失效、可治理建议等类型分组
2. 每组展示数量与简短说明
3. 支持按严重度或最近发现时间排序

### 5.2 结果详情与证据摘要

1. 点击结果后展示目标页面、发现原因、简短证据摘要
2. 明确哪些结果只需了解，哪些可进一步处理
3. 保持术语可理解，避免把内部治理名词直接堆给用户

### 5.3 跨区跳转

1. 支持跳转到目标 Memory Wiki 页面
2. 若已形成待审核项，支持跳转到对应待审核候选
3. 若需要回看历史操作，支持跳转到相关审计记录

### 5.4 空态与历史感知

1. 当巡检结果为空时，展示健康空态
2. 当某类问题已处理完时，能给出清楚状态反馈
3. 保持巡检区与待审核区职责边界清晰

### 5.5 测试补齐

1. 覆盖分类分组渲染
2. 覆盖信息型与治理型结果分层
3. 覆盖跳转入口
4. 覆盖健康空态与已处理状态

## 6. 验收标准

1. 用户可以快速理解巡检结果的分类与轻重缓急
2. 用户可以从巡检区顺畅跳到页面、待审核区、审计区
3. 巡检结果区从“有列表”提升为“可阅读工作区”
4. 对应前端测试通过
