# 006 待办与日程功能升级

## 1. 任务目标

建立待办、日程及其类目体系，并支持 AI 在对话中：

- 新增待办
- 修改待办
- 完成待办
- 新增日程
- 修改日程
- 查询待办和日程
- 在无法映射类目时发起新增类目确认

本任务完成后，还要为对话上下文提供：

- 未完成待办摘要
- 近期日程摘要
- 完整待办/完整日程只读补查能力

## 5. 数据结构设计

### 5.1 待办表

```sql
CREATE TABLE IF NOT EXISTS todo_entries (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  category_id TEXT,
  category_name TEXT,
  due_at TEXT,
  status TEXT NOT NULL,           -- pending | done | cancelled
  source_text TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 5.2 待办类目表

```sql
CREATE TABLE IF NOT EXISTS todo_categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  is_active INTEGER NOT NULL DEFAULT 1,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 5.3 日程表

```sql
CREATE TABLE IF NOT EXISTS schedule_entries (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  category_id TEXT,
  category_name TEXT,
  start_at TEXT NOT NULL,
  end_at TEXT,
  status TEXT NOT NULL,           -- scheduled | cancelled | done
  location TEXT,
  source_text TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 5.4 日程类目表

```sql
CREATE TABLE IF NOT EXISTS schedule_categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  is_active INTEGER NOT NULL DEFAULT 1,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

## 8. 实现步骤

### Step 1

改造 `electron/db.js`

- 增加待办、待办类目、日程、日程类目表
- 提供 CRUD 操作

### Step 2

新增 `todo/service.js` 与 `schedule/service.js`

- 分别封装业务逻辑

### Step 3

新增 `todo/tools.js` 与 `schedule/tools.js`

- 把业务逻辑包装为工具

### Step 4

实现摘要生成函数

- 生成未完成待办摘要
- 生成近期日程摘要

### Step 5

注册工具并接入 Tool Policy Layer

- 新增类目仍需确认
- 删除与修改高风险操作要受控

## 9. 测试点

### 9.1 单元测试建议

- 待办新增成功
- 待办完成成功
- 日程新增成功
- 摘要生成逻辑正确过滤未完成项
- 类目新增走确认流

### 9.2 联调测试

- 用户说“明天提醒我交房租”能生成待办或日程
- 用户说“下周一下午两点我要开会”能生成日程
- prompt 中能带入未完成待办和近期日程摘要

## 10. 完成标准

- 待办与日程数据结构落地
- 对应工具可调用
- 摘要装载逻辑可接入对话编排模块
- 类目映射与新增确认可跑通

## 11. 注意事项

- 待办和日程的产品边界要在实现前再确认一次
- `todo` 更偏“要做的事”，`schedule` 更偏“带时间点的安排”
- 不要一开始就做太复杂的重复日程规则
