# 008 长期记忆与轻量RAG落地

## 1. 任务目标

建立 Cornie 的长期记忆机制，并在 MVP 阶段以“结构化记忆 + 关键词/标签检索”的轻量 RAG 方式落地。

本任务完成后：

- 长期记忆不再是一份大文档
- 长期记忆可写入、修改、删除、查询
- 每轮对话只注入相关记忆摘要
- 具备活跃、低频、归档三层机制

## 5. 数据结构设计

### 5.1 长期记忆表

```sql
CREATE TABLE IF NOT EXISTS memory_entries (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,             -- preference | dislike | goal | event | person | project
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  tags_json TEXT,
  source_text TEXT,
  weight REAL DEFAULT 1.0,
  is_active INTEGER NOT NULL DEFAULT 1,
  last_used_at INTEGER,
  archived_at INTEGER,
  superseded_by TEXT,
  summary_group TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

## 7. 检索策略

### 7.1 MVP 检索

先做：

- 关键词匹配
- 标签匹配
- 权重排序
- 最近使用时间排序

### 7.2 检索输出

返回最相关的 3-5 条记忆摘要，而不是整库原文。

## 8. 记忆分层

| 层级 | 说明 |
| --- | --- |
| 活跃记忆 | 高相关、高频、默认优先注入 |
| 低频记忆 | 默认不直接注入，相关时命中 |
| 归档记忆 | 默认不进 prompt，只在特定检索时使用 |

## 9. 写入规则

应写入：

- 稳定偏好
- 稳定厌恶
- 长期目标
- 重大事件

不应轻易写入：

- 一次性情绪
- 低价值闲聊
- 含糊表达

长期记忆写入默认属于高风险动作，应受 Tool Policy Layer 控制。

## 11. 测试点

### 11.1 单元测试建议

- 稳定偏好可写入记忆
- 低价值闲聊不会误写入
- 关键词检索能命中相关记忆
- 摘要函数能生成稳定输出

### 11.2 联调测试

- 用户表达“我不喜欢太甜的咖啡”后，系统可申请写入记忆
- 后续对话提到咖啡时，可命中相关记忆摘要
- 不会把全部历史记忆直接塞进 prompt

## 12. 完成标准

- 长期记忆具备结构化存储
- 轻量检索可用
- 摘要注入可接入对话编排链路
- 三层记忆机制已具备基础字段和业务逻辑

## 13. 注意事项

- MVP 不必引入向量库
- 先做轻量 RAG，不要一开始搞复杂 embedding 基础设施
- 记忆压缩和归档可以先做基础规则，后续再增强
