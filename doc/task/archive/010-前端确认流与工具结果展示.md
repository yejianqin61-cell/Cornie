# 010 前端确认流与工具结果展示

## 1. 任务目标

让用户在前端清楚感知 AI 做了什么、准备做什么，以及哪些操作需要自己确认。

本任务完成后，前端至少要能正确展示：

- 普通回复
- 工具执行成功
- 工具执行失败
- 待确认操作
- 待追问操作

## 5. 状态设计

### 5.1 前端状态类型

- `reply`
- `tool_success`
- `tool_error`
- `confirm`
- `ask_back`

### 5.2 工具结果显示规则

| 状态 | 前端表现 |
| --- | --- |
| 回复 | 正常气泡显示 |
| 工具成功 | 显示轻提示或结果卡片 |
| 工具失败 | 显示错误提示和可重试信息 |
| 待确认 | 显示确认卡片，提供同意/拒绝 |
| 待追问 | 显示追问题，继续对话即可 |

## 6. 交互设计

### 6.1 新增类目确认卡片

应展示：

- 类目名称
- 触发来源
- 为什么要新增
- 同意 / 拒绝按钮

### 6.2 长期记忆确认卡片

应展示：

- 记忆标题
- 记忆内容
- 触发原因
- 同意 / 拒绝按钮

### 6.3 工具执行结果面板

建议展示：

- 工具名称
- 执行结果
- 成功/失败状态
- 关联来源文本

## 8. 测试点

### 8.1 单元测试建议

- 不同状态能渲染不同 UI
- 确认按钮可触发回调
- 追问状态可继续发送文本

### 8.2 联调测试

- 自动记账成功时能看到明确提示
- 新增类目时能看到确认卡片
- 写长期记忆时能看到确认卡片
- 高风险操作不会直接静默执行

## 9. 完成标准

- 用户能看懂 AI 的动作状态
- 高风险操作可明确同意或拒绝
- 交互不破坏主要聊天体验

## 10. 注意事项

- 过多弹窗会破坏陪伴感
- 展示信息不要做成后台管理系统风格
