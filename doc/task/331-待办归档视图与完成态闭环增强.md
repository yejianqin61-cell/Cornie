# 331-待办归档视图与完成态闭环增强

## 1. 任务目标

将待办从“能勾选完成”升级为“有主列表、有归档、有恢复”的完整闭环，使主待办区始终聚焦当前未完成事项。

## 2. 对应来源

- GitHub Issue `#4` 待办
- 设计文档：`doc/design/Cornie-0629-GitHub-Issue-001-005前端体验增强落地设计.md`

## 3. 背景与现状

当前待办页支持新增、完成、恢复、删除，但完成后的事项仍与未完成事项混在一起，只是变灰展示。  
这会带来：

1. 主列表不够清爽。
2. 已完成事项持续占据视觉注意力。
3. 缺少“归档回顾”和“恢复误操作”的空间。

## 4. 涉及范围

- `src/renderer/components/TodoHome.vue`
- `src/renderer/components/TodoWorkspace.vue`
- `src/renderer/api.js`

## 5. 前置依赖

1. Todo 接口已支持完成、重开、删除。
2. 列表接口至少能拿到 `status` 字段。

## 6. 开发项

### 6.1 重构页面信息结构

待办首页改为两层视图：

1. 当前待办
2. 已归档

推荐优先做页签式切换，而不是新开复杂路由。

### 6.2 调整主列表显示规则

1. 默认主列表只显示未完成待办。
2. 用户勾选完成后，该条目从主列表即时移除。
3. 已完成条目进入归档列表。

### 6.3 新增归档视图

归档视图至少支持：

1. 查看已完成条目
2. 恢复为未完成
3. 彻底删除

若数据结构中已有完成时间，可考虑展示；若当前没有，不强制本期新增后端字段。

### 6.4 摘要区改造

摘要卡至少展示：

1. 当前待办数量
2. 已归档数量

避免继续只展示一个简单数字。

### 6.5 空态与提示

为两种场景补空态：

1. 当前待办为空
2. 已归档为空

文案应偏温和鼓励，不使用治理或系统化表达。

## 7. 实现建议

### 7.1 数据处理

在前端根据 `status` 分组：

1. `done` 放入归档
2. 其余有效待办放入当前列表
3. `cancelled` 暂不作为普通主视图重点展示

### 7.2 交互建议

推荐顶部提供：

1. `待办`
2. `已归档`

两个切换入口。  
若担心信息密度，可在归档页签上附带数量角标。

### 7.3 保持轻量

本任务不做：

1. 批量归档
2. 拖拽排序
3. 多级过滤面板

## 8. 验收标准

1. 勾选完成后，条目会从主待办区移除。
2. 用户可在归档区看到已完成待办。
3. 归档区支持恢复与删除。
4. 主待办列表长期保持聚焦未完成事项。

## 9. 自测清单

1. 新建 3 条待办，确认都进入主列表。
2. 勾选其中 1 条，确认主列表减少、归档数量增加。
3. 在归档区恢复该条，确认重新回到主列表。
4. 在归档区删除该条，确认彻底消失。
5. 当前待办为空、归档为空时，确认空态文案正确。
