# 295-8.2-观察日志跨模块弱提示与本地恢复提示并存时的合并摘要增强

## 1. 任务目标

在 `240`、`283`、`287`、`291` 已补齐观察日志跨模块返回、工作现场恢复、互斥规则和跨天降级基础上，继续细化“跨模块带回来的弱提示”与“本地恢复提示”同时存在时的合并摘要、优先级与退场，避免观察日志页顶部堆满多条轻提示。

## 2. 背景与现状

观察日志工作台现在会承接两类上层语义：

1. 外部模块带回来的来源回跳、联动处理提示
2. 本地恢复现场提示，例如继续昨天整理、恢复草稿、恢复工作篮

当两类提示同时存在时，容易出现：

1. 顶部状态栏、来源面包屑、恢复提示卡各说各话
2. 用户不知道现在主要该先看外部来源，还是先续本地工作现场
3. 多条轻提示都不严重，但叠起来会非常嘈杂

## 3. 涉及范围

- 观察日志工作台顶部提示区
- 跨模块弱提示、本地恢复提示、来源面包屑
- 合并摘要、次级入口与退场逻辑
- 对应前端测试

## 4. 前置依赖

1. `240-8.2-观察日志跨模块返回来源面包屑与状态栏增强.md` 已完成或至少已有跨模块提示
2. `283-8.2-观察日志筛选条件持久化与按日工作上下文恢复增强.md` 已完成或至少已有本地恢复提示
3. `291-8.2-观察日志恢复现场跨天失效后的降级恢复与轻提示增强.md` 已完成或至少已有跨天恢复降级

## 5. 具体开发项

### 5.1 主语义判定

1. 明确当前应优先表达“从哪儿回来”还是“要恢复哪个现场”
2. 当外部来源只提供背景信息时，优先展示本地工作现场恢复
3. 当用户刚从外部模块明确跳回某条观察日志时，来源说明优先

### 5.2 合并摘要

1. 为弱提示并存场景设计一条合并摘要，概括当前上下文
2. 次级信息收进轻量入口或次级说明，不再分散占位
3. 合并摘要文案要能被人快速读懂，不写成系统日志

### 5.3 次级入口保留

1. 未成为主语义的另一类提示仍保留可访问入口
2. 次级入口不与主操作按钮重复
3. 用户进入主流程后，次级入口可进一步降级

### 5.4 退场规则

1. 用户开始编辑或批量整理后，非关键弱提示自动退场
2. 用户切换日期或条目后，旧来源提示与旧恢复提示都应重新评估
3. 与跨天降级、本地互斥恢复态规则兼容

### 5.5 测试补齐

1. 覆盖外部来源提示与本地恢复提示并存时的主语义判定
2. 覆盖合并摘要与次级入口保留
3. 覆盖用户进入实际整理流程后的提示退场
4. 覆盖切换日期或条目后的重新评估

## 6. 验收标准

1. 观察日志工作台顶部提示区在复杂场景下依然清爽可读
2. 用户能知道当前最主要的工作语义是什么
3. 次级提示没有消失，但也不会喧宾夺主
4. 对应前端测试通过
