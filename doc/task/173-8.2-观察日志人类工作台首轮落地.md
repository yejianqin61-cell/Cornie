# 173-8.2-观察日志人类工作台首轮落地

## 1. 任务目标

为观察日志补齐正式的人类前端入口，让用户可以像查看 Memory Wiki、聊天记录一样，直接查看和管理观察日志，而不是只让它停留在后端服务和模型上下文里。

## 2. 背景与现状

当前系统已经有：

1. 观察日志存储
2. 观察日志增删改查服务
3. 观察日志与 Topic Index / Memory Wiki 的联动
4. 对话编排中的观察日志摘要装载

但前端当前还没有正式工作台来承接这些能力，导致：

1. 人类看不到当天或历史观察日志
2. 人类无法手动补记、修正、删除观察日志
3. 观察日志与 Cornie 日记、聊天记录、长期记忆的边界缺少前端可见性

## 3. 涉及范围

- `src/renderer/App.vue`
- 新增观察日志工作台组件
- `src/renderer/api.js`
- 如有必要，补充后端人类路由
- 对应前端测试

## 4. 具体开发项

### 4.1 工作台入口接入

1. 在主工作台导航中新增“观察日志”入口
2. 保持与现有日记、收支、待办、日程、Memory Wiki 的壳层风格一致

### 4.2 观察日志列表与详情

1. 支持按日期查看观察日志
2. 支持查看单条观察日志的标题、类型、正文、来源文本、创建时间
3. 支持空态、加载中、加载失败提示

### 4.3 观察日志人类编辑能力

1. 支持新增观察日志
2. 支持编辑观察日志
3. 支持删除观察日志
4. 明确区分“观察日志”与“Cornie 日记”的用途差异

### 4.4 前端边界说明

1. 在界面上给出解释文案，说明观察日志是事实性记录，不等同于文学化日记
2. 让用户理解观察日志会成为 Cornie 日记和长期记忆的素材来源之一

### 4.5 测试补齐

1. 覆盖列表加载与空态
2. 覆盖新增、编辑、删除流程
3. 覆盖入口接线与基础渲染

## 5. 验收标准

1. 用户拥有正式的观察日志工作台入口
2. 观察日志支持基础 CRUD
3. 前端明确区分观察日志与日记边界
4. 对应前端测试通过
