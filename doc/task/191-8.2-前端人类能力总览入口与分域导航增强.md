# 191-8.2-前端人类能力总览入口与分域导航增强

## 1. 任务目标

在现有应用壳层与多个工作台入口基础上，补齐一个面向人类用户的“能力总览 + 分域导航”层，让用户能快速知道自己当前可以直接管理哪些内容，并顺畅进入：

1. 账本
2. 待办
3. 日程
4. 聊天记录
5. 观察日志
6. Memory Wiki / Topic Index

## 2. 背景与现状

当前前端已经逐步具备多个工作台，但仍存在问题：

1. 能力入口分散，用户需要靠记忆知道去哪里做什么
2. “模型能做的事”和“人类能直接管的事”之间缺少一个总览层
3. 随着工作台变多，主导航的信息架构会变得越来越重
4. 前端“人类接口全覆盖”的成果还没有被统一表达出来

## 3. 涉及范围

- `src/renderer/App.vue`
- 应用主壳层导航结构
- 如有必要，新增能力总览页或首页总览面板
- 对应前端测试

## 5. 具体开发项

### 5.1 能力总览入口

1. 在主壳层提供统一“总览”入口
2. 总览页按业务域展示当前可管理能力
3. 每个域至少有一句平实说明，告诉用户这里是干什么的

### 5.2 分域导航增强

1. 导航按账本、待办、日程、聊天、观察、记忆等域清晰分组
2. 当前未完成或待处理数量可在合适处轻量展示
3. 避免把导航做成拥挤的功能墙

### 5.3 人类接口与模型能力对齐表达

1. 在总览层表达“这些是你可以自己查看和管理的内容”
2. 不需要暴露 tool 概念，但要让用户感知系统能力边界
3. 对尚未完全落地的域，可明确标注“建设中”或“即将补齐”

### 5.4 跨域快速入口

1. 支持从总览页直接跳到常用工作台
2. 支持从总览页进入当天聊天记录、观察日志、Memory Wiki 待审核区等高频入口
3. 若某域当前为空，给出友好的空态引导

### 5.5 测试补齐

1. 覆盖总览入口渲染
2. 覆盖分域导航结构
3. 覆盖高频快捷入口跳转
4. 覆盖空态与建设中状态

## 6. 验收标准

1. 用户能够从前端快速理解当前系统有哪些可直接管理的域
2. 用户能够从统一入口进入各业务工作台
3. 导航结构清晰，不因工作台增多而失控
4. “前端人类接口全覆盖”的阶段成果具备统一展示层
5. 对应前端测试通过
