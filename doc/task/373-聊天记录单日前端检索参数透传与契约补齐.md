# 373-聊天记录单日前端检索参数透传与契约补齐

## 1. 任务目标

根据 `Cornie-0630-聊天记录存储与历史归档改造方案.md` 中“单日消息视图必须分页化”“支持关键词检索”的要求，补齐前端 `chatlog` API 对单日详情检索参数的透传契约，确保历史聊天页中的单日关键词过滤真正生效。

## 2. 任务来源

- `doc/design/Cornie-0630-聊天记录存储与历史归档改造方案.md`

## 3. 涉及范围

- `src/renderer/api.js`
- `scripts/`

## 4. 当前问题

当前后端 `GET /chatlogs/:date` 已支持：

- `q`
- `beforeId`
- `mode`
- `limit`
- `cursor`

但前端 `getChatlog()` 仅透传了：

- `limit`
- `cursor`

这会导致：

- 历史聊天页虽然传入了 `query`
- 但请求 URL 中没有带上 `q`
- 单日消息区看起来支持关键词过滤，实际上没有真正命中后端检索能力

## 5. 目标设计

- 让 `getChatlog()` 支持透传 `query`
- 一并补齐 `beforeId` 与 `mode`，避免后端已存在能力在前端 API 层继续断裂
- 增加最小验证脚本，确保请求 URL 参数构造正确

## 6. 实现步骤

### Step 1

扩展 `src/renderer/api.js` 中 `getChatlog()` 的参数签名。

### Step 2

将 `query -> q`、`beforeId`、`mode` 正式写入请求参数。

### Step 3

补最小验证脚本，校验 URL 中已带出这些参数。

## 7. 测试点

- `query` 会被映射为 `q`
- `beforeId` 会被带入请求
- `mode` 会被带入请求
- 原有 `limit/cursor` 契约不回归
- `npm run build` 通过

## 8. 完成标准

- 单日聊天历史检索参数不再停留在界面层假接线
- 前端 API 与后端单日检索协议保持一致
