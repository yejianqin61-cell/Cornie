# 315-8.2-观察日志重开说明入口在跨条目后按钮文案与动作目标重算增强

## 1. 任务目标

在 `311` 已补齐观察日志来源说明跨条目重开时旧摘要语义清理基础上，继续细化跨条目后重开入口的按钮文案、分支标题和动作目标重算，避免入口语义虽然切了条目，按钮却还残留上一条的指向。

## 2. 背景与现状

来源说明重开入口不只承载摘要，还会带：

1. 查看来源
2. 返回相关模块
3. 查看恢复现场

当用户从 A 条目切到 B 条目再重开时，若按钮和分支标题不跟着重算，会出现：

1. B 条目里还有 A 的按钮描述
2. 用户点击后跳到 A 相关上下文
3. 分支标题和摘要不属于同一条目

## 3. 涉及范围

- 观察日志重开说明入口
- 按钮文案、分支标题与动作目标
- 条目切换后的完整重算
- 对应前端测试

## 4. 前置依赖

1. `311-8.2-观察日志来源说明跨条目重开时的旧摘要语义清理增强.md` 已完成或至少已有跨条目清理
2. `303-8.2-观察日志顶部合并提示退场后用户手动重开来源说明入口增强.md` 已完成或至少已有重开入口
3. `307-8.2-观察日志来源说明重开后再次收起的默认折叠层级增强.md` 已完成或至少已有层级规则

## 5. 具体开发项

### 5.1 跨条目后按钮重算

1. 切到新条目后，重开入口内所有按钮文案按新条目重算
2. 不保留旧条目相关动作描述
3. 若新条目无对应动作，则优雅降级隐藏或替换

### 5.2 分支标题一致性

1. 来源说明、本地恢复说明等分支标题与当前条目摘要保持一致
2. 不让标题、摘要、按钮分别来自不同条目
3. 与弱数据态标题分支兼容

### 5.3 动作目标绑定

1. 每个入口动作只绑定当前条目的上下文
2. 不因缓存或旧展开态而指回上一条
3. 与跨日期条目切换兼容

### 5.4 测试补齐

1. 覆盖跨条目后按钮文案刷新
2. 覆盖动作目标不串条目
3. 覆盖弱数据态下的按钮降级
4. 覆盖跨日期条目切换后的完整重算

## 6. 验收标准

1. 观察日志重开说明入口的按钮与标题都只属于当前条目
2. 用户不会因旧按钮残留而跳错上下文
3. 跨条目后说明区语义整体一致
4. 对应前端测试通过
