# 313-8.3-Memory-Wiki来源区跨来源类型切换时的旧新轮次语义隔离增强

## 1. 任务目标

在 `305`、`309` 已补齐来源区新轮次判定和旧正文提示清理基础上，继续细化用户在来源区内从一种来源类型切到另一种来源类型时，旧轮次语义如何隔离，避免“聊天记录来源阅读”和“观察日志来源阅读”这类不同来源类型之间互相串味。

## 2. 背景与现状

Memory Wiki 来源区可能包含多种来源类型，例如：

1. 聊天记录来源
2. 观察日志来源
3. 其他记忆来源

当用户在这些来源类型之间切换时，如果轮次隔离不明确，会出现：

1. 旧来源类型的提示语义带到新类型
2. 新来源类型沿用旧类型的恢复入口和上下文文案
3. 用户分不清当前到底在读哪一类来源

## 3. 涉及范围

- Memory Wiki 来源阅读区
- 来源类型切换时的新旧轮次语义隔离
- 来源组提示、比较视角和恢复状态的类型边界
- 对应前端测试

## 4. 前置依赖

1. `305-8.3-Memory-Wiki正文接管后再次进入来源区时的新一轮来源恢复判定增强.md` 已完成或至少已有来源新轮次判定
2. `309-8.3-Memory-Wiki来源区新轮次开启后旧正文接管提示的清理时机增强.md` 已完成或至少已有旧提示清理
3. `285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强.md` 已完成或至少已有跨来源切换能力

## 5. 具体开发项

### 5.1 来源类型切换即隔离

1. 当来源类型从 A 切到 B 时，A 的主阅读语义应立即失活
2. B 作为新类型应重新计算提示和恢复上下文
3. 不得沿用 A 的来源类型标签、按钮文案或过渡说明

### 5.2 类型内与类型间轮次区分

1. 同一来源类型内的切换可沿用更细的组内逻辑
2. 跨来源类型切换时，应优先视为更强的新轮次
3. 比较视角和弱数据态也要按当前类型重算

### 5.3 视觉与认知边界

1. 用户一眼能看懂当前自己在读的是哪类来源
2. 不让不同来源类型的提示并列竞争
3. 与正文阅读提示、来源恢复提示和滚动恢复兼容

### 5.4 反复切换稳定性

1. 在来源类型 A/B 之间来回切换时，当前类型始终唯一明确
2. 旧类型的说明不应残留到新类型
3. 页面布局和滚动不因反复切换而抖动

### 5.5 测试补齐

1. 覆盖跨来源类型切换后的旧语义失活
2. 覆盖新类型按自身规则重算提示
3. 覆盖来回切换时的唯一当前类型判定
4. 覆盖与比较视角、弱数据态并存时的结果

## 6. 验收标准

1. Memory Wiki 不同来源类型之间的阅读语义边界清楚
2. 新来源类型不会继承旧来源类型的残留提示
3. 用户持续知道自己当前在看哪类来源
4. 对应前端测试通过
