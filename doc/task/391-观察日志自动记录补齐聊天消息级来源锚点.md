# 391-观察日志自动记录补齐聊天消息级来源锚点

## 1. 任务目标

根据 `Cornie-0630-记忆层改进治理总纲-第一版.md` 第 11.4 节与 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 第 13 节，观察日志应作为“可回溯事实层档案”长期保留，并能支撑后续来源反查。

本任务要补齐的缺口是：

- 当前自动记录对话观察日志时，`relatedRef` 仅写入当天 `date`
- 这样只能回到“哪一天”，无法精确回到“哪一条聊天消息”
- 后续人物页 / Topic Index / 治理审核在查看观察日志来源时，证据粒度仍然偏粗

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 4. 当前问题

当前自动观察日志记录逻辑：

- 会在每轮对话后按需写一条 observation
- 会保存 `sourceText`
- 但 `relatedRef` 只写 `date`

这会导致：

- 同一天多轮对话无法精确锚定
- 观察日志到聊天原文的反查粒度不足
- 后续人物 / 主题 / 治理在引用 observation 时，来源透明度不够

## 5. 目标设计

- 自动记录观察日志时，优先把 `relatedRef` 写成 `date#messageId`
- 若缺少 `messageId`，仍兼容降级为 `date`
- 保持现有 observation 去重 / 增量合并规则不回退
- 不改 observation 的外层数据模型，只补强来源锚点语义

## 6. 实现步骤

### Step 1

调整 `recordConversationTurn()` 入参，支持传入当前用户消息 `messageId`。

### Step 2

调整自动 observation 构造逻辑：

- 有 `messageId` 时写 `relatedRef = ${date}#${messageId}`
- 无 `messageId` 时继续写 `date`

### Step 3

补专项验证脚本，证明：

- 自动 observation 能写出消息级锚点
- 缺少 `messageId` 时仍能安全回退到日期级锚点
- 不影响原有 observation 自动写入能力

## 7. 测试点

- `recordConversationTurn()` 产出的 observation 带有 `date#messageId`
- 回退场景下仍能产出合法 `date`
- `npm run build` 通过

## 8. 完成标准

- 自动 observation 正式具备消息级来源锚点
- 观察日志“事实层档案”的可追溯性与 0630 设计稿对齐
