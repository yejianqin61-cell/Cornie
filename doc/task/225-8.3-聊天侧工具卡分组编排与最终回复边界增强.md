# 225-8.3-聊天侧工具卡分组编排与最终回复边界增强

## 1. 任务目标

在 `189`、`212`、`216`、`220` 已补齐工具过程态、步骤回放、确认后恢复和展开密度控制的基础上，继续细化聊天区内“工具执行过程”和“最终自然语言回复”的边界与编排方式，避免复杂轮次中信息顺序混乱。

## 2. 背景与现状

当单轮对话涉及多个工具、确认卡、恢复执行和最终回复时，聊天区容易出现：

1. 工具卡和最终回复混在一起，用户不清楚哪里是过程，哪里是结论
2. 多个工具结果并列时，阅读顺序不稳定
3. 工具成功了，但最终答复没有很好承接过程结果

## 3. 涉及范围

- 聊天区工具卡与结果卡
- 最终回复渲染层
- 聊天轮次时间线编排
- 对应前端测试

## 4. 前置依赖

1. `189-8.3-聊天侧工具过程态与结果态反馈分层增强.md` 已完成或至少已有过程态与结果态分层
2. `212-8.3-聊天侧多工具步骤回放卡与摘要链路增强.md` 已完成或至少已有步骤回放结构
3. `216-8.3-聊天侧确认后恢复执行结果回显增强.md` 已完成或至少已有确认后回显
4. `220-8.3-聊天侧工具卡展开收起记忆与默认密度增强.md` 已完成或至少已有工具卡密度控制

## 5. 具体开发项

### 5.1 过程与结论分区

1. 明确区分“本轮工具执行过程”与“铃湾最后对你说的话”
2. 在同一轮次内把工具步骤放进统一过程容器或清晰分组
3. 最终回复应在视觉上形成收束，而不是继续堆叠在工具流里

### 5.2 多工具结果编排

1. 让多个工具卡按执行顺序稳定展示
2. 对同类工具结果做轻量分组，避免页面过碎
3. 在有确认中断的轮次里，明确前后两段执行链的边界

### 5.3 最终回复承接

1. 最终回复前显示轻量“本轮已完成事项”摘要
2. 让用户能从过程卡快速理解铃湾最后回复为什么这样说
3. 不把自然语言答复写成重复工具日志

### 5.4 密集轮次可读性

1. 在长轮次里控制过程区高度和默认展开策略
2. 保留查看细节的能力，但不让过程卡压过主对话
3. 保持成功、失败、待确认三类状态下的编排一致性

### 5.5 测试补齐

1. 覆盖多工具顺序渲染
2. 覆盖确认前后两段执行链分组
3. 覆盖最终回复与过程区的边界展示
4. 覆盖密集轮次下的收束布局

## 6. 验收标准

1. 聊天区能清楚看出“发生了什么”与“最后说了什么”
2. 多工具轮次阅读顺序稳定
3. 最终回复与工具结果之间的承接更自然
4. 对应前端测试通过
