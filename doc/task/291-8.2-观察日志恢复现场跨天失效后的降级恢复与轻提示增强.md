# 291-8.2-观察日志恢复现场跨天失效后的降级恢复与轻提示增强

## 1. 任务目标

在 `283`、`287` 已补齐观察日志工作现场恢复与恢复态互斥规则基础上，继续细化用户隔天返回工作台时，原恢复现场已跨天失效或上下文价值明显下降时的降级恢复、轻提示与默认落点，避免系统死守昨天的工作现场。

## 2. 背景与现状

观察日志工作台具有明显的按日整理属性。用户今天处理中断，明天再回来时，旧恢复状态可能出现：

1. 原工作日已经不是当前最需要整理的日期
2. 原条目仍存在，但“昨天的批处理现场”价值已下降
3. 原草稿仍在，但今天更适合先看当前日期整体情况

如果缺少跨天规则，会出现：

1. 系统一进来就恢复到昨天深处的条目
2. 用户不理解为什么今天一打开还停在昨天
3. 恢复态与“今天待整理素材”之间缺少平衡

## 3. 涉及范围

- 观察日志工作台按日入口
- 工作篮恢复态、草稿恢复态的跨天有效性判断
- 轻提示、恢复入口与默认落点
- 对应前端测试

## 4. 前置依赖

1. `283-8.2-观察日志筛选条件持久化与按日工作上下文恢复增强.md` 已完成或至少已有上下文恢复
2. `287-8.2-观察日志工作篮恢复态与编辑草稿恢复态的互斥规则增强.md` 已完成或至少已有恢复态优先级
3. `229-8.2-观察日志按日工作篮与整理进度提示增强.md` 已完成或至少已有按日工作篮能力

## 5. 具体开发项

### 5.1 跨天有效性判断

1. 判断恢复现场是否仍属于高价值续做场景
2. 区分“仍应优先续做的未完成现场”与“可退为次级入口的昨日现场”
3. 草稿未保存风险高时，可保留更高优先级

### 5.2 默认落点降级

1. 若昨日现场价值下降，默认先回到今天的按日列表或工作总览
2. 将昨日现场保留为轻量“继续昨天整理”入口
3. 若昨天现场已完全失效，则不再展示强恢复入口

### 5.3 用户提示

1. 用平实文案说明“今天先带你看今天的整理区，昨天的现场还在旁边”
2. 不把跨天降级写成错误或异常
3. 让用户能快速理解系统为什么没直接跳回旧现场

### 5.4 与互斥恢复态兼容

1. 跨天降级后，工作篮态与草稿态仍需保持互斥
2. 若昨日草稿仍高风险，优先级可覆盖“今日总览默认”
3. 与筛选持久化、跨模块回流状态保持一致

### 5.5 测试补齐

1. 覆盖隔天返回且昨日现场降级为次级入口
2. 覆盖昨日草稿仍高优先时的优先恢复
3. 覆盖昨日现场完全失效后的默认今日落点
4. 覆盖跨天降级提示与用户手动切回昨日现场

## 6. 验收标准

1. 观察日志工作台跨天进入时更符合人类直觉
2. 系统既不粗暴丢失昨日现场，也不死守昨日深层上下文
3. 跨天降级逻辑与恢复态优先级规则保持一致
4. 对应前端测试通过
