# 223-8.3-Topic详情区块折叠与阅读密度增强

## 1. 任务目标

在 `178`、`186`、`206`、`214` 已经补齐 Topic 详情主要信息结构的基础上，继续增强 Topic 详情页的区块折叠和阅读密度控制，让主题治理页既适合快速扫读，也适合深度追溯。

## 2. 背景与现状

随着主题详情里逐渐加入热度、最近活跃、时间轴、关联页面、别名、治理入口等信息，页面开始承担更多治理任务，但目前仍缺：

1. 长详情页的信息折叠能力
2. 扫读模式与深读模式之间的切换
3. 对不同数据充实程度的布局弹性

## 3. 涉及范围

- Topic 详情页
- Topic 详情区块头部交互
- 对应前端测试

## 4. 前置依赖

1. `178-8.3-Topic-Index详情与主题治理工作台增强.md` 已完成或至少已有 Topic 详情页
2. `186-8.3-Topic-Index日期联动与主题时间轴阅读增强.md` 已完成或至少已有时间轴区
3. `206-8.3-Topic热度与最近活跃可读化增强.md` 已完成或至少已有热度表达
4. `214-8.3-Topic详情弱数据态与空态表达增强.md` 已完成或至少已有弱数据态表达

## 5. 具体开发项

### 5.1 区块折叠

1. 支持对热度摘要、时间轴、关联页面、别名与治理信息分区折叠
2. 折叠后保留轻量摘要，避免页面只剩标题
3. 对弱数据区块默认采用更克制的展示方式

### 5.2 密度切换

1. 提供更适合快速扫描的紧凑视图
2. 提供更适合治理核对的展开视图
3. 让主题详情在“很多数据”和“很少数据”两类场景下都不显得笨重

### 5.3 焦点阅读

1. 从 Topic 列表、主题合并入口、错误关联修正入口跳入时，优先聚焦当前操作相关区块
2. 当用户的目标是治理而非阅读时，优先突出治理信息和关联证据
3. 当用户的目标是回顾主题历史时，优先突出时间轴与最近活跃

### 5.4 状态记忆

1. 记住当前 Topic 详情最近一次密度选择
2. 在合理范围内记住区块折叠状态
3. 保证不同 Topic 之间状态恢复策略清晰，不互相污染

### 5.5 测试补齐

1. 覆盖 Topic 详情区块折叠
2. 覆盖密度模式切换
3. 覆盖从不同入口进入详情时的焦点区展示
4. 覆盖状态记忆和隔离逻辑

## 6. 验收标准

1. Topic 详情页适合长时间治理与阅读
2. 弱数据态和强数据态都能得到合适表达
3. 用户进入详情后能更快聚焦当前任务
4. 对应前端测试通过
