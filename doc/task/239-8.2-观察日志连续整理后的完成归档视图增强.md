# 239-8.2-观察日志连续整理后的完成归档视图增强

## 1. 任务目标

在 `235` 已补齐观察日志连续整理小控制台的基础上，继续为“当天条目都补得差不多了”的场景提供完成归档视图和收尾提示，让用户知道今天的素材整理已经进入可收口状态。

## 2. 背景与现状

连续整理体验补齐后，下一步问题是“整理完以后页面该怎么收口”。如果没有专门设计，会出现：

1. 用户补完整天条目后，页面仍停留在高紧张度的待处理模式
2. 已完成与仍待处理的状态边界不明显
3. 无法给用户一个平稳的“今天差不多整理好了”反馈

## 3. 涉及范围

- 观察日志当日工作篮
- 连续整理控制台完成态
- 已完成条目归档或折叠视图
- 对应前端测试

## 4. 前置依赖

1. `235-8.2-观察日志批量补全小控制台与连续处理增强.md` 已完成或至少已有连续整理控制台
2. `229-8.2-观察日志按日工作篮与整理进度提示增强.md` 已完成或至少已有当日工作篮
3. `236-8.2-观察日志联动入口已处理态与消退规则增强.md` 已完成或至少已有联动状态治理基础

## 5. 具体开发项

### 5.1 完成态收口

1. 当当日结构性缺口基本清零时，显示轻量完成态摘要
2. 完成态要强调“今日素材已较完整”，而不是假装所有事情都结束了
3. 为后续去生成 Cornie 日记或继续看长期记忆联动保留入口

### 5.2 已完成条目归档视图

1. 已补完条目可折叠进“今日已整理”区域
2. 默认减少已完成条目的视觉权重，避免压过剩余待处理项
3. 用户仍可展开查看已完成条目，不做强隐藏

### 5.3 收尾动作建议

1. 在合适时机提示可前往 Cornie 日记生成链路
2. 若还有少量联动未完成，仅作轻量提醒，不打断完成感
3. 让用户知道“素材层收口”和“表达层生成”不是一回事

### 5.4 状态恢复

1. 当新的未补完条目出现时，完成态可自动退出
2. 已归档视图在切换日期后正确隔离
3. 返回当天页面时，在合理范围内恢复已完成区折叠状态

### 5.5 测试补齐

1. 覆盖当日缺口清零后的完成态
2. 覆盖已完成条目归档与展开
3. 覆盖有新增未补完条目时退出完成态
4. 覆盖切换日期后的状态隔离

## 6. 验收标准

1. 连续整理后的页面有自然的完成收口
2. 已完成条目不会继续压迫主工作流
3. 完成态与后续日记、记忆联动关系表达清楚
4. 对应前端测试通过
