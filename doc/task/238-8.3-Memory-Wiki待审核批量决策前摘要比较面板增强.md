# 238-8.3-Memory-Wiki待审核批量决策前摘要比较面板增强

## 1. 任务目标

在 `231` 已补齐待审核池排序和批量浏览基础上，继续增加批量决策前的摘要比较面板，让用户在进入逐条审核前，先对一组候选做轻量比对和优先级判断。

## 2. 背景与现状

待审核池一旦支持批量浏览，下一步问题就是“先处理哪一组、为什么”。如果完全依赖逐条打开详情，会带来：

1. 批量处理前缺少总览视角
2. 相似候选之间难以快速比较
3. 用户必须深入详情后才发现这批其实可以后放

## 3. 涉及范围

- Memory Wiki 待审核池列表上方摘要比较区
- 候选分组的轻量对比信息
- 进入详情前的优先级判断辅助
- 对应前端测试

## 4. 前置依赖

1. `231-8.3-Memory-Wiki待审核池排序模式与批量浏览增强.md` 已完成或至少已有排序与批量浏览
2. `182-8.3-治理候选分区与批量处置工作台增强.md` 已完成或至少已有候选分区
3. `200-8.3-Memory-Wiki高频治理快捷入口与状态概览增强.md` 已完成或至少已有概览信息

## 5. 具体开发项

### 5.1 分组摘要比较

1. 对候选分组展示数量、风险、涉及页面数、最近变动时间等摘要
2. 支持在进入详情前先比较两组或多组候选的大致差异
3. 比较区保持轻量，不替代正式审核细节

### 5.2 决策前优先级辅助

1. 提示哪些候选更适合先看
2. 提示哪些候选属于可稍后统一处理的低紧急项
3. 仅提供辅助排序，不替用户下最终结论

### 5.3 批量入口联动

1. 从比较面板可直接进入对应候选分组
2. 返回列表后保持用户原来的比较上下文
3. 与 `231` 的排序模式和浏览密度保持协同

### 5.4 视觉收口

1. 比较面板不应压过候选主列表
2. 在候选很少时可自动简化展示
3. 在候选很多时保持摘要信息可扫描

### 5.5 测试补齐

1. 覆盖有多组候选时的比较面板渲染
2. 覆盖候选很少时的简化态
3. 覆盖从比较面板进入候选分组
4. 覆盖返回列表后的上下文恢复

## 6. 验收标准

1. 用户在批量审核前能先做轻量排优先级
2. 比较面板提升治理效率，而不是增加阅读负担
3. 与现有待审核池排序和浏览逻辑保持一致
4. 对应前端测试通过
