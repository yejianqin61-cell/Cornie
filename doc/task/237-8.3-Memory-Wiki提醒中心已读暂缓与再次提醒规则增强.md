# 237-8.3-Memory-Wiki提醒中心已读暂缓与再次提醒规则增强

## 1. 任务目标

在 `232` 已建立巡检提醒中心与待审核入口统一收口的基础上，继续细化提醒项的已读、暂缓处理和再次提醒规则，避免提醒中心要么永远不消失，要么过早沉默。

## 2. 背景与现状

统一提醒中心建立后，真正的可用性取决于状态治理。若没有进一步规则，会出现：

1. 用户看过但暂时不处理的项，无法做轻量标记
2. 已读项持续高亮，形成提醒疲劳
3. 提醒一旦消失，后续又很难重新感知重要事项

## 3. 涉及范围

- Memory Wiki 提醒中心
- 提醒项已读 / 暂缓 / 重新提醒状态
- 状态持久化与展示降级
- 对应前端测试

## 4. 前置依赖

1. `232-8.3-巡检提醒中心与待审核入口统一收口增强.md` 已完成或至少已有提醒中心
2. `181-8.2-Memory-Wiki待审核角标与异步提醒增强.md` 已完成或至少已有提醒基础
3. `231-8.3-Memory-Wiki待审核池排序模式与批量浏览增强.md` 已完成或至少已有待审核池增强基础

## 5. 具体开发项

### 5.1 已读与暂缓

1. 支持把提醒项标记为已读
2. 支持对暂时不想处理的项做“稍后再看”标记
3. 已读和暂缓应有清晰区别，不能混成一种状态

### 5.2 再次提醒规则

1. 对暂缓项在后续合适时机重新提醒
2. 对已读但未处理且持续存在的问题，可降级后再次浮现
3. 对已处理完成的问题不再重复打扰

### 5.3 展示层级降级

1. 已读项从主提醒区降到次级区域
2. 暂缓项保留存在感，但不继续强高亮
3. 提醒中心在大量历史项存在时仍保持清爽

### 5.4 风险边界

1. 高风险项即使已读，也不能完全沉到底部不可见
2. 低风险项应允许更快静默
3. 再次提醒策略要与风险等级和最新变化联动

### 5.5 测试补齐

1. 覆盖已读状态流转
2. 覆盖暂缓后再次提醒
3. 覆盖高风险与低风险项的不同降级规则
4. 覆盖已处理项不再重复提醒

## 6. 验收标准

1. 提醒中心具备可长期使用的状态治理能力
2. 用户可以温和地管理提醒，而不是只能立即处理或忽略
3. 再次提醒规则既不骚扰，也不失联
4. 对应前端测试通过
