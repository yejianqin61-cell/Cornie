# 303-8.2-观察日志顶部合并提示退场后用户手动重开来源说明入口增强

## 1. 任务目标

在 `299` 已补齐观察日志用户进入实际整理流后的顶部合并提示退场基础上，继续细化提示退场后用户手动重开来源说明、恢复摘要或返回入口的机制，确保提示让位后不是“彻底消失”，而是变成可控的按需查看能力。

## 2. 背景与现状

顶部提示退场后，用户通常会进入真实工作流；但在某些时刻，用户仍可能需要再看一眼：

1. 自己是从哪里跳回来的
2. 当前这条观察日志和哪个外部模块有关
3. 刚才系统想让自己续上的本地恢复现场是什么

如果退场后没有重开路径，会出现：

1. 提示一消失就完全找不回
2. 用户被迫中断当前工作去别处找上下文
3. 顶部提示退场反而造成信息断层

## 3. 涉及范围

- 观察日志工作台顶部合并提示
- 退场后的次级入口、手动重开和再次收口逻辑
- 对应前端测试

## 4. 前置依赖

1. `299-8.2-观察日志用户进入实际整理流后的顶部合并提示退场增强.md` 已完成或至少已有退场规则
2. `295-8.2-观察日志跨模块弱提示与本地恢复提示并存时的合并摘要增强.md` 已完成或至少已有合并摘要
3. `240-8.2-观察日志跨模块返回来源面包屑与状态栏增强.md` 已完成或至少已有来源状态入口

## 5. 具体开发项

### 5.1 退场后的手动重开入口

1. 为退场后的合并提示提供稳定、非打断式的重开入口
2. 重开入口应足够轻，不重新占据主工作区
3. 用户一眼能看懂这是“查看刚才的来源/恢复说明”

### 5.2 重开内容范围

1. 重开后优先展示刚才被收起的合并摘要
2. 支持查看来源说明与本地恢复说明的次级分支
3. 不把所有旧提示重新全量弹回顶部

### 5.3 再次收口

1. 用户看完后可再次快速收起
2. 再次收起后仍回到轻量入口状态
3. 不因频繁重开收起造成顶部布局抖动

### 5.4 与实际整理流兼容

1. 手动重开不应打断当前编辑或批处理节奏
2. 当前主工作流状态保持不变
3. 与跨天降级、互斥恢复态和跨模块回流兼容

### 5.5 测试补齐

1. 覆盖提示退场后的轻量重开入口
2. 覆盖重开后只恢复摘要而非全量旧提示
3. 覆盖再次收起后的稳定状态
4. 覆盖与编辑态、批处理态并存时的布局稳定性

## 6. 验收标准

1. 观察日志顶部提示退场后仍具备按需回看的能力
2. 用户不会因提示退场而丢失关键上下文
3. 重开能力轻量、克制，不重新打断主工作流
4. 对应前端测试通过
