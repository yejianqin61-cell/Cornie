# 386 观察日志按主题与人物回查协议补齐

## 目标

补齐观察日志的正式 recall 协议，使模型侧和人类接口都能按“日期 / 主题 / 人物 / 关键词”回查历史观察日志，而不是只依赖一个模糊 `q` 参数。

## 设计依据

- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`
- 第 11 节观察日志生命周期规则
- 其中明确要求：
  - 应通过工具按需检索指定日期、指定主题或指定人物相关观察日志

## 当前缺口

- observation 当前已支持：
  - `list_by_date`
  - `list_by_range`
  - `list_today`
  - 前端 `listObservations({ date, from, to, type, q, limit })`
- 但还没有：
  - 明确面向 recall 的服务入口
  - 明确支持 `topic` / `person` 参数的路由协议
  - 对应的人类 API 与模型工具接口

## 本任务范围

1. 在 observation 服务层增加 `listByRecall`
2. 新增 `/observations/recall` 路由
3. 新增前端 API `recallObservations`
4. 新增模型工具 `observation.recall_history`
5. 保持现有 `listObservations` 与旧接口兼容

## 实现要求

1. recall 查询可支持：
   - `date`
   - `from`
   - `to`
   - `type`
   - `q`
   - `topic`
   - `person`
   - `limit`
2. `topic` / `person` / `q` 可合并为统一查询文本，但协议层必须显式区分字段
3. 观察日志查询匹配范围至少包括：
   - `title`
   - `content`
   - `sourceText`
   - `relatedRef`
4. 不破坏现有今天页、历史页与原有 observation 查询能力

## 验收标准

1. 服务层能按 `topic` 回查命中的观察日志
2. 服务层能按 `person` 回查命中的观察日志
3. `relatedRef` 中的人物或主题标识也可参与命中
4. 工具集存在 `observation.recall_history`
5. 路由 `/observations/recall` 可返回标准结果
6. 前端 API 可正确拼接 recall 参数
7. 验证脚本通过
8. `npm run build` 通过
