# 296-8.3-聊天侧记忆弱提示与工具失败提示并存时的收束顺序增强

## 1. 任务目标

在 `208`、`288`、`292` 已补齐聊天侧工具失败兜底、记忆弱提示多轮退场和新会话日重建基础上，继续细化“记忆弱提示”和“工具失败提示”同轮并存时的收束顺序、视觉层级和退场策略，避免弱提示在失败场景里抢走用户注意力。

## 2. 背景与现状

聊天侧透明提示体系越来越丰富后，同一轮可能同时出现：

1. 工具失败卡或失败兜底说明
2. 记忆引用弱提示
3. 最终回复或恢复建议

虽然前面文档已强调弱提示应让位，但在具体失败轮次里仍需补到更细，否则会出现：

1. 记忆提示出现在失败说明前面，优先级错误
2. 用户最需要看的恢复建议被弱提示切碎
3. 失败轮次结束后，弱提示依旧停留过久

## 3. 涉及范围

- 聊天侧失败提示卡
- 记忆弱提示与最终回复的同轮编排
- 收束顺序、退场与降级逻辑
- 对应前端测试

## 4. 前置依赖

1. `208-8.3-聊天侧工具失败兜底说明卡与恢复建议增强.md` 已完成或至少已有失败兜底
2. `288-8.3-聊天侧记忆引用弱提示在连续多轮中的退场与重现规则增强.md` 已完成或至少已有弱提示抑制规则
3. `292-8.3-聊天侧记忆弱提示在新会话日切换后的清空与重建规则增强.md` 已完成或至少已有日期边界重建规则

## 5. 具体开发项

### 5.1 同轮主次顺序

1. 工具失败说明在失败轮次中始终高于记忆弱提示
2. 若有恢复建议，恢复建议应紧跟失败说明
3. 记忆弱提示只能作为补充背景，不能插断失败主链路

### 5.2 视觉与停留时长降级

1. 失败轮次里的记忆弱提示默认更轻、更短停留
2. 若失败信息较长，可将记忆提示折叠为次级入口
3. 不让失败轮次顶部形成多层竞争提示

### 5.3 最终回复收束

1. 若最终回复主要是致歉或恢复说明，记忆提示不应出现在收束语之前
2. 失败轮次结束后，用户应自然看到“问题是什么、接下来怎么办”
3. 记忆提示若无助于理解失败，可直接不展示

### 5.4 退场与重评估

1. 失败轮次结束后，旧弱提示比普通轮次更快退场
2. 下一轮若问题已恢复，再按常规规则重新评估是否展示记忆提示
3. 与确认卡、工具结果卡、最终回复边界规则兼容

### 5.5 测试补齐

1. 覆盖工具失败提示与记忆弱提示并存时的顺序
2. 覆盖恢复建议插入后的编排
3. 覆盖记忆提示被折叠或不展示的分支
4. 覆盖失败轮次结束后的退场速度差异

## 6. 验收标准

1. 失败轮次里用户优先看到的是失败说明和恢复建议
2. 记忆弱提示不会在失败场景下抢戏
3. 聊天侧失败轮次的收束路径更自然、更清楚
4. 对应前端测试通过
