# 250-8.1-聊天记录与Cornie日记之间的回看面包屑增强

## 1. 任务目标

在 `180`、`245`、`246` 已建立聊天记录、观察日志与 Cornie 日记之间的同日关系和回看链路基础上，继续细化聊天记录页与 Cornie 日记页之间的回看面包屑，让用户能沿着“原始对话 -> 日记表达 -> 再回看原始对话”的路径稳定往返。

## 2. 背景与现状

Cornie 日记和聊天记录之间虽然已经通过同日总览建立了关系，但直接来回跳转时仍可能出现：

1. 用户不知道当前是从聊天记录来的还是从观察日志来的
2. 回到聊天记录后，缺少“为什么会跳回来”的上下文说明
3. 同一日里多条来源链路并存时，回看路径容易混乱

## 3. 涉及范围

- 聊天记录页
- Cornie 日记页
- 两者之间的面包屑来源说明
- 对应前端测试

## 4. 前置依赖

1. `180-8.1-聊天记录与观察日志日记关系工作台.md` 已完成或至少已有同日关系路径
2. `245-8.2-观察日志到Cornie日记生成后回看链路与来源回跳增强.md` 已完成或至少已有日记回跳
3. `228-8.1-聊天记录消息区滚动恢复与锚点跳读增强.md` 已完成或至少已有聊天记录定位能力

## 5. 具体开发项

### 5.1 面包屑来源说明

1. 从聊天记录跳去 Cornie 日记后，日记页显示轻量面包屑说明来源
2. 从日记页回到聊天记录后，聊天记录页也能说明本次回流来自同日 Cornie 日记
3. 面包屑只表达当前回看链路，不模拟完整历史栈

### 5.2 回看定位保持

1. 回到聊天记录时尽量恢复原本查看的日期和消息区位置
2. 若是从同日关系入口进入，保持与总览页的状态一致
3. 不让日记回流打断聊天记录长对话阅读节奏

### 5.3 链路区分

1. 区分“来自日记回看”与“来自普通同日导航”
2. 在多来源场景下保持回看说明清楚，不互相覆盖
3. 用户应能看懂当前这次往返主要是为了回看哪一层内容

### 5.4 视觉边界

1. 面包屑应轻量，不压过聊天正文或日记正文
2. 可短暂展示后自动降级，也可手动关闭
3. 文案保持平实易懂，不引入技术术语

### 5.5 测试补齐

1. 覆盖聊天记录到日记再回来的双向面包屑
2. 覆盖回流后的聊天记录定位恢复
3. 覆盖普通导航与回看导航的区分
4. 覆盖多来源时的说明优先级

## 6. 验收标准

1. 聊天记录与 Cornie 日记之间具备稳定的双向回看说明
2. 回看后聊天记录阅读位置不轻易丢失
3. 面包屑表达清楚、克制、不打扰
4. 对应前端测试通过
