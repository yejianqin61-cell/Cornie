# 324-8.3-Memory-Wiki来源区与聊天透明提示异步替换时的状态播报与读屏语义增强

## 1. 任务目标

在 `174`、`175`、`284-321` 这批聊天透明提示与 Memory Wiki 来源阅读任务基础上，继续补齐来源区异步替换、比较视角降级、透明提示静默重建、失败例外入口跨主题重置时的状态播报与读屏语义，让“内容已经被系统替换或重建”的过程也能被用户理解。

## 2. 背景与现状

当前两条链路已经逐步补齐：

1. 聊天侧工具透明提示的可达性与键盘顺序
2. 失败静默态下的例外查看与跨主题重置
3. Memory Wiki 来源区跨来源切换、弱数据降级、默认入口重算
4. 来源区与正文之间的多轮回流判定

但若没有状态播报，仍会出现：

1. 比较视角因数据不足被自动降级后，用户不知道为什么界面突然变短了
2. 失败静默例外入口跨主题重置后，用户只看到按钮变了，不知道当前已是新主题
3. 来源区刷新恢复或重新进入后，读屏用户难以判断当前读到的是哪一类来源

## 3. 涉及范围

- 聊天侧透明提示、失败静默例外入口
- Memory Wiki 来源阅读区、比较视角、来源类型切换入口
- 状态替换、自动降级、静默重建时的轻播报与读屏语义
- 对应前端测试

## 4. 前置依赖

1. `284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强.md` 已完成或至少已有透明提示语义基础
2. `320-8.3-失败静默例外入口跨主题开关循环后的键盘焦点与静默语义同步增强.md` 已完成或至少已有跨主题语义同步
3. `321-8.3-Memory-Wiki跨来源类型切换后来源区开关循环的焦点锚点与默认入口同步增强.md` 已完成或至少已有来源区锚点与默认入口同步

## 5. 具体开发项

### 5.1 聊天透明提示状态替换播报

1. 当记忆弱提示因轮次变化、失败静默或主题切换而被静默、重建或替换时，提供低打扰的状态语义
2. 状态说明只帮助用户理解变化，不抢最终回复的主阅读位
3. 若用户主动追问失败原因，则优先保持排障主链路，不重复播报次要变化

### 5.2 Memory Wiki 来源区降级与重建播报

1. 比较视角自动降级、来源组恢复失败、重新回到正文等场景，需要有可理解的状态说明
2. 切换来源类型后，说明语义应明确当前读的是哪类来源，而不是只换按钮文案
3. 弱数据态下的播报应简洁克制，不制造额外阅读负担

### 5.3 读屏语义与区域身份补齐

1. 聊天透明提示区、失败例外区、Memory Wiki 来源区需要清晰区分区域身份
2. 自动替换前后的区域标题、状态描述、当前上下文应对读屏用户可辨认
3. 不把内部工程状态直接暴露为最终用户文案

### 5.4 测试补齐

1. 覆盖聊天透明提示被静默、重建、替换时的状态说明
2. 覆盖 Memory Wiki 比较视角降级与来源类型切换后的状态说明
3. 覆盖读屏语义在区域替换前后的稳定性
4. 覆盖最终回复和来源阅读主链路不被状态播报打断

## 6. 验收标准

1. 聊天透明提示与 Memory Wiki 来源区的异步替换过程对用户可理解、可感知
2. 读屏用户能知道当前正在读哪个区域、哪个来源上下文
3. 状态播报克制，不抢最终回复或正文阅读主位
4. 对应前端测试通过
