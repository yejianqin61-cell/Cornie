# 417-观察日志详情页普通用户语义化改造

## 1. 任务目标

把当前观察日志详情页从“简单输入框 + 文本域”的技术编辑态，升级为更适合普通用户阅读和整理的详情页。

本任务重点是让用户点开一条观察后，能明白：

1. 这是一条什么样的小事
2. 为什么铃湾会把它记下来
3. 如果想修改，它应该怎样改

## 2. 对应来源

- `doc/design/Cornie-0701-记忆层存储与长期记忆前端入口设计说明.md`
- 第 7 节：普通用户可查看观察日志
- 第 8.2 节：普通用户长期记忆入口目标

## 3. 背景与现状

当前观察日志详情页已经可以：

1. 查看
2. 编辑
3. 删除

但它还有明显问题：

1. 页面像原始编辑器，没有普通用户语义
2. 类型展示太生硬
3. 没有告诉用户这条观察更像“生活片段”还是“事实记录”
4. 标题和内容输入区过于裸露，阅读感偏弱

## 4. 涉及范围

- `src/renderer/components/ObservationDetail.vue`

## 5. 开发项

### 5.1 增加详情页说明区

在观察详情页增加一块轻量说明：

1. 这条观察属于哪一类
2. 这类观察通常是在什么情况下被记下来

### 5.2 类型语义化

对不同 observation type 给出普通用户可读文案，例如：

1. 生活事件
2. 事实片段
3. 情绪变化
4. 偏好线索
5. 小事记录

### 5.3 字段文案优化

把详情页里的：

1. 标题
2. 内容
3. 元信息展示

改成更像“整理一条生活观察”，而不是“编辑数据库记录”。

### 5.4 删除与错误提示优化

删除确认、加载失败、保存失败文案都要改成普通用户语气，不要只剩机械报错。

## 6. 验收标准

1. 观察详情页具备普通用户可读的说明区
2. 类型展示完成语义化
3. 标题与内容输入区文案更自然
4. 错误与删除提示不再生硬

## 7. 自测清单

1. 打开不同类型的观察，检查说明区是否切换
2. 编辑标题与内容后保存，确认保存链路正常
3. 删除观察，确认文案与回流正常
4. 手机宽度下详情页不应挤坏
