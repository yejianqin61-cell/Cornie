# 412-普通用户长期记忆新建编辑删除闭环

## 1. 任务目标

为普通用户补齐长期记忆页面的基础 CRUD 闭环，让用户不进入高级治理工作台，也能在“观察与记忆”里完成：

1. 新建一页长期记忆
2. 编辑已有长期记忆
3. 删除（归档）不想保留的长期记忆

本任务的重点不是治理能力，而是把“长期记忆对普通用户可见、可改、可删、可新建”这条主链正式打通。

## 2. 对应来源

- `doc/design/Cornie-0701-记忆层存储与长期记忆前端入口设计说明.md`
- 其中第 7、8、9 节关于普通用户长期记忆入口的能力边界与正式改造目标

## 3. 背景与现状

当前普通用户在“观察与记忆”里已经能：

1. 看见最近的长期记忆卡片
2. 进入长期记忆列表
3. 打开某一页长期记忆详情

但仍有明显缺口：

1. 列表页缺少明确的新建入口
2. 列表页仍带有原始 `pageType` 技术字段
3. 详情页只有非常简陋的标题/正文编辑
4. 普通用户还不能在普通入口中删除（归档）长期记忆页

这导致长期记忆当前仍然是“能看一点、能摸一点”，但不是完整的人类入口。

## 6. 开发项

### 6.1 为普通用户长期记忆列表补新建入口

在长期记忆列表页中补齐清晰的“新建记忆”入口：

1. 顶部有主按钮可发起新建
2. 空状态下也有明确入口
3. 从“观察与记忆”首页也可以进入新建

### 6.2 去掉原始技术术语直出

列表页和详情页中，不直接向普通用户暴露：

1. `identity_profile`
2. `identity_person`
3. `identity_preference`
4. `identity_trait`

而应转换为普通人能理解的文案，例如：

1. 关于你
2. 重要的人
3. 你的偏好
4. 你的特征

### 6.3 详情页支持创建与编辑双模式

长期记忆详情页应支持：

1. 进入已有页面时编辑
2. 进入“新建”时创建
3. 创建成功后进入正式详情页

最少字段：

1. 记忆类型
2. 标题
3. 简短摘要
4. 正文内容

### 6.4 普通用户删除采用“归档”语义

普通用户删除长期记忆时，不做技术型“硬删除”表达，而使用更温和的产品语义：

1. 删除按钮文案面向普通用户
2. 底层调用归档接口
3. 删除成功后回到列表页

### 6.5 错误态与空态友好化

要求：

1. 创建失败提示友好
2. 保存失败提示友好
3. 删除失败提示友好
4. 空状态不只告诉用户“没有”，还要告诉用户“下一步可以做什么”

## 7. 实现建议

### 7.1 视图流建议

建议在 `observe-memory` 子路由里新增：

1. `memory-create`
2. `memory-detail`

创建成功后：

1. 自动切到新建页面的详情态
2. 后续返回列表即可看到新增项

### 7.2 交互建议

1. 新建页默认记忆类型使用“关于你”
2. 提供类型切换下拉框
3. 不暴露高级字段、状态、importance、topic、governance 等

### 7.3 不做事项

本任务不处理：

1. 来源追溯详情阅读
2. Topic Index 暴露
3. 版本历史
4. 回滚
5. 审计
6. 页面合并

## 8. 验收标准

1. 普通用户可从“观察与记忆”发起新建长期记忆
2. 可成功创建一页长期记忆
3. 可编辑已有长期记忆标题、摘要、正文
4. 可删除（归档）已有长期记忆
5. 页面中不再直出原始 `pageType` 技术字段

## 9. 自测清单

1. 从长期记忆列表进入“新建记忆”，填写后成功保存
2. 创建成功后返回列表，能看到新页面
3. 打开已有页面，修改标题或正文，保存后成功
4. 删除一页长期记忆后，返回列表，该项不再出现
5. 检查所有类型文案是否都为普通用户语言
