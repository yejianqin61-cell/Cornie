# 343-观察日志按天归档展示与历史检索体验收口

## 1. 任务目标

围绕“观察日志按天归档、不清空、历史按需检索”的设计，补齐前后端查询和展示体验，让观察日志真正承担事实层档案角色。

## 2. 任务来源

- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/observation/service.js`
- `electron/backend/observation/routes.js`
- `src/renderer/components/ObservationList.vue`
- `src/renderer/api.js`

## 4. 当前问题

当前观察日志虽然按天存储，但用户侧仍缺：

- 明确的按天归档浏览体验
- 历史筛选 / 搜索 / 定位入口
- 与当天高频 prompt 装载边界一致的产品表达

## 5. 目标设计

- 观察日志默认按自然日归档浏览
- 支持切换日期、按关键词查找、按类型过滤
- 历史记录可查，但不会误导为“每天全量装进 prompt”

## 6. 实现步骤

### Step 1

补齐观察日志按日查询与筛选接口结构。

### Step 2

重构前端列表视图，突出“今日 / 历史 / 类型筛选”。

### Step 3

在界面提示中明确其角色是事实档案层，不是自动全量记忆注入层。

## 7. 测试点

- 用户可按天翻阅观察日志
- 可通过关键词或类型定位历史观察
- 前端文案不会误导观察日志的使用边界

## 8. 完成标准

- 观察日志历史检索体验闭环
- 与记忆治理总纲中的生命周期表达一致
