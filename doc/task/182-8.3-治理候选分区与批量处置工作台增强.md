# 182-8.3-治理候选分区与批量处置工作台增强

## 1. 任务目标

在 `168`、`171`、`179` 的治理产品化基础上，继续把 Memory Wiki 待审核区从“单条查看 + 单条确认”为主的模式，升级为更适合真实治理工作的“分区浏览 + 批量处置”工作台。

## 2. 背景与现状

当前待审核区已经具备：

1. 基础列表
2. 筛选能力
3. 单条证据查看
4. 高风险确认承接

但当候选数量上来后，仍会遇到问题：

1. 合并候选、归档候选、压缩候选、修复建议混在一起，认知负担高
2. 用户需要一条条点进去，处理效率低
3. 缺少批量忽略、批量标记稍后处理等轻治理动作

## 3. 涉及范围

- `src/renderer/components/MemoryWikiWorkspace.vue`
- 如有必要，补充治理请求批量状态接口
- 对应前端测试

## 4. 前置依赖

1. `181-8.2-Memory-Wiki待审核角标与异步提醒增强.md` 已完成或至少有待审核计数能力
2. `179-8.3-Memory-Wiki巡检结果与审计工作台落地.md` 已完成或至少提供巡检入口

## 5. 具体开发项

### 5.1 待审核分区视图

1. 至少按合并候选、归档候选、压缩候选、修复建议四类分区
2. 每个分区显示未处理数量
3. 分区切换应明显降低用户扫描成本

### 5.2 批量轻治理动作

1. 支持批量标记“稍后处理”
2. 支持批量忽略低优先级候选
3. 对高风险正式执行动作仍保持逐条确认，不做危险批量提交

### 5.3 分区级摘要

1. 在每个分区顶部显示“这批候选为什么出现”
2. 用平实文案解释该类候选的治理含义
3. 对信息量大的分区给出排序与优先级提示

### 5.4 测试补齐

1. 覆盖分区切换渲染
2. 覆盖批量稍后处理动作
3. 覆盖批量忽略动作
4. 覆盖高风险动作仍需逐条确认的边界

## 6. 验收标准

1. 待审核区具备清晰的分类分区
2. 用户可对低风险候选进行批量轻处置
3. 高风险治理动作仍保持安全边界
4. 对应前端测试通过
