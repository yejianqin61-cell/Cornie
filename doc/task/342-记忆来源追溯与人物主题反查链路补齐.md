# 342-记忆来源追溯与人物主题反查链路补齐

## 1. 任务目标

补齐长期记忆页、人物页、主题索引对聊天记录与观察日志的来源追溯能力，让用户和模型都能反查“这条记忆从何而来”。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`
- `doc/design/Cornie-0630-聊天记录存储与历史归档改造方案.md`

## 3. 涉及范围

- `electron/backend/memory-wiki/`
- `electron/backend/observation/`
- `electron/backend/chatlog/`
- `electron/backend/topic-index/` 或对应主题索引实现
- `src/renderer/components/MemoryWikiWorkspace.vue`

## 4. 当前问题

目前虽然有部分来源补链能力，但还没有围绕 Identity / Topic / Chatlog / Observation 形成完整反查闭环。

## 5. 目标设计

- Wiki 页可查看关联聊天日期、观察日志、主题索引
- Topic Index 可反查关联页和来源日期
- 人物页可快速回溯共同经历来自哪些聊天或观察记录
- 前后端接口契约统一

## 6. 实现步骤

### Step 1

梳理现有来源字段与引用结构，补齐缺失的链接字段。

### Step 2

为人物页与 Topic Index 建立稳定的来源互链规则。

### Step 3

补前端展示与跳转入口，确保人类可见可查。

## 7. 测试点

- 可从人物页看到来源聊天 / 观察日期
- 可从主题索引反查人物页与相关来源
- 链接断裂时有明确兜底表现

## 8. 完成标准

- 记忆来源追溯形成闭环
- 人物与主题的反查链路可用
