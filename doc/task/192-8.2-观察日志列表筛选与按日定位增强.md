# 192-8.2-观察日志列表筛选与按日定位增强

## 1. 任务目标

在 `173` 观察日志首轮工作台基础上，继续把观察日志从“有入口、能 CRUD”提升为更接近正式工作台的可浏览、可筛选、可按日定位的人类入口，让用户能够：

1. 快速定位某一天的观察日志
2. 区分当天有几条、是什么类型
3. 在历史观察日志较多时保持可读性

## 2. 背景与现状

`173` 已经定义了观察日志工作台的首轮目标，但仍偏向“先把基础入口立起来”。继续往正式工作台推进时，还缺：

1. 按日浏览的结构化列表体验
2. 类型筛选、空态、无结果态
3. 当天条数与摘要信息的轻量展示
4. 从长列表中回到今天或最近记录日的快捷定位

## 3. 涉及范围

- 观察日志工作台组件
- 如有必要，补充列表读取参数或前端聚合逻辑
- 对应前端测试

## 4. 前置依赖

1. `173-8.2-观察日志人类工作台首轮落地.md` 已完成或至少已有观察日志工作台骨架

## 5. 具体开发项

### 5.1 按日分组列表

1. 观察日志列表按日期分组展示
2. 每个日期组展示当天条数
3. 每条摘要展示标题、类型、更新时间或创建时间

### 5.2 筛选与定位

1. 支持按类型筛选观察日志
2. 支持快速回到今天
3. 支持快速跳转到最近有记录的日期

### 5.3 空态与无结果态

1. 当系统还没有任何观察日志时，展示全局空态
2. 当筛选后没有命中结果时，展示筛选空态
3. 文案明确说明观察日志的定位是事实记录层

### 5.4 列表信息密度优化

1. 在不挤压阅读空间的前提下补充条目元信息
2. 明确当前选中日期与当前选中条目
3. 长日期列表下保持扫描效率

### 5.5 测试补齐

1. 覆盖按日分组渲染
2. 覆盖类型筛选
3. 覆盖回到今天 / 最近记录日
4. 覆盖全局空态与筛选空态

## 6. 验收标准

1. 用户可以顺畅浏览历史观察日志
2. 用户可以按日期和类型快速定位记录
3. 观察日志列表具备正式工作台级别的基础可读性
4. 对应前端测试通过
