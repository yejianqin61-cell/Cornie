# 202-8.3-Topic与页面错误关联修正与解绑入口增强

## 1. 任务目标

在 `178` Topic 详情治理工作台基础上，继续补齐“错误关联修正”和“页面解绑入口”，让用户能在前端主动修正 Topic 与 Memory Wiki 页面之间的错误关联，而不必只能被动等待治理候选。

## 2. 背景与现状

`178` 已经提出 Topic 与页面关系工作区，但仍需更细化的任务承接：

1. 误关联页面的识别与修正入口
2. 解绑前风险说明
3. 解绑后的状态同步

## 3. 涉及范围

- Topic 详情页与页面关系区
- 如有必要，解绑确认弹层
- 对应前端测试

## 4. 前置依赖

1. `178-8.3-Topic-Index详情与主题治理工作台增强.md` 已完成或至少已有 Topic 与页面关系区

## 5. 具体开发项

### 5.1 错误关联识别入口

1. 在 Topic 关联页面列表中提供“这条关联可能不对”的入口
2. 明确区分普通阅读入口与治理入口
3. 不让用户误以为点击页面就是直接解绑

### 5.2 页面解绑确认

1. 解绑前说明会影响主题阅读和后续匹配
2. 允许用户确认解绑或取消
3. 对高频主题保持更清楚的影响提示

### 5.3 解绑后状态同步

1. 解绑成功后更新 Topic 详情页中的关联页面数
2. 同步刷新相关页面详情中的 Topic 表达
3. 若解绑失败，保留当前视图并提示失败原因

### 5.4 空态与误操作保护

1. 无关联页面时保持清楚空态
2. 避免高频误触解绑
3. 不把解绑操作设计成过于隐蔽的入口

### 5.5 测试补齐

1. 覆盖解绑入口展示
2. 覆盖解绑确认 / 取消分支
3. 覆盖解绑成功与失败分支
4. 覆盖无关联页面空态

## 6. 验收标准

1. 用户能够在 Topic 详情中修正明显错误的页面关联
2. 解绑动作风险边界清楚
3. Topic 与页面关系区具备更主动的人类治理能力
4. 对应前端测试通过
