# 014 前端确认流接线与联调验收

## 1. 任务目标

把当前前端“仅展示确认卡”的状态升级为“可提交确认结果、可展示执行结果、可恢复确认状态”的完整交互链路，并完成确认流端到端联调验收。

本任务完成后，应至少具备：

- 用户在确认卡上点击同意 / 拒绝后可真实调用后端接口
- 前端能显示处理中状态
- 前端能显示执行成功 / 拒绝 / 失败结果
- 刷新后仍能恢复待确认状态或已处理状态

## 5. 前端行为要求

### 5.1 同意按钮

点击后应：

- 禁用重复点击
- 展示处理中状态
- 调用 `submitConfirmationDecision(id, 'approve')`
- 收到成功结果后展示：
  - 工具执行结果
  - Cornie 最终回复

### 5.2 拒绝按钮

点击后应：

- 禁用重复点击
- 展示处理中状态
- 调用 `submitConfirmationDecision(id, 'reject')`
- 收到成功结果后展示：
  - 已拒绝提示
  - Cornie 的收口回复

### 5.3 异常场景

需明确处理：

- 网络失败
- 状态冲突
- 后端返回执行失败
- 已被其他操作处理

## 6. 状态设计

建议在前端消息状态中补充：

- `confirm_pending`
- `confirm_processing`
- `confirm_approved`
- `confirm_rejected`
- `confirm_failed`

或在原有 `confirm` 消息结构上增加：

```ts
type ConfirmUiState = {
  status: 'pending' | 'processing' | 'approved' | 'rejected' | 'failed'
  pendingConfirmationId: string
  errorMessage?: string
}
```

## 7. 实现步骤

### Step 1

在 `api.js` 中接入确认流接口：

- `submitConfirmationDecision`
- `getConfirmation`
- `listConfirmations`

### Step 2

升级 `ConfirmCard.vue`

增加：

- `loading` 状态
- `disabled` 状态
- `error` 展示
- 已处理状态展示

### Step 3

修改 `CorniePet.vue`

实现：

- 点击确认按钮后真实调用接口
- 将后端返回的 `toolExecution` 与 `cornieMessage` 注入聊天流
- 对失败状态给出前端提示

### Step 4

补刷新恢复逻辑

可选方式：

- 打开当天聊天时，查询当天待确认动作
- 若某条确认仍为 `pending`，前端恢复其卡片状态

## 8. 联调验收要求

至少覆盖以下场景：

### 场景 A：新增类目确认通过

- 前端出现确认卡
- 用户点击同意
- 后端创建类目
- 前端看到工具结果与 Cornie 最终回复

### 场景 B：长期记忆写入确认通过

- 前端出现确认卡
- 用户点击同意
- 后端写入记忆
- 前端看到执行结果

### 场景 C：用户拒绝

- 前端出现确认卡
- 用户点击拒绝
- 不产生副作用
- 前端看到收口提示

### 场景 D：执行失败

- 用户点击同意
- 工具执行或回复生成失败
- 前端看到失败状态
- 不会无限 loading

## 9. 完成标准

- 前端确认按钮已真实接入后端
- 用户可完成同意 / 拒绝操作
- 工具执行结果与最终回复可稳定回显
- 确认流形成完整端到端闭环

## 10. 注意事项

- 前端不要自行拼装确认结果，必须以服务端返回为准
- 处理中的确认卡应防止重复点击
- 展示风格保持陪伴感，避免变成后台管理系统风格
