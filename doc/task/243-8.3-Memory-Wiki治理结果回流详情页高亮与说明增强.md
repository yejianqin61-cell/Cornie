# 243-8.3-Memory-Wiki治理结果回流详情页高亮与说明增强

## 1. 任务目标

在 `242` 已补齐批量审核后结果汇总入口的基础上，继续增强从治理结果回流到具体 Memory Wiki 页面或 Topic 详情页时的高亮与说明体验，让用户能快速看到刚才的治理动作到底影响了哪里。

## 2. 背景与现状

用户从结果汇总页跳回具体页面后，如果没有额外提示，常会遇到：

1. 知道刚处理成功了，但看不出页面哪里变了
2. 回流到详情页后缺少“你是从治理结果来的”上下文
3. 治理动作对页面的影响感知不强，难形成闭环

## 3. 涉及范围

- Memory Wiki 页面详情页
- Topic 详情页
- 从治理结果页跳回的高亮定位与来源说明
- 对应前端测试

## 4. 前置依赖

1. `242-8.3-Memory-Wiki批量审核后结果汇总与回退入口增强.md` 已完成或至少已有结果回流入口
2. `217-8.3-Memory-Wiki详情页滚动定位与回退体验增强.md` 已完成或至少已有详情定位能力
3. `223-8.3-Topic详情区块折叠与阅读密度增强.md` 已完成或至少已有 Topic 详情区块能力

## 5. 具体开发项

### 5.1 回流来源说明

1. 从治理结果页进入详情时，显示轻量来源说明
2. 说明本次是查看刚才哪一条治理动作的影响
3. 来源说明应可关闭，不长期占据视觉焦点

### 5.2 影响区高亮

1. 页面详情中被变更的关键区块有短暂高亮或标识
2. Topic 详情中被影响的关系、热度或别名区也可做轻量提示
3. 高亮应短暂、克制，不制造动画噪音

### 5.3 对比理解辅助

1. 必要时提供“查看本次变更前后差异”的快捷入口
2. 用户无需重新通读整页即可知道变化落点
3. 不把详情页变成大段 diff 展示，而是保持阅读优先

### 5.4 回退链路

1. 支持从详情页返回结果汇总页
2. 切换到其他页面后，旧的治理结果来源说明应自动退场
3. 与详情页自身的滚动定位和回退逻辑保持兼容

### 5.5 测试补齐

1. 覆盖从结果页回流详情时的来源说明
2. 覆盖关键区块高亮展示
3. 覆盖返回结果页链路
4. 覆盖来源说明自动退场逻辑

## 6. 验收标准

1. 用户能从治理结果自然追踪到具体页面影响
2. 详情页具备轻量但明确的“刚改了哪里”表达
3. 回流体验不破坏原有详情阅读结构
4. 对应前端测试通过
