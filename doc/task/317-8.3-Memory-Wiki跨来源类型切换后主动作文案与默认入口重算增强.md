# 317-8.3-Memory-Wiki跨来源类型切换后主动作文案与默认入口重算增强

## 1. 任务目标

在 `313` 已补齐 Memory Wiki 来源区跨来源类型切换时的旧新轮次语义隔离基础上，继续细化切换来源类型后，主动作文案、默认入口顺序和返回按钮目标如何全部按当前来源类型重算，避免来源类型虽切换了，但动作区仍是上一类型的逻辑。

## 2. 背景与现状

来源区切换类型后，除了提示语义，还会影响：

1. 默认展开哪个入口
2. 主按钮文案
3. 次级动作排序

如果动作区不跟着重算，会出现：

1. 当前读的是观察日志来源，但主按钮像聊天记录来源
2. 默认入口顺序还沿用旧来源类型
3. 用户需要先理解“系统为什么还在按上一类来源行动”

## 3. 涉及范围

- Memory Wiki 来源阅读区动作区
- 主动作、次级动作、默认入口顺序
- 跨来源类型切换后的动作重算
- 对应前端测试

## 4. 前置依赖

1. `313-8.3-Memory-Wiki来源区跨来源类型切换时的旧新轮次语义隔离增强.md` 已完成或至少已有类型隔离
2. `285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强.md` 已完成或至少已有来源切换动作区
3. `289-8.3-Memory-Wiki来源比较视角在弱数据态下的自动降级与空态衔接增强.md` 已完成或至少已有弱数据态动作降级

## 5. 具体开发项

### 5.1 主动作文案重算

1. 来源类型切换后，主按钮文案应立即按新类型重算
2. 不允许保留旧来源类型的动作措辞
3. 若新类型无主动作，则回落到通用阅读动作

### 5.2 默认入口顺序重算

1. 不同来源类型的默认入口顺序按当前类型独立定义
2. 切换类型后立即采用新顺序
3. 弱数据态和比较视角降级态也按新类型重算

### 5.3 动作目标一致性

1. 主动作和次级动作目标只绑定当前来源类型
2. 不得把旧类型的返回或查看动作带到新类型
3. 与正文阅读主上下文和来源恢复提示兼容

### 5.4 测试补齐

1. 覆盖跨来源类型切换后的主按钮文案刷新
2. 覆盖默认入口顺序重算
3. 覆盖弱数据态下的新类型动作降级
4. 覆盖动作目标不串类型

## 6. 验收标准

1. Memory Wiki 来源动作区始终跟随当前来源类型
2. 用户不会因为动作区滞后而误判当前来源
3. 跨来源类型切换后动作、文案、顺序三者保持一致
4. 对应前端测试通过
