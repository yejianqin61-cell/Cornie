# 416-观察日志普通用户首页入口首轮落地

## 1. 任务目标

把当前“观察与记忆”首页中的观察记录入口，从“只有说明文案和查看全部按钮”，升级成“普通用户一眼能看见最近观察内容”的首轮正式入口。

本任务的重点不是重做观察日志工作台，而是先把首页入口补成真正有内容、有预览、有回流的普通用户入口。

## 3. 背景与现状

当前“观察与记忆”首页已经具备：

1. 长期记忆入口
2. 新建记忆入口
3. 观察记录的说明文案
4. 跳转到观察记录列表页的入口

但观察记录这一块仍然偏弱：

1. 首页上看不到任何真实观察内容
2. 用户不知道“铃湾到底记下了什么”
3. 观察记录入口当前更像占位区，而不是正式首页模块

## 5. 开发项

### 5.1 首页读取最近观察记录

首页应直接读取最近的观察记录，并展示一个轻量预览区。

要求：

1. 默认优先展示今天的观察
2. 若今天为空，可自然显示空态
3. 最多展示少量卡片，不把首页做得太长

### 5.2 展示轻量预览卡片

每条观察至少展示：

1. 标题
2. 类型的普通用户文案
3. 简短内容片段或说明

要求：

1. 文案要像“生活片段”，不要像运维数据
2. 不暴露 prompt、治理、压缩等术语

### 5.3 强化回流

用户在首页观察卡片上应能：

1. 点击进入观察详情
2. 从首页直接进入观察记录列表

### 5.4 空态优化

如果今天还没有观察记录，应明确告诉用户：

1. 铃湾不会把每句闲聊都记成流水账
2. 只有在值得留一下的时候，才会写进观察

## 6. 验收标准

1. 首页观察区域能展示最近观察内容
2. 用户可以直接从首页点进观察详情
3. 空态文案自然，不制造“系统坏掉”的感觉
4. 不暴露治理术语或技术术语

## 7. 自测清单

1. 今天有观察时，检查首页是否正常展示卡片
2. 点击卡片时，检查是否能进入观察详情
3. 今天没有观察时，检查空态是否自然
4. 手机宽度下观察区域卡片不应挤坏
