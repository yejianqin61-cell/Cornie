# 304-8.3-聊天侧失败排障静默态下用户主动查看记忆来源的例外通道增强

## 1. 任务目标

在 `300` 已补齐聊天侧失败排障阶段记忆弱提示静默策略基础上，继续细化当用户在静默态里主动想看“本轮参考了哪些记忆来源”时的例外通道，确保系统默认保持安静，但用户若主动要看，仍有稳定入口。

## 2. 背景与现状

失败排障阶段，记忆弱提示应默认静默，这是正确方向；但仍可能存在少量场景：

1. 用户自己想确认本轮参考了哪些旧线索
2. 用户怀疑记忆来源影响了回答
3. 用户想核对“是不是拿错了历史上下文”

如果静默等于完全不可见，就会出现：

1. 默认虽然安静，但用户失去主动查看透明信息的能力
2. 用户必须跳出当前对话才能排查来源
3. 透明性和专注度之间失去平衡

## 3. 涉及范围

- 聊天侧失败排障静默态
- 记忆来源查看入口、展开卡与例外通道
- 对应前端测试

## 4. 前置依赖

1. `300-8.3-聊天侧记忆弱提示在用户连续追问失败原因时的静默策略增强.md` 已完成或至少已有失败排障静默态
2. `199-8.3-聊天侧记忆来源展开卡与引用边界增强.md` 已完成或至少已有来源展开能力
3. `284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强.md` 已完成或至少已有可达性约束

## 5. 具体开发项

### 5.1 静默态例外入口

1. 在不打断主阅读的前提下提供主动查看记忆来源的轻量入口
2. 入口默认低调，不与失败说明竞争主位置
3. 键盘和屏幕阅读顺序保持可达

### 5.2 查看内容边界

1. 只在用户主动展开时展示来源摘要或来源卡
2. 展开内容继续保持克制，不抢失败恢复建议主视线
3. 查看后用户能快速回到排障主链路

### 5.3 静默策略不被破坏

1. 默认静默仍成立，例外入口不等于重新启用主动提示
2. 用户未点击时，不自行展开
3. 关闭后回到静默入口态，而不是再次出现主动提示

### 5.4 与失败追问阶段兼容

1. 连续追问阶段中，例外入口仍保持稳定可用
2. 问题恢复后，入口再并回常规透明提示体系
3. 与失败卡、恢复建议和最终回复收束顺序兼容

### 5.5 测试补齐

1. 覆盖静默态下的主动查看入口
2. 覆盖展开后不打断失败主链路
3. 覆盖关闭后回到静默入口态
4. 覆盖恢复正常轮次后并回常规提示体系

## 6. 验收标准

1. 失败排障阶段默认安静，但透明性仍可被用户主动取回
2. 用户主动看记忆来源时不会打断排障主链路
3. 静默规则和透明查看能力能同时成立
4. 对应前端测试通过
