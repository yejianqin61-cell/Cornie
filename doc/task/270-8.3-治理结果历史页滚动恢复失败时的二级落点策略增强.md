# 270-8.3-治理结果历史页滚动恢复失败时的二级落点策略增强

## 1. 任务目标

在 `266` 已补齐治理结果历史页跨页返回后的滚动恢复细则基础上，继续把“恢复失败时落到哪里”单独收口成可实现规则，确保失败兜底可预测、不迷路。

## 2. 背景与现状

滚动恢复逻辑越细，越需要明确定义失败后的二级落点。否则会出现：

1. 目标结果卡不存在时，落点像随机跳转
2. 用户不清楚系统为什么停在这个位置
3. 不同失败场景下的兜底行为前后不一致

## 3. 涉及范围

- 治理结果历史页列表区
- 滚动恢复失败兜底逻辑
- 轻量兜底说明
- 对应前端测试

## 4. 前置依赖

1. `266-8.3-治理结果历史页跨页返回后的滚动恢复细则增强.md` 已完成或至少已有滚动恢复主逻辑
2. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有列表与筛选持久化

## 5. 具体开发项

### 5.1 二级落点矩阵

1. 若原结果项不存在，优先落到原分组顶部
2. 若原分组也不存在，落到当前筛选下最近相关分组
3. 若当前筛选整体无结果，转入空态恢复逻辑而不是强行落点

### 5.2 失败原因分类

1. 区分“结果被过滤掉”“结果已失效”“分组结构变化”三类失败原因
2. 不同原因映射到不同兜底落点
3. 不让所有失败都走同一条粗暴回退

### 5.3 轻量说明

1. 需要时提示“已回到最接近的位置”
2. 文案保持简短，不抢列表注意力
3. 对普通用户可理解，不暴露内部状态细节

### 5.4 状态一致性

1. 二级落点策略与当前筛选、排序、折叠分组保持一致
2. 不因兜底而破坏历史页当前浏览上下文
3. 与空态和来源提示体系兼容

### 5.5 测试补齐

1. 覆盖原结果项失效场景
2. 覆盖原分组消失场景
3. 覆盖筛选无结果转空态场景
4. 覆盖轻量兜底说明展示

## 6. 验收标准

1. 滚动恢复失败后仍有稳定、可预测的落点
2. 用户不会因兜底跳转而迷失上下文
3. 二级落点策略与历史页其他状态保持一致
4. 对应前端测试通过
