# 185-8.3-Memory-Wiki页面合并审核工作台增强

## 1. 任务目标

在现有待审核区、治理候选分区、证据面板基础上，继续把 `页面合并` 这类高风险治理动作做成真正可执行的前端审核工作台，支持用户在同一界面里完成：

1. 查看候选产生原因
2. 对比两页差异
3. 选择保留策略
4. 确认或拒绝合并

## 2. 背景与现状

当前前端已经具备：

1. Memory Wiki 工作台
2. 待审核区入口与角标提示
3. 候选分区与基础证据面板
4. 巡检结果与审计工作台任务拆解

但页面合并仍缺少关键承接：

1. 合并候选仍偏列表化，不足以支撑正式审核
2. 用户看不到两页内容如何冲突、互补或重复
3. 用户无法明确选择主保留页、副页和合并策略
4. 高风险动作的风险提示仍不够具体

## 3. 涉及范围

- `src/renderer/components/MemoryWikiWorkspace.vue`
- 如有必要，拆分独立的 `MergeReviewPanel` / `MergeDiffPanel` 组件
- 如有必要，补充页面合并候选详情接口
- 对应前端测试

## 4. 前置依赖

1. `168-8.3-治理待审核区与确认中心产品化收口.md` 已完成
2. `171-8.3-治理筛选与详情证据面板增强.md` 已完成
3. `182-8.3-治理候选分区与批量处置工作台增强.md` 已完成或至少具备分区式待审核结构

## 5. 具体开发项

### 5.1 合并候选详情卡

1. 在合并候选详情中展示候选类型，例如别名重复、信息互补、冲突覆盖
2. 展示候选产生原因、命中规则、最后活跃时间、关联来源数量
3. 展示主候选页与副候选页的基础信息

### 5.2 双页并排对比

1. 支持左右并排查看两页标题、别名、摘要、正文、来源引用
2. 明确高亮重复段、互补段、冲突段
3. 当正文较长时，支持分区折叠或锚点跳转

### 5.3 合并策略选择

1. 支持选择保留主页面
2. 支持选择副页面并入主页面
3. 支持选择仅建立别名关系、暂不真正合并
4. 支持填写简短合并说明，便于审计回看

### 5.4 风险提示与确认

1. 明确说明合并将影响来源引用、主题索引、页面版本
2. 明确说明合并后仍可通过版本或审计回看
3. 高风险执行前必须再次确认
4. 拒绝合并时允许用户写入拒绝原因或标记稍后处理

### 5.5 与巡检 / 审计联动

1. 审核通过后，同步刷新待审核池状态
2. 审核结果可跳转查看审计记录
3. 合并后页面详情与 Topic 详情应可继续回溯原始候选来源

### 5.6 测试补齐

1. 覆盖合并候选详情渲染
2. 覆盖双页并排 diff 展示
3. 覆盖合并策略选择分支
4. 覆盖确认、拒绝、稍后处理三类路径
5. 覆盖处理后待审核状态同步

## 6. 验收标准

1. 用户能够在前端完整审阅一次页面合并候选
2. 用户能够清楚看见两页差异与合并风险
3. 用户能够选择合适的合并策略并完成确认
4. 合并审核与待审核区、审计区、页面详情区联动正常
5. 对应前端测试通过
