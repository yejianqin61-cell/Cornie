# 312-8.3-失败静默例外入口跨主题回流后的静默入口重置增强

## 1. 任务目标

在 `304`、`308` 已补齐失败静默例外入口与回静默状态基础上，继续细化当对话已经离开失败排障主题，随后又回到另一个新失败主题时，静默入口如何重置，避免旧失败主题的静默入口状态污染新主题。

## 2. 背景与现状

用户的失败排障并不总是单线程，可能会：

1. 先排查失败主题 A
2. 暂时离开 A，进入别的话题
3. 后续又进入失败主题 B

如果静默入口状态不重置，会出现：

1. B 主题继承了 A 的展开/关闭痕迹
2. 用户在新失败主题里看到旧静默入口状态
3. 透明入口和失败主题之间的绑定关系变模糊

## 3. 涉及范围

- 聊天侧失败排障静默态
- 不同失败主题之间的静默入口重置
- 例外入口展开/关闭状态与主题边界
- 对应前端测试

## 4. 前置依赖

1. `304-8.3-聊天侧失败排障静默态下用户主动查看记忆来源的例外通道增强.md` 已完成或至少已有例外入口
2. `308-8.3-失败静默例外入口展开后再次关闭的回静默状态增强.md` 已完成或至少已有回静默规则
3. `300-8.3-聊天侧记忆弱提示在用户连续追问失败原因时的静默策略增强.md` 已完成或至少已有失败主题静默规则

## 5. 具体开发项

### 5.1 失败主题边界识别

1. 明确何时算离开旧失败主题、进入新失败主题
2. 主题 A 的静默入口状态不应被主题 B 继承
3. 新失败主题应从干净的静默入口基线开始

### 5.2 入口状态重置

1. 进入新失败主题时，旧展开/关闭状态应被清理
2. 新主题默认仍保持静默，但可重新获得可查看入口
3. 不让用户在新主题里看到旧主题残留的展开层级

### 5.3 与普通轮次并回兼容

1. 从失败主题回到普通轮次时，静默入口应退出失败专用逻辑
2. 再次进入新失败主题时重新初始化
3. 与新会话日、主题切换、多轮静默规则兼容

### 5.4 用户认知清晰度

1. 用户应能感知这是新的失败问题，而不是旧问题续集
2. 若用户主动打开来源说明，看到的只应属于当前失败主题
3. 不制造“系统把不同失败事件混在一起”的感觉

### 5.5 测试补齐

1. 覆盖从失败主题 A 离开再进入失败主题 B 的入口重置
2. 覆盖 B 不继承 A 的展开/关闭状态
3. 覆盖普通轮次并回后的重新初始化
4. 覆盖与新会话日、主题切换规则并存时的结果

## 6. 验收标准

1. 失败静默例外入口在跨失败主题时状态干净、独立
2. 新失败主题不会继承旧失败主题的展开痕迹
3. 用户能持续分清当前自己在排查哪一个问题
4. 对应前端测试通过
