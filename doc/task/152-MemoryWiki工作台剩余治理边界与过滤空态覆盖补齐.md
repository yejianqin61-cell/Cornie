# 152-MemoryWiki工作台剩余治理边界与过滤空态覆盖补齐

## 1. 任务目标

在 `8.5 前端测试脚手架与回归模块` 内，继续补齐 `MemoryWikiWorkspace.vue` 的剩余低覆盖分支，重点收口治理待审核区、确认中心、Topic Index 详情、页面过滤与空态分支，推动前端覆盖率继续向 `95%+` 目标逼近。

本任务属于 `Cornie-013-当前项目完成度复评与后续行动建议.md` 的 `8.5` 子任务，完成后仍不能直接宣告 `8.5` 结束，必须继续根据真实覆盖率结果决定下一步。

## 2. 背景与现状

根据当前 `coverage/frontend/coverage-summary.json`，`MemoryWikiWorkspace.vue` 仍是前端核心页面中的主要低覆盖热点：

- Statements：`88.18%`
- Branches：`69.26%`
- Functions：`81.03%`
- Lines：`89.58%`

当前已覆盖主链路，但仍有明显未测区域：

1. 治理筛选切换后的选择清空分支
2. Topic Index 详情中的空数组 / 回退显示分支
3. Governance 详情中的无原因、无证据回退分支
4. 确认中心空态分支
5. 回滚 prompt 取消分支
6. 治理筛选、确认筛选、页面筛选的边界交互

## 3. 开发范围

本任务只处理前端测试与必要的测试桩增强，不修改业务功能语义。

涉及范围：

- `tests/frontend/memory-wiki-workspace-async.test.mjs`
- 如有必要，可补充测试辅助 mock 逻辑
- `doc/acceptance/8.5-前端测试脚手架与回归模块阶段进展验收.md`

## 4. 具体开发项

### 4.1 治理筛选与选择清空分支

补测试覆盖以下行为：

1. 已选中的治理项在筛选结果中消失后，`selectedGovernanceId` 与 `governanceDetail` 应自动清空。
2. 治理状态筛选、分区筛选切换后，应重新请求列表并刷新界面。

### 4.2 Topic Index 空态与回退文案分支

补测试覆盖以下行为：

1. `dates` 为空时显示 `无`
2. `pageIds`、`memoryPageIds` 均为空时显示 `无`
3. 未选择主题时显示默认空态提示

### 4.3 Governance 详情回退分支

补测试覆盖以下行为：

1. `reason` 缺失时显示 `暂无原因说明`
2. `evidence` 为空时不渲染证据区块
3. 未选择治理请求时显示默认空态提示

### 4.4 确认中心边界分支

补测试覆盖以下行为：

1. 确认列表为空时显示空态提示
2. 确认筛选切换后重新请求列表

### 4.5 页面回滚取消分支

补测试覆盖以下行为：

1. 用户在 `window.prompt` 中取消或输入空值时，不应发起回滚请求

## 5. 验收标准

完成本任务时，至少应满足：

1. 新增测试全部通过
2. `npm.cmd run test:frontend` 通过
3. `npm.cmd run test:frontend:coverage` 通过
4. `MemoryWikiWorkspace.vue` 覆盖率较任务前有可见提升，尤其是 branch / function 指标
5. 更新 `8.5` 阶段验收文档中的测试结果与覆盖率记录

## 6. 备注

本任务目标是继续推进 `8.5`，不是提前结束 `8.5`。若完成后总覆盖率仍未达到 `95%+`，则必须继续留在 `8.5`，按新的低覆盖热点继续拆下一份 task。
