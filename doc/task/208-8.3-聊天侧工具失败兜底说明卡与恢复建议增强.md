# 208-8.3-聊天侧工具失败兜底说明卡与恢复建议增强

## 1. 任务目标

在 `189` 的工具结果态分层基础上，继续把“失败结果”单独细化成更好懂的兜底说明卡，让用户在工具调用失败时，不只是知道失败了，还知道大概为什么、接下来能怎么做。

## 2. 背景与现状

`189` 已经提出失败结果要展示原因和下一步建议，但如果继续推进到更直接可开发的任务粒度，还需要：

1. 失败原因分类与统一表达
2. 对用户可操作恢复路径的提示
3. 避免把后端或协议错误原文直接扔给用户

## 3. 涉及范围

- `ToolResultPanel.vue`
- 聊天消息渲染链路
- 对应前端测试

## 4. 前置依赖

1. `189-8.3-聊天侧工具过程态与结果态反馈分层增强.md` 已完成或至少已有失败态基础结构

## 5. 具体开发项

### 5.1 失败说明卡结构

1. 失败时展示统一说明卡
2. 至少包含失败类型、简短原因、建议动作
3. 不直接暴露底层异常原文给普通用户

### 5.2 恢复建议分类

1. 对可重试类失败提示“稍后重试”
2. 对配置问题提示检查对应设置
3. 对权限或确认中断类失败提示当前被停在哪一步

### 5.3 语气与边界

1. 文案保持平实，不制造恐慌
2. 不让失败提示抢占聊天主阅读链路
3. 对未知错误使用诚实兜底说明，而不是瞎解释

### 5.4 测试补齐

1. 覆盖不同失败类型说明
2. 覆盖不同恢复建议分支
3. 覆盖未知错误兜底分支
4. 覆盖失败卡与正常回复并存的渲染

## 6. 验收标准

1. 用户在失败时能看懂发生了什么级别的问题
2. 用户能得到基本可执行的下一步建议
3. 失败提示不会把技术噪音直接甩给用户
4. 对应前端测试通过
