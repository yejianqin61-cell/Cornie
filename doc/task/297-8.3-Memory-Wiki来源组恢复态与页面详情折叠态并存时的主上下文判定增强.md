# 297-8.3-Memory-Wiki来源组恢复态与页面详情折叠态并存时的主上下文判定增强

## 1. 任务目标

在 `221`、`222`、`293` 已补齐页面详情折叠、来源区展开记忆和刷新后来源组上下文恢复基础上，继续细化“来源组恢复态”和“页面详情折叠态”同时存在时，详情页应优先恢复哪个主上下文，避免一进页面既想恢复正文阅读密度，又想跳回来源区，结果两边都不稳定。

## 2. 背景与现状

Memory Wiki 页面详情现在存在两层阅读上下文：

1. 页面正文区块的折叠/展开和阅读密度
2. 来源阅读区当前来源组和组内位置

用户刷新或重进后，这两层状态都可能想恢复。如果没有主次判定，就会出现：

1. 页面先恢复正文折叠态，随后又跳去来源区
2. 来源区刚恢复完，正文区又重新撑开影响落点
3. 用户不知道当前系统想帮自己续上的是“正文阅读”还是“来源追溯”

## 3. 涉及范围

- Memory Wiki 页面详情区
- 正文折叠态、阅读密度与来源区恢复态
- 主上下文判定、次级状态降级与提示
- 对应前端测试

## 4. 前置依赖

1. `221-8.3-Memory-Wiki详情区块折叠与阅读密度控制增强.md` 已完成或至少已有详情折叠和密度控制
2. `222-8.3-Memory-Wiki来源区展开记忆与批量查看增强.md` 已完成或至少已有来源区展开记忆
3. `293-8.3-Memory-Wiki来源阅读区刷新后来源组上下文恢复与误跳防护增强.md` 已完成或至少已有来源组恢复逻辑

## 5. 具体开发项

### 5.1 主上下文判定

1. 明确当前进入页面时优先恢复“正文阅读”还是“来源追溯”
2. 当用户上次停留明显在来源区时，来源区恢复态优先
3. 当用户上次停留在正文编辑/阅读区时，正文折叠态优先

### 5.2 次级状态降级

1. 未成为主上下文的另一层状态保留但不立即抢落点
2. 来源区为主时，正文折叠态只做安静恢复
3. 正文区为主时，来源组恢复降级为可稍后返回的次级入口

### 5.3 布局与滚动兼容

1. 正文折叠变化不应把来源区主落点顶偏
2. 来源区恢复也不应破坏正文当前阅读密度
3. 与来源比较视角降级、弱数据态和详情滚动恢复兼容

### 5.4 用户提示

1. 用轻提示说明“已先帮你回到刚才在看的来源组”或“已恢复上次正文阅读方式”
2. 不同时展示两条平级恢复提示
3. 提示在用户继续阅读后自动退场

### 5.5 测试补齐

1. 覆盖来源区为主上下文时的恢复结果
2. 覆盖正文区为主上下文时的恢复结果
3. 覆盖次级状态静默恢复而不抢落点
4. 覆盖提示合并与自动退场

## 6. 验收标准

1. Memory Wiki 详情页刷新后只有一个清楚主上下文
2. 正文阅读恢复和来源追溯恢复不会互相打架
3. 用户能持续理解当前页面是在续上哪一种阅读任务
4. 对应前端测试通过
