# 316-8.3-失败静默例外入口跨主题后按钮语义与展开标题重置增强

## 1. 任务目标

在 `312` 已补齐失败静默例外入口跨主题回流后的静默入口重置基础上，继续细化进入新失败主题后，入口按钮文案、展开标题和来源说明标题如何一起重置，避免新主题继承旧主题的话术。

## 2. 背景与现状

静默入口不只是一个开关，它还会带出：

1. 查看来源按钮
2. 展开标题
3. 来源摘要标题

若跨失败主题时只重置状态、不重置语义，会出现：

1. 主题 B 用着主题 A 的按钮话术
2. 展开标题像在解释旧问题
3. 用户误以为还在排查同一个故障

## 3. 涉及范围

- 聊天侧失败静默例外入口
- 按钮文案、展开标题、来源标题
- 跨主题后的完整语义重置
- 对应前端测试

## 4. 前置依赖

1. `312-8.3-失败静默例外入口跨主题回流后的静默入口重置增强.md` 已完成或至少已有跨主题重置
2. `304-8.3-聊天侧失败排障静默态下用户主动查看记忆来源的例外通道增强.md` 已完成或至少已有入口和展开结构
3. `308-8.3-失败静默例外入口展开后再次关闭的回静默状态增强.md` 已完成或至少已有关闭回静默规则

## 5. 具体开发项

### 5.1 跨主题按钮语义重置

1. 进入新失败主题时，按钮文案应按新主题问题重算
2. 不保留旧失败主题的动作措辞
3. 若新主题不适合展示某动作，则按当前主题降级

### 5.2 展开标题与来源标题重置

1. 展开标题只解释当前失败主题
2. 来源摘要标题不引用旧主题描述
3. 按钮、标题、内容三者保持同一主题语义

### 5.3 与静默规则兼容

1. 默认仍保持静默，不因语义重置而主动展开
2. 用户主动打开时看到的就是新主题版本
3. 与普通轮次并回、新会话日重建兼容

### 5.4 测试补齐

1. 覆盖跨主题后按钮文案刷新
2. 覆盖展开标题和来源标题同步重置
3. 覆盖不合适动作在新主题下的降级
4. 覆盖静默规则未被破坏

## 6. 验收标准

1. 失败静默例外入口跨主题后语义完全刷新
2. 新主题不会继承旧主题的话术残留
3. 用户能清楚感知当前正在查看的是哪个问题的来源
4. 对应前端测试通过
