# 224-8.2-观察日志编辑离开保护与草稿恢复增强

## 1. 任务目标

在 `193` 已完成观察日志编辑表单基础收口后，继续补强“切换条目、关闭页面、跨区域跳转、异常刷新”场景下的离开保护与草稿恢复体验，避免人工整理观察日志时因为误操作丢内容。

## 2. 背景与现状

观察日志会承接大量人工补录、纠正、精修工作，编辑时长往往比普通表单更长。当前即使已有未保存提示，仍可能存在：

1. 用户切换列表项时丢失长文本修改
2. 从日志页跳去记忆页或日记页后，回来需要重写
3. 浏览器刷新、窗口关闭等边界场景保护不足

## 3. 涉及范围

- 观察日志编辑表单
- 观察日志列表与详情联动
- 草稿恢复提示
- 对应前端测试

## 4. 前置依赖

1. `193-8.2-观察日志详情编辑表单与删除确认收口.md` 已完成或至少已有未保存提示
2. `204-8.2-观察日志到Cornie日记生成联动入口收口.md` 已完成或至少已有跨模块跳转入口
3. `215-8.2-观察日志中的长期记忆引用提示与跳转增强.md` 已完成或至少已有观察日志到长期记忆跳转链路

## 5. 具体开发项

### 5.1 离开保护增强

1. 切换列表条目时明确提示当前编辑内容是否未保存
2. 从观察日志页跳转到日记、长期记忆等其他工作台前进行轻量确认
3. 在关闭窗口、刷新页面等高风险动作前给出浏览器级或应用级离开保护

### 5.2 草稿恢复能力

1. 对编辑中的长文本在本地做轻量草稿暂存
2. 当保存失败、异常刷新或误离开后，支持恢复最近草稿
3. 草稿恢复要明确区分“正式保存内容”和“本地暂存内容”

### 5.3 冲突与取舍提示

1. 当服务端内容已更新而本地仍有旧草稿时，提示用户选择恢复、丢弃或重新比对
2. 避免静默覆盖已保存内容
3. 对恢复后的草稿内容给出明显提示，防止用户误以为已提交

### 5.4 体验收口

1. 草稿提示要克制，不把编辑页做成告警页
2. 仅在确有风险时打断，不对普通查看造成干扰
3. 保存成功后及时清理对应草稿缓存

### 5.5 测试补齐

1. 覆盖切换条目时的离开确认
2. 覆盖刷新或关闭前的保护逻辑
3. 覆盖草稿恢复与草稿清理
4. 覆盖草稿与服务端内容冲突分支

## 6. 验收标准

1. 观察日志长文本编辑不容易因误操作丢失
2. 用户能清楚分辨正式保存与本地草稿
3. 跨模块跳转不会破坏当前编辑安全感
4. 对应前端测试通过
