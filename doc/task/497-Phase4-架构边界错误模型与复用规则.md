# 497 Phase 4 架构边界错误模型与复用规则

## 1. Where this task sits

- **Phase 4 工程规则与当前产品一致**：目标是把模块边界、错误模型和业务链复用规则留成可查的事实源。
- 本任务收口架构约定，说明 renderer、API、路由、领域服务和持久化之间的责任与错误转换。
- **开始前**：任务 491 至 496 完成。**完成后**：Phase 4 可以收口并生成总结。

## 2. What the developer needs to know

**Read first**

- `doc/Cornie-027-当前项目四维评估简报.md` — 评估中的架构问题和优先级。
- `src/renderer/api/` — 前端 API 复用边界。
- `electron/server.js` — HTTP 路由入口和错误返回。
- `electron/backend/` — 领域服务、存储和现有错误语义。
- `doc/Cornie-028-产品Demo改进施工计划.md` — 新业务链的复用要求。

**Settled**

- 页面复用已有 API；API 复用已有路由；路由复用已有领域服务。
- 错误在产生处保留结构，在 UI 边界翻译为可见反馈。
- 不新增平行服务、平行错误类型或为文档制造抽象代码。

**Edges and seam**

- 接缝是架构约定文档与现有调用链的对应关系。
- 只记录已经存在的模块责任和新增业务链复用规则。

**Run**

- `npm run lint`
- `npm run test:full`

**Unknowns**

- 若现有模块责任互相冲突，记录具体路径和影响，停在冲突处，不用文档掩盖实现问题。

## 3. The workflow

1. 阅读第 2 部分，复述：每一层复用既有边界，错误只在 UI 边界翻译。
2. 从一条已完成业务链追踪请求、服务、存储和错误返回。
3. 写入模块边界、错误模型和复用规则的单一事实源。
4. 对照新业务链搜索重复服务和绕过边界的调用。
5. 若发现缺口，只修最小共享边界并补验证。
6. 运行 lint、全量门禁并提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 组件复用 | 新增页面数据请求 | 使用已有 renderer API | API 模块 |
| 错误保留 | 领域服务失败 | 路由保留结构化错误 | `/api` 路由 |
| UI 翻译 | 结构化错误 | 用户看到明确反馈 | UI 边界 |
| 业务复用 | 新增业务动作 | 调用已有领域服务 | domain service |
| 边界检查 | 搜索直连调用 | 无未记录的绕过 | 架构约定 |
