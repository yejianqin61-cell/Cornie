# 227-8.1-聊天记录日期列表搜索筛选与最近访问增强

## 1. 任务目标

在 `172`、`194`、`203` 已补齐聊天记录日期摘要、跨日联动和长对话阅读基础上，继续增强聊天记录左侧日期列表的搜索、筛选和最近访问能力，让高频翻阅历史聊天时不再只能靠手动逐月翻找。

## 2. 背景与现状

当前聊天记录工作台已经能按天浏览，但真实使用中仍会遇到：

1. 聊天记录积累变多后，逐月翻找成本很高
2. 用户常常只记得“大概哪几天聊过”，而不是精确日期
3. 最近刚看过的日期再次回看时，没有快捷返回入口

## 3. 涉及范围

- 聊天记录工作台日期侧栏
- 日期列表顶部工具区
- 前端本地状态持久化
- 对应前端测试

## 4. 前置依赖

1. `172-8.1-聊天记录工作台产品化增强.md` 已完成或至少已有正式日期列表
2. `194-8.1-聊天记录日期摘要与长对话阅读收口.md` 已完成或至少已有日期摘要信息
3. `203-8.1-聊天记录与观察日志跨日联动定位增强.md` 已完成或至少已有跨日定位语义

## 5. 具体开发项

### 5.1 日期搜索与筛选

1. 支持按日期文本、月份范围或“仅看有沉淀记录的日期”等轻量条件筛选
2. 搜索结果为空时，给出明确无结果提示，而不是空白侧栏
3. 搜索过程保持克制，不引入复杂查询语言

### 5.2 最近访问区

1. 在日期列表顶部增加最近访问日期区
2. 记住用户最近浏览的若干天，便于快速回跳
3. 最近访问应与正常日期列表清晰分区，避免误以为是系统推荐

### 5.3 快速返回能力

1. 支持一键回到今天
2. 支持一键回到最近一次有聊天记录的日期
3. 支持从最近访问区恢复上次阅读位置

### 5.4 状态记忆

1. 记住最近一次筛选条件和最近访问列表
2. 返回聊天记录页时，在合理范围内恢复上次浏览上下文
3. 不让过旧状态妨碍今天的新浏览任务

### 5.5 测试补齐

1. 覆盖搜索有结果与无结果分支
2. 覆盖最近访问记录与恢复
3. 覆盖回到今天和回到最近有记录日期
4. 覆盖筛选状态持久化与重置逻辑

## 6. 验收标准

1. 聊天记录日期列表适合长期积累后的高频翻阅
2. 用户无需频繁逐月手动定位目标日期
3. 最近访问和筛选不会破坏原有日期阅读结构
4. 对应前端测试通过
