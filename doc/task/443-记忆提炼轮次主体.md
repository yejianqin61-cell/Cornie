# 443 记忆提炼轮次主体（Memory Distillation Turn）

## 背景

当前对话轮次结束后，`orchestrator.runTurn` 尾部（`electron/backend/agent/orchestrator.js` L424-500）无条件执行 6 条记忆写入链（观察日志、Wiki 升级候选、4 个身份 upsert），全部由后端正则/关键词判定"是否记录、记什么"，LLM 无决策权（Cornie-019 §5.1 / Cornie-018 D-18）。

设计定稿（Cornie-019 V1.2 §6）：**是否计入记忆、记什么内容，只由 LLM 决定**；新增对话后"记忆提炼轮次"，LLM 输出结构化决策 JSON，后端只执行与治理；正则全面弃用（V1.1 决策），LLM 不可用时本轮不写入记忆并引导配置 Key。

## 目标

1. 新增记忆提炼轮次：对话结束后由 LLM 对"今日对话片段 + 今日观察摘要 + 相关记忆页摘要"输出结构化决策（observations / identity_updates / memory_wiki_requests）。
2. 后端按决策执行：观察日志 create/update/skip、身份字段走现有 upsert 落库、破坏性 Wiki 动作入治理队列。
3. 落地 `memory_distillation` 审计事件与遥测。

## 范围

- 新增 `electron/backend/agent/memoryDistillation.js`（提炼轮次主体：输入构建、LLM 调用、解析校验、三类提议执行、审计）
- `electron/backend/agent/promptBuilder.js`（新增 `buildMemoryDistillationPrompt`）
- `electron/backend/agent/jsonProtocol.js`（复用 JSON 候选提取与修复重试机制）
- `electron/backend/agent/orchestrator.js`（接入提炼轮次，替换 6 链）
- `electron/backend/observation/service.js`、`electron/backend/identity/*Upsert.js`（被提炼轮次调用的执行入口）

## 设计要求

### 1. 提炼轮次输入（轻量，控成本）

- 今日最近对话 N 条（建议 10 条内，含本轮用户消息与回复）。
- 今日已有观察日志摘要（标题 + 类型，内容截断）。
- 相关记忆页摘要（主身份 + 活跃页，仅 title/summary/pageType，≤6 条）。
- 总量控制在 ~1-2K token。

### 2. LLM 调用

- 低温度（≤0.3）、短输出（maxTokens ≤ 700）。
- 沿用 `jsonProtocol` 的 JSON 解析与修复重试（1 次重试）。
- 支持注入 `chatFn`（默认走 deepseek client），便于验收脚本模拟 LLM 输出。

### 3. 输出 schema（严格校验，字段白名单）

```json
{
  "observations": [
    { "action": "create|update|skip", "type": "event|misc|emotion|idea|note",
      "title": "", "content": "事实提炼，非原话", "observationId": "update 时必填" }
  ],
  "identity_updates": [
    { "entity": "profile|person|preference|trait", "action": "create|update|skip",
      "fields": { "…": "实体白名单字段" } }
  ],
  "memory_wiki_requests": [
    { "action": "create_page|update_page|merge_pages|rollback_page|archive_page|delete_page",
      "pageType": "", "title": "", "body": "", "importance": "",
      "pageId": "", "targetPageId": "", "sourcePageId": "", "versionId": "" }
  ],
  "reasoning": "不超过一句话"
}
```

- schema 非法（未知 entity/action/类型错误）→ 判定为 LLM 不可用，走"不可用策略"（见 443-4），不降级正则。

### 4. 后端执行边界（收窄为执行与治理）

- 观察日志：按提议 create（经 `addNoteSmart` 指纹去重/合并）/ update（按 observationId，不存在则 skip）/ skip。
- 身份页面：LLM 提议字段 → 现有 upsert 落库路径（冲突检测、治理入队、topic 补链保留）；候选不再来自正则（依赖 445）。
- Memory Wiki 请求：create/update 直接执行（ownerConfirmed: false）；merge/rollback/archive/delete 等破坏性动作入治理队列（人类审核）。
- **不可用策略**：LLM 不可用（无 Key/超时/解析失败/schema 非法）时，本轮不写入任何记忆，不创建观察日志、不创建身份页面、不入治理队列；界面引导配置 Key（复用现有配网引导遮罩）。**不做正则兜底。**

### 5. 审计与可观测

- 每次提炼轮次写入 `memory_distillation` 审计事件（提议数/采纳数/跳过数/不可用原因/耗时）。
- 遥测埋点（调用次数、时长、token 估算），沿用 `metrics.js` 模式。

## 验收标准

1. 对话轮次后，观察日志内容为"提炼后的事实"而非"主人/铃湾原话拼接"。
2. 身份字段写入来自 LLM 提议而非正则命中（配合 445 验证）。
3. 破坏性 Wiki 动作进入治理队列，页面未被直接修改。
4. LLM 不可用（模拟无 Key/超时/非法 JSON）时零写入，审计含不可用原因，无正则兜底执行。
5. `data/memory-wiki/audit/events.jsonl` 出现 `memory_distillation` 事件。
