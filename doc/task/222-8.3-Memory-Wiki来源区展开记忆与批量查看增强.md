# 222-8.3-Memory-Wiki来源区展开记忆与批量查看增强

## 1. 任务目标

在 `201` 和 `217` 已建立来源分组阅读能力的基础上，继续细化来源区的展开策略、分组批量查看和状态记忆，让来源核对操作更接近正式治理工作流。

## 2. 背景与现状

来源区是人工判断“这条记忆为什么存在、从哪里来的”的核心证据面板。当前即使已经能分组阅读，仍会遇到：

1. 来源较多时需要反复展开相同分组
2. 用户只想核对某类来源时，切换成本仍然偏高
3. 返回详情页后，来源展开状态容易丢失

## 3. 涉及范围

- Memory Wiki 来源引用区
- 来源分组列表与展开交互
- 对应前端测试

## 4. 前置依赖

1. `201-8.3-Memory-Wiki来源引用区分组阅读与原始来源跳转增强.md` 已完成或至少已有来源分组阅读结构
2. `217-8.3-Memory-Wiki详情页滚动定位与回退体验增强.md` 已完成或至少已有详情页区块回退能力
3. `221-8.3-Memory-Wiki详情区块折叠与阅读密度控制增强.md` 已完成或至少已具备详情区块折叠体系

## 5. 具体开发项

### 5.1 分组展开状态记忆

1. 记住当前页面来源分组最近一次展开状态
2. 从原始来源页返回后，尽量恢复之前展开到的来源分组
3. 页面切换后重置不合理的旧展开状态

### 5.2 批量展开与批量收起

1. 支持“一次展开全部来源”
2. 支持“仅展开有原文摘录的来源”
3. 支持“一次收起全部来源”，回到摘要视图

### 5.3 分组阅读效率增强

1. 在分组头部展示来源数量、最新日期、来源类型等轻量摘要
2. 让用户在不展开全文的情况下，先判断是否值得继续查看
3. 为长来源列表保留稳定的滚动和定位体验

### 5.4 来源展开边界

1. 默认不自动展开过多长文本来源，避免淹没页面
2. 原文引用较长时提供截断与继续查看机制
3. 明确区分“来源摘要预览”和“原始内容全文阅读”

### 5.5 测试补齐

1. 覆盖分组展开状态记忆
2. 覆盖批量展开与批量收起
3. 覆盖长来源截断与继续查看
4. 覆盖从来源跳出再返回后的状态恢复

## 6. 验收标准

1. 来源区可以支撑高频核对场景，而不是只适合偶发查看
2. 用户不需要重复展开相同分组
3. 长来源列表仍保持可读、可控
4. 对应前端测试通过
