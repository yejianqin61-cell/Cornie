# 098 收支补查工具扩展与查询语义补齐

## 1. 任务目标

补齐收支领域第一批只读补查能力，让模型和后端能够稳定完成：

- 按类目查看收支记录
- 查看最近 N 条收支记录
- 批量按 id 查询收支记录

本任务完成后，应至少具备：

- `ledger.list_by_category`
- `ledger.list_recent`
- `ledger.list_by_id_batch`

## 2. 任务来源

- `doc/design/Cornie-0628-工具对齐与记忆治理及测试体系设计.md` 第 4.3 节 A 部分

## 3. 前置依赖

- 当前 `ledger.get_entry / list_today / list_by_range / update_entry / delete_entry` 已存在

## 4. 涉及范围

- `electron/backend/ledger/service.js`
- `electron/backend/ledger/tools.js`
- `electron/db.js`
- `scripts/`
- `package.json`

## 5. 当前问题

当前收支补查能力不足，模型只能：

- 查单条
- 查当天
- 查时间区间

但不能：

- 按类目补查
- 快速回看最近记录
- 批量读取若干指定记录

这会直接影响：

- 记账纠错
- 类目映射追问
- 确认流恢复执行前的信息核对

## 6. 目标设计

### 6.1 服务层要求

- 新增按类目筛选的列表方法
- 新增最近记录查询方法
- 新增批量按 id 读取方法

### 6.2 工具层要求

- 三个工具均为只读
- 风险等级均为 `low`
- 返回结构稳定，适合模型直接二次推理

## 7. 实现步骤

### Step 1

补齐 `ledger/service.js` 的三类只读补查方法。

### Step 2

在 `ledger/tools.js` 注册对应工具。

### Step 3

补最小验证脚本并接入 `package.json`。

## 8. 测试点

- 能按类目正确筛出记录
- 能按时间倒序返回最近记录
- 批量读取时返回顺序稳定、缺失 id 不报错

## 9. 完成标准

- 三个只读补查工具可通过统一工具网关调用
- 返回结构稳定
- 最小验证通过

## 10. 交付物

- 收支补查能力代码
- 对应验证脚本
