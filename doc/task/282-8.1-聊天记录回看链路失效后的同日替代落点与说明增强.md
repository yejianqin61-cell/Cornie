# 282-8.1-聊天记录回看链路失效后的同日替代落点与说明增强

## 1. 任务目标

在 `250` 已补齐聊天记录与 Cornie 日记双向回看面包屑基础上，继续细化“原回看链路失效”时的替代落点、说明文案与状态恢复规则，避免用户从日记或同日总览回到聊天记录时落入空白或错误位置。

## 2. 背景与现状

当前回看链路已经开始具备：

1. 聊天记录到 Cornie 日记的来源说明
2. Cornie 日记回到聊天记录的双向回流提示
3. 聊天记录滚动恢复与锚点跳读基础

但在正式产品化场景里，仍会出现：

1. 原消息锚点已不可用，回流后无法精确回到原位置
2. 该日仍有聊天记录，但精确消息已失效时缺少合理替代落点
3. 用户分不清“没有找到原消息”与“今天根本没有聊天记录”的区别

## 3. 涉及范围

- 聊天记录工作台
- 聊天记录与 Cornie 日记之间的回看回流状态
- 回流提示条、空态提示与替代定位逻辑
- 对应前端测试

## 4. 前置依赖

1. `228-8.1-聊天记录消息区滚动恢复与锚点跳读增强.md` 已完成或至少已有锚点跳读能力
2. `250-8.1-聊天记录与Cornie日记之间的回看面包屑增强.md` 已完成或至少已有双向回看面包屑
3. `255-8.1-同日总览多来源回流提示优先级规则增强.md` 已完成或至少已有多来源回流提示优先级

## 5. 具体开发项

### 5.1 原锚点失效后的替代落点

1. 若原消息锚点失效，但当天仍有聊天记录，则自动回落到该日最近可用消息区域
2. 若该日存在多段可读消息区，优先落到最接近原时间位置的区域
3. 若无法判断接近位置，则回落到当日顶部并明确说明

### 5.2 回流原因说明

1. 明确区分“已回到原消息附近”“原消息未找到，已回到当天记录”“当天无聊天记录”三类文案
2. 说明文案保持轻量，不写成报错弹窗
3. 提供一键回到当天顶部或重新查看日记来源入口

### 5.3 替代落点后的状态保持

1. 替代落点生效后，聊天记录侧栏日期选中状态保持正确
2. 替代落点提示不应覆盖已有同日关系提示的主语义
3. 用户手动继续滚动后，替代落点提示自动降级或收起

### 5.4 异常与边界

1. 跨日期回流时若日期本身已失效，优先回落到最近有聊天记录的日期
2. 数据刷新导致消息数量变化时，不重复弹出多层提示
3. 替代落点逻辑与最近访问、滚动恢复能力兼容

### 5.5 测试补齐

1. 覆盖原消息锚点失效但当日仍有聊天记录时的回落
2. 覆盖整日无聊天记录时的空态说明
3. 覆盖提示条与同日关系提示并存时的优先级
4. 覆盖用户手动继续浏览后的提示退场

## 6. 验收标准

1. 聊天记录回看链路失效时仍有稳定、可理解的替代落点
2. 用户能看懂当前是“精确回看失败”还是“当日数据不存在”
3. 回流提示不打断聊天记录主阅读流
4. 对应前端测试通过
