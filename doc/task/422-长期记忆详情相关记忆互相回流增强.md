# 422-长期记忆详情相关记忆互相回流增强

## 1. 任务目标

当前普通用户在长期记忆详情页中，已经能看到“和它有关的记忆”，但这部分仍停留在静态展示层。  
本任务要补齐相关记忆之间的互相跳转能力，让用户可以顺着记忆网络继续往下读，而不是回到列表重新找。

完成后，普通用户应当能够：

1. 在一页长期记忆中点击“和它有关的记忆”。
2. 直接打开对应的另一页长期记忆详情。
3. 在长期记忆阅读过程中形成自然的页与页之间回流。

## 3. 当前问题

当前长期记忆详情页已经展示：

1. 聊天来源
2. 观察来源
3. 相关记忆

其中：

- 观察来源已经可以回流到观察详情
- 相关记忆仍只能看标题和类型
- 用户如果想继续读另一页，还得退回列表重新找

这会让“相关记忆”失去一半价值，因为它没有真正承担“继续阅读线索”的职责。

---

## 4. 设计原则

1. 保持普通用户语义  
   这是“继续看看和它有关的记忆”，不是页面关系图谱操作。

2. 不暴露治理概念  
   不出现 related graph、link management、source trace 等术语。

3. 仅对可打开的页面提供点击态  
   需要有 `pageId` 或 `id` 才允许跳转。

4. 保持阅读连续性  
   用户点击后应直接进入对应记忆详情，而不是中转复杂页面。

---

## 5. 具体改造

### 5.1 `MemoryPageDetail.vue`

新增一个对外事件：

- `open-memory`

改造相关记忆列表：

1. 对有 `pageId` 或 `id` 的相关记忆项添加点击能力
2. 点击后发出 `open-memory`
3. 事件参数为目标记忆页 id
4. 增加 hover / cursor 提示
5. 在文案上提示可以继续点开阅读

### 5.2 `App.vue`

在普通用户“观察与记忆”主链中接住该事件：

1. 收到 `open-memory`
2. 复用当前 `omDetailId`
3. 切换到 `memory-detail`

这样形成：

`长期记忆详情 -> 另一页长期记忆详情`

的回流链路。

---

## 6. 验收标准

满足以下条件视为完成：

1. 相关记忆卡片可点击进入对应记忆详情
2. 点击后进入正确页面
3. 无 id 的项不会误导性表现为可点击
4. 页面仍保持普通用户口吻
5. 构建通过，不影响现有记忆详情编辑与观察回流
