# 408-记账页类目创建入口与回流闭环

## 1. 任务目标

为记账首页补齐“新建类目”人类侧闭环，让普通用户在记账主流程中可以直接新增收入/支出类目，并在创建成功后无缝回到当前记账动作，不丢失已填写内容。

## 2. 对应来源

- GitHub Issue `#11` 记账页面
- 设计文档：`doc/design/Cornie-0701-GitHub-Issue-011-015前端问题分级与落地设计.md`

## 3. 背景与现状

当前记账相关能力存在以下割裂：

1. 记账表单支持选择已有类目。
2. 类目管理能力存在于独立工作台或其它入口。
3. 但用户在“正在记这一笔”的当下，缺少明确、轻量、可原地完成的新建类目入口。

这会导致：

1. 人类接口与模型工具能力不对齐。
2. 用户被迫离开当前记账上下文。
3. 新建类目后无法顺畅继续记账。

  - `src/renderer/components/LedgerWorkspace.vue`

## 5. 前置依赖

1. 后端已有收支类目创建接口可用。
2. 当前记账页已有类目下拉选择能力。
3. 类目创建失败时，接口能返回基本错误信息。

## 6. 开发项

### 6.1 为记账表单增加“新建类目”入口

在记账首页表单中的类目选择区域附近提供明确入口：

1. 文案建议为 `新建类目`。
2. 入口层级应低于“保存记账”，避免喧宾夺主。
3. 不应跳转到复杂工作台。

### 6.2 新建类目采用轻量交互容器

推荐使用弹层、抽屉或内嵌展开区，而不是整页跳转。

最小必填项：

1. 类目名称
2. 类目类型
   - 收入
   - 支出

如当前记账表单已选中收入/支出类型，则新建类目弹层应默认同步该类型。

### 6.3 创建成功后的原地回流

类目创建成功后，必须完成以下动作：

1. 自动关闭新建类目交互层。
2. 自动刷新类目列表。
3. 自动选中新建类目。
4. 保留当前记账表单中已填写的：
   - 金额
   - 日期
   - 事项
   - 收支类型

不得因为新建类目而重置整张记账表单。

### 6.4 错误态与冲突态处理

至少处理以下场景：

1. 类目名称为空
2. 类目名称重复
3. 接口报错
4. 用户取消创建

要求：

1. 错误提示面向普通用户，不暴露原始技术错误。
2. 取消创建后不影响当前记账内容。
3. 若后端返回重复类目错误，应给出友好提示。

### 6.5 普通用户能力边界收口

本任务只补“为了完成当下记账而新建类目”的最小闭环，不扩大为复杂治理界面。

本期不做：

1. 类目排序治理
2. 类目停用恢复
3. 批量类目编辑

## 7. 实现建议

### 7.1 交互建议

推荐结构：

1. 类目下拉框右侧放 `新建类目`
2. 点击后打开轻量弹层
3. 创建成功后自动回填选择框

### 7.2 状态管理建议

建议为记账页增加独立状态：

1. `showQuickCategoryCreate`
2. `creatingCategory`
3. `categoryCreateError`
4. `draftCategoryName`
5. `draftCategoryType`

### 7.3 数据刷新建议

创建成功后不要粗暴重置整个页面状态，优先：

1. 单独刷新类目列表
2. 更新当前表单的 `categoryId/categoryName`
3. 保留其它表单字段

## 8. 验收标准

1. 用户可在记账首页直接发起“新建类目”。
2. 创建成功后，新类目会自动出现在类目选择框中。
3. 创建成功后，新类目会自动被选中。
4. 当前记账输入内容不会丢失。
5. 重复类目、空名称、接口失败时有友好提示。

## 9. 自测清单

1. 在支出模式下新增一个支出类目，确认创建成功并自动选中。
2. 在收入模式下新增一个收入类目，确认创建成功并自动选中。
3. 先填写金额和事项，再新建类目，确认金额和事项不丢失。
4. 输入重复类目名称，确认提示友好且不清空原有输入。
5. 点击取消，确认记账表单保持原样。
