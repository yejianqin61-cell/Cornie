# 247-8.3-Memory-Wiki历史提醒筛选搜索与批量清理边界增强

## 1. 任务目标

在 `241` 已补齐提醒中心历史区与静默归档视图的基础上，继续增强历史提醒的筛选、搜索和批量清理边界，让历史区长期积累后仍可管理，但不会误删高价值治理痕迹。

## 2. 背景与现状

历史提醒区一旦存在，就会自然积累越来越多记录。若没有进一步管理能力，会出现：

1. 历史区越来越长，难以回顾
2. 用户想清理噪音项，却担心把重要治理痕迹也一起删掉
3. 没有清楚边界时，批量清理会很危险

## 3. 涉及范围

- Memory Wiki 提醒中心历史区
- 历史提醒筛选与搜索工具区
- 批量清理与保留边界提示
- 对应前端测试

## 4. 前置依赖

1. `241-8.3-Memory-Wiki提醒中心历史区与静默归档视图增强.md` 已完成或至少已有历史区
2. `237-8.3-Memory-Wiki提醒中心已读暂缓与再次提醒规则增强.md` 已完成或至少已有提醒状态流转

## 5. 具体开发项

### 5.1 历史区筛选与搜索

1. 支持按已处理、已过期、已暂缓、风险等级、时间范围等条件筛选
2. 支持搜索提醒标题、主题名或相关页面名
3. 保持搜索与筛选轻量，不引入复杂查询负担

### 5.2 批量清理边界

1. 仅允许对低风险、低价值、长期静默的历史提醒进行批量清理
2. 高风险或关键治理痕迹默认不可被一键清空
3. 在清理前明确说明“清理的是提醒视图，不是删除底层治理事实”

### 5.3 安全确认与回退

1. 批量清理前要求轻量确认
2. 清理后保留短暂撤销或恢复入口
3. 若用户筛选条件过宽，系统应提醒当前影响范围

### 5.4 可回顾性保留

1. 即使执行清理，也应保留关键统计或审计摘要
2. 历史区清理后不影响主提醒区当前状态判断
3. 让用户放心清噪，不担心把治理历史完全抹掉

### 5.5 测试补齐

1. 覆盖历史区筛选与搜索
2. 覆盖可清理与不可清理两类项
3. 覆盖批量清理确认与撤销
4. 覆盖高风险项被保护的分支

## 6. 验收标准

1. 历史提醒区可以长期积累且仍可管理
2. 批量清理有明确安全边界
3. 清噪行为不影响关键治理痕迹的可回顾性
4. 对应前端测试通过
