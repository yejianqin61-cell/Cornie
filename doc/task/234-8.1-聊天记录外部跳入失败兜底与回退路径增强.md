# 234-8.1-聊天记录外部跳入失败兜底与回退路径增强

## 1. 任务目标

在 `228` 已补齐聊天记录锚点跳读基础上，继续完善来自观察日志、记忆引用、同日关系面板等外部入口跳入聊天记录失败时的兜底提示与回退路径，避免用户跳进去后迷路。

## 2. 背景与现状

一旦聊天记录支持外部深链定位，就一定会出现目标消息不存在、日期失效、锚点过旧等情况。若没有专门收口，会带来：

1. 用户跳进来却没看到目标内容，不知道是不是系统坏了
2. 消息已变更或不存在时，没有替代定位方案
3. 从外部模块来的上下文关系在失败后完全丢失

## 3. 涉及范围

- 聊天记录外部跳入定位逻辑
- 跳入失败提示卡
- 返回来源模块的回退路径
- 对应前端测试

## 4. 前置依赖

1. `228-8.1-聊天记录消息区滚动恢复与锚点跳读增强.md` 已完成或至少已有锚点跳读
2. `203-8.1-聊天记录与观察日志跨日联动定位增强.md` 已完成或至少已有跨模块定位
3. `199-8.3-聊天侧记忆来源展开卡与引用边界增强.md` 已完成或至少已有记忆来源跳转入口

## 5. 具体开发项

### 5.1 跳入失败分类

1. 区分“日期存在但目标消息不存在”
2. 区分“日期本身不存在或无数据”
3. 区分“定位参数失效”和“加载失败”

### 5.2 兜底定位策略

1. 目标消息不存在时，先回退到对应日期顶部或附近时间段
2. 日期无效时，提供最近相关日期或来源日期提示
3. 无法定位具体消息时，至少保留当天聊天上下文可读性

### 5.3 回退路径提示

1. 明确告诉用户本次是从哪个模块跳来的
2. 支持一键返回来源模块
3. 在失败卡中保留“继续查看当天聊天”与“回到来源页面”两种路径

### 5.4 文案与边界

1. 提示应平实，避免吓人式报错
2. 让用户理解“定位失败”不等于“聊天记录消失”
3. 不把内部参数异常直接暴露成技术细节

### 5.5 测试补齐

1. 覆盖目标消息失效分支
2. 覆盖日期失效分支
3. 覆盖加载失败与兜底回退
4. 覆盖返回来源模块链路

## 6. 验收标准

1. 外部跳入失败时，用户仍有清晰的替代阅读路径
2. 用户能理解自己为何没落到目标消息
3. 来源上下文不会在失败后完全断掉
4. 对应前端测试通过
