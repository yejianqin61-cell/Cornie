# 332-日程月历视图与按日筛选联动

## 1. 任务目标

为日程首页增加顶部月历视图，并实现“点击日期筛选下方日程列表”的联动能力，让用户能快速按天定位安排。

## 2. 对应来源

- GitHub Issue `#5` 日程
- 设计文档：`doc/design/Cornie-0629-GitHub-Issue-001-005前端体验增强落地设计.md`

## 3. 背景与现状

当前日程页仅提供：

1. 今日摘要
2. 快速新增
3. 近期列表

它更像顺序列表，而不是可管理的时间视图。  
用户难以快速回答“某天有没有安排”“这个月哪几天比较满”。

## 4. 涉及范围

- `src/renderer/components/ScheduleHome.vue`
- 建议新增 `src/renderer/components/ScheduleCalendar.vue`
- `src/renderer/api.js`

## 5. 前置依赖

1. Schedule 列表接口可按日期范围查询。
2. 当前页面已有基础列表展示和新增能力。

## 6. 开发项

### 6.1 在日程页顶部新增月历区

月历区至少应提供：

1. 当前年月展示
2. 上一月 / 下一月切换
3. 每天格子的基础展示
4. 今天高亮

### 6.2 渲染有安排日期的标记

对于当前月中有日程的日期：

1. 使用轻量圆点、角标或数量标记
2. 不必初版就展示复杂堆叠

### 6.3 实现日期筛选联动

用户点击某一天后：

1. 该日历格进入选中态
2. 下方列表仅展示该日安排
3. 页面顶部或日历下方展示当前筛选说明

### 6.4 增加快捷恢复入口

至少提供：

1. 回到今天
2. 清除日期筛选，回到“本月全部”或默认列表

### 6.5 与新增表单共存

新增日程表单与日历视图应和平共处：

1. 日历在上
2. 新增区居中段
3. 列表在下

避免表单遮挡或挤压日历的主要阅读空间。

## 7. 实现建议

### 7.1 数据拉取策略

建议按“当前展示月份”请求一次该月数据，再在前端：

1. 计算哪些日期有安排
2. 点击某日后本地过滤下方列表

这样可减少频繁请求。

### 7.2 组件拆分建议

将月历独立成组件，`ScheduleHome.vue` 负责：

1. 当前月份状态
2. 当前选中日期状态
3. 与列表和新增区的联动

### 7.3 初版边界

本任务不做：

1. 周视图
2. 拖拽改期
3. 重复日程高级规则

## 8. 验收标准

1. 日程页顶部可看到稳定可用的月历视图。
2. 有日程的日期具有清晰提示。
3. 点击日期后，下方列表会正确筛选。
4. 可一键回到今天或清除筛选。

## 9. 自测清单

1. 当前月无日程时，月历空态是否自然。
2. 当前月有多天日程时，日期标记是否正确。
3. 点击某一天后，列表是否只显示对应日期内容。
4. 切换月份后，标记和列表是否同步更新。
5. “回到今天”和“清除筛选”是否表现稳定。
