# 326-桌宠共享聊天会话与双窗口同步

## 1. 任务目标

在桌宠壳层完成后，继续把桌宠聊天从“局部自维护消息列表”升级为“与主窗口共享同一份当日会话”的实现，保证桌宠聊天与主窗口聊天同步。

## 2. 背景与现状

当前问题：

1. 桌宠和主聊天页虽然都能调用相同 API，但状态管理没有统一收口。
2. 桌宠端缺乏明确的“只展示最近两条，但同源完整会话”的处理逻辑。
3. 两个窗口在新增消息、恢复历史、待确认恢复时缺乏稳定一致的同步策略。

## 3. 涉及范围

- `src/renderer/composables/useChat.js`
- `src/renderer/CorniePet.vue`
- `src/renderer/components/ChatHome.vue`
- `src/renderer/syncSignals.js`
- 如有必要新增桌宠专用聊天适配层

## 4. 前置依赖

1. `325-桌宠极简壳层与视觉语言首轮落地.md` 已完成。

## 5. 具体开发项

### 5.1 共享会话层收口

1. 让桌宠直接复用共享聊天 composable，而不是再维护一套局部拷贝逻辑。
2. 收口：
   - 历史加载
   - 发送消息
   - 恢复待确认项
   - 滚动到底部
   - 数据变化通知

### 5.2 双窗口同步

1. 桌宠发消息后，主窗口聊天页能看到。
2. 主窗口发消息后，桌宠能同步最新消息。
3. 桌宠显示最新消息时不要求完整展开，但数据源必须是同源的。
4. 若需要额外同步信号，应通过统一事件层实现。

### 5.3 桌宠视图适配

1. 桌宠只展示最近两条消息。
2. 桌宠允许滚动查看更早消息。
3. 桌宠可在发送后、恢复历史后、收到新回复后稳定滚动到正确位置。

## 6. 验收标准

1. 桌宠与主窗口看到的是同一天同一份会话。
2. 双窗口任一侧发送后，另一侧能刷新出最新消息。
3. 桌宠默认只显示最近两条，但可以回看历史。
4. 项目构建通过。
