# 289-8.3-Memory-Wiki来源比较视角在弱数据态下的自动降级与空态衔接增强

## 1. 任务目标

在 `175`、`201`、`222`、`285` 已补齐来源区阅读、分组、展开记忆和跨来源切换基础上，继续细化来源比较视角在“来源过少、来源过散、来源缺正文”场景下的自动降级与空态衔接，避免比较视角在弱数据态反而制造负担。

## 2. 背景与现状

来源比较视角适合多组来源并存的页面，但并不是所有页面都适用。若页面只挂了极少来源，或来源仅有标题没有可读正文，就可能出现：

1. 比较视角存在感过强，但其实没有可比较内容
2. 用户点击“看下一组来源”却进入几乎空白的区块
3. 来源区空态、弱数据态、比较态三者衔接不自然

## 3. 涉及范围

- Memory Wiki 来源阅读区
- 来源比较入口、继续阅读入口与弱数据态表达
- 对应前端测试

## 4. 前置依赖

1. `175-8.3-Memory-Wiki来源引用与关联阅读增强.md` 已完成或至少已有来源区
2. `201-8.3-Memory-Wiki来源引用区分组阅读与原始来源跳转增强.md` 已完成或至少已有来源分组阅读
3. `285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强.md` 已完成或至少已有比较视角基础

## 5. 具体开发项

### 5.1 自动降级判定

1. 当来源组少于比较阈值时，不展示明显比较视角
2. 当来源虽多但正文缺失严重时，比较视角降级为普通顺序阅读
3. 当只有单一来源类型时，不强行展示“切换下一组来源”

### 5.2 弱数据态衔接

1. 明确区分“有来源但信息稀薄”和“几乎没有来源”
2. 比较视角降级后，空态或弱数据态文案要能无缝接上
3. 保留最必要的阅读入口，不让来源区突然显得断层

### 5.3 连续阅读入口收口

1. 在弱数据态下隐藏不必要的“继续比较”入口
2. 如仍保留下一步动作，应改成更平实的“查看剩余来源”
3. 不让用户因为弱数据页面误以为系统坏了

### 5.4 与滚动锚点兼容

1. 比较视角降级后，最近来源阅读位置仍可恢复
2. 不因降级导致滚动锚点跳回顶部
3. 与来源展开记忆和详情区块折叠逻辑兼容

### 5.5 测试补齐

1. 覆盖来源组过少时的比较视角自动降级
2. 覆盖正文缺失严重时的弱数据态衔接
3. 覆盖降级后连续阅读入口的替换文案
4. 覆盖降级前后滚动锚点保持

## 6. 验收标准

1. Memory Wiki 来源比较视角只在真正有价值时出现
2. 弱数据页面不会被过度设计的比较入口干扰
3. 降级后的来源区仍有清楚、连续的阅读路径
4. 对应前端测试通过
