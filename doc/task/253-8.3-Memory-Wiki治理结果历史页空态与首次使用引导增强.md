# 253-8.3-Memory-Wiki治理结果历史页空态与首次使用引导增强

## 1. 任务目标

在 `251` 和 `252` 已补齐治理结果历史页长期浏览和分组摘要能力的基础上，继续收口历史页的空态与首次使用引导，让没有历史数据或历史很少时，页面依然清楚、好懂、不空洞。

## 2. 背景与现状

治理结果历史页如果只为“历史很多”的情况设计，刚开始使用时会显得非常空。常见问题包括：

1. 新用户打开后只有空白，不知道这个页面未来会装什么
2. 历史只有一两轮时，摘要区显得尴尬
3. 用户不清楚“这里记录的是结果历史”还是“当前待处理事项”

## 3. 涉及范围

- 治理结果历史页
- 空态卡与首次使用引导
- 低数据量下的简化视图
- 对应前端测试

## 4. 前置依赖

1. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有历史页
2. `252-8.3-Memory-Wiki治理结果历史页分组摘要与多轮次比较增强.md` 已完成或至少已有摘要区

## 5. 具体开发项

### 5.1 首次使用空态

1. 当治理结果历史还没有数据时，明确说明这里未来会记录什么
2. 引导用户区分“历史页”和“当前待审核池 / 提醒中心”
3. 提供进入当前治理工作台的快捷入口

### 5.2 低数据量简化视图

1. 当历史仅有一轮或两轮时，自动简化摘要区表达
2. 避免在数据太少时硬做趋势和比较
3. 让页面在少量数据下依然自然

### 5.3 无结果与空历史区分

1. 区分“当前筛选无结果”和“历史页还没有数据”
2. 对筛选无结果提供清空筛选或回到最近结果的快捷动作
3. 不让用户把无结果误解为系统异常

### 5.4 文案边界

1. 首次引导文案应平实、直白
2. 不把历史页说成当前工作区
3. 铃湾口吻可以轻轻陪伴，但不应妨碍信息判断

### 5.5 测试补齐

1. 覆盖空历史空态
2. 覆盖低数据量简化视图
3. 覆盖筛选无结果分支
4. 覆盖从空态跳到当前治理工作台入口

## 6. 验收标准

1. 治理结果历史页在首次使用时也能自解释
2. 少量数据场景不显得生硬或空洞
3. 空态、无结果、当前治理入口三者边界清楚
4. 对应前端测试通过
