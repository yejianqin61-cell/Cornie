# 418-观察日志列表页普通用户产品化收口

## 1. 任务目标

把当前观察日志列表页从“开发治理感较强的工具页”，升级成普通用户可以长期使用的正式工作台。

重点不是新增后端能力，而是把现有：

1. 今天视图
2. 历史检索
3. 新建观察
4. 删除观察

这些能力重新包装成更平实、更像生活记录产品的页面。

## 3. 背景与现状

当前观察日志列表页已经具备真实功能，但仍有较重的系统感：

1. 页面说明里出现 prompt / Wiki 补查等偏技术表达
2. “使用边界”卡片更像内部设计注释
3. “历史检索”入口语义偏硬
4. 整个页面能用，但不够像普通用户产品页

## 4. 涉及范围

- `src/renderer/components/ObservationList.vue`

## 5. 开发项

### 5.1 顶部文案去技术术语化

把页头说明改成普通用户能理解的说法，例如：

1. 观察日志是铃湾留下的生活片段
2. 今天页适合看当下的小事
3. 历史页适合回翻以前的片段

不再直接出现 prompt、Wiki、补查、策略之类术语。

### 5.2 使用边界卡片产品化

保留“观察日志不是流水账”的产品理念，但要改成普通用户语义：

1. 为什么不是每句聊天都会记
2. 为什么值得保留的小事会留在这里
3. 这和长期记忆有什么直觉区别

### 5.3 观察卡片阅读感增强

今天页和历史页里的观察卡片，应更像“生活片段卡片”，而不是数据库项：

1. 类型文案使用普通用户标签
2. 标题、日期、片段排版更自然
3. 删除按钮不要太突兀

### 5.4 筛选区与空态优化

让历史页筛选更像“回翻以前的小事”，空态更自然，不像查不到数据。

## 6. 验收标准

1. 列表页整体不再暴露明显技术术语
2. 今天页、历史页、空态文案更贴近普通用户
3. 观察卡片阅读感明显增强
4. 页面仍保持原有功能闭环

## 7. 自测清单

1. 今天页有记录时，检查卡片是否自然
2. 今天页无记录时，检查空态是否自然
3. 历史页切换日期、类型、关键词后仍能正常工作
4. 删除观察后列表刷新正常
5. 手机宽度下筛选区与卡片不应挤坏
