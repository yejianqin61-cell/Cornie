# 105 记忆治理待审核池存储模型与基础读写

## 1. 任务目标

为 `7.2` 的治理待审核区建立正式后端存储模型，支持巡检触发与对话触发的治理候选统一落盘。

本任务完成后，应至少具备：

- 治理待审核项数据结构
- 待审核池持久化文件
- 基础读写、更新状态、列表查询能力

## 2. 任务来源

- `doc/design/Cornie-0628-工具对齐与记忆治理及测试体系设计.md` 第 5.1 节

## 3. 涉及范围

- `electron/backend/memory-wiki/`
- `scripts/`
- `package.json`

## 4. 当前问题

当前已有断链巡检、孤儿页巡检、页面合并等能力，但：

- 没有“待审核池”这一正式存储对象
- 巡检结果不能沉淀为后续可处理的候选
- 对话触发与巡检触发没有统一治理对象

## 5. 目标设计

- 候选项需至少包含：
  - `requestId`
  - `requestType`
  - `triggerSource`
  - `status`
  - `riskLevel`
  - `pageIds / topicKeys`
  - `evidence`
  - `createdAt / updatedAt`
- 状态至少支持：
  - `pending`
  - `approved`
  - `rejected`
  - `deferred`
- 支持按状态、候选类型、触发来源进行列表过滤

## 6. 实现步骤

### Step 1

新增治理待审核项模型与持久化文件格式。

### Step 2

补待审核池基础 store：创建、读取、更新状态、列表查询。

### Step 3

补最小验证脚本。

## 7. 测试点

- 待审核项可创建并持久化
- 可按状态过滤列表
- 可更新为 approved / rejected / deferred

## 8. 完成标准

- Memory Wiki 后端存在正式待审核池
- 基础读写能力稳定
- 最小验证通过

## 9. 交付物

- 待审核池存储代码
- 验证脚本
