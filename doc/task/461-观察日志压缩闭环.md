# 461 观察日志压缩闭环

## 背景

观察日志压缩候选可入队（治理队列），但无 apply 消费端、无自动调度（Cornie-018 D-07）：`enqueueObservationCompressionCandidates` 已存在（`observation/governance.js`），压缩候选悬空，观察日志有流水账膨胀风险。

## 目标

1. 新增压缩执行端 `observation/compressionApply.js`：候选入队 → 人类批准 → 压缩执行 → 原始归档。
2. 接入治理路由，前端待审核区可选展示。
3. 压缩后补 sourceRef 与治理审计事件。

## 范围

- 新增 `electron/backend/observation/compressionApply.js`
- `electron/backend/observation/routes.js` / `electron/backend/observation/governance.js`
- `electron/backend/memory-wiki/routes.js`（治理执行入口同级接入）
- 前端待审核区（可选，`MemoryWikiWorkspace.vue` / `ObservationList.vue`）

## 设计要求

1. `applyObservationCompressionRequest`：读取同日同主题观察日志 → 生成压缩摘要观察 → 归档原始条目 → 补 sourceRef 与审计事件。
2. 接入治理路由（与 `applyGovernanceUpgradeRequest` 同级入口）。
3. 前端待审核区可选展示压缩候选（普通用户界面不强制）。

## 验收标准

1. verify 脚本模拟"候选入队 → 批准 → 压缩执行 → 原始归档"闭环。
2. 压缩后观察日志可读性提升（摘要替代多条流水账），来源可追溯。
3. 治理队列压缩项状态流转正常（配合 459 状态机）。

## 依赖与衔接

- 依赖：459（状态机，压缩项状态流转）。
- 上游设计：Cornie-018 I-08（Phase 2）。
