# 273-8.3-治理结果历史页二级落点提示文案分支增强

## 1. 任务目标

在 `270` 已补齐治理结果历史页滚动恢复失败时的二级落点策略基础上，继续把不同失败原因对应的提示文案分支拆清楚，让用户知道系统是“为什么落在这里”，而不是只看到笼统兜底。

## 2. 背景与现状

二级落点策略一旦明确，下一步就是解释策略本身。若所有情况都只显示同一句“已回到最接近的位置”，会出现：

1. 用户仍然不理解为什么没有回到原位置
2. 不同失败原因的提示区分度不足
3. 兜底逻辑虽然正确，但解释层面不够透明

## 3. 涉及范围

- 治理结果历史页列表区
- 二级落点提示文案
- 失败原因到文案的映射
- 对应前端测试

## 4. 前置依赖

1. `270-8.3-治理结果历史页滚动恢复失败时的二级落点策略增强.md` 已完成或至少已有二级落点矩阵
2. `266-8.3-治理结果历史页跨页返回后的滚动恢复细则增强.md` 已完成或至少已有主恢复逻辑

## 5. 具体开发项

### 5.1 文案分支映射

1. 为“结果被过滤掉”“结果已失效”“分组结构变化”等场景定义不同提示文案
2. 文案应说明落点原因，但不过度展开内部实现
3. 不同场景下提示长度和语气保持一致

### 5.2 主次信息层级

1. 主句说明当前落点结果
2. 次句可简短补充为何没有回到原位置
3. 保持提示轻量，不把列表页变成说明页

### 5.3 空态协同

1. 当二级落点最终转入空态时，提示文案应与空态说明协同
2. 避免用户同时看到两套相互冲突的解释
3. 让文案链路保持连续

### 5.4 国际化与口吻边界

1. 文案保持平实直接
2. 铃湾口吻可保留温度，但不应削弱可判断性
3. 不使用容易引发误判的模糊措辞

### 5.5 测试补齐

1. 覆盖不同失败原因的文案差异
2. 覆盖主次信息层级渲染
3. 覆盖转入空态时的文案协同
4. 覆盖提示关闭后的状态表现

## 6. 验收标准

1. 二级落点提示不再只给笼统说明
2. 用户能更容易理解系统为何停在当前位置
3. 文案与空态、列表逻辑保持一致
4. 对应前端测试通过
