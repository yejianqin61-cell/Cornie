# 267-8.2-Cornie日记来源侧栏重置后的确认反馈微交互增强

## 1. 任务目标

在 `262` 已补齐 Cornie 日记来源侧栏恢复默认入口与偏好重置逻辑的基础上，继续细化重置后的确认、撤销与状态反馈微交互，让“恢复默认”既明确又不生硬。

## 2. 背景与现状

一旦提供恢复默认入口，用户就会需要更细的交互反馈。若没有补足，会出现：

1. 点击后不确定是否真的重置成功
2. 害怕误触，没有安全感
3. 反馈过重又会把简单动作做得像系统设置

## 3. 涉及范围

- Cornie 日记回看页
- 来源侧栏恢复默认入口
- 确认反馈与撤销微交互
- 对应前端测试

## 4. 前置依赖

1. `262-8.2-Cornie日记来源侧栏恢复默认入口与偏好重置增强.md` 已完成或至少已有恢复默认入口
2. `254-8.2-Cornie日记来源侧栏折叠状态记忆与默认密度增强.md` 已完成或至少已有状态记忆

## 5. 具体开发项

### 5.1 触发前确认策略

1. 对低风险的恢复默认动作采用轻量确认，而不是重弹窗
2. 当用户在短时间内重复触发时，可减少确认打扰
3. 明确说明会重置哪些偏好，不夸大后果

### 5.2 执行后反馈

1. 重置成功后给出短暂确认反馈
2. 反馈文案应让用户知道页面已回到推荐状态
3. 反馈表现应轻量，不打断正文阅读

### 5.3 撤销与回退

1. 在合适时间窗口内提供撤销入口
2. 撤销后恢复上一次偏好状态
3. 过期后自然失效，不长期占据界面

### 5.4 弱数据态兼容

1. 在弱数据态日记页执行重置时，反馈仍应解释为“回到适合今天素材量的默认样子”
2. 不让用户误以为重置失败只是因为页面变化不大
3. 保持重置反馈与弱数据态逻辑协调

### 5.5 测试补齐

1. 覆盖恢复默认前的轻量确认
2. 覆盖重置成功后的反馈展示
3. 覆盖撤销入口与撤销恢复
4. 覆盖弱数据态下的反馈差异

## 6. 验收标准

1. Cornie 日记来源侧栏重置动作具有清楚且轻量的反馈
2. 用户对“恢复默认”有足够安全感
3. 微交互不会把简单动作做得过重
4. 对应前端测试通过
