# 376-重要人物关系冲突的治理候选收口

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 中“重要人物关系定义建议进入确认流或至少进入治理候选”的要求，补齐 `identity_person` 在关系冲突场景下的治理候选沉淀链路。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/identity/personUpsert.js`
- `scripts/`

## 4. 当前问题

当前重要人物页如果遇到：

- `relationshipToUser`
- `roleSummary`
- `emotionalWeight`

这类高风险关系字段冲突时，只会：

- 返回 `action: 'conflict'`
- 保留旧值，不直接覆盖

但不会进一步：

- 进入治理候选池
- 为人类留下可见、可审阅、可决策的治理入口

这会导致高风险人物关系冲突停留在隐性状态。

## 5. 目标设计

- 当 `identity_person` 出现关系字段冲突时，自动创建治理候选
- 治理候选中保留：
  - 页面 id
  - 冲突字段
  - 旧值 / 新值
  - 来源消息信息
- 对同一人物页的未决关系冲突避免重复堆积

## 6. 实现步骤

### Step 1

在 `personUpsert` 中新增“人物关系冲突治理候选”辅助方法。

### Step 2

在 `conflict` 分支中创建治理候选，而不是只返回冲突结果。

### Step 3

新增验证脚本，证明关系冲突会沉淀进治理候选池。

## 7. 测试点

- 人物关系冲突不会直接覆盖正式页
- 人物关系冲突会创建治理候选
- 治理候选中能看到冲突字段与旧新值
- `npm run build` 通过

## 8. 完成标准

- `identity_person` 的高风险关系冲突对人类可见
- 重要人物关系定义与 0630 设计稿的治理要求对齐
