# 322-8.1-聊天记录回流与日期切换异步状态的轻播报与读屏可感知性增强

## 1. 任务目标

在 `172`、`194`、`228` 以及 `282-318` 这批聊天记录工作台产品化任务基础上，继续补齐日期切换、回流定位、替代落点降级、刷新后恢复等异步状态变化的轻播报与读屏可感知性，避免界面已经换了上下文，但键盘或读屏用户不知道刚刚发生了什么。

## 2. 背景与现状

当前聊天记录侧已经逐步补齐：

1. 日期摘要与长对话阅读收口
2. 锚点跳读与滚动恢复
3. 回流失败后的替代落点
4. 跨来源切换后的主动作与焦点同步

但若没有异步状态播报，仍会出现：

1. 日期已切换成功，用户却不知道当前读的是哪一天
2. 原始回流落点失效后，系统已降级到替代落点，但用户只看到画面变化
3. 刷新恢复成功或失败后，读屏用户不知道当前处于恢复态、空态还是普通浏览态

## 3. 涉及范围

- 聊天记录工作台日期切换与回流提示区
- 状态切换时的轻提示、读屏播报与非打断式反馈
- 对应前端测试

## 4. 前置依赖

1. `194-8.1-聊天记录日期摘要与长对话阅读收口.md` 已完成或至少已有日期摘要区
2. `282-8.1-聊天记录回看链路失效后的同日替代落点与说明增强.md` 已完成或至少已有替代落点降级
3. `318-8.1-聊天记录跨来源快速切换后键盘焦点回落与主动作同步增强.md` 已完成或至少已有焦点同步

## 5. 具体开发项

### 5.1 日期切换状态播报

1. 用户切换日期后，需要有轻量且不抢主阅读位的状态说明，明确“已切到哪一天”
2. 对键盘与读屏用户，提供可感知的状态播报，不要求用户自己猜测是否已切换成功
3. 同一日期重复点击时，不重复制造高噪声播报

### 5.2 回流降级与替代落点播报

1. 当原始回流目标失效并回落到同日替代落点时，需说明“已改为带你看同日相关位置”
2. 文案保持产品语气平实，不暴露工程术语如“fallback”“anchor miss”
3. 替代落点说明应与页面当前高亮、主动作语义一致

### 5.3 刷新恢复与异常分支播报

1. 刷新后若恢复到上次阅读现场，需有轻量说明帮助用户确认当前上下文
2. 恢复失败或降级为空态时，需明确说明结果，而不是只让界面静默变化
3. 若用户已手动接管浏览，则不再重复播报系统恢复细节

### 5.4 测试补齐

1. 覆盖日期切换成功后的状态播报
2. 覆盖回流失败改走替代落点后的说明分支
3. 覆盖刷新恢复成功、失败、空态降级三类播报
4. 覆盖用户手动接管后的静默规则

## 6. 验收标准

1. 聊天记录关键异步状态变化对普通用户和读屏用户都可感知
2. 状态播报不抢正文和主提示区焦点
3. 替代落点、恢复态、空态之间的说明语义清晰一致
4. 对应前端测试通过
