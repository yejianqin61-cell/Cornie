# 469 双引擎统一

## 背景

聊天记录存在双引擎读写并存（Cornie-018 D-15）：写走 sql.js、读走 better-sqlite3（`server.js` 显式 `CHATLOG_REPOSITORY_DRIVERS.betterSqlite3`），且 `repository.js` L270 明确"better-sqlite3 chatlog repository is not implemented yet"——已注册为运行驱动但实现是死骨架，行为一致性风险高（Cornie-019 后端审查 P0-3）。

## 目标

1. 明确唯一写引擎（推荐 better-sqlite3 全面接管，sql.js 仅作兼容读取/迁移）。
2. 消除"两份真相"（sql.js 内存态 vs better-sqlite3 磁盘态）。
3. 原生依赖打包校验（electron-rebuild）。

## 范围

- `electron/backend/chatlog/repository.js`（实现 better-sqlite3 驱动或明确回退 sql.js 单引擎）
- `electron/backend/server.js`（驱动选择）
- `electron/db.js`（持久化策略配合）
- 打包/依赖脚本（electron-rebuild 校验）

## 设计要求

### 1. 方案决策（二选一，需记录决策）

- 方案 A（推荐）：聊天记录读写全部迁移 better-sqlite3（repository 已抽象，删除 sql.js 写路径）。
- 方案 B：明确 sql.js 保留范围并文档化边界，删除 better-sqlite3 死骨架。

### 2. 一致性

- 读写一致性测试通过（同一文件同一引擎）。
- 删除 `createBetterSqlite3ChatlogRepositorySkeleton` 死骨架（配合 467）。

### 3. 打包校验

- 原生依赖（better-sqlite3）在 Electron 运行时 ABI 匹配校验（electron-rebuild 纳入构建流程）。

## 验收标准

1. 单一引擎路径生效（读与写同一实现）。
2. 读写一致性测试通过。
3. 决策记录写入本任务文档修订。
4. 打包后聊天记录读写正常（原生模块 ABI 校验通过）。
