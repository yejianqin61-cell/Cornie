# 465 删除/合并索引回写

## 背景

`memory-wiki/service.js` 的 `delete` / `mergePages` 不回写 topicIndex 的 `memoryPageIds`、对端页面的 `relatedPageIds`（Cornie-018 D-11），产生孤儿引用，依赖巡检兜底修复。

## 目标

1. delete/merge 时同步清理 topicIndex、对端 relatedPageIds、keyword-index 关联。
2. 删除页保留审计记录。
3. 删除/合并后运行巡检零孤儿发现。

## 范围

- `electron/backend/memory-wiki/service.js`（delete / mergePages）
- `electron/backend/memory-wiki/topicIndex.js`
- 审计（`memory-wiki/audit.js`）

## 设计要求

1. `delete`：清理 topicIndex `memoryPageIds`、对端页面 `relatedPageIds`、keyword-index 关联；保留删除审计。
2. `mergePages`：目标页吸收源页关联后，清理源页在索引中的引用。
3. 删除/合并后运行巡检（460 优化后）零孤儿发现。

## 验收标准

1. 删除/合并后运行巡检零孤儿引用。
2. 索引与页面状态一致（配合 462）。
3. 审计含删除/合并事件。

## 依赖与衔接

- 依赖：460（巡检，作为验收工具）、462（索引一致性）。
- 上游设计：Cornie-018 I-12（Phase 3）。
