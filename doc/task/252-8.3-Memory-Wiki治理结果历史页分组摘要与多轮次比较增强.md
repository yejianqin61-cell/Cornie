# 252-8.3-Memory-Wiki治理结果历史页分组摘要与多轮次比较增强

## 1. 任务目标

在 `251` 已补齐治理结果历史页长期浏览态和筛选持久化的基础上，继续增强历史页中的分组摘要和多轮次比较能力，让用户可以从更高层视角看治理节奏，而不是只能逐条翻结果。

## 2. 背景与现状

当治理结果页开始长期积累后，用户会自然想知道：

1. 最近几轮治理主要在处理什么问题
2. 哪些主题或页面反复出现
3. 某段时间治理成功率或失败情况有何差别

如果只保留逐条列表，就难以支撑这类回顾。

## 3. 涉及范围

- 治理结果历史页
- 分组摘要区
- 多轮次轻量比较视图
- 对应前端测试

## 4. 前置依赖

1. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有历史页稳定浏览能力
2. `238-8.3-Memory-Wiki待审核批量决策前摘要比较面板增强.md` 已完成或至少已有比较面板设计经验
3. `242-8.3-Memory-Wiki批量审核后结果汇总与回退入口增强.md` 已完成或至少已有单轮结果摘要结构

## 5. 具体开发项

### 5.1 分组摘要

1. 按日期、治理类型、结果状态等维度展示历史分组摘要
2. 让用户不进入单轮详情也能先看懂大概发生了什么
3. 摘要区应服务于扫描，而不是替代详情

### 5.2 多轮次比较

1. 支持轻量比较两轮或多轮治理结果的规模和结果差异
2. 可比较成功数、失败数、涉及页面数、主要问题类型等摘要项
3. 不要求完整报表化，但要足够支撑人类回顾判断

### 5.3 高频问题感知

1. 提示哪些主题或页面在多轮治理中反复出现
2. 帮助用户发现“总在返工”的区域
3. 保持表达克制，不把历史页做成预警中心

### 5.4 结果历史与当前治理的关系

1. 支持从历史摘要快速跳到当前仍相关的页面或提醒
2. 让历史页和当前治理工作台之间保持轻量连通
3. 避免历史页变成完全静态的死档案

### 5.5 测试补齐

1. 覆盖历史分组摘要渲染
2. 覆盖两轮及多轮轻量比较
3. 覆盖高频问题提示
4. 覆盖从历史摘要回到当前相关页面的入口

## 6. 验收标准

1. 治理结果历史页不仅能看单轮，也能看多轮趋势
2. 用户可以更快理解过去一段时间的治理节奏
3. 分组摘要与比较能力不破坏历史页的简洁性
4. 对应前端测试通过
