# 375-高优先级人物页跨天稳定注入收口

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 与 `Cornie-0630-记忆层改进治理总纲-第一版.md` 中“高优先级人物稳定注入”的要求，修正 `wikiContext` 的选页策略，避免高优先级 `identity_person` 在无 query 场景下被非默认注入页挤出主链。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/agent/wikiContext.js`
- `scripts/`

## 4. 当前问题

当前主链选页逻辑是：

- profile 固定优先
- 其余页面统一排序后直接按 `pageLimit` 截断

这会带来一个隐蔽问题：

- 无 query 时，`identity_preference` 页面虽然最终不会注入 `memorySummary`
- 但它们仍然先参与 `selectedPages` 截断
- 结果可能把 `importance=high/critical` 的 `identity_person` 挤出选页上限

这样会导致：

- 设计稿要求的“高优先级人物稳定注入”失效
- 主链摘要出现“主身份在，但重要人物消失”的跨天断层

## 5. 目标设计

- 在无 query 场景下，优先保证高优先级 `identity_person` 进入 `selectedPages`
- 不让默认不注入的 `identity_preference` 抢占稳定注入名额
- 保持 query 命中时 preference / trait 的按需召回能力不变

## 6. 实现步骤

### Step 1

在 `wikiContext` 中拆分“稳定人物页候选”和“其余页面候选”。

### Step 2

无 query 时，优先装入高优先级人物页，再装其余页面。

### Step 3

新增验证脚本，证明在 `pageLimit` 很小且 preference 很多的情况下，重要人物页仍能进入主链摘要。

## 7. 测试点

- 无 query 时，高优先级人物页稳定进入主链摘要
- 无 query 时，未命中的 preference 页不再抢占稳定注入名额
- 有 query 时 preference / trait 的条件注入行为不回归
- `npm run build` 通过

## 8. 完成标准

- `identity_person` 的跨天稳定注入与 0630 设计稿对齐
- 选页上限不再误伤高价值人物记忆
