# 382-聊天记录单日前端分页响应标准化补齐

## 1. 任务目标

根据 `Cornie-0630-聊天记录存储与历史归档改造方案.md` 与 `368-聊天记录单日长会话分页与懒加载契约深化.md` 的要求，补齐前端 `getChatlog()` 对单日分页模式响应的标准化适配，让后端已经存在的 `items / nextCursor / hasMore / context` 正式成为前端可依赖契约，而不是仍停留在“只兼容 legacy messages 数组”。

## 2. 任务来源

- `doc/design/Cornie-0630-聊天记录存储与历史归档改造方案.md`
- `doc/task/368-聊天记录单日长会话分页与懒加载契约深化.md`

## 3. 涉及范围

- `src/renderer/api.js`
- `scripts/`

## 4. 当前问题

当前后端在 `mode=page` 时已经返回：

- `items`
- `nextCursor`
- `hasMore`
- `context`

但前端 `getChatlog()` 仍主要只标准化：

- `messages`
- `pagination`

这意味着：

- 前端若直接接 `page` 模式，还要自己再判断一遍后端响应结构
- 单日长会话懒加载契约没有在 renderer API 层真正收口

## 5. 目标设计

- `getChatlog()` 在 legacy / page 两种响应下都返回统一结构
- 至少补齐：
  - `messages`
  - `items`
  - `pagination`
  - `context`
  - `meta.responseType`
- `page` 模式下的 `items` 与 `messages` 保持可并用，降低后续接线复杂度

## 6. 实现步骤

### Step 1

扩展 `getChatlog()` 的响应标准化逻辑，同时兼容 `messages` 与 `items`

### Step 2

把 `nextCursor / hasMore / context` 正式回填到统一返回对象中

### Step 3

新增验证脚本，证明 `mode=page` 响应在 renderer API 层可被稳定消费

## 7. 测试点

- legacy 模式下 `messages` 契约不回归
- page 模式下 `items` 被保留
- page 模式下 `messages` 也能回退拿到同一批消息
- `context / pagination / meta.responseType` 正常保留
- `npm run build` 通过

## 8. 完成标准

- 前端 API 层正式对齐单日分页契约
- 后续长会话懒加载不必再次手写适配分支
