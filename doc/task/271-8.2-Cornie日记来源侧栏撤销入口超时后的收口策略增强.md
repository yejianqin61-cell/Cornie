# 271-8.2-Cornie日记来源侧栏撤销入口超时后的收口策略增强

## 1. 任务目标

在 `267` 已补齐 Cornie 日记来源侧栏重置后的确认反馈与撤销微交互基础上，继续把撤销入口超时后的收口策略拆清楚，避免撤销入口消失前后给用户造成割裂感。

## 2. 背景与现状

撤销入口一旦存在，就必须明确它何时退场、退场后用户还能获得什么反馈。若没有细则，会出现：

1. 撤销入口突然消失，用户不确定是否错过了
2. 超时后页面状态虽然稳定，但缺少收口感
3. 不同重置场景下撤销窗口长短与退场方式不统一

## 3. 涉及范围

- Cornie 日记回看页
- 来源侧栏重置后的撤销入口
- 超时退场与后续反馈
- 对应前端测试

## 4. 前置依赖

1. `267-8.2-Cornie日记来源侧栏重置后的确认反馈微交互增强.md` 已完成或至少已有撤销入口
2. `262-8.2-Cornie日记来源侧栏恢复默认入口与偏好重置增强.md` 已完成或至少已有重置主逻辑

## 5. 具体开发项

### 5.1 超时窗口规则

1. 明确撤销入口可见的时间窗口
2. 针对不同重置强度保持统一规则，避免随机长短
3. 在弱数据态与普通态下保持一致感知

### 5.2 退场收口

1. 撤销入口超时后平滑退场
2. 退场后保留轻量“已应用默认视图”的稳定状态感
3. 不让入口凭空消失得像界面故障

### 5.3 错过撤销后的用户感知

1. 用户错过撤销时，仍能通过恢复偏好入口继续调整
2. 超时后不再保留“假可撤销”错觉
3. 文案与状态反馈帮助用户理解当前已进入稳定态

### 5.4 状态兼容

1. 超时收口后，偏好记忆正式更新为当前默认态
2. 与跨日期回看和弱数据态切换逻辑兼容
3. 不让超时逻辑污染后续新的重置动作

### 5.5 测试补齐

1. 覆盖撤销入口正常超时退场
2. 覆盖超时后稳定态反馈
3. 覆盖错过撤销后的再次调整入口
4. 覆盖连续两次重置动作之间的超时隔离

## 6. 验收标准

1. Cornie 日记来源侧栏撤销入口超时后具备自然收口
2. 用户不会因撤销退场而困惑
3. 超时后的状态更新稳定、可理解
4. 对应前端测试通过
