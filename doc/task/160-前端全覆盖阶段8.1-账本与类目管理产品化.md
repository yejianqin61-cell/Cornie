# 160-前端全覆盖阶段8.1-账本与类目管理产品化

## 1. 任务目标

根据 [Cornie-014-当前项目进度评估文档-V2.md](/C:/Users/USER/Desktop/Cornie/Cornie/doc/Cornie-014-当前项目进度评估文档-V2.md:1) 的 `8.1 第一优先级`，先把“账本页与类目管理页”从当前工作台雏形补到真正可供人类使用的正式前端操作面。

本任务完成后，账本域至少应满足：

1. 人类可直接查看记录列表
2. 人类可新建、编辑、删除记录
3. 人类可查看并管理收入/支出类目
4. 人类可执行类目新增、编辑、停用/恢复
5. 页面结构和交互不再只是测试友好的工作台，而是明确的人类操作入口

## 2. 背景与现状

当前仓库已经存在：

- `src/renderer/components/LedgerWorkspace.vue`
- `src/renderer/api.js` 中对应 ledger / ledger category 接口
- 对应后端路由与工具能力
- 覆盖率与前端测试体系

但从产品化角度看，仍存在问题：

1. 页面更偏“内部工作台”而不是正式操作面
2. 类目管理虽有能力，但交互分层和信息组织仍不够清晰
3. 账本记录与类目治理没有形成明显的人类操作闭环

## 3. 开发范围

涉及范围：

- `src/renderer/components/LedgerWorkspace.vue`
- 如有必要，补充或调整 `src/renderer/App.vue` 中的入口与标题
- 如有必要，补充 `src/renderer/api.js` 的前端使用方式
- 相关前端测试文件

## 4. 具体开发项

### 4.1 账本记录区产品化

补齐或重构以下能力：

1. 列表区与编辑区信息层级更清晰
2. 收入 / 支出记录的筛选、选择、编辑状态更符合人类直觉
3. 新建记录、编辑记录、删除记录路径更明确
4. 空态、失败态、加载态保持统一

### 4.2 类目管理区产品化

补齐或重构以下能力：

1. 类目列表按收入 / 支出分区
2. 当前选中类目、已停用类目、可恢复类目的状态更清楚
3. 新增类目、编辑类目、停用类目、恢复类目形成完整操作闭环
4. 提示文案采用面向普通用户的表达

### 4.3 人类接口全覆盖验收点

本任务完成时，账本域至少应实现：

1. 记录 CRUD
2. 类目新增
3. 类目编辑
4. 类目停用 / 恢复
5. 人类可见的失败提示与操作结果反馈

## 5. 验收标准

1. 账本页面可以完整完成人类账本操作闭环
2. 类目管理不再依赖模型侧工具才能完成
3. 前端测试补齐并通过
4. 不破坏现有 `95%+` 前端测试体系

## 6. 备注

本任务是“前端人类接口全覆盖”阶段的第一步，优先目标是把账本域从“工作台”推进到“正式可用的人类操作面”。
