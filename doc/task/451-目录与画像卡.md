# 451 目录与画像卡（消费侧基座）

## 背景

消费侧渐进钻取架构（Cornie-019 §7）要求把"每轮全量注入"改为"固定小基座 + 按需钻取"。基座的核心是：**用户画像卡（L0）+ 分层目录（L0 常驻 + L1 候选）**，并给 LLM 提供目录条目"三信号"（摘要 + 重要性 + 最近提及/更新时间）以便判断是否钻取。

## 目标

1. 构建 L0/L1 记忆目录（基于 page-index 轻量输出，不逐页读全文）。
2. 用户画像卡：由提炼轮次（443）维护的"关于主人"紧凑摘要卡。
3. 每轮注入量恒定且 ≤ 预算（~1-2K token），目录随记忆库增长不线性膨胀（分层剪枝）。

## 范围

- `electron/backend/agent/wikiContext.js`（按 449 结论改造为基座 + 目录输出）
- `electron/backend/agent/memoryDistillation.js`（443，画像卡更新入口）
- `electron/backend/memory-wiki/service.js`（如需要：轻量目录读取接口，避免 N+1，配合 463）

## 设计要求

### 1. 分层目录

| 层 | 内容 | 规模 |
| --- | --- | --- |
| L0 常驻 | 用户画像卡 + 身份/重要人物/高热度主题目录条目 | 常驻，≤10 条 |
| L1 候选 | 按查询命中 / 热度 / 最近更新排序的目录条目 | 10-20 条，各 30-60 字 |

- 目录条目必含三信号：摘要 + 重要性 + 最近提及/更新时间。
- 剪枝规则（按 449 结论）：身份页常驻，普通页按热度/最近更新取 TOP-N；全量目录走 L2（工具翻页，不注入）。

### 2. 用户画像卡

- 内容：名字/称呼/与铃湾关系/当前阶段/关注/压力/沟通偏好 + 重要人物与偏好要点，≤300 字。
- 维护者：提炼轮次（443）每次提炼后更新画像卡字段（走身份 upsert 落库路径）；本任务只负责"读取侧渲染画像卡"与"画像卡字段来源约定"。

### 3. 注入格式

- 输出给 prompt 的目录/画像文本格式与 LLM 钻取决策匹配（LLM 能据此判断"值不值得钻取、钻哪一页"）。
- 保留现有 fallback：目录构建失败时注入降级文案（现有 `buildWikiContext` 的 catch 分支）。

## 验收标准

1. 目录条目含摘要/重要性/最近提及三信号，可被 LLM 直接决策。
2. 每轮注入量 ≤ 预算（可埋点断言 prompt 字符数）。
3. 画像卡字段来源可溯源到提炼轮次（审计事件）。
4. 100 页规模下目录构建不逐页读全文（配合 463 的 listSummaries 优化）。
