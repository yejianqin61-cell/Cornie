# 452 钻取预算与跨轮缓存

## 背景

消费侧渐进钻取（Cornie-019 §7.3）要求：LLM 可顺着目录逐层钻取读取页面，但必须受预算硬约束（防止延迟叠加与死循环），并配缓存消除重复读取。现状：orchestrator 支持最多 2 轮工具轮（`MAX_TOOL_ROUNDS`），`toolRoundState` 已有轮内只读缓存与域级轮次限制；跨轮页面缓存不存在（对应 Cornie-018 I-11 追溯缓存缺口）。

## 目标

1. 钻取轮次预算：每轮对话最多 3-4 次钻取，单页读取截断。
2. 轮内缓存（已有）确认生效 + 新增跨轮缓存（pageId 短 TTL）。
3. 写侧必失效：页面更新/删除后缓存立即失效。

## 范围

- `electron/backend/agent/orchestrator.js`（钻取轮次预算上限调整）
- `electron/backend/agent/toolRoundState.js`（轮内缓存复用/扩展）
- 新增跨轮缓存模块（如 `electron/backend/memory-wiki/pageCache.js`，进程内短 TTL）
- `electron/backend/memory-wiki/service.js` / `storage.js`（写路径触发缓存失效）
- 消费侧工具执行入口（`memory_wiki.get_page` 等，配合 450）

## 设计要求

### 1. 钻取预算

- 每轮对话钻取轮次上限 3-4（可配置常量，如 `MAX_DRILL_ROUNDS`）。
- 单页读取截断：正文前 N 字符 + 结构化字段（N 建议 2000）。
- 域级只读轮次限制沿用 `toolRoundState.canExecuteReadOnlyLookupRound` 思路，防同一域反复补查。

### 2. 跨轮缓存

- 按 `pageId` 缓存页面读取结果，TTL 建议 60s~5min（可配置）。
- 同一对话连续轮次命中缓存直接返回，不重新读文件/DB。
- 缓存命中计入遥测（沿用 metrics 模式）。

### 3. 写侧失效

- 页面 create/update/delete/rollback/merge/archive 后，对应 pageId 缓存条目立即失效。
- 提炼轮次（443）写入路径同样触发失效。
- 验收覆盖"写后读新"：写入后立刻读取必须拿到新内容。

## 验收标准

1. 同一轮对话内重复钻取同一页：第二次命中缓存（遥测可证）。
2. 写入后立即读取同一页：返回新内容（缓存已失效）。
3. 钻取轮次超预算被截断（无死循环）。
4. 单页读取长度有截断上限。
