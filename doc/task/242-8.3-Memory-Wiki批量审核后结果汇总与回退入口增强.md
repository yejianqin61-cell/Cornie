# 242-8.3-Memory-Wiki批量审核后结果汇总与回退入口增强

## 1. 任务目标

在 `231` 和 `238` 已补齐待审核池排序、批量浏览与决策前比较面板的基础上，继续补全批量审核完成后的结果汇总页和回退入口，让一组治理动作结束后有清晰收口。

## 2. 背景与现状

批量审核前的工作流越来越完整后，后半段也需要被照顾。否则会出现：

1. 用户批量处理完一组候选后，不清楚刚才到底处理了哪些
2. 成功、失败、跳过的候选混在一起，没有一个统一总结
3. 缺少返回待审核池、继续处理下一组或查看相关页面的明确路径

## 3. 涉及范围

- Memory Wiki 待审核池批量处理收口页
- 批量处理结果摘要卡
- 回退入口与下一步动作区
- 对应前端测试

## 4. 前置依赖

1. `231-8.3-Memory-Wiki待审核池排序模式与批量浏览增强.md` 已完成或至少已有批量浏览能力
2. `238-8.3-Memory-Wiki待审核批量决策前摘要比较面板增强.md` 已完成或至少已有决策前比较面板
3. `185-8.3-Memory-Wiki页面合并审核工作台增强.md` 或其他治理详情任务已提供基础审核动作

## 5. 具体开发项

### 5.1 批量结果汇总

1. 对本次批量处理展示总数、成功数、跳过数、失败数
2. 让用户一眼看懂本轮治理完成了什么
3. 失败项要单独可见，不与成功项混淆

### 5.2 结果分组阅读

1. 支持按成功、失败、跳过分组查看本次结果
2. 对成功项提供查看页面或相关 Topic 的快捷入口
3. 对失败项提供重试或返回单条处理的入口

### 5.3 回退与下一步动作

1. 提供返回待审核池的入口
2. 提供继续处理下一组候选的入口
3. 在合适情况下提供查看刚变更页面或相关巡检结果的入口

### 5.4 收口体验

1. 批量结果页应有明确“这一轮结束了”的收束感
2. 不把结果页做成又一个冗长列表
3. 让用户在结束一轮治理后能自然决定下一步

### 5.5 测试补齐

1. 覆盖批量结果汇总渲染
2. 覆盖成功 / 失败 / 跳过分组阅读
3. 覆盖返回待审核池与继续下一组入口
4. 覆盖存在部分失败时的兜底收口

## 6. 验收标准

1. 批量审核后具备明确的结果收口
2. 用户能快速理解本轮治理成效与遗留问题
3. 结果页提供清晰的下一步路径
4. 对应前端测试通过
