# 438-普通用户长期记忆入口去治理术语与能力边界收口

## 1. 任务目标

在普通用户长期记忆入口中，继续清理残留的技术术语、治理术语和高级字段表达，把“能做什么、不能看到什么”进一步固化为产品边界。

本任务重点不是新增功能，而是收口边界，让普通用户看到的始终是“铃湾帮我记住的内容”，而不是“系统治理对象”。

## 2. 对应来源

- `doc/design/Cornie-0701-记忆层存储与长期记忆前端入口设计说明.md`
- 第 6、7、8.2、9.2、10.2 节

## 3. 背景与现状

前序任务已经做过一轮普通用户长期记忆产品化，但按照 0701 文档的要求，仍需要再做一次专门的边界收口。

风险点主要有三类：

1. 某些组件内部仍可能带出技术字段名或系统感很重的文案
2. 来源、状态、附加信息展示时，容易不小心把治理语义带给普通用户
3. 后续开发如果没有明确“禁止暴露项”，边界会再次变松

## 5. 开发项

### 5.1 全面清理普通入口中的治理术语

要求在普通用户记忆入口中，不直接出现或不突出出现以下内容：

1. Topic Index
2. governance
3. audit
4. rollback
5. diff
6. pageType
7. alias
8. internal status

若底层字段确实存在，也必须先翻译成普通用户能理解的表达，或干脆不展示。

### 5.2 来源信息保持轻量阅读态

来源信息允许存在，但表达原则是：

1. 告诉用户“这条记忆大致从哪来”
2. 不把用户带入治理、审计、索引视角
3. 优先使用“聊天里提到过”“观察里记下过”“铃湾后来整理进记忆里了”这类平实表达

### 5.3 主动作只保留普通用户必要操作

普通入口里，主动作应只围绕：

1. 查看
2. 新建
3. 编辑
4. 删除

不应把高级动作混进同一层主操作区。

### 5.4 空态与提示语义统一

空态和弱提示需要统一口径：

1. 平实
2. 易懂
3. 可以带一点铃湾口吻
4. 不要出现“治理、索引、审计、版本控制”这类系统术语

## 6. 不做事项

本任务不处理：

1. 新增高级能力
2. 工作台内部文案治理
3. Topic Index 页面产品化
4. 长期记忆后端协议改造

## 7. 验收标准

1. 普通用户长期记忆入口中不再直接暴露治理术语
2. 来源信息对普通用户可读，但不会把用户带入系统抽象层
3. 主操作区只保留普通用户必要操作
4. 空态、错误态、轻提示整体语义统一

## 8. 自测清单

1. 通读普通用户长期记忆首页、列表页、详情页，检查是否还有明显技术词
2. 打开来源摘要，检查是否仍有系统内部语义直出
3. 检查主按钮和次级按钮，确认未混入高级动作
4. 检查空态、加载态、失败态文案，确认口径一致
