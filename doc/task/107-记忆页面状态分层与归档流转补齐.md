# 107 记忆页面状态分层与归档流转补齐

## 1. 任务目标

把长期记忆页面状态从当前的 `draft / active / archived` 拓展为正式设计中的 `active / inactive / archived` 分层，并补齐归档流转能力。

本任务完成后，应至少具备：

- `inactive` 状态正式可用
- active / inactive / archived 状态流转
- 页面列表与摘要查询可按分层过滤

## 2. 任务来源

- `doc/design/Cornie-0628-工具对齐与记忆治理及测试体系设计.md` 第 5.2 节

## 3. 涉及范围

- `electron/backend/memory-wiki/pageModel.js`
- `electron/backend/memory-wiki/service.js`
- `electron/backend/memory-wiki/storage.js`
- `scripts/`
- `package.json`

## 4. 当前问题

当前 Memory Wiki 页面缺少正式的 `inactive` 层，导致：

- “不默认装载但仍可检索”的页面没有清晰状态
- 归档候选只能粗暴落到 archived
- 后续热度衰减和压缩策略无法依赖稳定分层

## 5. 目标设计

- `active`：默认装载
- `inactive`：不默认装载，但允许检索
- `archived`：仅强相关检索或人工查看

## 6. 实现步骤

### Step 1

补状态合法值与默认行为。

### Step 2

补服务层归档、降级、恢复流转能力。

### Step 3

补最小验证脚本。

## 7. 测试点

- 页面可切换到 inactive
- inactive 页面仍可被读取
- archived 页面可恢复

## 8. 完成标准

- 分层状态正式可用
- 流转语义清晰
- 最小验证通过

## 9. 交付物

- 状态分层代码
- 验证脚本
