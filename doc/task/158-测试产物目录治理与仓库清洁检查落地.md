# 158-测试产物目录治理与仓库清洁检查落地

## 1. 任务目标

在 `8.6 收紧测试产物与工程清洁度` 内，先处理当前最直接的仓库污染源：测试、验证脚本和专项检查脚本在仓库根目录落下大量 `tmp-*.sqlite` 临时产物。

本任务目标是把这类临时数据库统一收敛到专用临时目录，并补仓库清洁检查入口，确保后续跑验证时不再把仓库根目录越跑越脏。

## 2. 背景与现状

根据当前仓库实际状态：

1. 根目录存在大量 `tmp-task*.sqlite`、`tmp-tools-test-*.sqlite`、`tmp-service-test-*.sqlite` 文件
2. 虽然 `.gitignore` 已忽略 `*.sqlite`，但工程观感和人工排查体验仍然很差
3. 多个高频脚本仍直接使用 `./tmp-xxx.sqlite` 作为输出路径
4. `8.5` 已完成前端测试体系收口，进入 `8.6` 后应优先解决这类长期积累的工程卫生问题

## 3. 开发范围

本任务聚焦于“统一临时数据库目录 + 清理工具 + 清洁检查”这条主线，不在本任务中一次性改完所有历史脚本。

优先范围：

- `tests/shared/service-harness.mjs`
- `tests/tools/registry-gateway.test.mjs`
- `tests/policy/tool-policy.test.mjs`
- `scripts/verify-category-flow.mjs`
- `scripts/verify-ledger-tools.mjs`
- `scripts/verify-task048-tools.mjs`
- `scripts/verify-task049-tools.mjs`
- `scripts/verify-task050-policy.mjs`
- `scripts/verify-task098-ledger-read-tools.mjs`
- `scripts/verify-task099-ledger-category-tools.mjs`
- `scripts/verify-task100-todo-reopen-tools.mjs`
- `scripts/verify-task101-category-management-tools.mjs`
- `scripts/verify-task102-schedule-lifecycle-tools.mjs`
- `package.json`
- `.gitignore`
- `scripts/` 下新增临时目录/清洁检查辅助脚本

## 4. 具体开发项

### 4.1 统一临时目录能力

新增统一 helper，提供：

1. 获取仓库级临时目录，如 `tmp/runtime-tests/` 或等价路径
2. 为 caseName 生成唯一 sqlite 路径
3. 确保目录存在
4. 可选清理指定前缀的旧临时文件
5. 能区分“历史遗留根目录产物”和“本次运行新产生的根目录产物”

### 4.2 高频 sqlite 产物脚本改造

优先把当前最常用、最容易污染根目录的脚本改为写入统一临时目录：

1. policy tests
2. tools tests
3. service harness
4. 7.1 相关 ledger / todo / schedule / category verify 脚本
5. `verify-category-flow.mjs` 内仍使用仓库根目录 tmp sqlite 的分支

### 4.3 仓库清洁检查入口

补充脚本与命令：

1. 检查仓库根目录是否仍残留新的 `tmp-*.sqlite*`
2. 检查临时目录是否可被集中清理
3. 提供一个显式清理命令，便于开发者手动执行
4. 提供一次性清理历史根目录 `tmp-*.sqlite*` 的命令，帮助仓库恢复到干净基线

### 4.4 忽略与文档收口

补充：

1. `.gitignore` 中对统一临时目录的忽略
2. 必要时补充 coverage / tmp 目录的说明
3. 更新 `8.6` 后续验收时需要引用的清洁检查结果

## 5. 验收标准

完成本任务时，至少应满足：

1. 新增统一临时目录 helper 或等价机制
2. 上述高频脚本不再把 sqlite 产物默认写到仓库根目录
3. 存在可执行的仓库清洁检查命令
4. 存在可执行的临时产物清理命令
5. 跑相关验证后，仓库根目录不再新增 `tmp-*.sqlite` 文件

## 6. 备注

本任务是 `8.6` 的第一步，不要求一次性改完所有历史脚本，但必须先把最常用、最显眼、最容易反复制造脏产物的路径收口。
