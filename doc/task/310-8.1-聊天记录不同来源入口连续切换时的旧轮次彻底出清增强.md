# 310-8.1-聊天记录不同来源入口连续切换时的旧轮次彻底出清增强

## 1. 任务目标

在 `302`、`306` 已补齐聊天记录同来源重复触发和关闭记忆隔离基础上，继续细化用户在不同来源入口之间连续切换时，旧轮次状态如何被彻底出清，避免 A 来源的关闭、失活或引导逻辑串到 B 来源上。

## 2. 背景与现状

聊天记录后续会承接多个来源入口：

1. 同日总览
2. Cornie 日记
3. 观察日志
4. 其他历史导航入口

当用户快速在不同入口之间切换时，如果轮次边界不够干净，会出现：

1. A 入口的关闭状态影响 B 入口
2. B 入口进来时还残留 A 入口的提示文案
3. 用户感觉系统把不同来源混成了一锅

## 3. 涉及范围

- 聊天记录工作台
- 多来源入口切换时的轮次切换与状态出清
- 提示文案、落点和关闭记忆的来源隔离
- 对应前端测试

## 4. 前置依赖

1. `302-8.1-聊天记录已失活回流提示在同来源重复触发时的新旧轮次判定增强.md` 已完成或至少已有同来源轮次判定
2. `306-8.1-聊天记录同来源新轮次重开后再次手动关闭的记忆隔离增强.md` 已完成或至少已有关闭作用域隔离
3. `286-8.1-聊天记录多入口回流并发时的主落点判定与提示降级增强.md` 已完成或至少已有多入口基础规则

## 5. 具体开发项

### 5.1 来源切换即出清

1. 当来源从 A 切到 B 时，A 的主引导状态应立即失活
2. A 的关闭记忆不得被 B 继承
3. B 应获得独立的新轮次判定资格

### 5.2 文案与落点隔离

1. 来源切换后，顶部提示文案只允许使用当前来源语义
2. 自动落点只服务当前来源，不延续旧来源锚点
3. 次级来源说明也不得保留误导性旧标签

### 5.3 快速切换边界

1. 用户短时间内来回切换多个来源时，状态机仍保持单一当前来源
2. 不因快速切换造成多条提示同时复活
3. 用户最后一次明确点击的来源应成为唯一主来源

### 5.4 与空态/手动接管兼容

1. 来源切换后若目标日期为空，应按新来源重算空态说明
2. 用户手动接管后，旧来源状态仍不得回流
3. 与刷新防重放和最近访问恢复规则兼容

### 5.5 测试补齐

1. 覆盖 A 来源切到 B 来源时的旧轮次出清
2. 覆盖关闭状态不跨来源继承
3. 覆盖快速多来源切换后的最终主来源判定
4. 覆盖切到空态日期时的新来源空态重算

## 6. 验收标准

1. 聊天记录不同来源入口之间不会互相串味
2. 用户无论怎么切入口，最后都只有一个清楚当前来源
3. 旧来源的关闭、失活和文案不会污染新来源
4. 对应前端测试通过
