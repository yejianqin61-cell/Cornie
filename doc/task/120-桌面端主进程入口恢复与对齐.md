# 120 桌面端主进程入口恢复与对齐

## 1. 任务目标

恢复 Cornie 桌面端正式主进程入口，让 `package.json` 指向的 Electron 启动文件重新回到可运行状态。

## 2. 任务来源

- `doc/Cornie-013-当前项目完成度复评与后续行动建议.md` 第 `8.1` 节

## 3. 前置依赖

- 无

## 4. 涉及范围

- `electron/main.cjs`
- `electron/main.js`
- 必要时补充 `package.json`

## 5. 当前问题

当前 `electron/main.cjs` 不是正式主进程入口，而是调试退出脚本；与此同时，真实桌面端启动逻辑实际位于 `electron/main.js`。这导致工程存在“启动实现存在，但正式入口失效”的断层。

## 6. 目标设计

- 恢复 `electron/main.cjs` 为正式 Electron 主入口
- 让 `main.cjs` 与 `main.js` 的职责关系清晰
- 消除当前调试脚本导致的启动异常

## 7. 实现步骤

### Step 1

确认 `main.js` 中现有主进程实现是否可作为正式入口使用。

### Step 2

重写 `main.cjs`，使其作为稳定桥接入口加载正式主进程实现，而不是继续执行调试退出脚本。

### Step 3

核对 `package.json`、Electron 启动路径与开发/打包时的主入口关系。

## 8. 测试点

- `electron/main.cjs` 不再直接 `process.exit(0)`
- Electron 启动时会进入正式主进程逻辑
- 不破坏现有 `main.js` 的桌面端窗口创建与本地 API 启动逻辑

## 9. 完成标准

- `main.cjs` 被恢复为正式主入口
- 桌面端启动链路不再停在调试脚本

## 10. 交付物

- 恢复后的 `electron/main.cjs`
