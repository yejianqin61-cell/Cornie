# 275-8.2-Cornie日记来源判定矩阵在跨日期回流中的一致性增强

## 1. 任务目标

在 `272` 已补齐 Cornie 日记来源弱数据态与固定偏好冲突判定矩阵基础上，继续明确该矩阵在跨日期回流、跨模块回流和同日总览往返中的一致性要求，避免不同入口走出不同结论。

## 2. 背景与现状

判定矩阵一旦存在，就不只要在“直接打开某天日记”时生效，还要在各种回流链路下保持一致。否则会出现：

1. 直接打开日记和从同日总览回流打开日记表现不同
2. 从聊天记录或观察日志跳入时走了另一套判定
3. 用户很难理解为什么同一天的页面展示前后不一样

## 3. 涉及范围

- Cornie 日记回看页
- 跨日期切换
- 从同日总览 / 聊天记录 / 观察日志回流到日记页的入口
- 对应前端测试

## 5. 具体开发项

### 5.1 入口一致性规则

1. 明确无论从哪个入口进入同一天日记，都应套用同一判定矩阵
2. 不允许不同入口偷偷覆盖矩阵优先级
3. 将入口差异限制在提示说明层，而不是展示结果层

### 5.2 跨日期一致性

1. 从 A 日切到 B 日再切回 A 日时，矩阵判定结果保持一致
2. 回流链路中的临时提示不应污染核心展示判定
3. 保持与固定偏好、恢复默认和弱数据态的组合逻辑稳定

### 5.3 可验证性

1. 让开发与测试可以基于统一矩阵验证所有入口
2. 将“入口不同但结果应相同”的场景明确列为验收要求
3. 避免实现时出现隐性分叉

### 5.4 例外边界

1. 若某入口只携带部分上下文，也只能影响提示，不应影响矩阵主判定
2. 若数据在回流过程中发生变化，应重新按同一矩阵计算
3. 明确什么是合法差异，什么是不允许的漂移

### 5.5 测试补齐

1. 覆盖直接打开日记与从同日总览回流的矩阵一致性
2. 覆盖从聊天记录 / 观察日志回流的矩阵一致性
3. 覆盖跨日期往返后的判定稳定性
4. 覆盖数据变化后的重新计算

## 6. 验收标准

1. Cornie 日记来源判定矩阵在各种入口下保持一致
2. 回流链路不会偷偷改变核心展示结果
3. 开发和测试可以据此建立统一验收口径
4. 对应前端测试通过
