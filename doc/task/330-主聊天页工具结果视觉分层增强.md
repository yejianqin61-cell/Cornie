# 330-主聊天页工具结果视觉分层增强

## 1. 任务目标

增强主聊天页中“工具已调用 / 已执行 / 待确认 / 失败”的视觉反馈层次，让用户一眼看懂铃湾这轮到底只是回复了，还是已经帮自己做了事。

## 2. 对应来源

- GitHub Issue `#3` 主聊天页面
- 设计文档：`doc/design/Cornie-0629-GitHub-Issue-001-005前端体验增强落地设计.md`

## 3. 背景与现状

当前聊天页已经存在：

1. 普通用户气泡
2. 铃湾回复气泡
3. 工具结果面板
4. 追问卡
5. 确认卡

但目前问题是：

1. 普通回复和“已完成工具执行的回复”差异不够明显。
2. 工具结果面板视觉存在感不够强。
3. 用户不容易迅速理解这轮交互是否已经落库、是否需要确认。

## 4. 涉及范围

- `src/renderer/components/ChatHome.vue`
- `src/renderer/components/ToolResultPanel.vue`
- `src/renderer/components/ConfirmCard.vue`
- `src/renderer/style.css`

## 5. 前置依赖

1. 当前聊天流、工具结果流和确认流已基本可用。
2. 前端视觉方向以“轻量、可爱、清晰”为主，不再走重型治理面板路线。

## 6. 开发项

### 6.1 建立消息状态分层

至少区分以下视觉层级：

1. 普通回复
2. 本轮已调用工具后的回复
3. 待用户确认的动作
4. 工具执行失败或异常提示

### 6.2 强化工具回复气泡

对于工具调用完成后的铃湾回复：

1. 使用更强对比度的气泡底色或边框。
2. 可加入轻量前缀提示，例如：
   - 已帮你记下
   - 已写进待办
   - 已加入日程
3. 保持与普通铃湾回复同一视觉家族，不能突兀像报错框。

### 6.3 优化工具结果卡

`ToolResultPanel` 需要增强以下部分：

1. 卡片头部增加状态标题。
2. 针对不同工具结果类型提供更清楚的摘要。
3. 让工具结果卡与普通消息之间保持留白与层次。
4. 如果一轮有多条结果，清楚区分每条结果，而不是糊成一块。

### 6.4 确认卡与结果卡的连续性

对于“需要确认”的动作：

1. 确认卡应明显区别于普通回复。
2. 用户确认后，后续结果卡与回复应让人能感知“这是刚刚那张确认卡的后续结果”。
3. 若当前实现中确认后结果回显较弱，可补轻量标题或关联说明。

### 6.5 失败态与兜底态

1. 工具失败应使用明确的危险色，但不要过度惊悚。
2. 失败态需要保留可读性，不能只靠颜色表达。
3. 对于 ask-back、deny 等情况，保持提示样式与错误样式区分。

## 7. 实现建议

### 7.1 样式变量

在全局样式中补统一变量，避免组件内直接写死颜色：

1. `--chat-tool-accent`
2. `--chat-confirm-accent`
3. `--chat-error-accent`
4. `--chat-tool-surface`

### 7.2 组件判断方式

建议通过消息结构或最近一轮工具执行结果，给对应消息增加 class，而不是在模板中堆过多内联判断。

### 7.3 不建议做的事

本任务不建议引入：

1. 大量装饰图案
2. 复杂动效
3. 面向普通用户的专业术语标签

## 8. 验收标准

1. 用户可快速分辨普通回复与工具执行回复。
2. 工具结果卡的结构层次明显增强。
3. 待确认、成功、失败三类状态清晰可辨。
4. 整体页面不因增强反馈而变得拥挤或嘈杂。

## 9. 自测清单

1. 发送普通闲聊消息，确认样式正常。
2. 发送记账消息，确认“已记下”的反馈比普通回复更显眼。
3. 发送需确认的动作，确认卡样式足够醒目。
4. 人工制造失败场景，检查失败态是否清晰。
5. 连续多轮工具调用时，界面是否仍然整洁。
