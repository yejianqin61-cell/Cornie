# 453 联想式层间话语（消费侧核心交互）

## 背景

Cornie-019 V1.2 §7.4 定稿：层间话语**不是流程播报**（"让我找找""正在查询记忆"是胡扯），而是基于本轮已见目录/内容的**联想话语**——铃湾"想起了什么"，而不是"在检索什么"。联想内容必须基于本轮已见内容（防虚构护栏），并可被用户确认/纠正后回流为记忆信号。

## 目标

1. 钻取轮之间，LLM 输出基于已见目录/页面内容的联想话语，实时亮到气泡。
2. 护栏：联想可溯源本轮输入，禁止编造"我记得你…"的未见过内容。
3. 用户对联想话语的确认/纠正回流提炼轮次（443），成为高置信度记忆信号。

## 范围

- `electron/backend/agent/promptBuilder.js`（钻取/对话 prompt 增加联想规则与护栏）
- `electron/backend/agent/memoryDistillation.js`（443，确认/纠正信号接收入口）
- 前端消息渲染（`src/renderer/composables/useChat.js` 及聊天组件，`assistant_reply` 实时上屏）
- 协议层（`jsonProtocol.js`，`assistant_reply` 字段语义确认）

## 设计要求

### 1. 联想规则（prompt 指令）

- 每次决定读取一页记忆时，若已见内容触发联想，用一句话说出（"嗯……她是你高中同桌，你总说她笑起来眼睛弯弯的。"）。
- 联想必须基于本轮已见内容（目录条目或页面片段），像"哦对…""我记得…""提到这个…"。
- 没有联想就不说；**不得播报查找过程**（"让我找找"等文案禁止）。
- 输出位置：钻取请求 `assistant_reply` 字段。

### 2. 防虚构护栏

- 联想内容必须能溯源到本轮输入中的某条目录/某段文字；拿不准就沉默。
- 审计记录联想文本供抽查（可并入 `memory_distillation` 审计或对话遥测）。
- 验证用例：mock LLM 输出含未见过内容联想时，验收判定其违反护栏（或在 prompt 层拦截）。

### 3. 确认/纠正回流

- 用户对联想话语的回复（"对！""不是啦"）作为记忆信号：
  - 确认 → 强化/固化对应记忆（提高 evidence/importance，或直接批准治理候选）；
  - 纠正 → 修正记忆（写入纠错记录，进入提炼轮次输入）。
- 回流通道与提炼轮次（443）输入对齐，本任务定义信号格式与触发时机。

### 4. 上屏

- 钻取轮 `assistant_reply` 实时渲染为气泡消息（短句），随后最终回复接续。
- 前端不把联想话语当最终答案落库；最终回复仍走现有 `saveMessage`。

## 验收标准

1. 全库无流程播报文案（"让我找找""正在查询""已检索"等）作为层间话语。
2. mock 钻取场景：联想话语可溯源到本轮输入内容。
3. 用户"对/不是啦"回复产生对应记忆信号（确认/纠正）并进入提炼轮次输入或治理队列。
4. 联想话语实时上屏，最终回复正常接续并落库。

- 衔接：454（流式说话段，联想与流式分层）。
