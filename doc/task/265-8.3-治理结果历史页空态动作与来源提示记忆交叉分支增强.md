# 265-8.3-治理结果历史页空态动作与来源提示记忆交叉分支增强

## 1. 任务目标

在 `260`、`261`、`263` 已补齐治理结果历史页空态、来源提示记忆和空态动作排序基础上，继续处理“空态动作推荐”和“来源提示关闭记忆”交叉时的规则，避免两套机制互相干扰。

## 2. 背景与现状

历史页在跨页回流后若刚好无结果，页面会同时进入：

1. 来源提示可能需要降级或隐藏
2. 空态动作需要推荐下一步
3. 用户又可能此前手动关闭过某类来源提示

如果没有交叉规则，页面会显得忽明忽暗、逻辑不稳。

## 3. 涉及范围

- 治理结果历史页
- 空态动作区
- 来源提示记忆与显示逻辑
- 对应前端测试

## 4. 前置依赖

1. `260-8.3-治理结果历史页跨页回流后的空态降级与语义澄清增强.md` 已完成或至少已有空态降级逻辑
2. `261-8.3-治理结果历史页手动关闭来源提示后的记忆规则增强.md` 已完成或至少已有来源提示关闭记忆
3. `263-8.3-治理结果历史页空态下次级入口排序与默认动作增强.md` 已完成或至少已有空态动作排序

## 5. 具体开发项

### 5.1 交叉展示规则

1. 当空态动作区出现时，来源提示默认降为次级说明
2. 若用户曾手动关闭来源提示，则空态动作区不应再次被其抢焦点
3. 若来源提示承载关键风险语义，则允许在空态中保留最低可见度

### 5.2 动作优先级保护

1. 空态下最相关的恢复动作始终保持主位置
2. 来源提示不应挤占主动作按钮区域
3. 若无主动作必要，则来源说明可稍微上浮，但仍不主导页面

### 5.3 记忆与重现边界

1. 用户关闭提示后的记忆在空态场景下继续生效
2. 但当来源链路出现关键变化时，次级说明仍可温和重现
3. 避免因交叉逻辑导致提示时有时无、难以预测

### 5.4 恢复默认兼容

1. 若用户重置筛选或清空空态条件，来源提示恢复到正常评估逻辑
2. 保持空态解除前后行为连续
3. 不让空态时期的特殊处理污染普通历史浏览态

### 5.5 测试补齐

1. 覆盖空态动作与来源提示并存时的层级关系
2. 覆盖用户曾关闭提示后的空态表现
3. 覆盖关键变化下的次级提示重现
4. 覆盖解除空态后的逻辑恢复

## 6. 验收标准

1. 治理结果历史页在空态与来源提示记忆交叉时仍保持清楚主次
2. 用户能稳定看到最该执行的下一步动作
3. 交叉逻辑不制造突兀和随机感
4. 对应前端测试通过
