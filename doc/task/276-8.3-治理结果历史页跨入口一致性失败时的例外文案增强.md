# 276-8.3-治理结果历史页跨入口一致性失败时的例外文案增强

## 1. 任务目标

在 `273` 已补齐治理结果历史页二级落点提示文案分支的基础上，继续细化“跨入口一致性未满足”这类少见例外场景下的说明文案，让用户知道这是结果上下文变化，而不是页面坏掉了。

## 2. 背景与现状

即便有统一的滚动恢复和回流规则，仍可能出现少量极端情况：从不同入口回来的预期上下文已经发生变化。若没有单独文案，会出现：

1. 用户觉得当前页面和刚才离开时不一致
2. 普通兜底文案无法解释“为什么这次和上次不一样”
3. 极端分支会显得像随机 bug

## 3. 涉及范围

- 治理结果历史页
- 跨入口一致性失败时的提示文案
- 例外说明与普通兜底说明的边界
- 对应前端测试

## 4. 前置依赖

1. `273-8.3-治理结果历史页二级落点提示文案分支增强.md` 已完成或至少已有失败原因文案分支
2. `266-8.3-治理结果历史页跨页返回后的滚动恢复细则增强.md` 已完成或至少已有跨入口恢复主规则

## 5. 具体开发项

### 5.1 例外场景识别

1. 区分普通恢复失败与跨入口一致性失效场景
2. 例如来源入口上下文变化、筛选条件更新、结果分组重排等
3. 仅在确有必要时触发例外文案

### 5.2 例外文案设计

1. 文案应解释“当前结果上下文已变化，因此回到了最接近的位置”
2. 避免把例外场景表述成系统故障
3. 保持与普通兜底文案语气一致，但信息更明确

### 5.3 层级边界

1. 例外文案不长期驻留
2. 例外文案优先于普通兜底文案，但不压过空态主说明
3. 与来源提示体系不互相抢位置

### 5.4 用户后续动作

1. 必要时提供回到最近稳定分组或重置筛选入口
2. 不让用户读完文案后仍然不知道下一步做什么
3. 保持动作数量克制

### 5.5 测试补齐

1. 覆盖一致性失败时的例外文案触发
2. 覆盖普通兜底与例外兜底的区分
3. 覆盖与空态、来源提示并存时的层级关系
4. 覆盖后续动作入口展示

## 6. 验收标准

1. 极端跨入口分支下仍有可理解的说明
2. 用户不会把上下文变化误读为页面故障
3. 例外文案与普通兜底、空态文案边界清楚
4. 对应前端测试通过
