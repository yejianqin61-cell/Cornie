# 257-8.3-治理结果历史页多入口回流下的提示降级与冲突消解增强

## 1. 任务目标

在 `256` 已建立治理结果历史页与提醒中心、待审核池之间的跨页回流说明基础上，继续细化多入口来回切换时的提示降级和冲突消解规则，避免历史页顶部被各种来源说明反复占据。

## 2. 背景与现状

一旦历史页、提醒中心、待审核池、结果详情页都能互相回流，常见问题会变成：

1. 来源提示频繁出现，用户产生疲劳
2. 不同来源说明相互覆盖或抢焦点
3. 多次往返后很难判断当前哪条提示还重要

## 3. 涉及范围

- 治理结果历史页顶部提示区
- 多入口来源说明
- 提示降级与冲突消解规则
- 对应前端测试

## 4. 前置依赖

1. `256-8.3-治理结果历史页到提醒中心与待审核池的跨页回流说明增强.md` 已完成或至少已有跨页说明
2. `255-8.1-同日总览多来源回流提示优先级规则增强.md` 已完成或至少已有多来源优先级经验模式
3. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有历史页持久化能力

## 5. 具体开发项

### 5.1 提示降级规则

1. 对重复出现的同类型来源说明自动降级强度
2. 用户已经理解链路后，后续同类提示仅保留轻量痕迹
3. 对关键首次回流说明保留完整表达

### 5.2 冲突消解

1. 当多个来源说明同时满足时，按优先级只展示最相关的一条
2. 其余说明降级到次级入口或收纳区
3. 冲突消解规则应清楚、稳定、可预测

### 5.3 手动控制

1. 支持用户关闭某类来源提示
2. 对被关闭的提示在合理范围内减少重复出现
3. 不让手动关闭影响真正高风险或关键引导提示

### 5.4 与浏览状态兼容

1. 提示降级和冲突消解不影响历史页自身筛选和位置恢复
2. 切换时间范围或结果分组后，旧提示正确退场
3. 保持与提醒中心、待审核池回流说明一致的表达逻辑

### 5.5 测试补齐

1. 覆盖重复回流时的提示降级
2. 覆盖多来源同时命中的冲突消解
3. 覆盖手动关闭后的重复出现控制
4. 覆盖页面状态切换后的提示退场

## 6. 验收标准

1. 治理结果历史页在多入口往返下仍能保持提示清爽
2. 用户不会因反复回流而被提示疲劳打断
3. 提示降级和冲突消解规则稳定可靠
4. 对应前端测试通过
