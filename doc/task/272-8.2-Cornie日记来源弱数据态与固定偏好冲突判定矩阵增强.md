# 272-8.2-Cornie日记来源弱数据态与固定偏好冲突判定矩阵增强

## 1. 任务目标

在 `264` 和 `268` 已补齐 Cornie 日记来源弱数据态、过渡边界与用户偏好交叉规则基础上，继续把“弱数据态”和“用户固定偏好”发生冲突时的最终判定矩阵明确下来，便于后续直接实现和测试。

## 2. 背景与现状

当用户明确选择固定密度或固定展开状态，而系统又判断当天属于弱数据态时，最容易出现隐性冲突：

1. 系统想更克制，用户却希望固定展开
2. 用户想固定紧凑，但数据充足时系统又想扩展展示
3. 若没有矩阵，开发时容易各处各写一套规则

## 3. 涉及范围

- Cornie 日记来源侧栏
- 弱数据态判断
- 用户固定偏好策略
- 对应前端测试

## 4. 前置依赖

1. `264-8.2-Cornie日记来源弱数据态与手动关闭记忆交叉分支增强.md` 已完成或至少已有交叉规则
2. `268-8.2-Cornie日记来源弱数据态切换时的过渡边界增强.md` 已完成或至少已有切换边界
3. `262-8.2-Cornie日记来源侧栏恢复默认入口与偏好重置增强.md` 已完成或至少已有恢复默认逻辑

## 5. 具体开发项

### 5.1 冲突矩阵定义

1. 明确列出“弱数据态判断结果 x 用户固定偏好类型”的判定矩阵
2. 为每种组合定义最终采用的展示状态
3. 让同类冲突在所有日期和入口下保持一致

### 5.2 优先级边界

1. 明确哪些固定偏好拥有更高优先级
2. 明确哪些弱数据态保护规则不可被完全覆盖
3. 让系统既尊重用户选择，又保持最基本的界面克制

### 5.3 可解释性

1. 用户不需要看到矩阵本身，但界面行为应可预测
2. 在明显冲突场景下，必要时通过轻量反馈解释为何这样显示
3. 不把偏好冲突做成神秘黑盒

### 5.4 重置与回退兼容

1. 恢复默认后矩阵回到系统主规则
2. 撤销重置后重新启用用户固定偏好判定
3. 切换不同日期时继续沿用同一矩阵

### 5.5 测试补齐

1. 覆盖弱数据态 x 固定展开偏好
2. 覆盖弱数据态 x 固定紧凑偏好
3. 覆盖正常态 x 固定偏好
4. 覆盖重置与撤销前后的矩阵变化

## 6. 验收标准

1. Cornie 日记来源侧栏对弱数据态与固定偏好冲突有统一判定矩阵
2. 后续实现不容易出现规则漂移
3. 用户能感受到界面行为稳定可预测
4. 对应前端测试通过
