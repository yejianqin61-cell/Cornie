# 198-8.3-Topic-Index别名编辑与主题合并入口收口

## 1. 任务目标

在 `178` Topic Index 详情与治理工作台基础上，继续把“别名编辑”和“主题合并入口”这两块收口成真正可执行的人类治理入口，为后续主题治理正式落地打好前端基础。

## 2. 背景与现状

`178` 已经定义了 Topic 详情、别名管理和主题治理入口，但还偏“具备入口”。继续往前推进时，还需要：

1. 把别名编辑细化成正式表单与校验体验
2. 把主题合并从预留入口细化成明确的候选发起入口
3. 明确区分低风险别名调整与高风险主题合并

## 3. 涉及范围

- Topic 详情面板
- 如有必要，Topic 别名编辑弹层或子表单
- 主题治理入口与待审核联动入口
- 对应前端测试

## 4. 前置依赖

1. `178-8.3-Topic-Index详情与主题治理工作台增强.md` 已完成或至少已有 Topic 详情区
2. `185-8.3-Memory-Wiki页面合并审核工作台增强.md` 已形成高风险治理审核方向

## 5. 具体开发项

### 5.1 别名编辑正式化

1. 支持新增、删除、修改 Topic 别名
2. 清楚区分主主题名与别名
3. 对重复别名、空别名、异常格式给出校验

### 5.2 别名变更影响提示

1. 在保存前说明别名会影响后续检索与匹配
2. 对高频主题保持更清楚的风险提示
3. 保存失败时保留用户编辑内容

### 5.3 主题合并入口收口

1. 为主题详情提供明确的“发起合并建议”入口
2. 支持用户查看可能相近的其他主题候选
3. 允许把主题合并建议送入待审核或治理区，而不是直接执行

### 5.4 低风险与高风险边界

1. 别名编辑默认视为较低风险治理动作
2. 主题合并明确视为高风险动作
3. 高风险动作只发起候选，不在本任务中直接落地执行

### 5.5 测试补齐

1. 覆盖别名新增、删除、修改
2. 覆盖别名校验分支
3. 覆盖发起主题合并建议入口
4. 覆盖跳转待审核或治理区的分支

## 6. 验收标准

1. 用户可在前端稳定完成 Topic 别名编辑
2. 用户可以明确发起主题合并建议
3. Topic 治理入口风险边界清晰
4. 对应前端测试通过
