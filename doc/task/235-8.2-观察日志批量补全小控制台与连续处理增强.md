# 235-8.2-观察日志批量补全小控制台与连续处理增强

## 1. 任务目标

在 `229` 和 `230` 已补齐观察日志按日工作篮与跨模块整理队列基础上，继续提供一个适合“同一天连续补完多条素材”的小控制台，支持批量识别缺口、逐条补全、连续跳转下一条。

## 2. 背景与现状

观察日志整理经常不是处理一条就结束，而是同一天里连续补标题、补来源、补正文。当前即使已有工作篮，也仍可能：

1. 用户每处理完一条都要回列表重新找下一条
2. 无法快速识别“今天哪些条目最值得先补”
3. 缺少适合连续整理的轻量控制区

## 3. 涉及范围

- 观察日志工作台当日工作篮
- 观察日志详情侧的轻量整理控制台
- 同日连续处理链路
- 对应前端测试

## 4. 前置依赖

1. `229-8.2-观察日志按日工作篮与整理进度提示增强.md` 已完成或至少已有工作篮视图
2. `230-8.2-观察日志跨模块整理队列与返回原位增强.md` 已完成或至少已有连续处理语义
3. `193-8.2-观察日志详情编辑表单与删除确认收口.md` 已完成或至少已有表单编辑基础

## 5. 具体开发项

### 5.1 小控制台入口

1. 在当日工作篮或详情区加入“今日待补完”小控制台
2. 汇总缺标题、缺来源、缺正文等结构性缺口数量
3. 提供一键进入待补完队列的入口

### 5.2 连续处理链路

1. 保存当前条目后自动提供“处理下一条待补完”入口
2. 支持上一条 / 下一条快速切换
3. 让同日整理尽量少依赖回列表反复定位

### 5.3 优先级提示

1. 先展示缺口更大的条目，或用户当前最容易补完的条目
2. 提示哪些条目已经足够完整，避免重复打扰
3. 优先级仅作为辅助，不替代用户判断

### 5.4 轻量完成感反馈

1. 每补完一条后更新当日工作篮统计
2. 当当天结构性缺口清零时，给出温和完成提示
3. 不把整理控制台做成过于强打断的任务系统

### 5.5 测试补齐

1. 覆盖待补完控制台渲染
2. 覆盖保存后跳到下一条
3. 覆盖优先级排序与已完成条目过滤
4. 覆盖当日缺口清零后的反馈

## 6. 验收标准

1. 观察日志支持同日连续整理，而不是零散点修
2. 用户能更高效地补全当天素材缺口
3. 小控制台不会破坏观察日志主阅读体验
4. 对应前端测试通过
