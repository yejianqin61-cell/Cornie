# 449 注入侧评估与结论（消费侧前置）

## 背景

Cornie-019 §4.11 将注入侧规则（`wikiContext.js` 的 `scorePage` / `identityProfileNeedsExtendedDetails` / `personNeedsRiskyDetails` / `traitMatchesEmotionalScene` 关键词表）单列：它们不决定"是否写入"，但决定"哪些记忆注入 prompt"，与"LLM 决定"原则存在张力（N-06）。消费侧渐进钻取架构（Cornie-019 §7）落地前，需先定论这些关键词表的去留。

## 目标

1. 评估 4 处注入侧关键词/评分规则在"固定基座 + 按需钻取"架构中的角色。
2. 输出设计结论：哪些保留为"目录排序信号"、哪些删除（由 LLM 全权决定）。
3. 结论落文档（本任务产出设计结论，作为 451 目录与画像卡的输入）。

## 范围

- `electron/backend/agent/wikiContext.js`（仅评估，不实现；改动随 451）
- 本任务产出：设计结论文档（可并入本 task 文档或 Cornie-019 §7 修订）

### 1. 逐项评估

| --- | --- | --- |

## 评估结论（决策记录，449 交付物）

> 评估对象：`agent/wikiContext.js` 的 4 处注入侧规则（Cornie-019 §4.11）。评估基准：消费侧渐进钻取架构（Cornie-019 §7）——"读取什么、读到多深由 LLM 决定"，后端不拦截。

### 1. 结论总表

| 现状规则 | 位置 | 结论 | 理由 |
| --- | --- | --- | --- |
| `scorePage`（importance + ownerConfirmed + summary 加权） | wikiContext L25-30 | **保留为 L1 目录排序信号** | 纯排序，不构成读取拦截；目录顺序需要稳定的优先级信号，LLM 仍可钻取任意页 |
| `identityProfileNeedsExtendedDetails`（压力/沟通词表） | wikiContext L245-285 | **降级为目录排序信号，语义不变** | "是否注入扩展字段"的判定改由 LLM 钻取决定；词表仅用于 L1 候选排序 |
| `personNeedsRiskyDetails`（13 riskyTerms） | wikiContext L320-343 | **降级为目录排序信号** | 敏感字段（意义/性格）是否读取由 LLM 决定；词表仅参与排序；ownerConfirmed 仍作为可信度权重保留 |
| `traitMatchesEmotionalScene`（18 情绪词） | wikiContext L165-193 | **降级为目录排序信号** | 侧写是否随情绪场景"注入"改为"LLM 按需钻取"；词表仅排序 |

### 2. 决策原则

1. **排序信号 ≠ 读取拦截**：上述 4 处规则在钻取架构中只决定 L1 目录条目的先后顺序，**绝不阻止 LLM 通过 `memory_wiki.get_page` 等工具读取任意页面全文**（450 已接线）。
2. **删除"仅命中词表才注入字段"的语义**：现状 `personNeedsRiskyDetails`/`identityProfileNeedsExtendedDetails` 决定是否把敏感/扩展字段拼进注入文本；钻取架构下改为"LLM 需要时读全页"，词表不再充当注入闸门。
3. **ownerConfirmed 语义保留**：作为可信度权重参与排序（`scorePage`），不参与字段级注入判定。
4. **451 输入要求**：L1 目录条目按"importance + ownerConfirmed + summary 是否有 + 查询词表命中"排序；目录条目固定含摘要/重要性/最近提及三信号，供 LLM 决策钻取。

### 3. 451 实现指引（本结论的直接输出）

- `buildWikiContext` 输出改为：L0 画像卡 + L1 目录（排序规则见上）+ 钻取工具摘要；不再把"扩展字段/敏感字段"按词表拼入注入文本。
- 保留 `personNeedsRiskyDetails` / `identityProfileNeedsExtendedDetails` / `traitMatchesEmotionalScene` 的**排序函数**（重命名为排序语义，如 `scorePersonDirectoryEntry`），删除其"注入闸门"用途。
- 钻取路径（452/453）读取页面全文，敏感字段的暴露由 LLM 决定 + 确认流兜底（身份页 ownerConfirmed=false 仍受治理保护）。
