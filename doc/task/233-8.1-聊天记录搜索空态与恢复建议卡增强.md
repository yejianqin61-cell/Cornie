# 233-8.1-聊天记录搜索空态与恢复建议卡增强

## 1. 任务目标

在 `227` 已补齐聊天记录日期列表搜索和筛选基础上，继续细化搜索无结果、筛选过严、数据暂缺等场景下的空态表达与恢复建议卡，让用户在“没找到”时知道下一步该怎么做。

## 2. 背景与现状

聊天记录搜索一旦可用，空态体验就会直接影响可用性。当前即使未来有搜索和筛选，也仍可能出现：

1. 用户筛选太严后，以为聊天记录丢了
2. 某个月确实没有记录，但页面没有给出清晰解释
3. 用户不知道是该清空条件、切月份，还是回到最近访问日期

## 3. 涉及范围

- 聊天记录日期搜索与筛选区
- 聊天记录左侧列表空态区
- 恢复建议卡与快捷操作
- 对应前端测试

## 4. 前置依赖

1. `227-8.1-聊天记录日期列表搜索筛选与最近访问增强.md` 已完成或至少已有搜索筛选基础
2. `172-8.1-聊天记录工作台产品化增强.md` 已完成或至少已有列表与空态基础

## 5. 具体开发项

### 5.1 空态分类

1. 区分“当前筛选无结果”和“该时间范围本来就没有聊天记录”
2. 区分“搜索词无匹配”和“数据尚未加载完成”
3. 不把所有空态都做成同一种空白提示

### 5.2 恢复建议卡

1. 在无结果时提供“清空筛选”“回到最近访问”“回到今天”等快捷动作
2. 当某月份无记录时，提示可切换到最近有记录的月份
3. 恢复建议应简短直接，不做过度解释

### 5.3 轻量上下文说明

1. 让用户知道当前空态是由什么条件造成的
2. 展示当前生效的筛选摘要，便于用户自查
3. 避免用户把“无结果”误解为系统报错

### 5.4 视觉收口

1. 空态卡风格应与聊天记录工作台一致
2. 在空态下保持页面结构稳定，不让布局明显塌陷
3. 快捷动作不应抢走主列表的注意力

### 5.5 测试补齐

1. 覆盖搜索无结果分支
2. 覆盖月份无记录分支
3. 覆盖筛选过严后的恢复动作
4. 覆盖加载中与真正空态的区分

## 6. 验收标准

1. 用户在聊天记录搜索无结果时能清楚理解原因
2. 空态下具备明确恢复路径
3. 搜索空态不会制造“记录丢失”的误解
4. 对应前端测试通过
