# 121 桌面端启动链路稳态校验与最小验收

## 1. 任务目标

对桌面端启动链路进行稳态化校验，确认主进程、窗口创建、本地 API 服务和预加载脚本之间的关键依赖关系完整可用。

## 2. 任务来源

- `doc/Cornie-013-当前项目完成度复评与后续行动建议.md` 第 `8.1` 节

## 3. 前置依赖

- `120` 已完成

## 4. 涉及范围

- `electron/main.js`
- `electron/server.js`
- `electron/preload.cjs`
- 必要时补充 `scripts/`

## 5. 当前问题

即使主入口恢复，如果不对窗口创建、本地 API 监听、开发态加载 URL、预加载脚本绑定等关键环节做最小校验，桌面端仍可能存在“入口恢复了，但启动不稳”的问题。

## 6. 目标设计

- 校验主进程启动顺序
- 校验本地 API 在 `5174` 的监听能力
- 校验主窗口与 Cornie 窗口创建逻辑
- 校验 preload 暴露接口仍可被渲染层使用

## 7. 实现步骤

### Step 1

梳理桌面端启动关键节点与依赖关系。

### Step 2

补最小验收脚本或等效校验逻辑，验证主入口、主窗口、本地 API、preload 暴露是否齐备。

### Step 3

修正启动链路中发现的显式问题，确保开发态至少具备稳定启动基础。

## 8. 测试点

- 主进程入口可被加载
- `createServer` 启动逻辑存在
- `BrowserWindow` 创建逻辑存在
- preload 暴露 `cornieDesktop` 接口
- 开发态主窗口与 Cornie 窗口加载地址正确

## 9. 完成标准

- 桌面端启动链路具备最小可验证能力
- 存在可重复执行的最小验收方式

## 10. 交付物

- 启动链路稳态校验代码或脚本
