# 302-8.1-聊天记录已失活回流提示在同来源重复触发时的新旧轮次判定增强

## 1. 任务目标

在 `298` 已补齐聊天记录用户手动接管后系统回流提示彻底失活规则基础上，继续细化同一个外部来源在提示已失活后再次触发时，系统应判定为“恢复旧轮次”还是“开启新轮次”，避免重复点击同一入口导致引导状态混乱。

## 2. 背景与现状

用户可能在短时间内多次从同一个来源进入聊天记录，例如：

1. 在同日总览里连续点两次同一聊天入口
2. 从 Cornie 日记回到聊天记录后，又再次点击来源回看
3. 来源提示刚退场，用户马上又主动点开原入口

如果没有清楚的新旧轮次判定，会出现：

1. 系统把旧失活提示重新强行复活
2. 系统又完全不响应，像入口失效
3. 用户不知道自己这次点击是否会重新触发引导

## 3. 涉及范围

- 聊天记录工作台
- 回流来源再次触发时的轮次边界判断
- 提示、自动落点与失活状态重建逻辑
- 对应前端测试

## 4. 前置依赖

1. `298-8.1-聊天记录用户手动接管后的系统回流提示彻底失活规则增强.md` 已完成或至少已有失活规则
2. `286-8.1-聊天记录多入口回流并发时的主落点判定与提示降级增强.md` 已完成或至少已有回流主次策略
3. `290-8.1-聊天记录刷新后回流语义残留与错误复现防护增强.md` 已完成或至少已有防重放逻辑

## 5. 具体开发项

### 5.1 新旧轮次判定

1. 明确同来源再次触发的时间窗口与上下文差异阈值
2. 若用户明确再次点击来源入口，应优先视为新轮次请求
3. 若只是旧状态残留导致重复触发，则不得重启引导

### 5.2 新轮次重建

1. 被判定为新轮次后，可重新展示主提示并重新计算落点
2. 新轮次应重置旧轮次的退场和失活记忆
3. 新轮次仍需遵守多入口冲突消解规则

### 5.3 非新轮次的静默处理

1. 不满足新轮次条件时，仅保留静默更新，不弹出主提示
2. 不因同源重复触发而再次自动滚动
3. 必要时只更新次级来源说明

### 5.4 用户认知边界

1. 用户主动重复点击时，系统行为应可预期
2. 文案上体现“这是你重新打开的回看”，而不是旧状态复活
3. 与空态、最近访问和手动接管规则兼容

### 5.5 测试补齐

1. 覆盖同来源重复点击被判定为新轮次
2. 覆盖旧状态残留重复触发不重启引导
3. 覆盖新轮次下旧失活状态重置
4. 覆盖与多入口并发规则共存时的结果

## 6. 验收标准

1. 聊天记录同来源重复触发时，新旧轮次边界清楚
2. 用户主动再点入口时能得到符合直觉的重新引导
3. 旧状态残留不会伪装成新一轮回流
4. 对应前端测试通过
