# 162-前端全覆盖阶段8.3-MemoryWiki与TopicIndex治理产品化

## 1. 任务目标

根据 [Cornie-014-当前项目进度评估文档-V2.md](/C:/Users/USER/Desktop/Cornie/Cornie/doc/Cornie-014-当前项目进度评估文档-V2.md:1) 的 `8.1 第一优先级`，继续推进 Memory Wiki / Topic Index / 治理待审核区的前端产品化，使其从“内部治理工作台”升级为“人类可直接管理长期记忆”的正式界面。

## 2. 背景与现状

当前已经存在：

- `src/renderer/components/MemoryWikiWorkspace.vue`
- Topic Index、治理详情、确认中心等基础能力
- 对应 API / 后端 / 测试能力

但仍缺少：

1. 更清晰的页面组织
2. 更强的人类治理视角
3. 版本 / 回滚 / 页面治理 / Topic 管理等显式操作路径

## 3. 开发范围

涉及范围：

- `src/renderer/components/MemoryWikiWorkspace.vue`
- 如有必要，补充新的子组件
- 如有必要，补充 `App.vue` 入口与视图组织
- 对应前端测试文件

## 4. 具体开发项

### 4.1 Memory Wiki 页面管理产品化

补齐或优化：

1. 页面列表、详情、编辑区层级更清晰
2. 页面新建、编辑、归档、恢复、回滚更显式
3. 页面状态、重要性、别名等信息更面向人类呈现

### 4.2 Topic Index 管理产品化

补齐或优化：

1. Topic 列表与详情可更直观查看
2. 关键词、别名、日期、关联页面信息更清晰
3. Topic alias 编辑更像正式管理动作，而不是测试入口

### 4.3 治理待审核区与确认中心产品化

补齐或优化：

1. 治理列表、详情、状态筛选、巡检入口更清楚
2. 确认中心的信息组织和卡片层级更适合普通用户理解
3. 人类可以更明确地区分“待审核治理建议”和“高风险确认请求”

## 5. 验收标准

1. Memory Wiki 页面管理可由人类直接完成主要治理动作
2. Topic Index 可由人类直接查看与维护
3. 治理待审核区与确认中心具备更明确的产品化交互
4. 前端测试补齐并通过
