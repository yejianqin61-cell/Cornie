# 266-8.3-治理结果历史页跨页返回后的滚动恢复细则增强

## 1. 任务目标

在 `251`、`256`、`257` 已补齐治理结果历史页的持久化、跨页回流说明与提示冲突消解基础上，继续细化从提醒中心、待审核池、结果详情页返回历史页后的滚动恢复细则，避免长列表回顾体验断裂。

## 2. 背景与现状

治理结果历史页一旦承载长期浏览，就会出现大量跨页跳转。若滚动恢复只有笼统设计，没有细则，会出现：

1. 返回历史页后总要重新找刚才看到的位置
2. 不同来源页面返回时，恢复策略不一致
3. 筛选、分组和滚动位置互相影响，导致体验不稳定

## 3. 涉及范围

- 治理结果历史页列表区
- 历史页与提醒中心 / 待审核池 / 结果详情页的返回链路
- 滚动位置与列表锚点恢复
- 对应前端测试

## 4. 前置依赖

1. `251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强.md` 已完成或至少已有历史页浏览状态持久化
2. `256-8.3-治理结果历史页到提醒中心与待审核池的跨页回流说明增强.md` 已完成或至少已有跨页回流说明
3. `257-8.3-治理结果历史页多入口回流下的提示降级与冲突消解增强.md` 已完成或至少已有多入口回流规则

## 5. 具体开发项

### 5.1 来源分场景恢复规则

1. 从结果详情页返回时优先恢复到原结果卡附近
2. 从提醒中心或待审核池返回时优先恢复原筛选上下文中的列表位置
3. 当原锚点失效时，回退到最近有效分组或时间段

### 5.2 筛选与滚动协同

1. 先恢复筛选与分组，再恢复滚动位置
2. 若筛选条件变化导致目标项不再可见，给出合理默认落点
3. 不让滚动恢复跳到与当前筛选无关的空位置

### 5.3 长列表阅读边界

1. 在长历史列表中保持滚动恢复稳定
2. 对折叠分组、分页或虚拟列表场景制定一致恢复策略
3. 恢复时避免明显布局抖动或突兀跳闪

### 5.4 失败兜底

1. 若无法精确恢复原位置，优先回到当前分组顶部
2. 给出轻量提示，说明已恢复到最接近位置
3. 不把位置恢复失败包装成报错

### 5.5 测试补齐

1. 覆盖从结果详情页返回的滚动恢复
2. 覆盖从提醒中心 / 待审核池返回的滚动恢复
3. 覆盖目标项失效时的兜底落点
4. 覆盖筛选变化后的恢复行为

## 6. 验收标准

1. 治理结果历史页跨页返回后具备稳定的滚动恢复体验
2. 不同来源页面返回时的恢复策略清楚一致
3. 长列表回顾不再反复丢位置
4. 对应前端测试通过
