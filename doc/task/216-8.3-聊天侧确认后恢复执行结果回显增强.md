# 216-8.3-聊天侧确认后恢复执行结果回显增强

## 1. 任务目标

在 `014` 前端确认流闭环和 `013` 后端恢复执行闭环基础上，继续把“用户确认后，系统恢复执行并产出最终结果”的回显体验做得更完整，让用户能清楚看到：

1. 自己刚刚同意了什么
2. 同意后系统恢复执行到了哪一步
3. 最终结果是成功、失败还是部分完成

## 2. 背景与现状

当前任务链已经打通确认流，但如果继续补前端产品体验，还缺：

1. 确认通过后的结果回显不够完整
2. 用户不一定看得出本次结果就是刚才确认触发的
3. 恢复执行和最终回复之间的承接仍可更清楚

## 3. 涉及范围

- `ConfirmCard.vue`
- 聊天消息流
- `ToolResultPanel.vue`
- 对应前端测试

## 4. 前置依赖

1. `014-前端确认流接线与联调验收.md` 已完成或至少已有端到端确认流
2. `013-确认后恢复工具执行与最终回复生成.md` 已完成或至少已有恢复执行结果返回

## 5. 具体开发项

### 5.1 确认后结果承接

1. 用户点击同意后，明确显示“正在继续处理”状态
2. 执行完成后，把结果挂接到对应确认卡或聊天上下文
3. 让用户能看出这是同一条确认链路的后续结果

### 5.2 最终结果回显

1. 展示工具执行结果摘要
2. 展示 Cornie 最终回复
3. 若中途失败，展示失败说明与停留位置

### 5.3 部分完成与失败边界

1. 若恢复执行中部分步骤成功、部分失败，状态要说清楚
2. 不把失败简单吞进最终自然语言回复里
3. 保持确认卡、结果卡、最终回复三者关系清晰

### 5.4 测试补齐

1. 覆盖确认通过后的处理中状态
2. 覆盖成功结果回显
3. 覆盖失败结果回显
4. 覆盖部分完成分支

## 6. 验收标准

1. 用户能看懂确认后的恢复执行结果
2. 结果回显与原确认卡之间关系明确
3. 确认流前端闭环从“能走通”提升为“能看懂”
4. 对应前端测试通过
