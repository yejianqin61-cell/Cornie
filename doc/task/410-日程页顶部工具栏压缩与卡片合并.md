# 410-日程页顶部工具栏压缩与卡片合并

## 1. 任务目标

压缩日程首页顶部的信息密度，减少“筛选状态卡片”和“新增安排卡片”的纵向堆叠，让页面首屏更聚焦查看安排本身。

## 2. 对应来源

- GitHub Issue `#14` 前端-日程页面
- 设计文档：`doc/design/Cornie-0701-GitHub-Issue-011-015前端问题分级与落地设计.md`

## 3. 背景与现状

当前日程页顶部通常包含：

1. 月历
2. 当前筛选状态卡
3. 新增安排卡

用户反馈这两块卡片上下连续堆叠，带来以下问题：

1. 页面上半区显得密集
2. 列表首屏可见区域被压缩
3. “看安排”和“新增安排”两个动作的主次关系不够清晰

## 4. 涉及范围

- `src/renderer/components/ScheduleHome.vue`
- 如需抽出头部工具栏组件，可新增：
  - `src/renderer/components/ScheduleToolbar.vue`

## 5. 前置依赖

1. 日程月历筛选能力已存在。
2. 新增安排表单已存在。
3. 按日筛选与回到今天逻辑可用。

## 6. 开发项

### 6.1 合并筛选状态与快捷操作区

将以下内容尽量收敛到同一个顶部工具区：

1. 当前筛选状态
2. 回到今天
3. 清除筛选
4. 新增安排入口

目标是避免“解释状态的卡片”和“发起操作的卡片”上下连续堆叠。

### 6.2 新增表单默认折叠

默认只展示新增入口按钮，不直接长期占据大面积页面空间。

点击 `新增安排` 后：

1. 原地展开表单
2. 表单展开时可占满一行
3. 收起后恢复紧凑状态

### 6.3 保持查看优先级高于编辑

页面顶部结构应体现：

1. 先看这个月和某一天有什么安排
2. 再决定是否新增

因此：

1. 状态信息应尽量短
2. 按钮应贴近筛选状态
3. 列表应更早进入用户视线

### 6.4 移动端兼容布局

桌面端可以并排压缩，移动端则允许回退为上下布局，但仍需保持：

1. 工具区整体比原先更紧凑
2. 不出现一长串堆叠说明卡

## 7. 实现建议

### 7.1 推荐结构

推荐改为以下顺序：

1. 月历
2. 单一工具栏卡片
   - 左侧：当前筛选状态
   - 右侧：回到今天 / 清除筛选 / 新增安排
3. 条件展开的新增表单
4. 日程列表

### 7.2 视觉策略

1. 减少大面积说明文字
2. 压缩按钮区高度
3. 保留必要留白，但避免“卡片罗列感”

### 7.3 不做事项

本任务不处理：

1. 日程新增字段扩展
2. 日程后端逻辑调整
3. 类目管理页重做

## 8. 验收标准

1. 页面顶部的两个工具性卡片不再明显纵向堆叠。
2. 当前筛选与快捷操作关系更清楚。
3. 日程列表首屏可见区域增加。
4. 新增安排仍然可快速展开，不影响现有功能。

## 9. 自测清单

1. 未选择日期时，确认顶部工具区简洁清楚。
2. 选择某一天后，确认筛选状态能正常显示且不挤压页面。
3. 点击新增安排，确认表单可展开、收起。
4. 在移动尺寸下查看，确认不会出现严重错位或按钮换行混乱。
5. 核对日程列表首屏比旧版更早可见。
