# 308-8.3-失败静默例外入口展开后再次关闭的回静默状态增强

## 1. 任务目标

在 `304` 已补齐聊天侧失败排障静默态下用户主动查看记忆来源的例外通道基础上，继续细化用户展开该例外入口后再次关闭时，应如何稳定回到“静默但可再打开”的状态，避免关闭后要么重新主动提示、要么彻底消失无入口。

## 2. 背景与现状

失败排障静默态里的例外入口本质上是：

1. 默认安静
2. 用户主动查看时临时展开
3. 看完后回到安静态

如果“回到安静态”的逻辑不清晰，会出现：

1. 关闭后又重新变成主动提示，破坏静默
2. 关闭后入口也没了，透明能力断层
3. 多次开关后状态越来越混乱

## 3. 涉及范围

- 聊天侧失败排障静默态
- 记忆来源例外入口的展开、关闭与回静默逻辑
- 对应前端测试

## 4. 前置依赖

1. `304-8.3-聊天侧失败排障静默态下用户主动查看记忆来源的例外通道增强.md` 已完成或至少已有例外入口
2. `300-8.3-聊天侧记忆弱提示在用户连续追问失败原因时的静默策略增强.md` 已完成或至少已有静默规则
3. `284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强.md` 已完成或至少已有可达性边界

## 5. 具体开发项

### 5.1 关闭后的目标状态

1. 关闭例外展开后，必须明确回到“静默入口态”
2. 不得回到主动提示态
3. 不得变成完全无入口态

### 5.2 多次开关稳定性

1. 用户多次展开/关闭后，入口位置和语义保持一致
2. 不因多次操作导致展开内容越来越多或越来越少
3. 键盘焦点和阅读顺序在多次开关后仍稳定

### 5.3 静默态完整性

1. 回到静默入口态后，失败主链路继续保持主导
2. 入口仅作为可选查看项存在
3. 与失败卡、恢复建议和最终回复收束顺序兼容

### 5.4 退出失败排障后的处理

1. 一旦离开失败排障主题，再按常规透明提示体系重评估
2. 静默入口态不应被错误继承到普通轮次
3. 与新会话日、新主题切换规则兼容

### 5.5 测试补齐

1. 覆盖展开后关闭回到静默入口态
2. 覆盖多次开关后的稳定性
3. 覆盖焦点与可达顺序保持
4. 覆盖退出失败排障主题后的重新并回常规体系

## 6. 验收标准

1. 失败静默态例外入口在反复开关后仍然稳定
2. 用户关闭查看后会回到安静但可再开的状态
3. 静默规则和可查看性之间的边界持续清楚
4. 对应前端测试通过
