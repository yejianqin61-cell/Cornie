# 285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强

## 1. 任务目标

在 `175`、`201`、`222` 已补齐 Memory Wiki 来源引用区、来源分组阅读和展开记忆基础上，继续细化用户在多个来源之间来回切换时的滚动锚点保持、当前来源聚焦与对比阅读体验，避免来源区变成一团散乱长列表。

## 2. 背景与现状

当前来源区已经逐步具备：

1. 按来源类型或来源组展开阅读
2. 批量查看来源内容
3. 来源展开状态记忆

但来源一多之后，仍会出现：

1. 在多个来源组之间切换后，滚动位置容易跳丢
2. 用户不清楚当前重点正在看哪一组来源
3. 相关来源之间缺少“并排比较”或“连续对读”的阅读线索

## 3. 涉及范围

- Memory Wiki 页面详情来源区
- 来源分组展开、切换、滚动与聚焦状态
- 对应前端测试

## 4. 前置依赖

1. `175-8.3-Memory-Wiki来源引用与关联阅读增强.md` 已完成或至少已有来源阅读区
2. `201-8.3-Memory-Wiki来源引用区分组阅读与原始来源跳转增强.md` 已完成或至少已有来源分组阅读
3. `222-8.3-Memory-Wiki来源区展开记忆与批量查看增强.md` 已完成或至少已有展开状态记忆

## 5. 具体开发项

### 5.1 跨来源切换的滚动锚点

1. 在来源组之间切换时，尽量保持用户刚才阅读位置附近的锚点
2. 若切换导致原锚点失效，则回落到新来源组标题或首条来源
3. 从详情其他区块返回来源区时，可恢复最近一次来源阅读位置

### 5.2 当前来源聚焦表达

1. 明确高亮当前正在阅读的来源组
2. 让用户一眼看懂当前是“单组深入阅读”还是“跨组比较浏览”
3. 切换来源组时提供轻量标题或状态提示

### 5.3 比较视角

1. 在相邻来源组间提供“继续看下一组相关来源”入口
2. 对同一主题下不同来源类型给出轻量对比阅读线索
3. 不做复杂分析器，但要让阅读顺序有迹可循

### 5.4 弱数据与长来源区边界

1. 来源很少时不强行展示比较视角
2. 来源很多时避免长滚动区反复跳顶
3. 与页面详情折叠、阅读密度控制策略兼容

### 5.5 测试补齐

1. 覆盖跨来源组切换后的滚动恢复
2. 覆盖原锚点失效后的回落落点
3. 覆盖当前来源组高亮与状态提示
4. 覆盖弱数据态下比较视角自动降级

## 6. 验收标准

1. Memory Wiki 来源区在多来源场景下更容易连续阅读
2. 用户能清楚知道当前正在看哪组来源、下一步该看哪里
3. 滚动锚点与比较视角不会让来源区交互更乱
4. 对应前端测试通过
