# 413-普通用户长期记忆来源摘要与关系阅读增强

## 1. 任务目标

为普通用户长期记忆详情页补一层轻量的“来源说明”和“关联阅读”能力，让用户能大致看懂：

1. 这页记忆是从哪里来的
2. 它和哪些聊天、观察记录、相关人物或相关记忆有关

本任务不暴露治理术语，也不把高级工作台原样搬过来，只做普通用户能理解的透明化说明。

## 2. 对应来源

- `doc/design/Cornie-0701-记忆层存储与长期记忆前端入口设计说明.md`
- 其中第 7、8、9 节关于“普通用户可查看页面来源摘要”的要求

## 3. 背景与现状

当前普通用户长期记忆详情页已经可以：

1. 新建
2. 编辑
3. 删除（归档）

但还缺一块很重要的信任感来源：

1. 用户不知道这页记忆是怎么来的
2. 用户不知道它是不是从聊天里沉淀出来的
3. 用户不知道它和其他记忆页之间有没有关系

这会让长期记忆虽然“能改”，但还不够“能理解”。

## 4. 涉及范围

- `src/renderer/components/MemoryPageDetail.vue`
- 如有需要可复用：
  - `src/renderer/api.js`
  - 已存在的 `getMemoryWikiPageSourceTrace`

## 5. 前置依赖

1. 后端已提供长期记忆页面 `source-trace` 接口
2. 返回中已包含：
   - 聊天来源
   - 观察来源
   - 关联页面

## 6. 开发项

### 6.1 增加“这页记忆从哪里来”的摘要区

在详情页中增加轻量摘要区，至少包括：

1. 聊天来源条数
2. 观察记录来源条数
3. 相关记忆页数量

要求文案友好，不直接使用 `source-trace` 等术语。

### 6.2 展示轻量来源预览

对已有来源提供简短可读的预览：

1. 聊天来源展示日期和一句片段
2. 观察来源展示标题和日期
3. 不展示原始技术 id

### 6.3 展示相关记忆页

如果该页和其他长期记忆存在关联，应让普通用户看到：

1. 相关页标题
2. 相关页类型的普通用户文案

### 6.4 空态与创建态处理

要求：

1. 新建模式下不展示空洞的来源区
2. 已有页面但暂无来源时，给出温和说明
3. 不让详情页因为来源缺失显得“坏掉了”

## 7. 实现建议

### 7.1 普通用户文案

建议使用：

1. “这页记忆是怎么来的”
2. “铃湾是从这些聊天和观察里慢慢记住它的”
3. “和它有关的记忆”

### 7.2 不做事项

本任务不处理：

1. 跳转到聊天原文
2. 跳转到观察详情
3. 版本历史
4. 审计
5. 治理问题提示

## 8. 验收标准

1. 普通用户在长期记忆详情页可看到来源摘要
2. 可看到聊天来源、观察来源的轻量预览
3. 可看到相关记忆页标题
4. 不暴露技术 id 或治理术语

## 9. 自测清单

1. 打开一页已有来源的长期记忆，检查来源摘要是否正常显示
2. 检查聊天来源片段是否可读
3. 检查观察来源标题和日期是否正常
4. 检查相关记忆页是否正常显示
5. 打开新建页，确认不会出现空洞来源区
