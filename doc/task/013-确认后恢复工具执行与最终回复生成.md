# 013 确认后恢复工具执行与最终回复生成

## 1. 任务目标

在用户提交“同意”之后，恢复原始待执行 `tool_calls`，执行工具，并继续完成本轮对话的最终回复生成，真正打通确认流后端闭环。

本任务完成后，应至少具备：

- 用户同意后，原始待确认工具调用被恢复执行
- 工具执行结果能正确写回
- Cornie 能基于工具结果生成最终回复
- 拒绝场景也有明确结果返回

## 5. 目标链路

确认流应形成以下完整顺序：

```text
1. 用户发送消息
2. 模型提出高风险 tool call
3. 策略层输出 confirm
4. 后端保存 pending confirmation
5. 前端展示确认卡
6. 用户点击同意
7. 后端读取原始 tool calls
8. 后端执行工具调用
9. 工具执行结果回传模型
10. 模型生成最终自然语言回复
11. 保存回复与执行结果
12. 返回前端展示
```

## 6. 执行要求

### 6.1 同意路径

当用户提交 `approve` 时：

- 读取 `pendingConfirmation`
- 校验状态必须为 `approved` 或由本次提交转为 `approved`
- 取出原始 `toolCalls`
- 调用 `executeToolCalls`
- 构造 follow-up prompt
- 调用模型生成最终回复
- 保存 Cornie 回复消息
- 将确认动作状态更新为 `executed` 或 `failed`

### 6.2 拒绝路径

当用户提交 `reject` 时：

- 确认动作更新为 `rejected`
- 返回一条可展示的系统结果
- 可选：保存一条 Cornie 回复，例如“好的，这次先不执行”

## 7. 结果返回结构建议

建议确认结果提交接口在 `approve` 成功后返回：

```ts
type ConfirmationExecutionResult = {
  confirmation: PendingConfirmation
  toolExecution: {
    used: boolean
    results: ToolResult[]
  }
  cornieMessage?: {
    id: string
    content: string
  }
}
```

拒绝时返回：

```ts
type ConfirmationRejectResult = {
  confirmation: PendingConfirmation
  cornieMessage?: {
    id: string
    content: string
  }
}
```

## 8. 实现步骤

### Step 1

新增 `confirm/executor.js`

职责：

- 从 `pendingConfirmation` 恢复原始工具调用
- 执行工具
- 组织工具结果回灌模型
- 生成最终回复

### Step 2

在 `confirm/service.js` 中增加：

- `executeApprovedConfirmation(id)`
- `rejectConfirmation(id)`

### Step 3

在确认提交接口中接入执行器

建议：

- `approve` 后直接同步执行第一版闭环
- 若后续耗时较长，再演进为异步任务

### Step 4

持久化执行结果

至少更新：

- `pending_confirmations.status`
- `resolved_at`
- 对话消息表中的最终 Cornie 回复

可选：

- 工具审计日志

## 9. 异常处理要求

至少处理：

- 原始 `toolCalls` 反序列化失败
- 工具执行失败
- 工具成功但二次模型生成失败
- 重复执行同一确认动作

失败时要求：

- `pendingConfirmation.status = failed`
- 错误可回传前端
- 不得静默吞掉错误

## 10. 测试点

### 10.1 单元测试建议

- 恢复执行时能正确读取原始 `toolCalls`
- 工具执行成功后状态转为 `executed`
- 工具执行失败后状态转为 `failed`
- 拒绝时状态转为 `rejected`

### 10.2 联调测试

- 新增类目确认通过后，真实创建类目并返回最终回复
- 长期记忆确认通过后，真实写入记忆并返回最终回复
- 用户拒绝后，不发生落库副作用

## 11. 完成标准

- 用户同意确认后，系统可继续执行原始待确认动作
- 工具执行结果与最终 Cornie 回复可返回前端
- 用户拒绝后，系统能稳定收口，不产生错误副作用

## 12. 注意事项

- 恢复执行时必须使用持久化保存的原始 `toolCalls`
- 不要再次让模型重新生成一遍待确认动作
- 本任务优先完成同步闭环，先不要过早引入复杂队列机制
