# 464 追溯查询缓存

## 背景

`memory-wiki/service.js` 的 `getPageSourceTrace` 与 inspector 对每个 chatRef 各查一次 `getMessagesByDate`（Cornie-018 D-10），多来源页面追溯时 DB 调用次数 = 来源条数，无复用。与消费侧跨轮缓存（452）同属读取侧优化。

## 目标

1. 追溯按日期批量取消息（同一天多个 chatRef 只查一次）。
2. 可选进程内短 TTL 缓存（与 452 的 pageCache 统一设计，避免两套缓存）。

## 范围

- `electron/backend/memory-wiki/service.js`（getPageSourceTrace）
- `electron/backend/memory-wiki/inspector.js`
- 跨轮缓存模块（452 的 pageCache，若已落地则复用）

## 设计要求

1. 同一天多个 chatRef 合并为一次 `getMessagesByDate`。
2. 复用 452 的跨轮缓存设施（同一 key 设计），不新建第二套缓存。
3. 追溯结果不因缓存陈旧（写侧失效原则同 452）。

## 验收标准

1. 同一页面追溯的 DB 调用次数 = 涉及日期数（非来源条数，可埋点断言）。
2. 缓存命中与失效行为与 452 一致。
3. 无新缓存实现重复。

## 依赖与衔接

- 依赖：452（跨轮缓存设施）。
- 上游设计：Cornie-018 I-11（Phase 3）。
