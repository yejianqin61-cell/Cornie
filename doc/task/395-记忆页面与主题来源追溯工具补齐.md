# 395-记忆页面与主题来源追溯工具补齐

## 1. 任务目标

根据以下设计文档：

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

当前 Memory Wiki 已经具备：

- 页面来源追溯接口
- Topic 来源追溯接口
- 服务层聚合聊天、观察日志、相关页面、时间线

但模型工具层还没有把这两类只读能力正式开放出去，导致：

- 模型可以读页面正文，但不能直接查“这条记忆从哪来”
- 模型可以查 Topic 索引，但不能直接查“这个主题在哪几天、哪些聊天、哪些观察日志里出现过”

本任务目标是把“来源追溯”补成正式工具能力。

## 2. 任务来源

- `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 第 8、9、11、12、13 节
- `Cornie-0630-记忆层改进治理总纲-第一版.md` 第 7、9、10、11 节

## 3. 涉及范围

- `electron/backend/memory-wiki/tools.js`
- `scripts/`

## 4. 当前问题

当前已有：

- `memoryWiki.getPageSourceTrace(pageId)`
- `memoryWiki.getTopicSourceTrace(normalizedKey)`
- 人类 HTTP route：
  - `GET /memory-wiki/pages/:pageId/source-trace`
  - `GET /memory-wiki/topic-index/:normalizedKey/source-trace`

但缺少模型只读工具：

- `memory_wiki.get_page_source_trace`
- `memory_index.get_source_trace`

这与“默认轻注入、细节按需补查”的设计边界不一致。

## 5. 目标设计

### Step 1

在 `memory-wiki` 工具层新增：

- `memory_wiki.get_page_source_trace`
- `memory_index.get_source_trace`

### Step 2

确保返回结果直接透传现有 service 聚合结构，包括：

- 页面 / 主题摘要
- 聊天来源
- 观察来源
- 相关页面
- 时间线聚合
- 关联问题提示

### Step 3

补专项验证脚本，证明：

- 工具已注册
- 页面来源追溯工具可正常返回聊天与观察来源
- Topic 来源追溯工具可正常返回 topic timeline

## 6. 测试点

- 工具注册成功
- 页面来源追溯返回 `chatSources`
- 页面来源追溯返回 `observationSources`
- Topic 来源追溯返回 `topicTimelineTrace`
- `npm run build` 通过

## 7. 完成标准

- 模型侧正式拥有“记忆来源追溯”只读工具
- 与 0630 设计稿“来源可追溯、按需补查”的要求对齐
