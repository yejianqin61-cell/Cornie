# 321-8.3-Memory-Wiki跨来源类型切换后来源区开关循环的焦点锚点与默认入口同步增强

## 1. 任务目标

在 `317` 已补齐 Memory Wiki 跨来源类型切换后主动作文案与默认入口重算的基础上，继续细化来源区在不同来源类型之间切换、展开比较视角、返回正文、再次进入来源区时的焦点锚点与默认入口同步规则，避免入口顺序已更新，但键盘锚点和回流落点仍沿用旧来源类型。

## 2. 背景与现状

当前 Memory Wiki 来源阅读链路已经逐步补齐：

1. 跨来源切换后的滚动锚点与比较视角
2. 刷新后的来源组上下文恢复
3. 跨来源类型切换后的主动作与默认入口重算

但在来源区开关循环中，还可能出现：

1. 来源类型已切到观察日志，焦点锚点却还停在聊天记录来源入口
2. 用户从正文重新进入来源区时，默认落点仍继承旧类型
3. 比较视角关闭后，焦点回到的不是当前类型的首选入口

## 3. 涉及范围

- Memory Wiki 来源阅读区
- 来源类型切换后的焦点锚点、默认入口与返回正文落点
- 比较视角开关循环中的主上下文同步
- 对应前端测试

## 4. 前置依赖

1. `317-8.3-Memory-Wiki跨来源类型切换后主动作文案与默认入口重算增强.md` 已完成或至少已有默认入口重算
2. `285-8.3-Memory-Wiki来源阅读区跨来源切换后的滚动锚点与比较视角增强.md` 已完成或至少已有锚点与比较视角基础
3. `305-8.3-Memory-Wiki正文接管后再次进入来源区时的新一轮来源恢复判定增强.md` 已完成或至少已有再次进入来源区的新轮次判定

## 5. 具体开发项

### 5.1 来源类型切换后的焦点锚点重建

1. 切换来源类型后，若旧焦点属于上一类型入口、比较区或返回按钮，必须重建到当前类型的首选入口
2. 不允许焦点残留在当前界面已不可见的旧类型控件上
3. 弱数据态下无首选入口时，回落到稳定的来源区标题或正文返回入口

### 5.2 默认入口与回流落点同步

1. 当前来源类型的默认入口顺序必须同时驱动首屏落点与键盘首焦点
2. 从正文重新进入来源区时，按当前类型重新计算默认入口，不继承旧类型记忆
3. 关闭比较视角或来源区子面板后，焦点回到当前类型的有效主入口

### 5.3 开关循环稳定性

1. 来源区与正文之间多次往返后，当前来源类型的锚点规则保持稳定
2. 跨类型切换后开启新一轮开关循环，旧类型的展开记忆不应污染新类型
3. 与来源组恢复态、正文接管态、弱数据降级态兼容

### 5.4 测试补齐

1. 覆盖跨来源类型切换后的焦点锚点重建
2. 覆盖正文返回来源区后的默认入口重算
3. 覆盖比较视角关闭后的焦点回落
4. 覆盖多次往返后旧类型状态不串入新类型

## 6. 验收标准

1. Memory Wiki 来源区在跨来源类型与反复开关场景下，默认入口和焦点锚点始终一致
2. 用户不会因旧来源类型残留而误判当前阅读上下文
3. 正文、来源区、比较视角三者之间的回流落点稳定可预测
4. 对应前端测试通过
