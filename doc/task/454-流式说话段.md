# 454 流式说话段

## 背景

Cornie-019 §7.5：最终回答阶段改为 `stream:true` + SSE（或 fetch ReadableStream）逐字渲染；思考段（钻取多轮）只吐联想话语（453），**tool_call 信封不流式**。现状：`model/deepseek/client.js` `stream:false`，整段生成完才返回；前端 `useChat` 无 streaming 状态。

## 目标

1. DeepSeek 最终回答改为流式生成，前端逐字渲染。
2. 思考段（信封协议多轮钻取）与说话段（纯文本流式）解耦。
3. tool_call 信封绝不流式（结构化指令，只给后端）。

## 范围

- `electron/backend/model/deepseek/client.js`（新增 stream 调用能力：解析 SSE `data:` 增量）
- `electron/backend/agent/orchestrator.js`（思考段/说话段拆分：钻取多轮完成后，说话段流式生成最终回复）
- 对话 API 路由（`electron/backend/conversation/routes.js`，SSE 响应通道或 fetch stream 透传）
- `src/renderer/composables/useChat.js`（`streaming` 消息项：delta 追加、done 定稿落库）
- 聊天组件（`ChatHome.vue` / `CorniePet.vue` 气泡逐字渲染）

## 设计要求

### 1. 模型侧流式

- `deepseekFetch` 支持 `stream: true`，按 SSE 行解析 `data: {"choices":[{"delta":{"content":"…"}}]}`，逐块回调。
- 保留现有超时/错误码归一；流中断时给出可感知的失败提示（沿用"没听懂"降级文案不适用于流式，需明确流式失败处理）。

### 2. 编排结构：思考段 + 说话段

- 思考段：现有信封协议多轮（含 452 钻取预算、453 联想话语），结束后得到"已定稿的待回答上下文"。
- 说话段：一次纯文本流式 LLM 调用（persona + 上下文 + 定稿理解），逐块下发前端。
- 两段解耦后协议更干净；代价为多一次模型调用（可接受，写入验收成本基准）。

### 3. 传输与前端

- 传输：SSE（`Content-Type: text/event-stream`）或 fetch `ReadableStream`（Chromium 原生支持），二选一并在实现时确认与现有 CORS/preload 配置兼容。
- `useChat`：新增 `streaming` 消息项，收到 delta 追加 `content`；`done` 后替换为正式消息并走现有 `saveMessage` 落库。
- 桌宠窗口（CorniePet）与主窗口共享同一 streaming 逻辑。

### 4. 边界

- 工具轮/tool_call 信封只在后端流转，不下发前端。
- 流式期间禁用重复发送（沿用 `sending` 状态）。

## 验收标准

1. 最终回复逐字渲染（前端可见增量），完成后定稿落库。
2. 钻取轮联想话语（453）正常上屏，不与被流式的最终回复混淆。
3. tool_call 信封不出现在前端消息流。
4. 流式中断/超时有明确失败提示，不产生半截假回复落库。
