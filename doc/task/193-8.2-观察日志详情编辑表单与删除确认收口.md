# 193-8.2-观察日志详情编辑表单与删除确认收口

## 1. 任务目标

在观察日志首轮工作台基础上，继续补齐详情编辑表单、删除确认、未保存提示和提交反馈，让观察日志的人类 CRUD 不只是“理论可做”，而是具备稳定、可放心使用的正式交互闭环。

## 2. 背景与现状

`173` 已经提出要支持新增、编辑、删除观察日志，但要真正落地，仍缺少对以下细节的任务化承接：

1. 新增 / 编辑表单字段边界
2. 删除前风险确认
3. 未保存内容保护
4. 成功 / 失败反馈一致性

## 3. 涉及范围

- 观察日志详情区或编辑弹层
- 聊天外的人类编辑交互
- 对应前端测试

## 4. 前置依赖

1. `173-8.2-观察日志人类工作台首轮落地.md` 已完成或至少已有 CRUD 基础流

## 5. 具体开发项

### 5.1 新增 / 编辑表单

1. 明确支持编辑标题、类型、正文、来源文本等字段
2. 区分新增态与编辑态
3. 对必填字段、超长内容、空内容给出清晰校验

### 5.2 删除确认

1. 删除观察日志前要求二次确认
2. 明确说明删除后会影响后续阅读链路，但不夸大风险
3. 删除成功后回退到合适的列表状态

### 5.3 未保存内容保护

1. 编辑中切换条目时提示未保存变更
2. 关闭编辑态时提示是否放弃修改
3. 尽量避免用户误操作丢失内容

### 5.4 提交结果反馈

1. 保存成功后提示并刷新详情
2. 保存失败后保留用户输入
3. 删除失败后提示失败原因或兜底说明

### 5.5 测试补齐

1. 覆盖新增态与编辑态
2. 覆盖字段校验
3. 覆盖删除确认与删除完成
4. 覆盖未保存提示分支
5. 覆盖成功 / 失败反馈

## 6. 验收标准

1. 观察日志新增、编辑、删除形成稳定闭环
2. 用户不会因误操作轻易丢失编辑内容
3. 删除与保存操作都具备清晰反馈
4. 对应前端测试通过
