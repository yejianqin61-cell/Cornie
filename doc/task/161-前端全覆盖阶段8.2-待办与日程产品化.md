# 161-前端全覆盖阶段8.2-待办与日程产品化

## 1. 任务目标

根据 [Cornie-014-当前项目进度评估文档-V2.md](/C:/Users/USER/Desktop/Cornie/Cornie/doc/Cornie-014-当前项目进度评估文档-V2.md:1) 的 `8.1 第一优先级`，继续补齐“待办页与类目管理页”“日程页与类目管理页”的人类前端操作闭环。

本任务完成后，待办域与日程域至少应满足：

1. 人类可直接查看、创建、编辑、完成/恢复/删除事项
2. 人类可管理待办类目和日程类目
3. 页面结构与账本域保持一致的产品化标准

## 2. 背景与现状

当前仓库已经存在：

- `src/renderer/components/TodoWorkspace.vue`
- `src/renderer/components/ScheduleWorkspace.vue`
- 对应 API 与后端能力
- 对应前端测试

但仍存在：

1. 页面偏内部工作台形态
2. 类目管理能力分散、治理层次不够清晰
3. 待办 / 日程生命周期动作还不够“面向人类用户”

## 3. 开发范围

涉及范围：

- `src/renderer/components/TodoWorkspace.vue`
- `src/renderer/components/ScheduleWorkspace.vue`
- 如有必要，补充 `App.vue` 中入口与页面标题
- 相关前端测试文件

## 4. 具体开发项

### 4.1 待办产品化

补齐或优化：

1. 待办列表区、详情区、编辑区布局
2. 新建、编辑、完成、恢复、删除操作闭环
3. 待办类目新增、编辑、停用/恢复、排序
4. 空态、错误态、反馈提示统一

### 4.2 日程产品化

补齐或优化：

1. 日程列表区、详情区、编辑区布局
2. 新建、编辑、取消、恢复、删除操作闭环
3. 日程类目新增、编辑、停用/恢复、排序
4. 空态、错误态、反馈提示统一

### 4.3 与账本域的统一性

要求：

1. 三个业务域的人类交互风格保持一致
2. 错误提示、空态提示、操作按钮命名尽量统一
3. 让后续 Memory Wiki / Topic Index 产品化时可以复用同一视觉与交互骨架

## 5. 验收标准

1. 待办域人类接口完整闭环可用
2. 日程域人类接口完整闭环可用
3. 类目管理能力可由人类直接完成
4. 前端测试补齐并通过

## 6. 备注

本任务是“前端人类接口全覆盖”阶段的第二步，重点是把已有 Todo / Schedule 工作台打磨成正式产品页面，而不是仅供内部验证的操作板。
