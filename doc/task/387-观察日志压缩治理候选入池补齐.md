# 387 观察日志压缩治理候选入池补齐

## 目标

补齐观察日志的“压缩治理候选”能力。  
当同一自然日内，同一主题出现多条相近观察事实时，系统应能生成待审核的压缩候选，而不是仅依赖写入时的即时去重。

## 设计依据

- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`
- 第 11.5 节“压缩规则”
- 其中明确要求：
  - 当天写入时避免重复低价值事实
  - 同日同主题的相近事实可做增量合并
  - 观察日志不应无限增长为冗长流水账，因此需要压缩治理

## 当前缺口

- observation 当前已支持：
  - 当天写入时查重
  - 同日增量合并
  - 升级到长期记忆 wiki 的治理候选
- 但尚未支持：
  - 观察日志自身的压缩治理候选入池
  - 将“同日同主题重复事实”沉淀到独立治理区

## 本任务范围

1. 新增观察日志压缩候选生成器
2. 候选进入治理队列，不直接改写观察日志
3. 新增模型工具入口，便于模型侧或系统巡检主动触发

## 实现要求

1. 候选基础条件：
   - 同一自然日
   - 同一主题键或相近主题
   - 至少两条观察日志存在明显文本重叠
2. 治理请求要求：
   - `requestType: observation_compression_candidate`
   - `triggerSource: observation_governance`
   - `queueSection: observation_archive_candidates`
3. 证据至少包含：
   - observationId
   - date
   - type
   - title
   - content
   - relatedRef
4. 保持幂等：
   - 相同 observation 组合不重复入池
5. 不在本任务里自动执行压缩，只生成候选

## 验收标准

1. 同日同主题的两条相近 observation 能生成压缩治理候选
2. 候选应进入治理队列
3. 候选应保留 observation 证据
4. 重复执行不应重复入池
5. 工具集存在 `observation.enqueue_compression_candidates`
6. 验证脚本通过
7. `npm run build` 通过
