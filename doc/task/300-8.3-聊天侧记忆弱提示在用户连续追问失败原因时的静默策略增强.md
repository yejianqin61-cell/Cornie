# 300-8.3-聊天侧记忆弱提示在用户连续追问失败原因时的静默策略增强

## 1. 任务目标

在 `296` 已补齐失败提示与记忆弱提示同轮并存时的收束顺序基础上，继续细化用户连续追问“为什么失败”“怎么恢复”“刚才哪一步出问题”这类失败追问轮次里，记忆弱提示的静默策略，避免每轮都插入与当前问题无关的背景提示。

## 2. 背景与现状

用户一旦进入失败排障对话，连续几轮通常都围绕：

1. 失败原因
2. 恢复路径
3. 是否重试
4. 刚才哪一步断掉

这类对话阶段，系统最重要的是帮助用户完成排障，而不是维持透明提示存在感。如果不加静默策略，会出现：

1. 失败追问的每轮都夹带记忆弱提示
2. 用户越想聚焦问题，页面越显得嘈杂
3. 记忆提示虽然弱，但在排障阶段依旧显得多余

## 3. 涉及范围

- 聊天侧失败排障轮次
- 记忆弱提示静默策略、恢复策略与上下文判断
- 对应前端测试

## 4. 前置依赖

1. `296-8.3-聊天侧记忆弱提示与工具失败提示并存时的收束顺序增强.md` 已完成或至少已有失败轮次主次顺序
2. `288-8.3-聊天侧记忆引用弱提示在连续多轮中的退场与重现规则增强.md` 已完成或至少已有多轮抑制规则
3. `292-8.3-聊天侧记忆弱提示在新会话日切换后的清空与重建规则增强.md` 已完成或至少已有日期边界规则

## 5. 具体开发项

### 5.1 失败追问阶段识别

1. 识别用户是否进入围绕同一失败事件的连续追问阶段
2. 连续追问阶段里，记忆弱提示默认进入静默态
3. 不因单轮恢复正常就过早退出静默

### 5.2 静默与恢复

1. 静默态下，记忆弱提示不再主动出现
2. 若后续对话已明显离开失败排障主题，再恢复常规评估
3. 静默不影响工具结果卡、失败原因和恢复建议

### 5.3 极少数例外

1. 只有当某条记忆线索直接帮助解释失败原因时，才允许最轻量提示
2. 例外提示仍不能抢失败说明主位置
3. 例外使用应比普通轮次更克制

### 5.4 与多轮规则兼容

1. 失败追问静默优先级高于普通多轮重现规则
2. 新会话日或新主题切换后，可重新评估是否退出静默
3. 与确认卡、恢复建议和最终回复边界兼容

### 5.5 测试补齐

1. 覆盖连续失败追问阶段的记忆提示静默
2. 覆盖离开排障主题后的恢复展示
3. 覆盖直接帮助解释失败原因时的极轻例外提示
4. 覆盖静默规则与多轮重现规则冲突时的优先级

## 6. 验收标准

1. 用户连续排障时，聊天侧能明显保持更安静、更聚焦
2. 记忆弱提示不会在失败追问阶段持续刷屏
3. 例外提示只在真正有解释价值时出现
4. 对应前端测试通过
