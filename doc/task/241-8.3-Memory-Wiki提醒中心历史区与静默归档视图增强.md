# 241-8.3-Memory-Wiki提醒中心历史区与静默归档视图增强

## 1. 任务目标

在 `237` 已补齐提醒中心已读、暂缓和再次提醒规则的基础上，继续增加提醒中心历史区与静默归档视图，让已处理、已过期或低优先级的提醒有一个稳定去处，而不是永远堆在主提醒区。

## 2. 背景与现状

提醒中心状态流转一旦丰富，前端就需要一个“退场区”。否则会出现：

1. 已处理或已读的提醒虽已降级，但仍长期混在主提醒结构里
2. 用户无法回看历史提醒，失去治理回顾能力
3. 提醒中心长期使用后会越来越臃肿

## 3. 涉及范围

- Memory Wiki 提醒中心
- 历史提醒区 / 静默归档区
- 主提醒区与历史区的切换关系
- 对应前端测试

## 4. 前置依赖

1. `237-8.3-Memory-Wiki提醒中心已读暂缓与再次提醒规则增强.md` 已完成或至少已有提醒状态流转
2. `232-8.3-巡检提醒中心与待审核入口统一收口增强.md` 已完成或至少已有提醒中心

## 5. 具体开发项

### 5.1 历史区结构

1. 为已处理、已过期、长期静默的提醒提供独立历史区
2. 历史区默认折叠或次级展示，不压迫主提醒区
3. 支持按已处理、已暂缓、已失效等类型轻量分组

### 5.2 静默归档规则

1. 满足条件的提醒可自动进入静默归档区
2. 高风险项即使归档，也应保留可回看入口
3. 归档不等于删除，仍保留必要上下文

### 5.3 回顾与回流

1. 用户可从历史区回看某条提醒当时的来源与状态
2. 若历史提醒对应问题再次活跃，可从历史区重新回流主提醒区
3. 让历史区服务于治理复盘，而不是变成垃圾堆

### 5.4 视觉层次

1. 主提醒区始终保持最重要、最活跃的事项
2. 历史区表达要安静、可收纳
3. 历史区信息密度高于主提醒区，但不应难读

### 5.5 测试补齐

1. 覆盖提醒进入历史区
2. 覆盖历史区折叠与展开
3. 覆盖历史提醒重新激活回流主区
4. 覆盖高风险项归档后的可回看入口

## 6. 验收标准

1. 提醒中心长期使用后仍保持清爽
2. 历史提醒有稳定归宿且可回顾
3. 主提醒区与历史区分工清楚
4. 对应前端测试通过
