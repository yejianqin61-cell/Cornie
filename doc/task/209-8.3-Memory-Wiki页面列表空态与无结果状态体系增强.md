# 209-8.3-Memory-Wiki页面列表空态与无结果状态体系增强

## 1. 任务目标

在 `196` 的 Memory Wiki 页面列表搜索筛选能力基础上，继续把“全局空态、搜索无结果、筛选无结果、治理后为空”等不同状态做成一套清楚的人类可读状态体系，避免用户面对空白页时无所适从。

## 2. 背景与现状

`196` 已经提到搜索为空与无结果空态，但如果继续推进到正式工作台体验，还需要更明确区分：

1. 系统还没有页面
2. 搜索词没命中页面
3. 筛选条件过严导致为空
4. 某类治理后当前暂时没有待处理项

## 3. 涉及范围

- Memory Wiki 页面列表区
- 搜索 / 筛选状态提示区
- 对应前端测试

## 4. 前置依赖

1. `196-8.3-Memory-Wiki页面列表搜索筛选与扫描效率增强.md` 已完成或至少已有列表搜索筛选能力

## 5. 具体开发项

### 5.1 全局空态

1. 当系统还没有任何 Memory Wiki 页面时，展示全局空态
2. 空态文案说明这里将承接长期记忆页面
3. 提供合适的下一步入口，例如新建或查看引导

### 5.2 搜索无结果态

1. 搜索词无命中时展示搜索无结果态
2. 清楚展示当前搜索词
3. 提示可尝试标题、别名或关键词变体

### 5.3 筛选无结果态

1. 筛选条件导致为空时展示筛选无结果态
2. 提示当前筛选条件组合
3. 提供一键清空筛选入口

### 5.4 治理后健康空态

1. 某些分区处理完后可展示“当前没有待处理项”的健康空态
2. 让用户知道这是好状态，不是加载失败
3. 不把健康空态做成冷冰冰留白

### 5.5 测试补齐

1. 覆盖全局空态
2. 覆盖搜索无结果态
3. 覆盖筛选无结果态
4. 覆盖治理后健康空态

## 6. 验收标准

1. 用户能区分不同类型的“空”
2. 页面列表在无数据或无结果时依然具备清晰可读性
3. 空态能给出合理下一步，而不是纯留白
4. 对应前端测试通过
