# 377-重要人物高风险字段的主链注入边界收紧

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 与 `364-重要人物页性格与意义字段谨慎补齐.md` 的约束，收紧 `identity_person` 中高风险字段在主链 `memorySummary` 里的默认注入边界，避免“人物性格 / 对用户意义”在普通跨天对话中被无条件带入。

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`
- `doc/task/364-重要人物页性格与意义字段谨慎补齐.md`

## 3. 涉及范围

- `electron/backend/agent/wikiContext.js`
- `scripts/`

## 4. 当前问题

当前重要人物页摘要会默认拼出高风险字段 `personalitySummary`、`meaningToUser`。这会让尚未确认的人物性格和人物意义，在普通跨天对话里也直接进入主链摘要，不够克制。

## 5. 目标设计

- `relationshipToUser`、`firstKnownPeriod`、`sharedExperienceSummary`、`timelineSummary` 仍可作为默认稳定人物摘要
- `personalitySummary`、`meaningToUser` 只在更相关的 query 场景下进入主链
- 若页面 `ownerConfirmed === true`，可适当放宽

## 6. 实现步骤

### Step 1

在 `wikiContext` 中为人物页增加“高风险字段是否允许注入”的判定。

### Step 2

仅在情感 / 人物 / 关系相关 query，或页面已 owner confirmed 的情况下，带出 `personalitySummary` 与 `meaningToUser`。

### Step 3

新增验证脚本，确认普通 query 不会无条件注入这些高风险字段。

## 7. 测试点

- 普通 query 下人物摘要不默认带出 `意义` / `性格`
- 情感相关 query 下可按需带出这些字段
- 已确认人物页可放宽注入
- `npm run build` 通过

## 8. 完成标准

- 重要人物高风险字段的主链注入边界与设计稿一致
- 默认跨天记忆更克制，减少误伤与恐怖谷风险
