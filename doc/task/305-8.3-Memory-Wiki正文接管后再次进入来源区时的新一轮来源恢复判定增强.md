# 305-8.3-Memory-Wiki正文接管后再次进入来源区时的新一轮来源恢复判定增强

## 1. 任务目标

在 `301` 已补齐 Memory Wiki 详情页用户主动切回正文后来源恢复提示失活规则基础上，继续细化用户随后再次主动进入来源区时，系统如何判定这是“恢复旧来源任务”还是“开启新一轮来源阅读任务”，避免来源提示反复带着旧语义回归。

## 2. 背景与现状

用户在正文和来源区之间来回切换是正常行为。当前已明确：

1. 切回正文后，旧来源恢复提示应失活
2. 正文阅读应重新成为主上下文

但接下来还会遇到：

1. 用户稍后又重新点开来源区
2. 用户重新进入来源区时，系统不知道该沿用旧来源状态还是重建新轮次
3. 旧提示可能带着过期语义重新出现

## 3. 涉及范围

- Memory Wiki 详情页来源区
- 来源阅读任务的新旧轮次判定
- 来源恢复提示、来源组入口和失活状态重建
- 对应前端测试

## 4. 前置依赖

1. `301-8.3-Memory-Wiki详情页用户主动切回正文后来源恢复提示失活增强.md` 已完成或至少已有正文接管后的失活规则
2. `293-8.3-Memory-Wiki来源阅读区刷新后来源组上下文恢复与误跳防护增强.md` 已完成或至少已有来源组恢复逻辑
3. `297-8.3-Memory-Wiki来源组恢复态与页面详情折叠态并存时的主上下文判定增强.md` 已完成或至少已有主上下文判定

## 5. 具体开发项

### 5.1 新旧轮次边界

1. 明确用户重新进入来源区时，哪些条件表示开启新一轮来源阅读任务
2. 若用户只是短暂路过，不应重启完整来源恢复提示
3. 若用户明确展开来源组或切换来源类型，应优先视为新轮次

### 5.2 新轮次重建

1. 新轮次下可重新启用来源恢复提示或来源引导
2. 新轮次应清理旧正文接管阶段残留的来源状态
3. 新轮次仍需遵守弱数据态和比较视角降级规则

### 5.3 非新轮次静默处理

1. 不满足新轮次条件时，只保留静默上下文，不恢复强提示
2. 不因轻微切换造成正文和来源主上下文来回抖动
3. 页面滚动与布局保持稳定

### 5.4 用户认知与提示文案

1. 用户重新进入来源区时，能感知到这是新一轮来源阅读
2. 若只是继续浏览，不制造多余提示
3. 与正文阅读提示不并列竞争

### 5.5 测试补齐

1. 覆盖重新进入来源区被判定为新轮次
2. 覆盖短暂切换不重启完整提示
3. 覆盖新轮次下旧来源失活状态重置
4. 覆盖与弱数据态、比较视角降级并存时的结果

## 6. 验收标准

1. Memory Wiki 来源区在二次进入时的新旧轮次边界清楚
2. 来源提示不会带着过期语义反复回归
3. 正文阅读和来源阅读两种任务之间切换更稳定
4. 对应前端测试通过
