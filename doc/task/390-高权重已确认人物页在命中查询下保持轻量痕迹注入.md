# 390-高权重已确认人物页在命中查询下保持轻量痕迹注入

## 1. 任务目标

根据 `Cornie-0630-Identity记忆实体模型与页面结构设计.md` 第 7.5 节“对极高权重人物，可在日常摘要里保留轻量痕迹”与第 11 节“条件注入”要求，补齐 `wikiContext` 对高权重重要人物页的保留策略。

本任务要解决的问题是：

- 现在高权重人物页只在“无 query”时稳定保留
- 一旦当前轮存在 query，人物页可能因为别的命中页被挤出 `pageLimit`
- 这会导致设计稿要求的“重要人物轻量痕迹”在相关查询场景下反而不稳定

## 2. 任务来源

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- `doc/design/Cornie-0630-记忆层改进治理总纲-第一版.md`

## 3. 涉及范围

- `electron/backend/agent/wikiContext.js`
- `scripts/`

## 4. 当前问题

当前 `wikiContext` 的规则是：

- `identity_profile` 固定优先
- 无 query 时，`importance=high/critical` 的人物页会作为稳定注入候选
- 有 query 时，这条稳定规则会失效，只剩统一排序 + 截断

这会造成一个边界问题：

- 如果用户当前轮提到人物名字或关系词
- 同时又命中了多个 preference / trait / 其他 page
- 高权重人物页仍可能被 `pageLimit` 挤掉

这和设计稿中“相关时优先召回”“极高权重人物保留轻量痕迹”的产品语义不完全一致。

## 5. 目标设计

- 将“稳定人物痕迹”从“仅空 query 生效”收口为“高权重 + 已确认 + 与当前 query 命中时优先保留”
- 只保留轻量人物摘要，不放宽风险字段注入边界
- 不影响 preference / trait 的按需召回逻辑
- 不把未确认的重要人物一律塞进主链，避免误记忆扩大

## 6. 实现步骤

### Step 1

在 `wikiContext` 中补一层“稳定重要人物页”判定：

- `pageType === identity_person`
- `importance in [high, critical]`
- `ownerConfirmed === true`

### Step 2

将这类人物页在以下场景优先保留：

- 无 query 时，继续保留
- 有 query 且 query 命中人物页标题 / 摘要 / alias / 结构化字段时，也保留

### Step 3

继续沿用现有风险门控：

- 普通场景下仍只注入轻量人物摘要
- 只有情感 / 关系 / 意义相关 query 下才扩展 personality / meaning 等风险字段

### Step 4

新增专项验证脚本，覆盖：

- 有 query 且命中人物时，高权重已确认人物仍保留在主链摘要
- 普通命中 preference 的 query 不应把无关人物强行塞入
- 未确认人物不应享受该“稳定保留”特权

## 7. 测试点

- 高权重已确认人物在相关 query 场景下稳定进入 `memorySummary`
- 未命中人物 query 时，不引入无关高权重人物噪音
- 未确认人物在 query 场景下不应被该规则强保留
- `npm run build` 通过

## 8. 完成标准

- 重要人物轻量痕迹规则与 0630 设计稿对齐
- prompt 主链在“相关人物被提起”时不再意外丢失关键人物记忆
- 风险字段边界不回退
