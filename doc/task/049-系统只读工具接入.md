# 049 系统只读工具接入

## 1. 任务目标

补齐模型侧所需的系统只读工具，让模型能够按需读取运行上下文和模型状态，而不是把所有状态硬塞进 prompt。

本任务完成后，应至少具备：

- `settings.get_runtime_context`
- `health.get_model_status`

## 2. 任务来源

- `doc/design/Cornie-0625-模型侧改进设计.md` 第 6.2.10 节
- `doc/Cornie-004-当前模块实现度评估与下阶段开发建议.md` 第 4.5、6.2 节

## 3. 前置依赖

- `046-工具层能力对齐清单与缺口矩阵.md` 已完成

## 4. 涉及范围

- `electron/server.js`
- `electron/backend/tools/registry.js`
- 新增系统工具模块
- `electron/backend/model/deepseek/client.js`
- 可能涉及 `electron/backend/model/config.js`

## 5. 当前问题

虽然前端已有 `/api/model/status`，但模型自身还不能通过 tool 方式读取这些只读状态，和设计目标不一致。

## 6. 目标设计

- 系统状态工具必须是低风险、只读
- 返回结构要稳定、简洁
- 运行上下文至少应包含当前日期、模型提供方、已启用的主要能力摘要

## 7. 实现步骤

### Step 1

设计并新增系统只读工具模块。

### Step 2

注册到统一工具注册表。

### Step 3

验证返回结构与风险级别。

## 8. 测试点

- 工具可被网关正常调用
- 模型状态结果与现有 API 口径一致
- runtime context 返回结果稳定

## 9. 完成标准

- 两个系统只读工具已正式接入
- 可被后续协议层与编排层使用

## 10. 交付物

- 系统只读工具代码
- 对应验证结果
