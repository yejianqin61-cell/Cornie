# 320-8.3-失败静默例外入口跨主题开关循环后的键盘焦点与静默语义同步增强

## 1. 任务目标

在 `316` 已补齐失败静默例外入口跨主题后按钮语义与展开标题重置的基础上，继续细化用户在多个失败主题之间切换、主动展开例外入口、再次关闭并继续排障时的键盘焦点回落与静默语义同步，避免例外入口虽然文案已更新，但焦点和关闭后状态仍残留上一主题。

## 2. 背景与现状

当前聊天侧失败静默链路已经逐步补齐：

1. 连续追问失败原因时的静默策略
2. 静默态下用户主动查看记忆来源的例外通道
3. 跨主题后的按钮文案与标题重置

但在反复开关和跨主题循环中，还可能出现：

1. 主题 B 已生效，焦点却还停在主题 A 的例外入口按钮
2. 用户关闭 B 的来源卡后，界面退回的是 A 的旧静默状态
3. 键盘用户继续 Tab 时进入的是已失效的旧展开内容

## 3. 涉及范围

- 聊天侧失败静默例外入口
- 展开、关闭、跨主题后的焦点回落
- 静默状态与例外入口的同步重建
- 对应前端测试

## 4. 前置依赖

1. `316-8.3-失败静默例外入口跨主题后按钮语义与展开标题重置增强.md` 已完成或至少已有跨主题语义重置
2. `308-8.3-失败静默例外入口展开后再次关闭的回静默状态增强.md` 已完成或至少已有关闭回静默规则
3. `284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强.md` 已完成或至少已有焦点可达性约束

## 5. 具体开发项

### 5.1 跨主题后的焦点重建

1. 失败主题切换后，若旧焦点位于上一主题的例外入口或展开内容，必须重建到当前主题的有效入口
2. 不允许键盘继续操作隐藏的旧主题来源卡
3. 若当前主题不适合展示例外入口，则焦点回落到失败主链路区域

### 5.2 关闭后的静默语义同步

1. 用户关闭当前主题的例外内容后，必须回到当前主题对应的静默态
2. 不允许回退到上一主题的静默副本或旧按钮文案
3. 关闭后的焦点应落回当前主题的例外入口或失败说明主区

### 5.3 开关循环稳定性

1. 同一主题内多次展开/关闭后，焦点回落规则保持稳定
2. 跨主题后开启新一轮开关循环，旧主题的开关记忆不应串入新主题
3. 与连续追问、恢复成功后的普通透明提示并轨规则兼容

### 5.4 测试补齐

1. 覆盖跨主题后旧焦点被清理并重建
2. 覆盖关闭后回到当前主题静默态
3. 覆盖同一主题多次开关后的焦点稳定性
4. 覆盖恢复正常轮次后不遗留旧静默入口状态

## 6. 验收标准

1. 失败静默例外入口在跨主题与反复开关下仍保持当前主题一致性
2. 键盘用户不会误入旧主题的隐藏来源内容
3. 静默规则、例外入口、焦点回落三者在多轮排障中同步成立
4. 对应前端测试通过
