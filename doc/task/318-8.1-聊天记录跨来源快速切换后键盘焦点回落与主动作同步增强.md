# 318-8.1-聊天记录跨来源快速切换后键盘焦点回落与主动作同步增强

## 1. 任务目标

在 `314` 已补齐聊天记录跨来源快速切换后主按钮语义与返回动作一致性的基础上，继续细化键盘用户在多来源快速切换、进入回流提示、手动返回和再次切换时的焦点回落规则，避免主动作虽已重算，但焦点仍停留在旧来源按钮或失效控件上。

## 2. 背景与现状

当前聊天记录工作台已经逐步补齐：

1. 多入口回流并发时的主落点判定
2. 旧轮次提示出清
3. 主按钮文案与动作目标重算

但对键盘用户来说，若只重算动作、不控制焦点，还会出现：

1. 来源已切到 B，焦点却还停在 A 的旧按钮
2. 用户按回车触发的是已失效动作
3. 快速切换后焦点跳回列表顶部，打断当前阅读链路

## 3. 涉及范围

- 聊天记录工作台回流提示区
- 主按钮、次级按钮与返回入口的焦点回落
- 跨来源快速切换后的焦点与动作同步
- 对应前端测试

## 4. 前置依赖

1. `314-8.1-聊天记录跨来源快速切换后主按钮语义与返回动作一致性增强.md` 已完成或至少已有主动作重算
2. `284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强.md` 已完成或至少已有焦点顺序规范
3. `310-8.1-聊天记录不同来源入口连续切换时的旧轮次彻底出清增强.md` 已完成或至少已有旧轮次清理

## 5. 具体开发项

### 5.1 来源切换后的焦点重挂载

1. 来源切换完成后，若旧焦点位于已失效按钮，必须重新挂到当前来源的主动作或首个可用动作
2. 不允许保留对旧来源按钮 DOM 的隐式引用
3. 若当前来源无主动作，则回落到安全的阅读型入口

### 5.2 主动作与焦点同步

1. 焦点所在控件的文案、动作目标、可用状态必须与当前来源保持一致
2. 不允许出现“按钮文案已更新，但焦点语义仍属旧来源”的状态
3. 回车、空格触发结果必须与当前视觉主动作一致

### 5.3 快速切换与手动接管兼容

1. 多次快速切换后，以最后一次来源为准重建焦点落点
2. 若用户已手动接管阅读，不应因后台重算再次抢焦点
3. 手动从提示区返回正文后，再次切换来源时才开启新一轮焦点判定

### 5.4 测试补齐

1. 覆盖 A/B 来源快速切换后的焦点回落
2. 覆盖旧按钮失效后键盘触发不串来源
3. 覆盖手动接管后的不抢焦点规则
4. 覆盖多次切换后最终主动作与焦点一致

## 6. 验收标准

1. 聊天记录跨来源快速切换后，焦点始终落在当前有效动作体系内
2. 键盘用户不会误触旧来源动作
3. 手动接管与系统回流之间的焦点边界清晰、可预测
4. 对应前端测试通过
