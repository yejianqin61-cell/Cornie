# 450 记忆工具接线（D-01 / I-01）

## 背景

`electron/backend/memory-wiki/tools.js` 已定义 `registerMemoryWikiTools`（33 个工具：`memory_wiki.*` / `memory_index.*` / `memory_governance.*`），`policy/rules.js` L502-585 已为这些工具写好策略（只读 allow、写入 confirm）；但 `server.js` 仅注册 ledger/todo/schedule/observation/system 五类工具，**全仓库对 `registerMemoryWikiTools` 零调用**（Cornie-018 D-01）——模型在对话中拿不到任何记忆工具，policy 记忆规则不可达，"模型工具集 = 人类接口集"运行时失效。

## 目标

1. 在 `server.js` 运行时注册全部记忆工具。
2. `baseDir` 统一从启动链显式传入（避免各模块各自 `process.cwd()`）。
3. policy 记忆规则可达：只读工具 allow、写入/治理工具 confirm。
4. 新增接线验证脚本，纳入验收体系。

## 范围

- `electron/backend/server.js`（`createServer` 注册记忆工具）
- `electron/main.js`（启动链显式解析并传入 `baseDir`）
- `electron/backend/agent/contextBuilder.js`（`summarizeTools` 自动包含记忆工具）
- 新增 `scripts/verify-memory-tools-registered.mjs`（或并入 448 体系）

## 设计要求

### 1. 注册与 baseDir

- `createServer` 内 `await registerMemoryWikiTools({ baseDir, store }, { registerTool })`。
- `baseDir` 与 orchestrator / identity upsert / 提炼轮次（443）使用同一来源（`data/memory-wiki` 所在目录），在 `main.js` 启动链解析一次并显式传入 `createServer`，消除 `process.cwd()` 分散使用。

### 2. 策略可达性

- 只读工具（`get_page` / `list_pages` / `search_topic_index` / `list_topic_index`）→ allow。
- 写入/治理工具（create/merge/rollback/archive/set_status 等）→ confirm（走现有确认流）。
- 核对 `policy/rules.js` 与 `riskLevels.js`：低风险只读工具统一 allow，避免不一致（Cornie-018 审查 P2-3）。

### 3. 接线验证脚本

- 启动 server → `listTools()` 断言含记忆工具 → 断言 `buildConversationContext` 产出的 `toolSummary` 含记忆工具 → 断言 policy 对 `memory_wiki.create_page` 返回 confirm。

## 验收标准

1. 运行时工具注册表含 `memory_wiki.*` / `memory_index.*` / `memory_governance.*`。
2. `toolSummary`（注入 prompt）包含记忆工具摘要。
3. policy 对只读记忆工具返回 allow、对写入工具返回 confirm。
4. 验证脚本全绿并纳入 `test:full`。

- 衔接：449（注入侧评估）、451（目录与画像卡）、453（联想式层间话语）。
