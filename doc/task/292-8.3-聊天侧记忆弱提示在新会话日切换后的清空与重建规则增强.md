# 292-8.3-聊天侧记忆弱提示在新会话日切换后的清空与重建规则增强

## 1. 任务目标

在 `288` 已补齐记忆弱提示连续多轮退场与重现规则基础上，继续细化“跨到新会话日”或“切换到新的聊天日期上下文”后，旧提示抑制状态的清空、来源语义重建与首轮提示策略，避免前一天关闭过提示导致今天也完全不再提示。

## 2. 背景与现状

记忆弱提示的抑制规则如果只按连续轮次粗略计算，会遇到：

1. 昨天关闭过记忆提示，今天继续聊天时仍被错误抑制
2. 切换到另一日聊天记录或新对话上下文时，旧提示状态污染新语境
3. 旧来源组已经不相关，但抑制逻辑还在沿用

## 3. 涉及范围

- 聊天侧记忆弱提示
- 会话日切换、聊天日期切换与提示状态重建逻辑
- 对应前端测试

## 4. 前置依赖

1. `288-8.3-聊天侧记忆引用弱提示在连续多轮中的退场与重现规则增强.md` 已完成或至少已有多轮抑制规则
2. `199-8.3-聊天侧记忆来源展开卡与引用边界增强.md` 已完成或至少已有来源组识别基础
3. `227-8.1-聊天记录日期列表搜索筛选与最近访问增强.md` 已完成或至少已有聊天日期切换入口

## 5. 具体开发项

### 5.1 会话日边界识别

1. 明确“新会话日”或“新聊天日期上下文”的判定条件
2. 当用户进入新的日期上下文时，旧提示抑制状态应默认失活
3. 不把上一日的关闭动作无限延续到下一日

### 5.2 提示状态重建

1. 新会话日的首轮若引用了关键记忆来源，可重新恢复基础透明提示
2. 提示仍保持轻量，不因“新的一天”升级为强提示
3. 若新会话日仍沿用近似来源组，也应重新评估而不是盲继承旧抑制态

### 5.3 与聊天日期浏览兼容

1. 在浏览历史聊天日期时，不把“历史查看”误判为新的实时会话日
2. 仅在真实新对话上下文或明确切换的当前对话日中重建提示状态
3. 历史浏览态下保留阅读克制，不额外制造提示噪音

### 5.4 关闭与再出现边界

1. 用户在新会话日再次关闭提示后，只作用于该新日上下文
2. 新旧日期之间的关闭状态不相互污染
3. 与确认卡、工具失败提示并存时仍遵守弱提示让位原则

### 5.5 测试补齐

1. 覆盖跨到新会话日后提示抑制状态清空
2. 覆盖新会话日首轮重新出现基础提示
3. 覆盖历史聊天日期浏览不误触发重建
4. 覆盖新旧日期关闭状态隔离

## 6. 验收标准

1. 记忆弱提示的抑制和重建具有清晰的日期边界
2. 前一天的关闭动作不会错误影响新一天的透明提示
3. 历史浏览态与真实新会话态的提示行为可区分
4. 对应前端测试通过
