# 263-8.3-治理结果历史页空态下次级入口排序与默认动作增强

## 1. 任务目标

在 `260` 已补齐治理结果历史页跨页回流后的空态降级与语义澄清基础上，继续细化空态下多个次级入口的排序规则和默认推荐动作，让用户在“现在没结果”时更容易做出下一步。

## 2. 背景与现状

当历史页出现空态时，通常会同时存在几个可能出口，例如清空筛选、回到最近结果、去提醒中心、去待审核池。如果没有排序规则，会出现：

1. 次级入口太多，用户不知道先点哪个
2. 当前情境下最相关的动作没有被突出
3. 空态卡看起来像菜单，而不是明确建议

## 3. 涉及范围

- 治理结果历史页空态卡
- 次级入口按钮区
- 默认推荐动作规则
- 对应前端测试

## 4. 前置依赖

1. `260-8.3-治理结果历史页跨页回流后的空态降级与语义澄清增强.md` 已完成或至少已有空态与快捷动作
2. `253-8.3-Memory-Wiki治理结果历史页空态与首次使用引导增强.md` 已完成或至少已有历史页空态体系

## 5. 具体开发项

### 5.1 默认动作优先级

1. 根据空态类型确定默认主动作，如筛选过窄时优先“清空筛选”
2. 若当前问题尚未形成历史结果，则优先引导去当前治理工作台
3. 若存在最近结果，则可将“回到最近结果”作为高优先级动作

### 5.2 次级入口排序

1. 其余入口按相关性排序展示
2. 保持入口数量克制，不在空态卡里塞满所有可能跳转
3. 不同空态类型下，排序策略应明显不同

### 5.3 情境化文案

1. 主按钮和次级按钮文案应反映当前空态原因
2. 避免一套按钮文案打天下
3. 让用户看到按钮就知道点击后会发生什么

### 5.4 弱打扰边界

1. 空态动作区服务于恢复，不抢占页面主说明
2. 动作区应与来源提示、空态解释形成清楚层次
3. 不因动作太多破坏空态页整洁度

### 5.5 测试补齐

1. 覆盖筛选过窄场景下的默认动作
2. 覆盖尚未形成历史结果场景下的默认动作
3. 覆盖有最近结果时的排序差异
4. 覆盖不同空态类型的按钮文案变化

## 6. 验收标准

1. 治理结果历史页空态下存在清楚的下一步推荐
2. 用户无需在多个入口中犹豫
3. 默认动作与次级入口排序符合当前情境
4. 对应前端测试通过
