# 301-8.3-Memory-Wiki详情页用户主动切回正文后来源恢复提示失活增强

## 1. 任务目标

在 `297` 已补齐 Memory Wiki 详情页“正文恢复”和“来源区恢复”主上下文判定基础上，继续细化当用户主动切回正文阅读后，来源恢复提示和来源组引导何时应失活、如何降级，以及什么时候才允许再次恢复来源上下文。

## 2. 背景与现状

来源区恢复提示的目的是帮助用户续上来源追溯任务。但如果用户已经明确切回正文阅读，再保留来源恢复提示就会出现：

1. 用户已经开始看正文，来源提示还在提醒“你刚才在看来源”
2. 来源恢复入口持续占位，破坏正文阅读沉浸感
3. 页面像在两个阅读任务之间摇摆不定

## 3. 涉及范围

- Memory Wiki 详情页正文区与来源区
- 来源恢复提示、来源组引导与正文主动接管识别
- 失活、降级与重新启用规则
- 对应前端测试

## 4. 前置依赖

1. `297-8.3-Memory-Wiki来源组恢复态与页面详情折叠态并存时的主上下文判定增强.md` 已完成或至少已有主上下文判定
2. `293-8.3-Memory-Wiki来源阅读区刷新后来源组上下文恢复与误跳防护增强.md` 已完成或至少已有来源组恢复提示
3. `221-8.3-Memory-Wiki详情区块折叠与阅读密度控制增强.md` 已完成或至少已有正文阅读模式控制

## 5. 具体开发项

### 5.1 正文主动接管识别

1. 明确哪些行为表示用户已切回正文任务，例如展开正文、调整阅读密度、持续正文滚动
2. 一旦判定成立，来源恢复提示应迅速从主提示降级
3. 不把短暂经过正文区误判为主动接管

### 5.2 来源提示失活

1. 用户切回正文后，来源恢复提示不再作为主上下文存在
2. 来源组引导降级为安静入口，不再抢正文顶部注意力
3. 若用户持续停留正文区，则旧来源提示彻底失活

### 5.3 重新启用条件

1. 用户再次明确进入来源区时，可视为新一轮来源阅读任务
2. 新一轮来源阅读任务应重新评估恢复提示，而不是沿用旧状态
3. 与来源比较视角降级、弱数据态和刷新恢复兼容

### 5.4 提示与布局收口

1. 正文主导时，页面只保留最必要的来源入口
2. 不同时保留正文恢复提示和来源恢复提示
3. 提示退场后不影响正文滚动稳定性

### 5.5 测试补齐

1. 覆盖用户主动切回正文后的来源提示降级
2. 覆盖正文区持续停留后的彻底失活
3. 覆盖再次进入来源区后的新一轮恢复评估
4. 覆盖与弱数据态、来源比较降级并存时的兼容

## 6. 验收标准

1. Memory Wiki 详情页在用户切回正文后会明显尊重正文阅读任务
2. 来源恢复提示不会在正文主导阶段长期占位
3. 来源追溯任务与正文阅读任务之间的边界更清楚
4. 对应前端测试通过
