# 436-聊天记录驱动状态自检与运行口径收口

## 1. 任务目标

在当前聊天记录已经进入 `better-sqlite3` 主路线的基础上，补齐“系统自己知道当前到底跑的是哪个驱动、前端和文档也能给出一致口径”的最小闭环。

本任务不重新实现聊天记录存储迁移本身，而是解决另外一个真实问题：

1. 运行时到底是不是 `better-sqlite3`
2. 如果不是，当前落在哪个兼容路径
3. 开发、排障、验收时如何快速确认

也就是说，本任务重点是“驱动状态透明、自检可验证、口径不再含糊”。

## 3. 背景与现状

前序任务已经完成：

1. `363-聊天记录Repository抽象与better-sqlite3驱动迁移骨架`
2. `367-better-sqlite3聊天记录驱动首版实现`
3. `396-better-sqlite3聊天记录运行时切换落地`

但当前还缺少一个对外一致的状态确认机制：

1. 代码里虽然支持驱动切换，但运行中不一定容易判断当前使用的是哪个驱动
2. 发生聊天记录异常时，不容易第一时间确认是否落在 fallback 路径
3. 验收与发布时，缺少统一的“聊天记录驱动现状”口径

## 5. 开发项

### 5.1 补齐聊天记录驱动状态读取能力

要求系统可明确返回：

1. 当前聊天记录运行时驱动名
2. 当前数据库路径
3. 是否处于 fallback / 兼容路径
4. 驱动初始化是否成功

返回结果应尽量结构化，便于前端、脚本和日志统一使用。

### 5.2 启动期驱动状态日志收口

在应用启动或聊天记录服务初始化时，补齐轻量但明确的状态输出：

1. 选中了哪个驱动
2. 是否成功初始化
3. 若发生降级，降级原因是什么

要求：

1. 日志简洁
2. 不刷屏
3. 可直接用于本地排障

### 5.3 暴露只读诊断接口

提供最小只读诊断能力，便于：

1. 本地验收
2. 启动自检
3. 前端如有需要可读到“当前聊天记录引擎状态”

该接口只允许读取，不允许任何存储层切换或写操作。

### 5.4 验证脚本补齐

新增或补齐专项脚本，至少覆盖：

1. 启动后可读取当前驱动状态
2. 驱动状态与实际读写链路一致
3. fallback 路径下状态字段仍正确

## 6. 不做事项

本任务不处理：

1. 再次重写 `better-sqlite3` 仓储实现
2. 聊天记录 API 契约大改
3. 前端历史聊天产品化
4. 全项目数据库统一迁移

## 7. 验收标准

1. 系统可通过只读方式明确读取当前聊天记录驱动状态
2. 启动日志能说明当前使用的聊天记录驱动
3. 如落入 fallback 路径，能明确识别且不靠猜
4. 配套验证脚本可稳定跑通

## 8. 自测清单

1. 正常启动时检查驱动状态是否为预期值
2. 执行一轮聊天记录写入和读取后，检查状态接口是否仍一致
3. 人工制造兼容路径或异常路径时，检查状态与日志是否可读
4. 验证脚本运行后，输出是否足以支撑验收
