# 228-8.1-聊天记录消息区滚动恢复与锚点跳读增强

## 1. 任务目标

在 `194` 和 `203` 已初步补齐聊天记录长对话阅读能力的基础上，继续增强消息区滚动恢复、锚点跳读和“回到上次阅读位置”的体验，让长对话真正具备档案式阅读工作台手感。

## 2. 背景与现状

当前长对话阅读虽然已经比最初版本完整，但仍存在：

1. 切换到别的日期再回来时，需要重新翻找刚才看到的位置
2. 从观察日志、记忆引用或同日关系面板跳入某天聊天后，缺少稳定锚点
3. 很长的对话里上下滚动查找上下文仍然费力

## 3. 涉及范围

- 聊天记录消息列表区
- 聊天记录与外部跳转入口的定位协议
- 前端本地阅读位置状态
- 对应前端测试

## 4. 前置依赖

1. `194-8.1-聊天记录日期摘要与长对话阅读收口.md` 已完成或至少已有长对话阅读结构
2. `203-8.1-聊天记录与观察日志跨日联动定位增强.md` 已完成或至少已有跨模块跳转定位
3. `180-8.1-聊天记录与观察日志日记关系工作台.md` 已完成或至少已有同日关系入口

## 5. 具体开发项

### 5.1 阅读位置恢复

1. 记住每个日期最近一次阅读滚动位置
2. 从别的日期切回时，尽量恢复上次停留位置
3. 对消息很少的日期保持轻量恢复，不制造额外复杂度

### 5.2 锚点跳读

1. 支持从观察日志、日记关系摘要、记忆引用等入口直接跳到相关消息附近
2. 被定位的消息要有短暂高亮或轻量提示，帮助用户建立方向感
3. 跳读后仍应保留继续上下浏览的自然滚动体验

### 5.3 长对话辅助导航

1. 提供回到顶部、回到最新消息、回到上次定位点等快捷入口
2. 对超长对话提供轻量分段提示或阶段锚点
3. 保持消息区布局稳定，不因跳读导致突兀抖动

### 5.4 状态边界

1. 区分“用户主动阅读位置”和“外部跳入定位点”
2. 切换到其他日期时正确隔离阅读状态
3. 在消息数据变化后合理兜底，不恢复到无效位置

### 5.5 测试补齐

1. 覆盖阅读位置恢复
2. 覆盖外部入口跳读与高亮提示
3. 覆盖快捷返回入口
4. 覆盖无效锚点或消息变化后的兜底恢复

## 6. 验收标准

1. 长对话阅读具备稳定的“看到哪、回到哪”体验
2. 跨模块跳入聊天记录时能快速找到目标上下文
3. 消息区跳读不会破坏正常浏览节奏
4. 对应前端测试通过
