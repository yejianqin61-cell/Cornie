# 309-8.3-Memory-Wiki来源区新轮次开启后旧正文接管提示的清理时机增强

## 1. 任务目标

在 `305` 已补齐 Memory Wiki 正文接管后再次进入来源区时的新一轮来源恢复判定基础上，继续细化一旦新来源阅读轮次成立，旧正文接管提示和正文主导说明应在何时清理，避免新旧两种阅读任务说明同时留在页面上。

## 2. 背景与现状

当来源区新轮次成立后，页面会经历：

1. 正文接管阶段的旧提示已存在过
2. 用户重新进入来源区
3. 新来源轮次开始接管

如果旧正文提示清理不及时，就会出现：

1. 页面同时像在说“你正在看正文”和“你正在回到来源区”
2. 来源新轮次被旧正文说明拖住
3. 用户分不清当前主任务已经换了

## 3. 涉及范围

- Memory Wiki 详情页正文区与来源区
- 旧正文提示、新来源提示与主任务切换时机
- 清理、替换与提示退场逻辑
- 对应前端测试

## 4. 前置依赖

1. `305-8.3-Memory-Wiki正文接管后再次进入来源区时的新一轮来源恢复判定增强.md` 已完成或至少已有新来源轮次判定
2. `301-8.3-Memory-Wiki详情页用户主动切回正文后来源恢复提示失活增强.md` 已完成或至少已有正文接管提示逻辑
3. `297-8.3-Memory-Wiki来源组恢复态与页面详情折叠态并存时的主上下文判定增强.md` 已完成或至少已有主上下文切换规则

## 5. 具体开发项

### 5.1 清理触发时机

1. 一旦来源区新轮次被确认成立，旧正文接管提示应进入清理流程
2. 清理可允许极短过渡，但不应长期并存
3. 清理时机应早于新来源提示完全展开后的稳定态

### 5.2 提示替换规则

1. 新来源轮次成为主上下文后，旧正文说明降级或退场
2. 不同时保留两个平级主说明
3. 若新来源轮次仅为短暂浏览，则不必重启完整替换

### 5.3 用户认知一致性

1. 用户应一眼看懂当前主任务已经从正文阅读切到来源追溯
2. 过渡提示要轻，不制造“页面跳模式”的惊扰感
3. 与弱数据态、比较视角降级和滚动恢复兼容

### 5.4 再次回正文的回切边界

1. 若用户很快又回正文，应按新一轮正文接管重新评估
2. 不保留上上一轮来源说明残影
3. 正文和来源两套提示状态保持可回收、可重建

### 5.5 测试补齐

1. 覆盖来源新轮次成立后旧正文提示清理
2. 覆盖短暂浏览不触发完整替换
3. 覆盖快速再次回正文时的新一轮回切评估
4. 覆盖与弱数据态、比较视角降级并存时的结果

## 6. 验收标准

1. Memory Wiki 页面不会同时保留两套平级主任务说明
2. 来源区新轮次开启后，旧正文接管提示会及时让位
3. 正文阅读和来源阅读之间的任务切换更清晰
4. 对应前端测试通过
