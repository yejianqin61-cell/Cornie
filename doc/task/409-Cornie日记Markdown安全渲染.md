# 409-Cornie日记Markdown安全渲染

## 1. 任务目标

为 Cornie 日记页面补齐 Markdown 渲染能力，让模型生成的标题、强调、段落等结构在前端被正确展示，避免用户直接看到原始 Markdown 标记。

## 2. 对应来源

- GitHub Issue `#15` 前端-日记页面
- 设计文档：`doc/design/Cornie-0701-GitHub-Issue-011-015前端问题分级与落地设计.md`

## 3. 背景与现状

当前 Cornie 日记内容来自模型生成，文本中可能包含：

1. `#` `##` 标题
2. `**加粗**`
3. 引用或列表
4. 段落留白

如果前端仅按纯文本渲染，会导致：

1. 文本结构感消失
2. 文学表达效果被破坏
3. 用户直接看到 `##`、`**` 等符号

## 4. 涉及范围

- 需要定位当前日记页实际组件，通常可能涉及：
  - `src/renderer/components/*Diary*.vue`
  - `src/renderer/components/*Entry*.vue`
  - `src/renderer/App.vue` 内的日记展示区域
- `package.json`
- 如需新增渲染封装组件，可新增：
  - `src/renderer/components/CornieDiaryMarkdown.vue`

## 5. 前置依赖

1. 当前日记页面已有原始文本展示能力。
2. Cornie 日记正文数据链路稳定可读。
3. 项目允许引入轻量 Markdown 渲染依赖，或已有可复用方案。

## 6. 开发项

### 6.1 接入 Markdown 渲染能力

为 Cornie 日记正文接入 Markdown 渲染，至少支持：

1. 标题
2. 粗体
3. 斜体
4. 段落
5. 无序列表
6. 引用块

### 6.2 仅开放安全、轻量的 Markdown 子集

本期应明确限制：

1. 不允许原始 HTML 直接注入页面
2. 不支持脚本执行
3. 不允许不受控富内容透传

若使用第三方渲染库，必须确认默认配置安全，或手动关闭 HTML 渲染。

### 6.3 处理格式异常的容错

当模型返回非标准 Markdown 或半结构化文本时：

1. 能识别的部分正常渲染
2. 无法识别的部分按纯文本展示
3. 不允许因为局部格式错误导致整块内容空白或报错

### 6.4 优化正文阅读样式

渲染后需要补齐日记阅读样式：

1. 标题层级清晰
2. 正文行高舒展
3. 段落间距自然
4. 引用和强调样式柔和，不做技术博客风格

### 6.5 保持普通用户视角

日记页最终呈现应更像“被排版后的日记”，而不是“Markdown 演示页”。

不应出现：

1. 代码风格过强
2. 技术味过重的语法展示
3. 复杂调试性 UI

## 7. 实现建议

### 7.1 组件封装建议

建议封装独立渲染组件，例如：

1. `CornieDiaryMarkdown.vue`

职责：

1. 接收原始字符串
2. 完成 Markdown 到安全 HTML 或 VNode 的转换
3. 承担样式隔离

### 7.2 依赖选择建议

优先选择轻量、前端常见、支持关闭 HTML 的 Markdown 方案。

要求在开发中明确：

1. 为什么选该库
2. 是否支持安全模式
3. 是否会额外引入过重体积

### 7.3 样式建议

建议单独定义日记正文容器样式，而不是污染全局 Markdown 样式。

## 8. 验收标准

1. `#` `##` `**` 等常见 Markdown 在日记页能正确渲染。
2. 非法 Markdown 不会导致页面报错或空白。
3. 页面最终阅读体验明显优于纯文本直出。
4. 不存在原始 HTML 注入风险。

## 9. 自测清单

1. 准备一段带 `##`、`**`、列表的 Cornie 日记，确认渲染正确。
2. 准备一段普通纯文本日记，确认仍正常显示。
3. 准备一段格式不完整的 Markdown，确认页面不崩溃。
4. 检查标题、段落、强调样式是否符合日记阅读场景。
5. 检查是否存在原始 HTML 被当作真实标签插入页面。
