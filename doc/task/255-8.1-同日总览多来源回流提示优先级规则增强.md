# 255-8.1-同日总览多来源回流提示优先级规则增强

## 1. 任务目标

在 `244`、`249`、`250` 已补齐同日总览状态、Cornie 日记回流和聊天记录面包屑基础上，继续细化多来源同时回流到同日总览时的提示优先级规则，避免面板顶部同时出现多条竞争说明。

## 2. 背景与现状

随着聊天记录、观察日志、Cornie 日记、人类日记都能围绕同日总览来回跳转，真实使用中会出现：

1. 多条回流说明同时满足触发条件
2. 用户不清楚当前最相关的是哪条来源链路
3. 面板顶部提示堆叠后反而降低可读性

## 3. 涉及范围

- 同日总览面板
- 跨模块回流提示条
- 多来源提示优先级与合并规则
- 对应前端测试

## 4. 前置依赖

1. `244-8.1-同日关系面板已查看已完成状态与收口增强.md` 已完成或至少已有同日总览状态体系
2. `249-8.2-Cornie日记回到同日总览的状态保持与回流提示增强.md` 已完成或至少已有日记回流提示
3. `250-8.1-聊天记录与Cornie日记之间的回看面包屑增强.md` 已完成或至少已有聊天与日记回流说明

## 5. 具体开发项

### 5.1 优先级规则

1. 明确不同来源回流提示的优先级，如刚生成成功的日记高于普通查看返回
2. 高优先级提示展示时，低优先级提示自动降级或延后
3. 规则应稳定、可预测，不让用户觉得随机

### 5.2 提示合并策略

1. 当多条提示含义接近时，尝试合并成一条更高信噪比的说明
2. 合并后仍保留必要来源信息，不做模糊化处理
3. 不把完全不同性质的提示硬合成一句难懂的话

### 5.3 时间窗口与退场

1. 不同来源提示拥有合理的展示时长
2. 用户完成当前关注动作后，低优先级旧提示应自然退场
3. 切换日期或离开同日总览后，提示状态正确清理

### 5.4 可见性边界

1. 同日总览同一时刻只突出最值得注意的一条提示
2. 其余来源信息可通过次级入口或轻量历史查看
3. 保持总览面板“总览优先”，不被提示流淹没

### 5.5 测试补齐

1. 覆盖多来源同时命中的优先级判断
2. 覆盖提示合并策略
3. 覆盖切换日期后的提示清理
4. 覆盖展示时长与自动退场

## 6. 验收标准

1. 多来源回流下，同日总览仍然清楚不乱
2. 用户能快速理解当前最相关的回流链路
3. 提示优先级与合并规则稳定、可预测
4. 对应前端测试通过
