# 383 重要人物页到关系内侧写页的弱关联补齐

## 目标

补齐 `identity_person -> identity_trait` 的弱关联链路。  
当重要人物页中沉淀出“用户在这段关系中的状态特征”时，系统应尝试把该人物页和已有的 `identity_trait` 页建立双向弱关联，便于后续记忆回查、Prompt 补查和人工治理。

## 设计依据

- `doc/design/Cornie-0630-Identity记忆实体模型与页面结构设计.md`
- 第 9.1 节推荐关系要求：
  - `identity_person -> identity_trait`
  - 如果某人物页中沉淀出“用户在此关系中的状态特征”，可做弱关联

## 当前缺口

- `personUpsert.js` 当前只补：
  - `identity_profile <-> identity_person`
  - `identity_person -> Topic Index`
  - 高风险人物意义/关系冲突治理候选
- `traitUpsert.js` 当前只补：
  - `identity_profile <-> identity_trait`
- 还没有：
  - `identity_person <-> identity_trait` 自动弱关联

## 本任务范围

1. 在重要人物页创建 / 更新 / 冲突回写场景中，尝试扫描已有 `identity_trait` 页
2. 当人物候选中的关系内状态特征与 trait 页存在弱匹配时，补齐双向 `relatedPageIds`
3. 保持幂等，重复执行不重复写入
4. 不在本任务里新建 trait 页，只做“已有 trait 页的弱关联补链”

## 实现要求

1. 在 `electron/backend/identity/personUpsert.js` 新增弱关联补链函数
2. 关系内状态特征的匹配来源可包含：
   - `personalitySummary`
   - `meaningToUser`
   - `sharedExperienceSummary`
   - `timelineSummary`
3. trait 页匹配来源可包含：
   - `title`
   - `traitSummary`
   - `triggerKeywords`
   - `aliases`
4. 若命中，则：
   - `identity_person.relatedPageIds` 补 trait pageId
   - `identity_trait.relatedPageIds` 补 person pageId
5. 若未命中，不报错，不强行创建新页

## 验收标准

1. 先创建一个 `identity_trait` 页
2. 再创建一个 `identity_person` 页，且其内容可表达出关系内状态特征
3. 验证：
   - 人物页 `relatedPageIds` 包含 trait 页
   - trait 页 `relatedPageIds` 包含人物页
4. 重复执行相同写入时：
   - 不重复追加关联
5. 运行验证脚本通过
6. `npm run build` 通过
