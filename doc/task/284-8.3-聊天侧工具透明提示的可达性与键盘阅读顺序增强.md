# 284-8.3-聊天侧工具透明提示的可达性与键盘阅读顺序增强

## 1. 任务目标

在 `174`、`189`、`225` 已补齐聊天侧工具透明反馈、过程态分层和结果编排基础上，继续补齐工具结果卡、确认卡、记忆引用提示的键盘可达性、焦点顺序与阅读顺序，避免这些透明提示只对鼠标用户友好。

## 2. 背景与现状

当前聊天侧已经逐步具备：

1. 工具结果卡与失败兜底说明
2. 过程卡、确认卡、结果卡分层
3. 记忆引用的轻量透明提示

但随着卡片越来越多，若不补可达性，会出现：

1. 键盘切换时焦点顺序混乱，不知道先读过程还是先读结论
2. 展开收起工具卡后，焦点容易丢失
3. 记忆引用提示、确认卡、最终回复并存时，屏幕阅读顺序不稳定

## 3. 涉及范围

- 聊天侧工具结果卡、确认卡、记忆引用提示
- 聊天消息区焦点与键盘导航规则
- 对应前端测试

## 4. 前置依赖

1. `174-8.3-记忆引用透明提示与工具结果面板增强.md` 已完成或至少已有工具结果与记忆提示基础
2. `189-8.3-聊天侧工具过程态与结果态反馈分层增强.md` 已完成或至少已有过程态和结果态分层
3. `225-8.3-聊天侧工具卡分组编排与最终回复边界增强.md` 已完成或至少已有过程区与最终回复分区

## 5. 具体开发项

### 5.1 键盘阅读顺序

1. 明确单轮次内默认键盘阅读顺序为：轮次摘要 / 过程区 / 确认区 / 结果区 / 最终回复
2. 当某些区块不存在时，顺序自动收口，不出现焦点黑洞
3. 同一轮次内多张工具卡的焦点顺序与视觉顺序一致

### 5.2 展开收起后的焦点保持

1. 展开某张工具卡后，焦点稳定落在展开内容首个可读位置
2. 收起后，焦点回到触发该操作的按钮
3. 多卡连续展开收起时，不发生焦点跳到聊天区顶部的问题

### 5.3 透明提示与最终回复的可达边界

1. 记忆引用提示作为辅助信息，不抢最终回复主阅读顺位
2. 失败提示和确认卡需要可被明确访问，但不压过最终结论
3. 轮次结束后，最终回复仍是最自然的收束阅读落点

### 5.4 辅助语义

1. 为工具卡、确认卡、记忆提示增加清晰的语义标签或标题
2. 区分“这是过程信息”“这是确认请求”“这是执行结果”“这是最终回复”
3. 文案保持用户语言，不直接暴露工程术语

### 5.5 测试补齐

1. 覆盖单轮次内多区块的键盘访问顺序
2. 覆盖展开收起后的焦点恢复
3. 覆盖最终回复与辅助提示并存时的主次顺序
4. 覆盖缺失部分区块时的自动收口

## 6. 验收标准

1. 聊天侧工具透明提示体系对键盘用户同样可用
2. 焦点顺序、视觉顺序、语义顺序三者基本一致
3. 透明提示增强不会破坏最终回复的自然阅读节奏
4. 对应前端测试通过
