# 200-8.3-Memory-Wiki高频治理快捷入口与状态概览增强

## 1. 任务目标

在现有 Memory Wiki 工作台、待审核区、巡检区、审计区基础上，补齐一个“高频治理快捷入口 + 当前状态概览”层，让用户进入 Memory Wiki 时，不必先读完整页，先看到当前最值得处理的治理事项。

## 2. 背景与现状

当前已经有多个治理相关区域，但随着能力增加，前端会逐渐出现问题：

1. 用户不知道先进哪个区最有价值
2. 待审核、巡检、审计之间缺少一个总览层
3. 高频治理入口还不够聚焦

## 3. 涉及范围

- `src/renderer/components/MemoryWikiWorkspace.vue`
- 工作台首页概览区
- 对应前端测试

## 4. 前置依赖

1. `181-8.2-Memory-Wiki待审核角标与异步提醒增强.md` 已完成或至少已有计数
2. `182-8.3-治理候选分区与批量处置工作台增强.md` 已完成或至少已有分区
3. `195-8.3-Memory-Wiki巡检结果分类阅读与跳转收口.md` 已形成巡检阅读方向

## 5. 具体开发项

### 5.1 治理状态概览区

1. 在 Memory Wiki 首页展示待审核数、巡检问题数、最近关键审计数
2. 用平实摘要提示“现在最值得处理的是什么”
3. 不把全部细节堆在首页

### 5.2 高频快捷入口

1. 提供进入待审核区的快捷入口
2. 提供进入巡检结果区的快捷入口
3. 提供进入最近被频繁修改页面或高优先级治理候选的快捷入口

### 5.3 状态优先级表达

1. 区分高优先级治理事项与普通查看项
2. 让用户一眼知道哪些问题值得先处理
3. 保持克制，不做过度惊扰的红色告警墙

### 5.4 与聊天侧提示联动

1. 若聊天侧提示有新的治理建议，这里应能承接对应入口
2. 保证聊天侧轻提示和 Wiki 内工作台不是两套割裂体验
3. 进入后可快速定位到对应分区

### 5.5 测试补齐

1. 覆盖概览区渲染
2. 覆盖快捷入口跳转
3. 覆盖高低优先级状态展示
4. 覆盖无治理事项时的健康空态

## 6. 验收标准

1. 用户进入 Memory Wiki 后能快速掌握当前治理状态
2. 用户可从首页概览快速进入最关键的治理区
3. 多个治理区之间形成统一的信息架构
4. 对应前端测试通过
