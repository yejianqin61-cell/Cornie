# 258-8.1-同日总览手动关闭提示后的记忆规则与重现边界增强

## 1. 任务目标

在 `255` 已补齐同日总览多来源回流提示优先级规则的基础上，继续细化用户手动关闭提示后的记忆规则与再次出现边界，让提示既尊重用户意愿，又不丢关键链路。

## 2. 背景与现状

一旦同日总览支持多来源提示，用户自然会希望关闭自己已经看懂的说明。如果没有清楚规则，会出现：

1. 用户刚关闭提示，下一次又立刻出现，造成烦躁
2. 用户关闭后系统永远不再提示，反而丢失关键引导
3. 同类型提示和高风险提示没有被区别对待

## 3. 涉及范围

- 同日总览提示条
- 用户手动关闭行为持久化
- 提示重新出现边界
- 对应前端测试

## 4. 前置依赖

1. `255-8.1-同日总览多来源回流提示优先级规则增强.md` 已完成或至少已有提示优先级体系
2. `244-8.1-同日关系面板已查看已完成状态与收口增强.md` 已完成或至少已有同日总览状态基础

## 5. 具体开发项

### 5.1 手动关闭记忆

1. 记录用户手动关闭过哪类提示
2. 在合理时间窗口内减少相同提示的重复出现
3. 手动关闭只影响当前类型提示，不误伤其他提示

### 5.2 重现边界

1. 当来源链路发生实质变化时，提示可以重新出现
2. 对首次生成成功、关键状态回退等重要变化，不受普通关闭记忆完全压制
3. 对普通重复提示则应更克制

### 5.3 时间与范围规则

1. 关闭记忆应具有合理时效，不做永久沉默
2. 不同日期之间的提示关闭状态需要正确隔离
3. 切换到不同来源链路时，重新判断是否应出现提示

### 5.4 用户感知

1. 用户应能感受到系统“记得我刚关过”
2. 但在真正重要的新变化出现时，也能重新被温和提醒
3. 文案与行为都要保持可预测

### 5.5 测试补齐

1. 覆盖手动关闭后的重复抑制
2. 覆盖关键状态变化后的重新出现
3. 覆盖不同日期之间的关闭状态隔离
4. 覆盖关闭记忆过期后的再次展示

## 6. 验收标准

1. 同日总览提示不会因重复出现而让用户疲劳
2. 手动关闭规则清楚、可预测
3. 重要变化仍能重新被提示到
4. 对应前端测试通过
