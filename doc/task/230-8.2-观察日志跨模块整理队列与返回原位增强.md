# 230-8.2-观察日志跨模块整理队列与返回原位增强

## 1. 任务目标

在 `177`、`204`、`215` 已补齐观察日志到聊天记录、Cornie 日记、长期记忆的联动入口基础上，继续增强跨模块整理时的队列感和返回原位能力，让用户从观察日志跳出去处理别的模块后还能顺畅回到刚才的整理上下文。

## 2. 背景与现状

观察日志常常是多模块整理工作的起点。当前虽然已经有联动入口，但仍会遇到：

1. 跳去看长期记忆或日记后，回来忘了刚才整理到哪一条
2. 一天内要连续处理多条观察日志时，缺少“下一条待整理”的连续性
3. 跨模块跳转后，上下文回流体验不足

## 3. 涉及范围

- 观察日志列表与详情联动
- 观察日志到聊天记录 / Cornie 日记 / Memory Wiki 的跳转链路
- 返回原位状态恢复
- 对应前端测试

## 4. 前置依赖

1. `177-8.2-观察日志联动阅读与来源追溯增强.md` 已完成或至少已有联动阅读入口
2. `204-8.2-观察日志到Cornie日记生成联动入口收口.md` 已完成或至少已有到日记的联动
3. `215-8.2-观察日志中的长期记忆引用提示与跳转增强.md` 已完成或至少已有到长期记忆的跳转
4. `224-8.2-观察日志编辑离开保护与草稿恢复增强.md` 已完成或至少已有编辑保护基础

## 5. 具体开发项

### 5.1 返回原位能力

1. 从观察日志跳去其他模块后，返回时恢复到原来的日期、条目和滚动位置
2. 若是从某条日志详情跳出，返回时尽量恢复详情展开状态
3. 保证恢复逻辑清晰，不把不同日期的上下文混在一起

### 5.2 整理队列提示

1. 在观察日志详情中提示同一天“上一条 / 下一条待整理”入口
2. 对已处理和未处理条目做轻量区分
3. 让用户可以连续处理同一日素材，而不是每次都回列表重新找

### 5.3 跨模块回流提示

1. 从 Cornie 日记或长期记忆页返回时，提示“你刚才是从哪条观察日志过来的”
2. 对跨模块跳转形成轻量面包屑或返回链路说明
3. 不把跨模块关系做得像浏览器历史一样复杂

### 5.4 边界处理

1. 若原条目已删除或日期变更，提供合理回退方案
2. 若用户在外部模块完成了相关处理，返回后同步更新对应联动提示
3. 与草稿恢复和离开保护逻辑保持兼容

### 5.5 测试补齐

1. 覆盖跨模块跳出再返回原位
2. 覆盖同日上一条 / 下一条待整理链路
3. 覆盖原条目失效后的兜底回退
4. 覆盖外部模块处理后联动状态同步

## 6. 验收标准

1. 观察日志可以支撑连续整理，而不是单次点状查看
2. 用户跨模块处理后能稳稳回到刚才的整理位置
3. 返回原位和待整理队列不与现有编辑保护冲突
4. 对应前端测试通过
