# 094 Memory Wiki 关键操作审计日志

## 1. 任务目标

为 `M11 审计与运维模块` 建立长期记忆 wiki 的关键操作审计日志，覆盖创建、更新、归档、恢复、合并、回滚、删除等高价值治理动作。

## 2. 任务来源

- `doc/design/Cornie-0627-长期记忆LLM-Wiki正式设计.md` 第 10.4A 节
- `doc/design/Cornie-0627-长期记忆LLM-Wiki正式设计.md` 第 16.3.11 节 `M11 审计与运维模块`

## 3. 前置依赖

- `M1-M10` 已完成

## 4. 涉及范围

- `electron/backend/memory-wiki/`
- `scripts/`

## 5. 当前问题

当前 memory wiki 已具备大量治理能力，但还没有形成正式、统一、可检索的操作审计日志，后续难以定位是谁在什么时候做了什么改动。

## 6. 目标设计

本任务完成后应具备：

- 关键操作写入结构化审计记录。
- 审计记录能标明动作类型、目标对象、关键参数、时间。
- 支持按时间查看最近审计事件。

## 7. 实现步骤

### Step 1

定义审计记录结构与落盘位置。

### Step 2

在 memory wiki 服务关键动作中接入审计记录。

### Step 3

补验证脚本。

## 8. 测试点

- 创建页面会写入审计。
- 合并、回滚、删除等高风险动作会写入审计。
- 审计记录可被读取。

## 9. 完成标准

- Memory Wiki 关键治理动作具备正式审计能力。

## 10. 交付物

- 审计日志代码
- 对应验证脚本
