# 279-8.3-治理结果历史页默认动作漂移后的恢复条件增强

## 1. 任务目标

在 `278` 已补齐治理结果历史页默认动作漂移保护基础上，继续明确当漂移已经发生时，系统应在什么条件下主动恢复到基线动作排序，避免保护逻辑只有“预防”没有“纠偏”。

## 2. 背景与现状

默认动作漂移保护如果只有检测和抑制，没有明确恢复条件，会出现：

1. 历史页动作排序已经偏了，但系统不知道何时拉回
2. 用户跨页往返结束后，临时优先级残留过久
3. 页面表现长期处于半漂移状态

## 3. 涉及范围

- 治理结果历史页空态动作区
- 漂移恢复条件
- 基线动作重新接管逻辑
- 对应前端测试

## 4. 前置依赖

1. `278-8.3-治理结果历史页多次往返后的默认动作漂移保护增强.md` 已完成或至少已有漂移保护规则
2. `263-8.3-治理结果历史页空态下次级入口排序与默认动作增强.md` 已完成或至少已有基线动作排序

## 5. 具体开发项

### 5.1 恢复触发条件

1. 明确哪些操作触发恢复基线，如清空筛选、离开再进入历史页、跨页链路结束
2. 明确哪些情况下不应立刻恢复，以免打断当前任务上下文
3. 让恢复条件可枚举、可测试

### 5.2 恢复方式

1. 直接恢复到对应空态的默认主动作
2. 次级动作顺序也同步回到基线
3. 不保留已失效的临时上浮痕迹

### 5.3 轻量感知

1. 基线恢复一般不需要强提示
2. 若恢复会明显改变按钮排序，可通过轻量说明帮助理解
3. 不把纠偏动作做成高打扰提醒

### 5.4 一致性边界

1. 在不同空态类型下恢复逻辑应一致
2. 与来源提示记忆和跨页来源说明保持兼容
3. 不让恢复基线影响当前非空态浏览页

### 5.5 测试补齐

1. 覆盖清空筛选后的基线恢复
2. 覆盖跨页链路结束后的基线恢复
3. 覆盖不应恢复的持续任务场景
4. 覆盖恢复后按钮顺序回归

## 6. 验收标准

1. 默认动作漂移后存在清楚的恢复条件
2. 临时优先级不会长期残留
3. 恢复策略与不同空态类型保持一致
4. 对应前端测试通过
