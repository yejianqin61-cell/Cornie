# 181-8.2-Memory-Wiki待审核角标与异步提醒增强

## 1. 任务目标

在现有治理待审核区基础上，继续补齐巡检候选和治理请求的异步提醒机制，让用户不必进入页面后才发现有新待审核项，也避免把这类治理事务耦合进聊天流。

## 2. 背景与现状

当前前端已经具备：

1. Memory Wiki 工作台
2. 治理待审核区
3. 高风险确认中心
4. 基础筛选与证据面板

但当前仍有明显缺口：

1. 侧边栏没有稳定的未处理数量提示
2. 模块内缺少“新候选已到达”的异步通知条
3. 用户可能只有进入具体面板后才知道治理池变化
4. 巡检触发的治理候选与聊天页之间的边界还不够产品化

## 3. 涉及范围

- `src/renderer/App.vue`
- `src/renderer/components/MemoryWikiWorkspace.vue`
- 如有必要，补充未处理计数接口或聚合读取逻辑
- 对应前端测试

## 4. 前置依赖

1. `168-8.3-治理待审核区与确认中心产品化收口.md` 已完成

## 5. 具体开发项

### 5.1 侧边栏角标

1. 在 Memory Wiki 导航入口上展示未处理待审核数
2. 数量应区分为“还有多少条待处理”，而不是模糊红点
3. 当无待审核项时保持界面克制

### 5.2 模块内异步提醒条

1. 进入 Memory Wiki 模块时，若存在新候选，展示轻量提醒条
2. 文案应强调“可稍后处理”，而不是制造强打断感
3. 支持从提醒条一键跳转到待审核区

### 5.3 聊天侧轻提示边界

1. 若聊天页需要提示，也只允许展示轻量跳转提示
2. 不在聊天区承接逐条审核
3. 避免把治理流误做成对话弹窗流

### 5.4 状态一致性

1. 当用户在待审核区处理完项目后，侧边栏角标应同步更新
2. 模块内提醒条状态应同步消失或减量

### 5.5 测试补齐

1. 覆盖有未处理项时的角标展示
2. 覆盖无待处理项时的静默状态
3. 覆盖模块内异步提醒条的展示与跳转
4. 覆盖处理后计数同步变化

## 6. 验收标准

1. 用户无需深入页面即可感知待审核池状态
2. 异步治理提醒不打断聊天主流程
3. 角标、提醒条、待审核区的状态保持一致
4. 对应前端测试通过
