# 052 协议与策略最小测试体系

## 1. 任务目标

优先为最容易回归、最影响全局的协议层和策略层建立最小自动化测试体系，作为 `7.4` 的第一阶段。

本任务完成后，应至少具备：

- JSON 协议解析测试
- JSON 修复提示相关测试
- tool policy / risk / category rule 测试

## 2. 任务来源

- `doc/Cornie-004-当前模块实现度评估与下阶段开发建议.md` 第 6.2 节
- `doc/Cornie-003-当前开发进度评估与下一阶段路线图.md` 第 7.4 节

## 3. 前置依赖

- `051-工具层联调与7.3验收.md` 已完成

## 4. 涉及范围

- `electron/backend/agent/jsonProtocol.js`
- `electron/backend/policy/toolPolicy.js`
- `electron/backend/policy/rules.js`
- 新增测试入口

## 5. 当前问题

当前协议层和策略层是主链路核心，但几乎没有系统化自动化测试，一旦后续改动，很容易无感回归。

## 6. 目标设计

- 不依赖真实模型
- 以纯函数和 mock tool_call 为主
- 优先覆盖合法 / 非法 / 边界输入

## 7. 实现步骤

### Step 1

建立测试运行入口。

### Step 2

补 JSON 协议解析测试。

### Step 3

补策略层分流测试。

### Step 4

整理覆盖边界与遗留空白。

## 8. 测试点

- reply / tool_call / tool_result 解析
- code block JSON / balanced JSON 提取
- category arguments 合法性校验
- allow / confirm / ask_back / deny 典型分流

## 9. 完成标准

- 协议层与策略层已有可重复执行的最小自动化测试
