# 251-8.3-Memory-Wiki治理结果历史页长期浏览态与筛选持久化增强

## 1. 任务目标

在 `242` 和 `243` 已补齐批量审核结果收口与结果回流详情页体验的基础上，继续为治理结果历史页补充长期浏览态、筛选持久化和回看恢复能力，让用户不止能看刚处理完的一轮结果，也能长期回顾过去的治理成果。

## 2. 背景与现状

批量治理结果如果只适合“刚做完时看一下”，长期就会失去价值。若没有继续设计，会出现：

1. 过几天后用户很难回头找之前某轮治理结果
2. 筛选条件每次都要重选，回顾效率低
3. 结果页更像一次性弹层，而不是可长期使用的历史页面

## 3. 涉及范围

- Memory Wiki 治理结果历史页
- 结果列表筛选与排序
- 浏览状态持久化
- 对应前端测试

## 4. 前置依赖

1. `242-8.3-Memory-Wiki批量审核后结果汇总与回退入口增强.md` 已完成或至少已有结果汇总页
2. `243-8.3-Memory-Wiki治理结果回流详情页高亮与说明增强.md` 已完成或至少已有结果回流详情链路
3. `213-8.3-Memory-Wiki筛选条件持久化与视图恢复增强.md` 已完成或至少已有筛选持久化经验模式

## 5. 具体开发项

### 5.1 长期浏览态

1. 提供按日期、按治理类型、按结果状态浏览历史结果的稳定页面
2. 支持从最近结果切到更早的治理记录
3. 让历史页适合长线回顾，而不是只适合刚做完那一刻

### 5.2 筛选与排序持久化

1. 记住用户最近一次使用的筛选条件和排序方式
2. 返回治理结果历史页时恢复上次浏览上下文
3. 提供显式重置入口，避免旧状态长期污染新任务

### 5.3 回看恢复

1. 从历史结果页进入具体结果再返回时，恢复原列表位置
2. 从历史结果页回流详情页后，再返回时保持当前时间范围和筛选
3. 保持与 Memory Wiki 其他工作台的一致回退体验

### 5.4 空态与长期积累表现

1. 对“当前筛选无结果”和“历史页本身还没有积累数据”做区分
2. 在历史很多时保持信息可扫描
3. 在历史较少时避免页面显得空壳

### 5.5 测试补齐

1. 覆盖筛选与排序持久化
2. 覆盖从结果详情返回历史页的位置恢复
3. 覆盖无结果与无历史两类空态
4. 覆盖重置筛选入口

## 6. 验收标准

1. 治理结果历史页具备长期使用价值，而非一次性查看页
2. 用户可以稳定回顾过去治理轮次
3. 筛选持久化与回退恢复逻辑清楚、可靠
4. 对应前端测试通过
