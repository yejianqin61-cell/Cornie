# 244-8.1-同日关系面板已查看已完成状态与收口增强

## 1. 任务目标

在 `180` 已建立聊天记录、观察日志、Cornie 日记、人类日记同日关系面板的基础上，继续细化各入口的“已查看”“已完成”状态表达与收口规则，让同日关系面板不会长期像待办清单一样悬着。

## 2. 背景与现状

同日关系面板一旦承担“今天的沉淀链路概览”职责，就会面临状态治理问题。若没有继续收口，会出现：

1. 用户已经点进去看过某个模块，但面板上看不出来
2. 某天 Cornie 日记已生成、观察日志已整理完成，但关系面板仍像一切都未处理
3. 入口长期高亮，时间久了会失去指导意义

## 3. 涉及范围

- 聊天记录同日关系面板
- 观察日志与日记关系摘要区
- 各模块入口状态标签
- 对应前端测试

## 4. 前置依赖

1. `180-8.1-聊天记录与观察日志日记关系工作台.md` 已完成或至少已有同日关系面板
2. `203-8.1-聊天记录与观察日志跨日联动定位增强.md` 已完成或至少已有跨模块定位
3. `239-8.2-观察日志连续整理后的完成归档视图增强.md` 已完成或至少已有观察日志完成态语义

## 5. 具体开发项

### 5.1 状态分层

1. 区分“未查看”“已查看”“已完成”三类状态
2. 已查看仅表示用户看过该模块，不应冒充已完成
3. 已完成应基于真实业务状态，如观察日志缺口清零或 Cornie 日记已生成

### 5.2 入口收口

1. 已完成模块入口降级显示，不再长期占据强提醒位
2. 已查看但未完成的模块保留轻量提示，避免用户误解为已结束
3. 当某个模块状态回退时，入口状态可重新激活

### 5.3 面板整体完成感

1. 当同日关键链路基本完整时，面板给出温和“今天记录链路较完整”的总结
2. 若仍缺关键一环，仅提醒真正缺失处，不把整面板做成报错板
3. 保持四层内容分工清晰，不让状态提示掩盖结构认知

### 5.4 视觉层级

1. 已完成项的视觉权重低于待处理项
2. 已查看态和已完成态要有清楚区分
3. 面板状态表达应克制，不制造过多颜色噪音

### 5.5 测试补齐

1. 覆盖三类状态渲染
2. 覆盖已完成后的入口降级
3. 覆盖状态回退后的重新激活
4. 覆盖面板整体完成总结分支

## 6. 验收标准

1. 同日关系面板不会长期停留在“所有事都待处理”的假象里
2. 用户能快速看懂哪些只是看过，哪些已经真正完成
3. 面板状态治理不破坏原有同日结构表达
4. 对应前端测试通过
