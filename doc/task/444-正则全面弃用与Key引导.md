# 444 正则全面弃用与 Key 引导

## 背景

Cornie-019 V1.1 决策：**正则匹配不是记忆决策的候选手段，全面弃用**；LLM 不可用时本轮不写入任何记忆，并引导用户配置 DeepSeek Key——而不是降级到正则写入。当前记忆写入侧的正则判定点全量清单见 Cornie-019 §4（32 个判定函数/点）。

## 目标

1. 删除写入侧全部正则/关键词记忆判定函数（Cornie-019 §4 清单中的 extract/detect/derive 系列）。
2. LLM 不可用时（无 Key/超时/解析失败）本轮零写入记忆，界面明确引导配置 Key。
3. 全仓库 grep 无正则记忆判定残留。

## 范围

- `electron/backend/identity/profileUpsert.js`（extractUserName/extractPreferredName/extractCornieRelationship/detectLifeStageSummary/detectCurrentFocus/detectStressors/detectCommunicationPreference/detectIdentitySummary/buildCandidate）
- `electron/backend/identity/personUpsert.js`（extractPersonalitySummary/extractMeaningToUser/extractExperienceSummary/extractTimelineSummary/buildCandidate 及关系映射表）
- `electron/backend/identity/preferenceUpsert.js`（guessPreferenceType/cleanupPreferenceTarget/takePreferenceTarget/buildCandidate）
- `electron/backend/identity/traitUpsert.js`（buildTraitPatterns/buildCandidate）
- `electron/backend/observation/service.js`（shouldRecordObservation/deriveConversationObservation）
- `electron/backend/observation/wikiUpgrade.js`（enqueueObservationWikiUpgradeCandidates，随 446 处理）
- `electron/backend/memory/service.js`（旧模块，随 470 退役）
- `electron/backend/agent/orchestrator.js`（记忆链入口改造）

## 设计要求

### 1. 删除正则判定函数

- 按 Cornie-019 §4 清单逐一删除；删除前 grep 全量复核引用（含测试与 verify 脚本引用）。
- 仅保留纯文本规范化工具（`stripTrailingParticles`、`normalizeString` 等），迁移到公共工具位置供提炼轮次复用。

### 2. 不可用策略落地

- orchestrator 中记忆链改为：提炼轮次（443）成功 → 按 LLM 决策执行；失败/不可用 → **跳过全部记忆写入**，返回明确状态。
- 前端：未配置 Key 时复用现有配网引导遮罩；对话/记忆写入不可用时提示用户配置 DeepSeek Key。
- 审计：记录不可用原因与频率（`memory_distillation` 事件，配合 443）。

### 3. 残留清理

- `doc/` 中旧设计对"正则兜底/FALLBACK"的表述以 Cornie-019 V1.1 为准（无 FALLBACK）。
- 更新受影响的测试与 verify 脚本断言（若其引用已删除函数）。

## 验收标准

1. `grep -r "我叫\|extractUserName\|shouldRecordObservation" electron/` 无写入侧正则判定残留（聊天/检索类功能正则除外，明确标注）。
2. 无 Key 时模拟一轮对话：零记忆写入（观察/身份/治理队列均无新增），界面出现配置 Key 引导。
3. 删除后 `npm run test:fast` 与前端 vitest 通过（或相关过时断言已同步更新）。

- 上游设计：Cornie-019 §2.2 补充原则、§6.2 不可用策略、§8 T-2。
