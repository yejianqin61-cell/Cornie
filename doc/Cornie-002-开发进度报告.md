## 2. 报告目的

本文档用于基于当前仓库代码、目录结构、设计文档与最近开发痕迹，对 Cornie 项目的实际开发进度进行一次阶段性盘点，明确：

- 当前版本完成到了什么程度
- 已经落地了哪些 MVP 能力
- 还有哪些核心能力尚未收口
- 当前项目面临的主要风险与下一阶段重点

## 3. 项目阶段结论

### 3.1 总体结论

Cornie 当前处于 **MVP 主干已搭建完成、核心功能进入收口阶段、但尚未达到稳定交付状态** 的开发阶段。

从“文档规划”与“代码实现”的对应关系来看，项目已经从早期概念验证阶段推进到 **可演示原型阶段**。当前版本已具备桌宠展示、本地数据库、主窗口日记管理、本地 API、对话能力接入、本地 Ollama 状态检测，以及基于对话生成 Cornie 日记的核心链路。

但从“可内测 MVP”标准看，项目仍存在体验未收口、异常处理不足、工程化薄弱、自动化触发缺失等问题，因此当前更适合定义为：

> **可演示的 MVP 原型**
>
> 而不是
>
> **可稳定发布的 MVP 内测版本**

## 4. 已完成内容

### 4.1 文档与方案层

已完成以下文档资产沉淀：

- 产品需求分析文档已完成，明确了 MVP / V1 / V2 的版本目标与能力边界。
- 技术架构详细设计已完成，覆盖进程模型、目录结构、数据模型与 API 规划。
- 桌宠、对话、双视角日记、往年今日、本地化与隐私等模块设计文档已建立。
- 文档规范、提交规范、后端 API 规范已整理，具备继续扩展的基础。

### 4.2 桌面应用主框架

已完成以下基础框架搭建：

- 使用 Electron + Vue 3 + Vite 搭建桌面应用主框架。
- 已形成主窗口 `index.html` 与桌宠窗口 `cornie.html` 的双窗口结构。
- 主进程已完成窗口创建、本地 API 启动、窗口拖拽 IPC 注册等逻辑。
- 已具备 Windows 桌面层挂载尝试方案，为后续桌面常驻体验预留实现路径。

### 4.3 本地数据与后端服务

已完成以下本地后端能力：

- 已使用 `sql.js` 建立本地 SQLite 存储方案。
- 已完成 `diary_entries` 与 `conversations` 两张核心表结构。
- 已实现数据库迁移、持久化写盘、按日期读取、列表查询、往年今日查询等基础能力。
- 已使用 Express 建立本地 HTTP API 服务。
- 已完成健康检查、日记 CRUD、Cornie 日记重新生成、往年今日查询等接口。

### 4.4 主窗口日记本能力

主窗口已具备较完整的 MVP 管理界面：

- 支持按月份查看条目列表。
- 支持选择日期并查看当日日记内容。
- 支持保存“我的日记”。
- 支持展示与编辑 “Cornie 的日记” 文本。
- 支持手动触发 “生成 Cornie 日记”。
- 支持查看“往年今日”历史记录。
- 支持检测 Ollama 与本地模型状态，并在 UI 中提示用户。

### 4.5 桌宠与对话能力

桌宠主链路已经搭起：

- Cornie 形象已采用 PNG 部件拼装方式实现。
- 已具备眨眼动画、头部轻微动作、输入框、聊天气泡等桌宠表现。
- 已支持桌宠窗口拖拽。
- 已实现对话发送逻辑，前端可将消息发送到本地 API。
- 已实现当日对话消息的本地存储。
- 已接入 Ollama `chat` 与 `generate` 接口。
- 已实现基于系统提示词的 Cornie 人设回复。

### 4.6 基于对话生成 Cornie 日记

这是当前代码中最重要的进展之一，且实现进度比旧提交记录更靠前：

- 已能够按日期读取当天全部对话记录。
- 已能够将对话内容组装为日记生成 Prompt。
- 已能够调用本地 Ollama 模型生成 Cornie 视角日记。
- 已能够将生成结果写回 `diary_entries.cornie_text`。
- 已提供失败兜底文案，避免生成失败时前端完全不可用。

## 5. 进行中内容

### 5.1 正在从“纯日记”向“对话驱动日记”切换

从工作区未提交改动判断，项目正处于一次明显的功能升级过程中：

- 新增了 `conversation` 后端模块。
- 新增了 `ollama` 客户端能力。
- 主窗口与桌宠窗口都在向“对话 + 日记联动”的 MVP 方向调整。
- 新的详细设计文档已补齐，说明研发思路正在从原型拼装转向结构化实现。

### 5.2 体验仍在收口

虽然核心逻辑存在，但产品体验仍处在半成品状态：

- 主窗口中的 “Cornie 的日记” 仍保留明显占位特征。
- 对话记录展示与主窗口联动还不够完整。
- 自动生成日记的时机还未完全产品化。
- 首次使用时的模型安装引导尚未打磨成完整流程。

## 6. 尚未完成或薄弱部分

### 6.1 MVP 闭环还未完全收口

距离 PRD 中的理想 MVP，还差以下关键能力：

- 对话结束后自动触发 Cornie 日记生成。
- 定时生成或日终生成机制。
- 主窗口对对话历史的完整展示与联动。
- “双视角日记” 的展示体验优化。
- 更完善的异常提示与失败恢复策略。

### 6.2 工程化基础偏弱

当前工程化成熟度较低，主要表现为：

- `lint` 仍为占位脚本，未建立统一代码检查。
- 未见自动化测试用例。
- 未见 CI / 构建校验流程。
- 未见正式打包发布配置与发布说明文档。
- 工作区存在较多未提交改动，阶段成果尚未沉淀。

### 6.3 平台兼容与稳定性待验证

以下部分仍需实机验证：

- Windows 桌面层挂载是否在不同设备上稳定可用。
- Electron 双窗口在打包后是否与开发态行为一致。
- Ollama 不同安装状态下的用户引导体验。
- 本地数据库长期累积后的性能与数据安全性。

## 7. 当前风险评估

| 风险类别 | 风险描述 | 当前判断 | 建议 |
| --- | --- | --- | --- |
| 需求收口风险 | 核心功能已较多，若继续扩展易影响 MVP 收敛 | 中 | 冻结 MVP 范围，优先打磨闭环 |
| 稳定性风险 | 已有功能较多，但缺少系统回归与自动化校验 | 高 | 优先补最小测试与手工验证清单 |
| 工程化风险 | lint、测试、CI、发布流程缺失 | 高 | 尽快建立最小工程化基线 |
| 集成风险 | Electron + 本地 API + Ollama + 桌面层多端联动复杂 | 中 | 分层验证，逐步锁定接口 |
| 体验风险 | 已有能力存在，但首次使用和异常路径体验偏粗糙 | 中 | 补引导、提示和失败兜底 |
| 提交管理风险 | 当前未提交改动较多，容易造成阶段成果丢失或混乱 | 中 | 尽快按模块整理并提交 |

## 8. 下一阶段建议

### 8.1 第一优先级：完成 MVP 最小闭环

建议下一阶段先不继续铺新功能，而是优先收口以下事项：

1. 打通“桌宠对话 -> 保存对话 -> 自动生成 Cornie 日记 -> 主窗口可查看”的完整闭环。
2. 让主窗口明确区分“用户日记”和“Cornie 日记”的最终展示形态。
3. 补齐 Ollama 不可用、模型未下载、生成失败等关键异常路径。

### 8.2 第二优先级：补工程化基线

建议尽快建立最小工程保障：

1. 增加真实可用的 `lint` 配置。
2. 增加最小 API 层测试或核心函数测试。
3. 增加一次稳定的本地构建校验。
4. 形成最小可执行的打包与运行说明。

### 8.3 第三优先级：准备内测版本

在闭环跑通后，再推进以下事项：

1. 首启引导与模型安装说明。
2. Windows 实机兼容性验证。
3. 手工测试清单与已知问题清单。
4. 形成 MVP 内测版本发布说明。

## 9. 结论

截至 2026-06-25，Cornie 项目已经完成了从“概念与文档阶段”到“可演示原型阶段”的跃迁。当前版本已具备桌宠展示、本地存储、主窗口日记管理、本地对话、本地模型接入、对话生成 Cornie 日记等核心能力，MVP 主干已经成形。

但从真正可交付的 MVP 标准来看，项目仍处于收口阶段，特别是在自动化生成时机、异常路径、稳定性、工程化与发布准备方面仍需继续推进。

因此，本次阶段判断为：

> **Cornie 当前开发状态：MVP 主干已成形，正在进入闭环收口与稳定化阶段。**
