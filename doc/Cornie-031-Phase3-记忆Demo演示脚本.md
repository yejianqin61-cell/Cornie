# Phase 3 记忆 Demo 演示脚本

**日期：** 2026-10-22  
**前提：** 本地开发态服务已启动；模型使用可控 Demo 配置或可用模型。  
**范围：** 证明“记住—想起—追溯—纠正”主链；不宣称安装包、云记忆或大规模检索能力。

## 重置

在单独的 Demo 数据目录运行
`npm run load:demo-memory -- --base-dir <demo-directory>`。它只创建固定 ID 缺失的页面，重复调用不会增加页面数量。

预置页包括：项目搭档林姐、咖啡偏好、作品集答辩事件，以及“作品集范围冲突”主题页。

## 1. 记住

用户说：“请记住，我长期喜欢喝拿铁。”

可见证据：记忆页出现“咖啡偏好”，摘要是“主人喜欢拿铁”。

预期状态：页面来源指向本轮用户消息；提炼输入含一次用户原话和一次最终回复。

## 2. 想起

用户问：“我下午该喝什么？”

可见证据：对话上下文会选中“咖啡偏好”摘要；页面仍可从记忆模块打开。

预期状态：回答可依据“喜欢拿铁、下午影响睡眠”给出建议，而非宣称无来源的记忆。

## 3. 追溯

在记忆模块打开“咖啡偏好”。

可见证据：详情下方显示聊天来源及消息预览。

预期状态：来源不可用时也会明确标记，不把缺失内容伪装成证据。

## 4. 纠正

在治理面板选择高风险归档请求，查看原因和 JSON 证据，点击“批准”，再点击“应用”。

可见证据：应用结果显示在面板内；目标页状态变为 `archived`。页面级纠正也可使用归档、恢复、版本回滚和重要性选择。

预期状态：拒绝只更新治理状态；未批准的请求没有“应用”入口。
