## 2. 文档目的

用户提出三项体验问题，本文档经代码级排查后将其转化为可开发、可验收的整改方案：

1. **聊天重复回复**：每次聊天 Cornie 回复两句一样的（前端双气泡 / 单条内重复）。
2. **记忆组织混乱**：记忆层应鲜明分为三栏——**观察日志 / 当天日记 / 记忆 Wiki**，且 Wiki 应像册子一样可翻阅。
3. **前端文案泛滥**：大量产品定义/功能说明文案展示给用户，页面拥挤、功能按钮不突出。

## 3. 问题陈述（Problem Statement）

### 3.1 问题一：聊天重复回复（已定位根因）

**现象**：每次聊天 Cornie 回复两句一样的。

**主因（后端落库时序 + 前端轮询去重失效 → 同 id 双气泡，几乎每轮必现）**：

1. `orchestrator.runTurn` 先 `saveMessage` 落库 cornie 消息（`orchestrator.js:373-378`），随后才执行**慢速记忆提炼 LLM 调用**（`orchestrator.js:398-410` → `memoryDistillation.js:230`，`maxTokens:700`，耗时数秒），再 return；SSE 的 `done` 事件在 return 后才写出（`conversation/routes.js`）。
2. 这数秒窗口内，前端每 3s 轮询（`useChat.js` 的 `startConversationSync`，ChatHome/CorniePet 启动）经 `syncConversation → loadConversation` 从 DB 拉到这条已落库的 cornie 消息。
3. `hasEquivalentMessage`（`useChat.js:39-49`）去重失败：
   - id 分支：流式占位消息 id 仍是 `live-cornie-*`（`useChat.js:139,150`），≠ DB 的正式 UUID；
   - 内容分支：要求 `item.pendingSync === true`（仅对 user 临时消息成立），cornie 占位无此标记 → 直接 `pushChatItem` 重复上屏。
4. 随后 `appendResponse` 的 replaceId 分支（`useChat.js:79-89`）把占位也替换成同 UUID 同内容 → 列表出现**两条同 id 消息**；ChatHome 渲染 `:key="m.id"`（`ChatHome.vue:155`）两条都渲染 → "两句一样的"。
5. 桌宠非流式路径（CorniePet `send`）同样中招（轮询先推 + `appendResponse` 再推，`useChat.js:90-97`）。

**次因（可能雪上加霜）**：`streamFinalSpeak`（`orchestrator.js:67-78`）用 `buildSpeakPrompt`（`orchestrator.js:57-64`）把 finalReply 原文喂给模型要求"重新说一遍"，模型易原样复述 → 单条气泡内也会出现两句一样（需实际输出确认）。

**已排除**：信封 JSON 解析（jsonProtocol）、流式 delta（client.js 已明确不重试防重复）、主对话系统提示（仅一套 JSON 协议指令）。

## 4. 解决方案（Solution）

1. **聊天不再重复**：后端落库与 SSE done 同刻（消灭轮询窗口）；前端去重改为"role+内容"级 + 同 id upsert 语义（杜绝双气泡）；说话段防复述（如确认次因）。
2. **记忆三栏鲜明**：导航拆为「观察日志」「当天日记」「记忆 Wiki」三个平级入口；各入口首页只做本栏内容；Wiki 列表像册子一样翻阅（类型 Tab + 分页 + 索引）；详情拆阅读/编辑两态。
3. **界面清爽**：A 类产品文案删除或压成一行副标题；操作引导 ≤8 字；空态保留但精简；CTA 用实心 primary 按钮，禁文字链冒充按钮；说明文字移卡片尾部弱化。

## 5. 用户故事（User Stories）

### 5.1 聊天去重

1. 作为聊天用户，我希望每轮对话 Cornie 只回复一次，这样不会被同样的两句话打断。
2. 作为聊天用户，我希望流式逐字显示与后台同步不产生重复气泡，这样聊天记录干净。
3. 作为聊天用户，我希望说话段是自然的"重说"而不是逐字复述，这样不会在一句里听两遍。
4. 作为开发者，我希望后端消息落库时机与流式完成一致，这样前端轮询不会拉到"未来"的消息。

### 5.2 记忆三栏

5. 作为用户，我希望"观察日志、当天日记、记忆 Wiki"是三个清晰分开的板块，这样我知道去哪里看什么。
6. 作为用户，我希望观察日志首页只放当天的生活片段，这样不会被长期记忆内容干扰。
7. 作为用户，我希望当天日记首页能预览我今天写的内容和铃湾写的，并看到当天观察的入口。
8. 作为用户，我希望记忆 Wiki 像一本册子：按类型翻页、可一页页看下去，这样浏览有节奏感。
9. 作为用户，我希望记忆详情先以阅读态打开，需要修改时才进入编辑，这样查看不被打断。
10. 作为用户，我希望普通记忆页（事件/主题/目标等）在首页和列表中都能看到，而不是只有身份 4 类。

### 5.3 文案精简

11. 作为用户，我希望页面不要堆"这是什么"的说明，这样界面不拥挤。
12. 作为用户，我希望功能按钮显眼、可点，而不是被长文案淹没。
13. 作为开发者，我希望文案分级有标准（产品说明 vs 操作引导 vs 空态），这样后续新增文案有据可依。
14. 作为开发者，我希望同一概念的解释只出现一处，这样不重复。

## 6. 实现决策（Implementation Decisions）

> 决策只描述职责与契约，不绑定具体文件路径；落地以本决策为准。

### ID-1 后端落库时序修正（问题一主因，P0）

- `orchestrator.runTurn`：将 cornie 消息的 `saveMessage` 从"记忆提炼之前"挪到"记忆提炼完成之后、return 之前"，使 DB 可见与 SSE `done` 几乎同刻，从源头消灭"轮询窗口"。
- 语义不变：消息内容、id 生成、返回结构均不变；仅落库时机后移。
- 验收锚点：前端轮询在流式完成前永远拉不到本轮 cornie 消息。

### ID-2 前端去重加固（问题一，P0）

- `hasEquivalentMessage`：对 cornie 消息放宽为 **role + content 相同即视为重复**（不再要求 `pendingSync === true`；user 消息保持原语义）；保留 id 精确匹配优先。
- `replaceMessageById` 升级为 **upsert 语义**：先按 id 删除已存在的同 id 项，再插入/替换新项，杜绝同 id 并存。
- 覆盖流式与非流式两条路径。

### ID-3 说话段防复述（问题一次因，P1）

- `buildSpeakPrompt`：去掉 finalReply 原文整段回显，改为传"要点"，并加负向约束（"不要逐字复述，不要重复原句"）。
- 若实际输出已自然（无复述），可仅加负向约束。

### ID-4 导航三入口分离（问题二 M1/M2，P0）

- 左侧导航拆为「观察日志」「当天日记」「记忆 Wiki」三个平级入口（替代原"观察与记忆"单入口）；「日记」入口保留并更名"当天日记"。
- 各入口独立 home 视图：观察日志 home（当天观察 + 记一件小事入口）、记忆 Wiki home（列表/翻阅入口 + 最新记忆 + 新建入口）。
- 旧 `ObserveMemoryHome` 拆解：观察相关区块归观察日志 home，记忆相关区块归记忆 Wiki home。

### ID-5 记忆 Wiki 册子化翻阅（问题二 M3，P1）

- 列表页加**类型 Tab**（身份 4 类 + 普通 5-6 类不并桶，或按大类分组展示）、**offset 分页**（复用 api 已支持的 limit/offset）、**时间/字母索引**（按月或按标题首字分组）。
- 首页与列表不再过滤只显示身份 4 类（去掉 `:69` 的 pageType 过滤）。

### ID-6 详情阅读/编辑两态（问题二 M4，P1）

- `MemoryPageDetail` 拆为阅读态（标题/摘要/正文/来源/相关页，干净排版）与编辑态（现有表单），默认阅读态，"编辑"按钮进入编辑。
- 来源溯源区块保留在阅读态底部（弱化展示，不占主导）。

### ID-7 收敛重复 UI（问题二 M7，P2）

- 前台列表（MemoryPageList/Detail）与高级设置内 MemoryWikiWorkspace **二选一**：建议前台为普通用户翻阅视图，MemoryWikiWorkspace 收敛为治理/高级功能（版本/回滚/巡检/审计），从"平行重复"变为"层级分工"；入口说明同步精简。

### ID-8 日记与观察联动（问题二 M6，P2）

- 当天日记首页双栏旁增加"当天观察"片段入口（跳观察日志），形成"观察 → 日记 → Wiki"的阅读流。

### ID-9 文案分级精简（问题三，P0）

- 分级标准：卡头只许标题 + ≤6 字副标题；"这是什么"类（A 类 28 处）删除或压成一行；"怎么用"类（B 类 12 处）压到 8 字内；空态/错误（C 类 8 处）保留但 ≤15 字。
- 按 §3.3 清单逐处处理：W1-W16 等删除/压缩；同一概念只留一处（如"不会写成流水账"在 ObserveMemoryHome 与 ObservationList 出现 4 次，只留一处）。
- 表单引导移入 placeholder/prompts（MemoryPageDetail 已示范）。

### ID-10 按钮强调（问题三，P0）

- 主 CTA 一律实心 primary 按钮（参照 AdvancedSettings toggle 样式），禁文字链冒充按钮（`omQuickLink` 改造为真按钮或并入区块 CTA）。
- 说明文字移卡片尾部弱化（`--muted` 小字），不夹在标题与按钮之间。
