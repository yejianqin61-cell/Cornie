# 类目脏数据修复操作说明

## 1. 适用场景

本说明用于开发阶段或发布前，对历史类目数据做一次安全巡检与最小修复。

当前工具链包含：

- `scripts/audit-category-data.mjs`
- `scripts/repair-category-data.mjs`

## 2. 默认原则

- 默认先巡检，不直接修
- 默认 `dry-run`
- 只自动修复低风险问题
- 高风险问题只报不修

## 3. 当前支持的异常类型

| 类型 | 含义 | 当前是否支持自动修复 |
| --- | --- | --- |
| `duplicate_category_name` | 同域重复类目名 | 否，只巡检 |
| `missing_category_reference` | 业务记录引用了不存在的类目ID | 否，只巡检 |
| `category_name_mismatch` | 业务记录的 `categoryName` 与类目表当前名称不一致 | 是，支持安全修复 |
| `generic_category_overuse` | 泛化类目占比偏高 | 否，只巡检 |

## 4. 常用命令

### 4.1 只读巡检

```powershell
node scripts/audit-category-data.mjs --db .\tmp-task038-verify.sqlite
```

### 4.2 输出 markdown 报告

```powershell
node scripts/audit-category-data.mjs --db .\tmp-task038-verify.sqlite --format markdown --output .\tmp-task038-report.md
```

### 4.3 预演修复

```powershell
node scripts/repair-category-data.mjs --db .\tmp-task038-verify.sqlite --dry-run
```

### 4.4 真正执行可修复项

```powershell
node scripts/repair-category-data.mjs --db .\tmp-task038-verify.sqlite --apply
```

## 5. 推荐操作顺序

1. 先执行 `audit-category-data`
2. 阅读问题清单，确认哪些属于低风险
3. 执行 `repair-category-data --dry-run`
4. 复核输出摘要
5. 确认无误后再执行 `--apply`
6. 修复后重新跑一次巡检，确认问题数下降

## 6. 风险提示

- 不要在正式用户数据库上直接首跑 `--apply`
- `missing_category_reference` 当前不自动修，因为无法安全猜测该改到哪个类目
- `duplicate_category_name` 当前不自动合并，因为涉及历史引用归并，风险过高
- 如果出现脚本未覆盖的问题类型，应先补脚本，再做处理

## 7. 建议回滚方式

- 修复前先备份数据库文件
- 开发期优先在临时测试库演练
- 若执行 `--apply` 后结果异常，直接恢复备份库，不建议人工逐条反改

## 8. 最小验收口径

本轮修复流程至少应证明：

- 巡检脚本能输出结构化问题清单
- `dry-run` 不会写库
- `--apply` 只会修复当前允许自动处理的问题
- 修复后重新巡检，相关问题计数会下降
