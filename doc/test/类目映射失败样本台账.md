# 类目映射失败样本台账

## 1. 文档目的

本台账用于沉淀类目映射链路中的高价值问题样本，支持：

- 复盘模型为什么做出了当前判断
- 把问题明确归类到 `prompt / rule / test / tool`
- 驱动后续补回归，而不是只做一次性人工修补

适用范围：

- `ledger`
- `todo`
- `schedule`

## 2. 使用原则

- 只记录高价值样本，不记录所有正常通过样本
- 优先记录“会误导后续策略优化”的样本
- 用户原文可做必要截断或脱敏
- 每条样本都应能指向一个后续动作

## 3. 字段说明

| 字段 | 含义 |
| --- | --- |
| 样本ID | 稳定标识，便于后续引用 |
| 来源 | `audit_log / verify_case / manual_test / production_feedback` |
| 域 | `ledger / todo / schedule` |
| 问题类型 | 当前最主要的问题归类 |
| 用户输入 | 触发问题的原始输入，允许截断 |
| 预期行为 | 理想情况下系统应如何处理 |
| 实际行为 | 当前模型/策略实际发生了什么 |
| 建议回灌入口 | `prompt / rule / tool / test / confirm` |
| 是否已补回归 | `是 / 否 / 待定` |
| 备注 | 其他需要补充的上下文 |

## 4. 问题标签建议

- `should_map_but_new`
- `should_map_but_ask`
- `should_ask_but_mapped`
- `wrong_domain_bias`
- `duplicate_category_proposal`
- `low_signal_generic_match`

## 5. 样本模板

| 样本ID | 来源 | 域 | 问题类型 | 用户输入 | 预期行为 | 实际行为 | 建议回灌入口 | 是否已补回归 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| CAT-SAMPLE-001 | audit_log | ledger | should_map_but_new | 今天买猫砂，应该记到宠物用品 | 直接命中“宠物用品”或建议复用 | 进入新增类目确认 | rule + test | 否 | 命中了现有类目但仍走新增 |
| CAT-SAMPLE-002 | verify_case | schedule | should_map_but_ask | 帮我安排复查 | 结合现有类目命中“提醒”或“宠物医疗” | 进入 ask_back | prompt + test | 否 | 输入信息不短，但策略仍偏保守 |
| CAT-SAMPLE-003 | audit_log | todo | duplicate_category_proposal | 新增宠物护理待办类目 | 识别已有“宠物护理”并复用 | 仍提出新增，后续被复用_existing 收口 | rule + prompt | 是 | 已有 `category_creation_reused_existing` 事件 |

## 6. 首批样本沉淀建议

当前优先沉淀：

1. `should_map_but_new`
2. `duplicate_category_proposal`
3. `should_map_but_ask`

原因：

- 这三类最容易反复出现
- 都会直接影响用户对“类目智能化”的信任
- 都能明确指向后续改造入口

## 7. 与回归的连接规则

- `P0` 样本：必须补自动化回归
- `P1` 样本：至少补文档 case 或验证记录
- 如果修复只改了 prompt，但没有新增回归，台账中的“是否已补回归”不得标记为“是”
