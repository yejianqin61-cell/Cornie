## 1. 需求

### 1.1 质量门禁

- **R-1 `npm run test:fast` 和 `npm run test:full` 在 Windows 检出上转绿** ← 评审·验证：Prettier 门禁报约 100 个文件。已核实原因：`core.autocrlf=true` 把文件检出为 CRLF，而 Prettier 默认要求 LF；仓库没有 `.gitattributes`。

### 1.2 记忆层治理

- **R-2 提炼轮能引用它要改动的页面和观察** ← 评审·记忆层：提示词里的记忆页和观察都不带 ID，模型提出的更新类提议只能编造 ID。
- **R-3 破坏性提议入队前校验目标存在** ← 评审·记忆层：合并、回滚、归档、删除以未校验的 ID 进入治理队列。
- **R-4 提炼输入按当前对话召回相关页面** ← 评审·记忆层：现在只取按标题排序的前 6 页，与对话无关，容易重复建页。
- **R-5 主人已确认的页面不被提炼直接覆盖** ← 评审·记忆层：提炼的 `update_page` 会改写 `ownerConfirmed` 页面。
- **R-6 主人能在界面上确认或取消确认一页记忆** ← 评审·记忆层：`setOwnerConfirmed` 没有路由，也没有界面入口。
- **R-7 记忆写入在进程内全局串行** ← 评审·记忆层：单写者队列按服务实例创建，而服务在路由、工具、提炼、身份 upsert 中分别实例化，跨实例的读改写仍会丢更新。
- **R-8 提炼不拖慢回复完成** ← 评审·记忆层：每轮要等提炼的模型调用结束才落库回复、发出 `done`；失败时的兜底回复也会被送去提炼。
- **R-9 巡检能从界面触发，审计日志能在界面查看** ← 评审·记忆层：巡检扫描只有路由；审计日志只对模型工具开放。

### 1.3 前后端联调

- **R-10 记忆页面能在界面上合并** ← 评审·联调：后端已有合并接口，界面未接。
- **R-11 收支、待办、日程的类目能在界面上管理** ← 评审·联调：三套类目的增删改、恢复、排序都没有界面。
- **R-12 聊天展示联想话语，工具结果刷新后不消失** ← 评审·联调：`interimReplies` 不渲染；工具结果面板只挂在临时消息上。
- **R-13 观察详情展示它关联的记忆** ← 评审·联调：前端读 `memoryLinks`，后端从不返回。
- **R-14 记忆列表返回真实总数** ← 评审·联调：`total` 是当前页条数。
- **R-15 治理面板用人话展示类型、状态和证据** ← 评审·联调：现在显示英文枚举和原始 JSON。

## 2. 方案（逐条需求）

### 2.1 质量门禁

#### R-1 `npm run test:fast` 和 `npm run test:full` 在 Windows 检出上转绿

- **Approach**：用仓库级换行约定把工作区固定为 LF，让 Prettier 与检出结果一致；随后把剩余格式差异一次性格式化。
- **Touches**：仓库根配置、全仓源码的换行。
- **Test seam**：现有 `npm run lint` 和 `scripts/run-tests.mjs`。不新增 seam。
- **Acceptance**：[ ] 新克隆后 `npm run lint` 零报错　[ ] `npm run test:fast` 通过　[ ] `npm run test:full` 通过
- **Hard part**：换行重规范化会产生一次全仓 diff，要与业务改动分开提交，否则后续 blame 和评审都会被淹没。

### 2.2 记忆层治理

#### R-2 提炼轮能引用它要改动的页面和观察

- **Approach**：提示词里的每页记忆和每条观察都带上 ID，并在规则中说明更新类动作必须引用已列出的 ID；后端只接受出现在本轮输入里的 ID。
- **Touches**：提炼轮的输入构建、提示词、提议执行。
- **Test seam**：现有的提炼输入测试和记忆 e2e 测试，用模型替身驱动。不新增 seam。
- **Acceptance**：[ ] 提示词中每页记忆、每条观察都带 ID　[ ] 引用本轮输入中 ID 的 `update_page` 生效　[ ] 引用不在输入中的 ID 时跳过并记入审计
- **Hard part**：ID 会增加提示词长度，要和 R-4 的召回预算一起算。

#### R-3 破坏性提议入队前校验目标存在

- **Approach**：入队前检查目标页面（合并时检查两页，回滚时检查版本）是否存在，不存在就跳过并写审计，不进入治理队列。
- **Touches**：提炼轮的提议执行。
- **Test seam**：现有记忆 e2e 测试。
- **Acceptance**：[ ] 目标存在的归档提议入队　[ ] 目标不存在的提议不入队且留审计　[ ] 回滚提议的版本不存在时不入队
- **Hard part**：不要只在入队时校验；应用时目标也可能已被删除，应用侧的报错要保持可读。

#### R-4 提炼输入按当前对话召回相关页面

- **Approach**：复用对话上下文装载已有的分层召回（画像卡、已确认重要人物、按查询与重要性排序的候选），用本轮用户消息作为查询，取代"标题前 6 页"。
- **Touches**：提炼轮的输入构建、记忆上下文装载。
- **Test seam**：现有提炼输入测试。
- **Acceptance**：[ ] 提到已有主题时，该主题页出现在提炼输入里　[ ] 输入页数仍受预算上限约束　[ ] 已有页面被命中时，替身模型输出 `update_page` 而不是 `create_page`
- **Hard part**：对话召回与提炼召回共用一套排序后，改其中一处会影响另一处，测试要同时覆盖两边。

#### R-5 主人已确认的页面不被提炼直接覆盖

- **Approach**：提炼的 `update_page` 命中已确认页面时，不直接写入，改为生成一条待审治理请求，携带拟修改内容；批准并应用后才写入。
- **Touches**：提炼轮的提议执行、治理请求的应用分发。
- **Test seam**：现有记忆 e2e 测试。
- **Acceptance**：[ ] 已确认页面被提炼更新时内容不变　[ ] 队列里出现一条带拟修改内容的请求　[ ] 批准并应用后页面更新，请求进入 `applied`　[ ] 未确认页面的更新行为不变
- **Hard part**：新请求类型要接入上一轮建立的"可应用"判定和终态流转，不能回到"批准后应用不了"的老问题。

#### R-6 主人能在界面上确认或取消确认一页记忆

- **Approach**：补一个设置确认状态的路由，记忆详情加一个确认开关。
- **Touches**：记忆路由、记忆详情界面、renderer API。
- **Test seam**：现有记忆路由测试与记忆页面前端测试。
- **Acceptance**：[ ] 详情页可切换确认状态，刷新后保持　[ ] 切换会留下版本快照和审计记录　[ ] 确认后的页面立即受 R-5 主人已确认的页面不被提炼直接覆盖 保护
- **Hard part**：无。

#### R-7 记忆写入在进程内全局串行

- **Approach**：写队列按数据目录在模块级共享，同一目录下所有服务实例拿到同一条队列；页面文件的写入也纳入队列。
- **Touches**：记忆存储、主题索引、版本、治理队列四个存储模块。
- **Test seam**：现有写入一致性验证脚本，扩成跨实例并发场景。
- **Acceptance**：[ ] 两个服务实例并发写 20 页，索引恰好 20 条　[ ] 两个实例并发入队 20 条治理请求，一条不丢　[ ] 现有单实例测试全部通过
- **Hard part**：队列里的任务如果再调用同一队列会死锁。合并、删除这类组合操作要先查清嵌套写入路径。

#### R-8 提炼不拖慢回复完成

- **Approach**：先保存回复并发出 `done`，再在后台跑提炼；兜底回复和中断的回合不提炼。为测试和验收保留一个等待提炼完成的钩子。
- **Touches**：对话编排、流式路由。
- **Test seam**：现有编排器测试和流式中止测试。
- **Acceptance**：[ ] `done` 不再等待提炼的模型调用　[ ] `done` 之后立即刷新历史，本轮回复已经可见　[ ] 兜底回复不触发提炼　[ ] 提炼失败只写审计，不影响已返回的回复
- **Hard part**：编排器里的旧决策（代码注释标为"R-01"，与本文编号无关）让提炼先于回复落库，以消除前端轮询窗口。新顺序必须保持"`done` 时回复已落库"，否则会重新引入旧问题。这条依赖之前要先确认没有其他代码假设"`done` 时提炼已完成"。

#### R-9 巡检能从界面触发，审计日志能在界面查看

- **Approach**：治理面板加"巡检"按钮，调用已有接口；补一个审计日志只读路由，记忆页加审计视图，按时间倒序并可按页面过滤。
- **Touches**：记忆路由、记忆界面、renderer API。
- **Test seam**：现有记忆路由测试与记忆页面前端测试。
- **Acceptance**：[ ] 点击巡检后新的修复建议出现在治理队列　[ ] 重复点击不产生重复请求　[ ] 审计视图能看到最近的页面创建、更新、归档、提炼事件
- **Hard part**：审计日志是只追加文件，长期会变大；路由要限制条数。

### 2.3 前后端联调

#### R-10 记忆页面能在界面上合并

- **Approach**：在记忆详情选一页作为合并来源，确认后调用已有合并接口，完成后跳到目标页。
- **Touches**：记忆界面。
- **Test seam**：现有记忆页面前端测试。
- **Acceptance**：[ ] 合并后来源页变为已归档　[ ] 目标页保留两页的来源和别名　[ ] 合并前有确认弹窗
- **Hard part**：合并不可轻易撤销，确认文案要写清哪一页会被归档。

#### R-11 收支、待办、日程的类目能在界面上管理

- **Approach**：做一个三域共用的类目管理组件，接已有的类目接口，分别挂在三个页面上。
- **Touches**：收支、待办、日程三个界面，renderer API。
- **Test seam**：现有三域前端测试，加类目路由的现有验证脚本。
- **Acceptance**：[ ] 三域都能新增、改名、停用、恢复类目　[ ] 待办和日程能调整类目顺序　[ ] 新类目立即出现在记录表单的下拉里
- **Hard part**：三域的类目接口形状不完全一致（收支按收入和支出分开）。组件只吸收差异，不改接口。

#### R-12 聊天展示联想话语，工具结果刷新后不消失

- **Approach**：完成结果里的联想话语渲染在回复上方；工具结果按回复消息 ID 在会话内缓存，历史刷新后重新挂回对应消息。
- **Touches**：聊天界面。
- **Test seam**：现有聊天面板前端测试。
- **Acceptance**：[ ] 钻取轮产生的联想话语在回复前可见　[ ] 发送完成、历史刷新后工具结果面板仍在　[ ] 切换日期再切回，同一会话内仍在
- **Hard part**：工具结果跨重启持久化需要后端存储，本计划不做；文档和界面都不应暗示它会跨重启保留。

#### R-13 观察详情展示它关联的记忆

- **Approach**：观察详情接口反查引用了这条观察的记忆页，以 `memoryLinks` 返回，前端已有组件直接展示。
- **Touches**：观察路由、记忆服务的反查。
- **Test seam**：现有观察路由测试。
- **Acceptance**：[ ] 被某页引用的观察，详情里出现该页标题　[ ] 点击能跳到记忆页　[ ] 没有关联时显示空状态
- **Hard part**：反查要遍历页面来源，页面多时偏慢；先用轻索引，必要时再建反向索引。

#### R-14 记忆列表返回真实总数

- **Approach**：列表接口在分页前计数，`total` 返回过滤后的总条数。
- **Touches**：记忆服务、记忆路由。
- **Test seam**：现有列表分页验证脚本。
- **Acceptance**：[ ] 共 30 页、每页 10 条时，`total` 为 30　[ ] 带类型过滤时，`total` 为过滤后的条数
- **Hard part**：无。

#### R-15 治理面板用人话展示类型、状态和证据

- **Approach**：类型和状态映射成中文标签；证据按类型渲染关键字段（涉及页面、动作、原因），原始 JSON 收进可展开区域。
- **Touches**：记忆界面。
- **Test seam**：现有记忆页面前端测试。
- **Acceptance**：[ ] 所有现有请求类型和五种状态都有中文标签　[ ] 证据默认显示摘要，原始数据可展开　[ ] 未知类型回退为原始值，不报错
- **Hard part**：请求类型散落在多个后端模块，要先列全，才能保证映射不漏。

#### R-16 日程可编辑，聊天可按关键词搜索

- **Approach**：日程列表加编辑入口，复用新建表单；聊天日期导航加搜索框，调用已有片段搜索接口，点击结果跳到对应日期。
- **Touches**：日程界面、聊天界面、renderer API。
- **Test seam**：现有日程与聊天前端测试。
- **Acceptance**：[ ] 编辑日程的标题、时间、地点后列表更新　[ ] 搜索关键词显示命中片段　[ ] 点击命中跳到对应日期
- **Hard part**：无。

### 2.4 产品功能

#### R-17 精灵窗口与主窗口数据联动

- **Approach**：主窗口写操作成功后广播变更事件；精灵订阅后刷新气泡内容（如今日待办数），主窗口订阅后刷新当前页。
- **Touches**：renderer 的请求层、精灵组件、各业务页面。
- **Test seam**：现有精灵前端测试，用桌面桥替身驱动。
- **Acceptance**：[ ] 主窗口新增待办后，精灵显示的数量更新　[ ] 对话中通过工具写入后，打开的业务页自动刷新
- **Hard part**：广播放在请求层统一做还是各页面各自做，要先定下来；放在请求层最省事，但会把"只读请求"也误判成变更。

#### R-18 待办和日程到点提醒

- **Approach**：主进程按分钟检查即将开始的日程和到期待办，用系统通知提醒，并让精灵冒泡；同一条只提醒一次。
- **Touches**：Electron 主进程、待办和日程服务、精灵。
- **Test seam**：一个新的 seam：提醒调度函数，注入当前时间和通知函数。这是最低可用的一个。
- **Acceptance**：[ ] 日程开始前 10 分钟收到一次通知　[ ] 应用重启后同一条不重复提醒　[ ] 已完成的待办和已取消的日程不提醒
- **Hard part**：提醒提前量是否可配置、错过的提醒是否补发，都还没定，开工前要确认。

#### R-19 日记的 Cornie 部分每日自动生成

- **Approach**：应用启动和跨日时，为前一天有聊天记录但没有 Cornie 日记的日期补生成；模型不可用时跳过，不写空内容。
- **Touches**：Electron 主进程、日记服务。
- **Test seam**：现有日记服务测试，加 R-18 待办和日程到点提醒 的调度 seam。
- **Acceptance**：[ ] 前一天有聊天、无日记时，启动后自动生成　[ ] 已有日记的日期不覆盖　[ ] 模型不可用时不写入，下次启动重试
- **Hard part**：会在用户不知情时调用外部模型，产生网络请求和费用；是否默认开启要先确认。

#### R-20 设置页能导出本地数据

- **Approach**：设置页加"导出数据"，把数据库和记忆文件目录打成一个压缩包，由主进程弹保存对话框。
- **Touches**：设置界面、Electron 主进程。
- **Test seam**：一个新的 seam：导出函数，注入数据目录和输出路径。
- **Acceptance**：[ ] 导出包含数据库文件和完整的记忆目录　[ ] 导出包不含模型密钥　[ ] 导出过程中继续写入不损坏导出包
- **Hard part**：导出时数据库仍在写入；应先落一次盘再复制。导入（恢复）不在本计划内。

## 3. 阶段

### Phase 1 — 门禁说的是真话

**Covers**：R-1 `npm run test:fast` 和 `npm run test:full` 在 Windows 检出上转绿。

**Goal**：**在一台新克隆的 Windows 机器上，`npm run test:full` 从头到尾通过。**

**Tasks**

- 在新克隆上跑一次完整门禁，记下每一处失败
- 加入仓库级换行约定，固定工作区为 LF
- 单独提交一次全仓换行重规范化
- 格式化剩余的 Prettier 差异
- 在新克隆上复跑 `npm run test:full` 并记录结果

**Proof**：新克隆上 `npm run test:full` 退出码为 0。
**Not here**：任何业务改动；CI 接入。

### Phase 2 — 提炼只改它看得见的页面

**Covers**：R-2 提炼轮能引用它要改动的页面和观察，R-3 破坏性提议入队前校验目标存在，R-4 提炼输入按当前对话召回相关页面，R-5 主人已确认的页面不被提炼直接覆盖。

**Goal**：**和铃湾聊到一个已有主题时，提炼更新的是那一页而不是新建一页；改动主人已确认的页面时，变更进入治理队列等待审批。**

**Tasks**

- 用模型替身打通一条路径：提示词带 ID，`update_page` 命中已列出的页面并生效
- 拒绝引用本轮输入之外 ID 的更新和破坏性提议，并记入审计
- 破坏性提议入队前校验目标页面和版本
- 提炼输入改用对话召回的分层排序
- 已确认页面的更新改为生成待审请求，并接入应用与终态流转
- 用替身覆盖端到端：聊到已有主题、更新已确认页、批准、应用

**Proof**：记忆 e2e 测试覆盖以上四条需求的全部验收项并通过。
**Not here**：界面上的确认开关；写队列并发；提炼时延。

### Phase 3 — 记忆写入不丢、回复不等

**Covers**：R-7 记忆写入在进程内全局串行，R-8 提炼不拖慢回复完成；加固 R-5 主人已确认的页面不被提炼直接覆盖（后台提炼与界面写入并发）。

**Goal**：**回复在模型说完后立即完成，提炼在后台写入；两路并发写入不丢任何一页。**

**Tasks**

- 写一个跨实例并发写入的红测试，复现丢更新
- 把四个存储模块的写队列改为按数据目录共享
- 理清合并、删除的嵌套写入路径，排除队列内死锁
- 把提炼移到 `done` 之后的后台执行，保留测试用的等待钩子
- 兜底回复和中断回合跳过提炼
- 覆盖"`done` 后立即刷新历史，回复已可见"

**Proof**：跨实例并发测试中索引和治理队列的条数精确；流式测试中 `done` 早于提炼完成，回复已落库。
**Not here**：多进程或多设备间的数据同步。

### Phase 4 — 主人能看见并纠正记忆治理

**Covers**：R-6 主人能在界面上确认或取消确认一页记忆，R-9 巡检能从界面触发、审计日志能在界面查看，R-10 记忆页面能在界面上合并，R-14 记忆列表返回真实总数，R-15 治理面板用人话展示类型、状态和证据。

**Goal**：**主人在记忆页能确认一页、合并两页、触发巡检，并在审计视图看到这些操作的记录；治理面板全部是中文。**

**Tasks**

- 打通确认开关：路由、renderer API、详情页开关，刷新后保持
- 治理面板加巡检按钮，并为全部请求类型和状态补中文标签与证据摘要
- 补审计日志只读路由和记忆页的审计视图
- 详情页加合并入口和确认弹窗
- 修正列表的总数
- 用前端测试覆盖确认、合并、巡检、审计四条交互

**Proof**：按 `doc/Cornie-031-Phase3-记忆Demo演示脚本.md` 装载 Demo 数据，手动走完确认、合并、巡检、查看审计，每一步在界面上可见；前端测试通过。
**Not here**：审计日志的轮转与清理。

### Phase 5 — 后端已有的能力都能在界面用上

**Covers**：R-11 收支、待办、日程的类目能在界面上管理，R-12 聊天展示联想话语、工具结果刷新后不消失，R-13 观察详情展示它关联的记忆，R-16 日程可编辑、聊天可按关键词搜索。

**Goal**：**主人能在界面上管理三域类目、编辑日程、搜索聊天，看到联想话语和关联记忆，不再需要通过对话绕路。**

**Tasks**

- 先接收支类目，做出三域共用的类目管理组件
- 把类目组件挂到待办和日程，补排序
- 渲染联想话语，并按回复 ID 保留工具结果
- 观察详情返回并展示关联记忆
- 日程加编辑入口，聊天加关键词搜索
- 逐页对照路由清单，确认没有遗漏的已有接口

**Proof**：路由清单中每个面向主人的接口都有界面入口，或在文档里写明为何不做；前端测试通过。
**Not here**：后端新接口；工具结果跨重启持久化。

### Phase 6 — 不打开主窗口也照顾得到主人

**Covers**：R-17 精灵窗口与主窗口数据联动，R-18 待办和日程到点提醒，R-19 日记的 Cornie 部分每日自动生成，R-20 设置页能导出本地数据。

**Goal**：**主窗口关着时，精灵会按时提醒待办和日程，第二天打开就有铃湾写好的日记；主人能一键导出全部本地数据。**

**Tasks**

- 先确认三项产品决策：提醒提前量、错过的提醒是否补发、自动生成日记是否默认开启
- 打通数据变更广播：主窗口写入后精灵刷新
- 做提醒调度 seam，接系统通知和精灵冒泡
- 启动与跨日时补生成前一天的日记
- 设置页加数据导出，排除模型密钥
- 安装包实机走一遍：提醒、跨日日记、导出

**Proof**：在 Windows 安装包上实测，提醒按时出现且不重复，跨日后日记自动生成，导出包能解开并包含数据库和记忆目录。
**Not here**：数据导入与恢复；云端同步；移动端提醒。
