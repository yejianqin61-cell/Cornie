# Cornie-doc文档规范

## 1. 文档目的

本文档用于统一 `docs/` 目录下的文件命名、结构版式和编写规则，确保产品、设计、研发、测试、运维等角色在同一套文档约束下协作，降低后续扩写和维护成本。

## 2. 文件命名体系

### 2.1 主干文档命名

主干文档统一采用以下格式：

`Cornie-顺序号-文档名称.md`

适用对象：

- 项目生命周期中的主基线文档
- 需要长期维护的正式文档

示例：

- `Cornie-00-文档规范.md`
- `Cornie-01-项目立项策划案.md`
- `Cornie-02-产品需求文档.md`

规则要求：

- `顺序号` 使用两位数字，例如 `00`、`01`、`02`。
- 文件名中不写版本号、日期、作者名；相关信息保留在正文元数据与修订记录中。
- `文档名称` 使用稳定、清晰的中文名称，避免同义词混用。

### 2.2 模块/专题文档命名

直接派生自上游文档某个功能模块、章节或专题的文档，采用以下格式：

`Cornie-章节号-模块名称-文档类型.md`

适用对象：

- 模块设计评估
- 模块详细设计
- 模块测试用例或专题分析

示例：

- `Cornie-10.1-登录身份认证与远程主机连接-设计评估.md`
- `Cornie-10.1-登录身份认证与远程主机连接-详细设计.md`

规则要求：

- `章节号` 继承上游主文档中的章节编号，可保留小数形式，例如 `10.1`。
- `模块名称` 在文件名中去掉顿号、逗号等阅读性标点，保留核心语义。
- `文档类型` 使用稳定后缀，例如 `设计评估`、`详细设计`、`测试用例`。

### 2.3 通用命名要求

- `项目名` 固定为 `Cornie`。
- 文件名统一使用半角连字符 `-` 分隔，不使用空格。
- 一个文件只承载一个稳定主题，不在同一文件中混入其他文档正文。
- 若文档定位变化，应优先调整 `文档类型` 后缀，而不是随意改动编号。

### 2.4 推荐主干编号

| 编号 | 文档类型             | 示例                                                 |
| ---- | -------------------- | ---------------------------------------------------- |
| 00   | 文档规范/目录说明    | `Cornie-00-文档规范.md`                              |
| 01   | 立项与策划           | `Cornie-01-项目立项策划案.md`                        |
| 02   | 产品需求             | `Cornie-02-产品需求文档.md`                          |
| 03   | 原型与交互           | `Cornie-03-交互原型说明.md`                          |
| 04   | 技术方案             | `Cornie-04-技术方案设计.md`                          |
| 05   | 测试方案             | `Cornie-05-测试计划.md`                              |
| 06   | 部署与运维           | `Cornie-06-部署运维手册.md`                          |
| 10.x | 模块级评估或专题设计 | `Cornie-10.1-登录身份认证与远程主机连接-设计评估.md` |

## 3. 文档格式规范

### 3.1 标准结构

所有正式文档建议至少包含以下结构：

1. 文档信息
2. 文档目的
3. 正文主体
4. 附录或引用说明（可选）

### 3.2 标题格式

- 主干文档一级标题使用 `# Cornie 文档名称`。
- 模块/专题文档一级标题使用 `# Cornie 章节号 模块名称文档类型`。
- 正文标题层级统一从 `## 1. ...` 开始编号，不跳级使用标题层级。

示例：

- `# Cornie 项目立项策划案`
- `# Cornie 10.1 登录、身份认证与远程主机连接设计评估`

### 3.3 文档信息

文档信息章节统一包含以下字段：

- 文档名称
- 文件名称
- 产品名称
- 文档编号
- 文档类型
- 文档版本
- 文档状态
- 编写日期
- 适用对象
- 上游文档
- 下游文档
- 关联规范
- 存放目录

### 3.4 修订记录

文档信息章节下应包含修订记录表，字段建议如下：

| 版本 | 日期       | 修订人 | 修订说明     |
| ---- | ---------- | ------ | ------------ |
| V1.0 | 2026-05-06 | 示例   | 首次建立文档 |

### 3.5 正文编排

- 一级章节使用 `## 1. 章节名` 格式。
- 二级章节使用 `### 1.1 章节名` 格式。
- 三级章节使用 `#### 1.1.1 章节名` 格式；如仅作局部说明，可保留无编号小标题。
- 流程、角色、需求项、指标项优先使用表格、列表和 Mermaid 图表达。
- 结构化信息优先使用表格，不在长段落中堆砌元数据。

### 3.6 引用与链接

- 引用 `docs/` 目录内文档时，统一使用相对路径，例如 `docs/Cornie-02-产品需求文档.md`。
- 正文中若引用上游章节，应明确标注章节号，便于追溯。
- 文件名与正文中出现的文档名需保持一致。

## 4. 维护规则

- 每次重要修改后同步更新修订记录。
- 新建主干文档时先分配顺序号，再确定文档名称。
- 新建模块/专题文档时先确认其上游章节号，再确定模块名称与文档类型。
- 同一主题仅保留一个正式主文件，历史变更通过 Git 与修订记录维护。
- 若文档性质发生变化，应优先调整正文内容与文档类型说明，避免频繁重命名。
