# task-004 聊天记录页、单日回看页与待确认事项页

## 目标

构建聊天相关的三个二级页面：聊天记录列表、单日聊天回看、待确认事项。

## 背景

当前 `ChatHistory.vue` 承担了聊天记录查看功能，`CorniePet.vue` 中的 `ConfirmCard` 和 `restorePendingConfirmations` 处理确认流。本次重构需要：
1. 重构聊天记录页符合新的视觉语言
2. 新增单日聊天回看页
3. 将待确认事项独立为一个干净的二级页面

## 变更规格

### 聊天记录页 (ChatHistory.vue 重写)

**首屏内容**：
- 按月筛选（保留现有 month input）
- 日期列表（按天分组，显示每天消息数）
- 点击进入单日回看
- 空状态：温和提示"这里还没有聊天记录"

**不应出现**：
- 阅读辅助细枝末节
- 回流提示
- 同日关联线索
- 内部跳转状态

**样式**：浅色底、轻卡片、列表疏朗

### 单日聊天回看页 (ChatDayView.vue 新建)

**内容**：
- 日期标题
- 按时间顺序的对话内容（用户 + Cornie）
- 返回聊天记录页的导航
- 简单加载/空状态

**不应出现**：
- 历史沉淀链路
- 记忆引用标注
- 透明技术面板

### 待确认事项页 (PendingConfirmations.vue 新建)

这是设计文档中强调的"少量打扰但必须确认的收口点"。

**内容**：
- 待确认列表（仅保留 4 类确认）：
  1. 新建类目确认
  2. 高风险删除确认
  3. 重要内容覆盖确认
  4. 高风险记忆写入确认
- 每条确认：简短说明 + 同意/拒绝 按钮
- 空状态："没有需要确认的事项"
- 处理中/已完成状态

**不应出现**：
- 页面合并确认
- 页面回滚确认
- 批量治理确认
- 巡检候选处理

**不应做成**：
- 治理中心
- 系统消息堆放区
- 低频复杂任务总入口

**API**：复用现有 `listConfirmations`、`submitConfirmationDecision`、`getConfirmation`

**样式**：
- 卡片简洁，每个确认项独立
- 同意按钮用 `var(--accent)`
- 拒绝按钮用次级样式
- 已处理项灰度

## 验收条件

1. 聊天记录页可按月筛选、按天查看消息数
2. 点击日期进入单日聊天回看，对话按时间顺序展示
3. 待确认事项页只显示 4 类确认
4. 待确认卡片可同意/拒绝
5. 所有页面视觉符合新设计语言
6. 页面间导航链路：聊天首页 → 聊天记录 → 单日回看；聊天首页 → 待确认页
